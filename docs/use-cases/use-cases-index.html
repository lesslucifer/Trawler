web-ui.html UC-6 The HAR 1.2 round trip: out over GET /flows/export — the export selects what the listing lists — and back in over POST /flows/import, whose entries become ordinary flows marked imported and selectable by that mark. A body Trawler never captured is marked as such in both directions, never treated as empty; a malformed document is refused whole, changing nothing. The same door under ?format=curl takes one pasted curl command — what a browser's "Copy as cURL" emits — as a request-only imported flow, refusing any flag outside that set by name active
web-ui.html UC-7 Clearing the capture: DELETE /flows removes what the listing filters select — the same filter, no third implementation — and DELETE /flows/{id} removes one, 404 when it is not there. Every live subscriber learns of it as one cleared event for the batch, distinct from the ring's own eviction. A cleared store is empty, not restarted: the connection tally and the running proxy are untouched active
web-ui.html UC-8 Sending a request again, edited or from scratch: POST /flows/{id}/replay merges overrides onto a seed (an absent field is the seed's own value) and POST /flows takes a whole request, through one sender that verifies TLS as the proxy does. The exchange lands as an ordinary flow marked sent, naming its seed, and selectable by that mark. A seed body never captured is refused rather than sent empty, and a send that got no reply lands no flow (DEC-58). The app's composer takes the detail pane: one draft, only the edited row marks itself, and the outcome lands under the send button active
