Use Cases — UI surfaces

What a user can do against a running Trawler from a UI, stated as observable contracts. Two surfaces, one API: the zero-setup web shell (UC-3) and the native desktop app (UC-4 watch · UC-5 inspect), plus the native app's guided onboarding to the first captured flow (UC-ONBOARD).

UC-3 — Watch live traffic in the browser, zero setup

With Trawler running, opening GET / on the control API port in a browser serves a self-contained flow-list page straight from the binary — no install, no build step, no configuration, no external assets required for the list to function.

  • The page lists captured flows newest-first (time, method, host, path, status, duration) and updates live as traffic passes the proxy — new flows appear without a manual refresh, driven by the GET /stream SSE events.
  • A filter bar narrows the list by host, method, status and free text with exactly the GET /flows query-parameter semantics — the page delegates filtering to the API rather than reimplementing it.
  • The page is a plain client of the public control API; everything it shows is equally reachable with curl. It renders untrusted capture data (URIs, methods from proxied traffic) as text, never as markup.
  • Shutting Trawler down stays clean even while the page holds its never-ending SSE connection open.

Pinned by ui_shell_serves_live_filterable_flow_list in tests/e2e_capture.rs (page served, filter narrows, SSE event arrives, clean shutdown with the stream open) and the shell contract tests in tests/api.rs. In-browser rendering is covered by a recorded manual check. The shell's minimal chrome is deliberate; the native app (UC-4) is the designed surface.

UC-4 — Watch live traffic in the native app

With Trawler running, launching the native desktop app (E-UIFOUND, Tauri + React) shows the captured flows (method, host, path, status, duration) in the Warp-styled base layout and updates live as new traffic passes the proxy, via the existing GET /stream SSE stream.

  • A filter bar narrows the list by host, method, status and free text — the same GET /flows query-parameter semantics as UC-3, because the app delegates filtering to the API rather than reimplementing it. Status color distinguishes 2xx / 4xx / 5xx at a glance. The two keys the API matches exactly are chosen, not typed: method from the closed set of verbs, host from the hosts capture has seen, each with an "any" option that clears it. Free text and status stay typed — the API substring-matches the first, and the second is deferred (a status class query is not expressible against the current API at all).
  • The app is a pure cross-origin client of 127.0.0.1:7421 — it reaches no core internals; everything it shows is equally reachable with curl. Because the webview origin differs from the API's, every API response carries an open CORS grant (DEC-12); without it the webview's fetch/EventSource would be blocked.
  • The API base URL is configurable (never a hardcoded port in component code): a runtime value wins over a build-time env, which wins over the :7421 dev default — the released app exposes it as configuration.

Six capabilities the redesign (E-REDESIGN W2/W4, designed at the flow-list run) made observable. The contract keeps its shape — these are things a user can now do or perceive that they could not before:

GainWhy it is a contract change and not a restyle
A status carries its reason phrase 403 announces as "403 Forbidden" in its title and accessible name. A screen-reader user previously got a naked number, and colour was the only channel telling outcomes apart.
The capture indicator is a real target with a name A 24 px hit area and an accessible name carrying its state phrase, so the app's one route back to setup is reachable and announced rather than a 10 px unnamed disc.
A row is operable by keyboard The list is a listbox with one tab stop: ↑/↓ move the selection without wrapping and Enter or Space opens the detail. Selecting a flow previously required a pointer — there was no keyboard path at all.
An empty list says which nothing it is Nothing captured yet names the proxy address to send traffic to; a filter that excludes the traffic says so and names the act that widens it. One sentence previously served both, telling users to send traffic they had already sent.
An exactly-matched filter is chosen rather than typed Method and host are dropdowns. Typing GE into the old free-text method box returned an empty list indistinguishable from no traffic, because the server matches the verb whole — a query the user could write but never satisfy. What the dropdown costs is stated: a partial host (api. matching every API host) is no longer expressible there, and the free-text key covers it.
The verb is toned by what it does to the resource GET/POST/PUT/PATCH/DELETE read apart at a glance in the method column, which previously carried no tone.

One rule is knowingly unmet. The host and path cells truncate rather than wrap, because a virtualized fixed-height row cannot both wrap and stay one line. The full value stays reachable — on the row's title and in the detail pane — and the missing rulebook clause is recorded against the epic close rather than papered over.

Pinned by the epic e2e (ui/e2e/specs/flows.spec.ts, cargo xtask ui e2e): WebdriverIO drives the real WebKit window against an ephemeral run(Config) core — empty layout renders, a proxied request appears live carrying every column, the status pill carries its reason phrase, the filter narrows and restores, an unmatched filter states its own absence, the keyboard alone selects a row and opens its detail, and a second request appends without refresh. Unit + integration layers (Vitest + Testing Library) cover the status-color mapping, the typed client, filter→params, and the layout+list against a mock API. Existing API contracts (GET /flows, GET /stream) are consumed unchanged; the CORS grant is the one API-response addition. UC-3 (web shell) stays valid — both surfaces are clients of the same API.

UC-5 — Inspect a captured flow in the native app

Clicking a flow row in the native app (E-UIINSPECT) opens the detail panel over GET /flows/{id} — request line, status with the 2xx/4xx/5xx functional color, total duration, per-leg HTTP versions, and the full request + response header tables. No new endpoint; the panel is a pure client of the existing API.

  • Both legs are on screen at once: the panel carries a Request body and a Response body section, each rendering one body with its own raw/decoded state — comparing the two is scrolling, not toggling.
  • Bodies render by content type over GET /flows/{id}/{leg}/body: JSON and XML/HTML as their pretty-printed source in a navigable, foldable surface, image/* as the image over a transparency checkerboard, form-urlencoded as decoded key/value rows (each value individually copyable), other text as text, anything else as a toned hex dump.
  • Raw shows the source, not the compression frames: the raw / decoded toggle switches between the bytes the server sent (?decode=source — transport encoding reversed, nothing re-indented or transcoded) and the fully rendered view (?decode=1 — decompressed, charset-normalised, JSON/XML pretty-printed). A gzipped JSON body therefore reads as its minified source in raw rather than as a hex dump of gzip frames, and hex is reserved for payloads that genuinely have no text form. The stored bytes stay reachable at ?decode=0.
  • A truncated body says so: renderings are capped (128 KiB of characters, 4 KiB of hex) and a capped body states "showing N of M — save to see all" in warn tone, naming the size shown, the real total, and the way to the rest. No cap is silent, and no body is re-indented client-side — what is shown is what crossed the wire, so a copy is evidence.
  • States are never blank: an empty, streaming-passthrough, too-large, read-error, not-yet-responded, in-flight or failed-to-load body shows an explicit notice instead of a viewer — one distinct sentence per cause, and warn tone only on the one that is a fault.
  • Copy-as-curl reproduces the request (method, URL, headers, body, shell-quoted); copy body puts the shown body on the clipboard (the hex dump for hex-rendered bodies; hidden for images); save body writes the shown leg's bytes to a file via the OS save dialog, named after the endpoint — the URI's last path segment, or the host when the path names nothing — plus the leg and the extension the served content type implies (charges-response.json, example.com-response.html), so a saved body is recognisable in a downloads folder and opens in the right application.
  • The ?decode=1 contract is server-side — gzip/deflate/brotli reversal, charset→UTF-8, JSON + XML pretty-printing — so curl and the web shell gain the same decoded view the app shows.

Pinned by the inspector e2e (ui/e2e/specs/flows.spec.ts): row click → headers / timing / versions; a JSON response renders as copy-exact source; the raw toggle shows the served source as text; the curl text is asserted in the DOM (WebDriver clipboard is unreliable — the real clipboard write is a recorded manual check, as is the native save dialog); a brotli-compressed JSON body still renders decoded — the decode chain proven through the UI; a proxied PNG renders as an image; an XML body renders as XML rather than falling through to text; a brotli body in raw shows its minified source rather than a hex dump of its frames; a body past the render cap states its truncation; and both leg sections stand on the page together. The decode chain itself is pinned at the API seam in tests/api.rs and the src/api/decode.rs unit suite; viewer dispatch, states, and copy/save are covered by the Vitest unit + integration layers. scripts/seed-proxy.mjs seeds one flow per case for manual checks.

UC-ONBOARD — Onboard a fresh machine to the first captured flow

On a machine that can't yet decrypt HTTPS, the native app opens a three-step guided setup — Trust the CA · Set the proxy · Make a request — instead of the flow list. Its rule (E-UISETUP): do the work for the user in the common case, tell the truth in every case, and prove success only by real capture.

  • Least manual work. On macOS/Windows each step offers one native action (install the CA, set the system proxy — both elevation-gated); the per-OS manual steps sit behind a "Set it up manually" disclosure that auto-opens if the action fails. Other OSes show the manual steps inline. Instructions are always plain text, never markup.
  • Two-truths status per step (never the stepper cursor — a step is never ✓ just because you clicked past it). Each step's honest status comes from either of two independent signals:
    • a fast local probe — does this machine trust the CA / route its system proxy to Trawler? (the ~90% single-machine case; instant, read-only OS queries), or
    • observed traffic — has anything actually reached Trawler, from any device?
    When the probe can't conclude (un-probeable OS, or a remote device) the wording says so and points at capture — it never shows a false "not set up".
  • The proxy step goes green on any connection, decrypt or not. An HTTPS attempt from a client that doesn't trust the CA fails its TLS handshake and produces no flow — so the core counts the tunnel itself: GET /stats returns a monotonic connections tally and a connection SSE event fires. That proves "traffic is routing through Trawler" even before decryption works. Traffic seen but not decrypting ⇒ the Trust step's verdict reads "arriving but not decrypting" and its remedy says "install the certificate on the device you're capturing from" — the verdict and what to do about it are two elements, so a short verdict never costs the instruction.
  • Only a decrypted flow reveals the list. A probe-green step or a bare connection never ends onboarding — the payoff (the last step → flow list) fires solely on the first https:// flow (a decrypted request the MITM rewrote to absolute form). The last step shows a concrete prove-it: open any site, or run a copyable curl -x http://<addr> https://example.com with the real proxy address. Capture, once proven, latches (the status dot re-invokes setup on demand; "Back to flows" returns).
  • The certificate is saved by an action, not by an instruction (E-REDESIGN.W10). Every manual route's first step names trawler-ca.pem, so the screen produces that file: save certificate fetches /ca.crt and writes it through the OS save dialog (native) or a download (browser), under exactly the name the following steps run against. The save reports what actually happened rather than assuming it: a failure says so, a cancelled dialog says nothing was saved (it resolves exactly like a write), and a save the user renamed — the offered name is only the dialog's default — is confirmed under the name that landed, with the mismatch against the steps below named outright.
  • A probe reading can be asked for again (E-REDESIGN.W10). Nothing pushes when the user changes the trust store or the system proxy outside Trawler, so a green verdict outlives its truth until something re-reads the machine. Each probed step carries check again, re-running both probes; the verdict that comes back replaces the stale one, green or not.
  • A copied command says whether it copied (E-REDESIGN.W10). Both commands — the prove-it and the per-OS proxy snippet — are the copy target themselves, confirming at the value; a clipboard write the browser refuses says copy failed rather than doing nothing visible.
  • Quitting with a proxy still set asks first, and can fix it (E-REDESIGN.W10). Where a proxy is set on this machine — Trawler's or another's, since turning the OS proxy off does not depend on whose address is set — the dialog offers to turn it off, and a failed attempt says so and opens the manual steps instead of quitting onto a dead proxy. Where nothing is set locally but a remote device may still route here, it is a notice with a durable "don't show this again". Esc, the backdrop and ✕ all cancel the quit.

  E["Enter setup (no decrypted flow yet)"] --> PR["Probe this machine: CA trusted? proxy set?"]
  PR --> ST["Trust and Proxy steps show local status instantly"]
  E --> W["Watch traffic: GET /stats + connection and flow SSE events"]
  W --> C{"What arrived?"}
  C -- "any connection" --> PX["Proxy step green: receiving traffic"]
  C -- "http flow, no https" --> TR["Trust: not decrypting, install the CA on the sending device"]
  C -- "https flow (decrypted)" --> OK["Trust green + last step green: reveal the flow list"]
Probes light the steps instantly for the local case; observed traffic confirms — and, for a remote device, is the only thing that can. The list reveal is decrypted-flow-only.

New API surface (consumed by onboarding, usable by any client): GET /stats → { connections } and the connection SSE event ({ authority }) on the existing /stream. The connection tally is a monotonic counter in the store, bumped when the proxy opens a CONNECT tunnel — kept outside the flow ring so eviction never touches it. The two local probes (CA-in-trust-store, system-proxy-address) live in the Tauri app, not the core; they read the real machine so they are not hermetically testable (the status derivation they feed is fully unit-tested). This deliberately supersedes two earlier "prove by capture only" stances (no trust-store inspection / no OS self-test): the probe covers the 90% for instant honest feedback; capture stays the authority for the remote cases and the sole thing that reveals the list. Pinned by tests/e2e_capture.rs::untrusted_https_records_a_connection_not_a_flow (a failed handshake bumps /stats + emits connection, records no flow), the status derivation + probe-parser unit tests, and the UC-ONBOARD e2e spine. Why these reversals were approved: DEC-13.
