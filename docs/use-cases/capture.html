Use Cases — Capture & Inspection

What a user can capture through the proxy and inspect on the control API, stated as observable contracts.

v1 · 2026-07-06 · Trawler · seeded by epic E-H2

UC-1 — Intercept HTTPS without protocol distortion

A client pointed at the proxy (http_proxy/https_proxy, CA from GET /ca.crt trusted) exchanges traffic with any origin exactly as it would directly — bodies, headers and status intact — while every exchange is captured.

  • Each TLS leg negotiates its HTTP version independently via ALPN: an h2-capable client speaks HTTP/2 to the proxy even when the origin is HTTP/1.1-only, and vice versa; an h1-only client keeps working unchanged.
  • The proxy offers h2, http/1.1 on both legs and the peer picks — no forced downgrade on either side, no protocol-version configuration surface.
  • Cleartext HTTP/2 (h2c) and HTTP/3 are out of scope; h2 arrives via ALPN on TLS only.

UC-2 — Inspect a flow's true protocol versions

GET /flows/{id} reports, per flow, the HTTP version actually spoken on each leg — never a normalized or assumed value:

FieldLegExample
request_http_versionclient → proxyHTTP/2.0
response_http_versionproxy → originHTTP/1.1

Mixed-version flows (h2 client with an h1-only origin, or the reverse) show the mismatch honestly. Wire format is HTTP/1.0 · HTTP/1.1 · HTTP/2.0.

Both contracts are pinned by the tests/suite/e2e_h2.rs scenarios (both-legs h2, mixed legs in both directions, correlation under h2 multiplexing) and the h1 regression suite in tests/suite/e2e_capture.rs.
