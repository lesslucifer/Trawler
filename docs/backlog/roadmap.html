Context

The capture core is complete (HTTP/1.1 + HTTPS MITM, capped body capture, SSE stream, filtered read-only API, in-memory ring) and nothing product-shaped is planned beyond it. The 2025–26 market read: table stakes everywhere are breakpoints, map local/remote, rewrite, HAR, replay/composer, WebSocket display, session persistence. Four gaps are real: no tool has a stable public control API (mitmproxy's is deliberately internal; only MS Dev Proxy has one, M365-scoped) · LLM traffic debugging is unserved in general proxies · OpenAPI-from-traffic demand is proven (mitmproxy2swagger ≈9.5k stars) but nobody does it first-class · WebSocket is weak everywhere. Trawler's API-first core sits exactly on the first gap.

Choices

ChoiceWhy — do not "simplify" it away
Two pillars, not one directionThe GUI is the adoption gate (nobody evaluates a proxy via curl; Charles proves a complete feature set doesn't survive bad ergonomics) and functionality is the retention floor (mitmproxy is the benchmark). The API-first core fuses them: every GUI capability is a call on the public API, so the GUI never forks the feature surface.
UI is four epics (E-UISHELL → E-UIFOUND → E-UIINSPECT → E-UISETUP), not oneOwner decision. One "UI epic" is unboundable; four bounded epics each carry their own requirement and test plan. E-UIFOUND exists as its own epic so every later UI surface slots into a designed layout — accreting features without one is the Charles failure mode.
Minimal shell (E-UISHELL) ships before the foundation epic (E-UIFOUND)Owner-confirmed order: visible traffic first. The shell's chrome is deliberately minimal and is migrated onto the foundation's layout as its first tenant — a small, accepted rework, priced in rather than accidental.
Native desktop app is the primary UI, not a web page reversal · DEC-12E-UIFOUND reversed the web-primary framing this roadmap opened with. The primary surface is a native Tauri desktop app (Vite + TS + React + Tailwind, mirroring Strata), an out-of-process client of the control API; the embedded web shell is kept as a second client, to be retired later at native-UI parity. The API-first invariant is unchanged — the app reaches no core internals, only 127.0.0.1:7421. Recorded as DEC-12; E-UIINSPECT / E-UISETUP build on this stack.
REST API + rules (E-RULE) instead of embedded scriptingmitmproxy's addon power without shipping a script runtime: anything that can drive HTTP can automate Trawler. Revisit (in-process WASM/JS hook) only if real rule usage proves insufficient.
HTTP/3/QUIC MITM and DNS/TCP/UDP proxying deferredLarge protocol investment with poor client CA support for QUIC; not what the two pillars need first. Revisit after the Wave 1–3 parity set lands.
Differentiators (E-LLM, E-MCP, E-OAS) last, not firstThey lead the market but sit on capture/replay/persistence machinery from earlier waves — sequencing them first would build that machinery twice. E-LLM additionally requires deciding to tee-capture text/event-stream bodies, today a deliberate passthrough invariant.

BodyViewer re-decodes the whole body on every render, and the JSON/XML over-cap fallback re-encodes it to count bytesW3 plumbed a size through BodyViewer → TextRenderer so the cut marker's total is taken rather than re-derived, but only on the text dispatch. It is not a one-line fix: Dispatch feeds those kinds through the lossy bodyText and has no whole flag to gate a size with, so passing one blindly would print a wrong total for a non-UTF-8 body — the CutMarker inversion W3's own round 1 fixed. Streaming the capture in both directions, and the peak memory a one-shot body costsDeferred at E-EXPORT's plan review for the export, and the epic's own close review found the import half owes the same. Export: GET /flows/export serializes the whole filtered capture into one in-memory response; W2's review measured roughly 4× the 256 MB cap on binary bodies, because the cloned flows, the base64-expanded document and the serialized JSON are all live at once — so the bound is that multiple, not the cap. Import: POST /flows/import holds the raw body, the deserialized HAR tree and the decoded flows at once, and its admission ceiling is now twice the cap (the epic close raised it, because the old one refused the store its own export), so its peak scales with that. A streaming parse is the one fix for both. Revisit when a real capture proves either too heavy.
The ring is weighted by body bytes, so a header-heavy capture has no export size any multiple of the cap can boundFound by E-EXPORT's close review. A capture of body-less exchanges — polling, heartbeats, chatty auth traffic — accumulates rows the ring's byte cap does not bound, so its own HAR export can outgrow any constant multiple of that cap. The mechanism, and what the import door therefore does and does not guarantee, are stated where they bind: import_body_limit in src/api/mod.rs. What is deferred is the fix, not the finding — two candidates, neither this epic's to choose: weight the ring by whole rows rather than body bytes, or stream the parse. Revisit with whichever epic next touches the ring's accounting.

Consequences

Landed so far: E-UISHELL and E-H2 (Wave 1) and E-UIFOUND and E-UIINSPECT and E-EXPORT (Wave 2 — the native UI foundation, see the DEC-12 reversal above; the flow inspector on it: UC-5, with the ?decode=1 chain completed server-side; and the capture's three new doors: HAR export and import, a pasted curl command as a flow, DELETE /flows, opt-in paging, and the app's first mutating controls — UC-6, UC-7, DEC-37–DEC-39). Two epics have also worked over that surface rather than adding to the sequence: E-REDESIGN put all five shipped screens through the design flow, and E-RFINISH paid the debt it named — four false registry docstrings, three performance costs behind a committed benchmark, the pane width and window as one decision (DEC-36), a status filter that reads a class end to end, and a flow list that states a core that is not answering instead of freezing on its last rows. Next epic to continue is E-UISETUP (guided onboarding — W1 already merged on its epic branch), whose two shipped screens are re-designed by E-ONBOARD, now unblocked. This roadmap is living — updated in place as epics land; a strategic reversal (dropping a pillar, resequencing a wave) is recorded as a decision and then reflected here. The research substance behind the market claims lives only in the archived scratch doc; if a claim needs re-verification, re-research rather than trusting the archive's age.
