Capture Core — Test Plan

The Testing Standard applied to the first epic: the capture core. Modules are the Working Units; their functions are the commits. This is the pattern every future epic's <epic>-testing.html copies.

Coverage map

Each module is a WU with an owning test level. A module with no row is a gap. The "what must be proven" items are the per-commit unit obligations; the integration/e2e rows name the boundary test that covers the WU/epic.

Invariants (property tests)

Properties that must hold for all inputs — where an unattended agent is most likely to slip. Each gets a proptest generator, not hand-picked cases.

InvariantPropertyApplies to
Byte round-tripFor any bytes and cap, the body capture() forwards is byte-identical to the input. The proxy's cardinal rule — a capture decision never corrupts or drops a byte.capture.rs
Ring accountingAfter any insert / set_response sequence, total_bytes = sum of retained_bytes() over held flows, and either total_bytes ≤ max_bytes or exactly one flow remains.store.rs
Cap honestyA retained body's kept length is always ≤ cap; anything larger is NotCaptured{TooLarge} with the true size — never a truncated body masquerading as complete.capture.rs
Decode lossless & safedecode(gzip(x)) == x and decode(deflate(x)) == x for arbitrary x; arbitrary junk decodes to itself and never panics.api/decode.rs
Filter soundnessAn all-None FlowFilter matches every flow; adding a constraint can only shrink the result set.store.rs
Listing orderlist() is always strictly newest-first by insertion, regardless of response arrival or eviction.store.rs

Testability seams

The capture core is almost testable, but two things in lib.rs::run block a hermetic e2e harness. These are small refactors that keep production behaviour identical by default — they exist so tests drive the real code, not a copy. They land as WUs before the epic's e2e is written; every future epic should likewise budget for the seams its e2e needs.

SeamProblem todayChange
Boot returns handlesrun() binds fixed ports and blocks on ctrl_c. Tests can't learn the :0 port or shut down.Split out serve(config) -> RunningServer { proxy_addr, api_addr, shutdown } that binds, spawns both servers, and returns the resolved addresses + a shutdown trigger. run() becomes serve(...) + signal wait.
Upstream trust hookThe proxy→origin connector trusts system/webpki roots, so a self-signed HTTPS test origin can't be reached through the MITM path.Optional Config field for extra upstream root certs (default none = today's behaviour). Tests inject the test origin's root.
Crypto provider initaws_lc_rs::default_provider().install_default() is process-global; multiple test binaries/threads race or double-install.Wrap the install in a std::sync::Once (or test-only init helper) so it's idempotent.
Clock injection optionalstarted_at/duration_ms use real time; exact values can't be asserted.v1: assert presence/ordering only. Inject a Clock behind the Store only if exact assertions ever matter. Deferred.

The epic's e2e flow

One e2e suite proves the whole capture epic: boot the engine (via the serve() seam) on ephemeral ports, stand up a local test origin, point a proxy-configured client at Trawler, drive traffic, and assert what the control API reports. Only this layer proves the hudsucker wiring, the CA/TLS path, and recorder correlation work together.

sequenceDiagram
    participant T as test
    participant P as Trawler (serve on :0)
    participant O as test origin (axum on :0)
    participant API as control API
    T->>P: serve(config) → {proxy_addr, api_addr, shutdown}
    T->>O: spawn origin (routes: /ok, /gzip, /sse, /big)
    T->>P: client GET via proxy → origin
    P->>O: forward (plain, or MITM-decrypt for HTTPS)
    O-->>P: response
    P-->>T: response body (must equal origin's)
    T->>API: GET /flows, /flows/{id} → assert captured flow
    T->>P: shutdown
Two things asserted every scenario: the client received the origin's bytes unaltered (the proxy is transparent), and the control API captured a faithful record.
ScenarioDrivesAsserts
Plain HTTP GET/POSTforward path, recorder, store, APIflow appears with method/uri/status; bodies captured; client got origin bytes.

HTTPS hermeticity. A real MITM test needs an HTTPS origin, but a self-signed origin is rejected by the proxy's upstream connector and its Trawler-signed leaf is rejected by the client. Fix, entirely test-side: one test CA signs the origin cert and is injected via the upstream trust seam, while the client trusts the Trawler CA fetched from /ca.crt. Both anchors are ephemeral; no network.

Build order

Unit-first, then WU integration, then seams + epic e2e, then hardening. Future epics follow the same shape.

PhaseDeliverableDepends on
1 — Unit + propertyInline tests for every module's commits; the six invariant property tests; shared builders. Highest correctness-per-effort.nothing (core is ready)
2 — WU integrationtests/api.rs via tower::oneshot; tests/ca.rs with tempfile; SSE liveness; JSON snapshots.Phase 1 fixtures

Out of scope (this epic)

Deferred until a feature needs them: fuzzing the HTTP parser (owned by hudsucker/hyper; at most our capture/decode boundary), loom exhaustive concurrency models (the stress test suffices for the store's simple mutex + broadcast design), load/throughput benchmarks (a criterion suite arrives with performance work), and cross-platform CA-trust installation (manual, per the platform table). Each slots in behind the same seams when its work lands.
