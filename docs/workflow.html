Workflow Standard

How work is planned, gated and merged: epic → working unit → commit, one hook-enforced DoD gate per level, completeness proven from git notes — never from an agent's word.

v1 · 2026-07-05 · Trawler · T1 process doc

The three levels

Work decomposes per the charter in the testing standard, which owns each level's definition and mandatory test. This doc owns everything around that: branches, gates, evidence, merges. Identity ids are E<n> for epics, E<n>.W<m> for working units; git is the registry — no tracker file.

Commiton its WU branch—DoD-C, hooks at commit/pushnone — hooks refuse red commits

Collapse rule: a small epic may be one WU, a small WU one commit — every gate is still met explicitly, with all notes written. Direct-to-main rule: docs/infra-only changes may land without a gate; a standalone code commit (outside any WU) carries a test/v2 note, level: commit, unit ≥ 1 or waived. Code paths are src/, xtask/, tests/.

The merge is the gate: pre-merge-commit runs the verifier and a red gate makes the merge itself fail. Merges are always --no-ff (repo config merge.ff=false) so every gated tip stays addressable from main.

DoD checklists

mechanical = a hook or verify-dod enforces it; judgment = a reviewer decides, and the gate verifies the judgment happened against exactly this diff. Where quality can't be mechanized, the mechanical check is that the judgment happened: a PASS note bound to the diff by diff_sha256.

Waivers

A required test layer may be consciously skipped: integration: { waived: "<why>" } replaces count ≥ 1 at any level. The gate accepts a waiver mechanically (present, non-empty reason); whether it is justified is a review question — an unjustified waiver is a review finding. Vocabulary: waived = judged unnecessary, reason recorded, reviewable · exempt = a rule says no evidence is needed (docs/infra-only diffs).

Every schema carries the same identity block — identity never rides on branch names: epic: E1 · wu: E1.W2 (WU work only) · branch: … (informative). Standalone commits omit epic/wu. Query by identity: cargo xtask dod list --epic E1.

The chain is tamper-evident: notes attach to commits, reviews pin the diff bytes. Amending or rebasing a gated branch orphans its notes — the next gate goes red by itself. Notes sync to origin automatically on push (pre-push hook). The receipt is written only by the gate tool and only on green, and is never blind-trusted: any tip can be re-verified at any time, offline.

The gate — cargo xtask verify-dod

cargo xtask verify-dod wu   wu/<epic>/<slug>      # target inferred from the name, or --target
cargo xtask verify-dod epic epic/<slug>           # target defaults to main
cargo xtask verify-dod commit <sha>               # standalone commit check
cargo xtask verify-dod hook <wu|epic>             # merge-hook mode: tip = MERGE_HEAD, target = HEAD
cargo xtask verify-dod range <old> <new>          # pre-push mode: standalone commits in a pushed range
cargo xtask dod list [--epic E1]                  # query receipts
#Check
1Required notes present on the tip, schemas parse, identity consistent across them
2Manifest level matches the gate; required layer (commit ⇒ unit, WU ⇒ integration, epic ⇒ e2e) shows count ≥ 1 or a waiver
3cr/v2 verdict is PASS
4Review base equals the current merge-base — stale reviews rejected
5diff_sha256 equals the gated diff recomputed now, byte-identical
6doc/v1 matches git diff --name-only exactly (no missing/phantom entries, tiers correct); code change ⇒ T2 entry or t2_waived; epic ⇒ no unarchived docs/work/*.html added in range, archives carry distilled_to
7Epic: first-parent walk — each merge's ^2 re-verified as a WU, each non-merge commit checked as standalone (docs-only exempt; the tip itself is covered by the epic gate). Octopus merges are refused, by the walk and by the hook: one WU per merge

All green ⇒ receipt written, exit 0. Anything red ⇒ exit 1 and one block per failure — check id, expected vs found, and a concrete fix → action — written for the fixing agent to consume. Red gates write nothing. Docs/infra-only diffs are exempt at every level: green, no notes demanded, no receipt written — one shared rule behind the hook's ungated doc merges and the walk's exempt seams.

Hooks

HookEnforces
pre-commitfmt + clippy -D warnings · when completing a conflicted merge (MERGE_HEAD on disk — those never reach pre-merge-commit), runs the same merge gate
pre-pushfull suite · auto-pushes refs/notes/* · range-checks standalone commits on main/epic/* pushes
pre-merge-commitruns the gate on MERGE_HEAD: into epic/* ⇒ wu gate, into main ⇒ epic gate; docs/infra-only merges pass ungated; red refuses the merge
post-checkoutheals merge.ff = false · worktree setup

Bypass honesty: --no-verify skips hooks and a fast-forward skips pre-merge-commit — but the next gate's walk re-verifies every seam, so smuggled content turns the epic gate red before it reaches main, and receipts can't be minted by hand without failing recomputation.

Who judges

Every judgment above is a run of the code-review skill (.claude/skills/code-review/): Gate 0 mechanical preflight, five fresh-context finders (one rubric dimension each), one adversarial verifier per finding that tries to refute it, verdict, and the cr/v2 note. The triggering session orchestrates but never judges its own diff; finders read the tip's test/v2 and doc/v1 notes so waivers and distillation claims get judged. On FAIL the triggering session fixes and re-reviews until PASS. The gate only verifies a PASS exists for exactly this diff — the review machinery can evolve without touching the gate.
