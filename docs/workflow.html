Workflow Standard

How work is planned, gated and merged: epic → working unit → commit, one hook-enforced DoD gate per level, completeness proven from git notes — never from an agent's word.

v16 · 2026-09-12 · Trawler · T1 process doc

The three levels

Work decomposes per the charter in the testing standard, which owns each level's definition and mandatory test. This doc owns everything around that: branches, gates, evidence, merges. Naming convention — an epic's id is E-<CODE> where <CODE> is a short uppercase abbreviation of its slug (e.g. E-INFRA, E-UI); working units are numbered within their epic, E-<CODE>.W<m> (e.g. E-INFRA.W1, E-UI.W5). Git is the registry — no tracker file.

Collapse rule: a small epic may be one WU, a small WU one commit — every gate is still met explicitly, with all notes written. Main is merge-only (DEC-6): the pre-commit hook refuses every non-merge commit on main — all work, docs included, starts on an epic/* or wu/* branch and lands through the merge gate (docs/infra-only merges pass it ungated, unless they carry a design artifact). Standalone commits exist only on epic/* branches: a code commit there (outside any WU) carries a test/v2 note, level: commit, unit ≥ 1 or waived; the epic walk and the pre-push range check verify them. Code paths are src/, xtask/, tests/, ui/src/, ui/e2e/.

The merge is the gate: pre-merge-commit runs the verifier and a red gate makes the merge itself fail. Merges are always --no-ff (repo config merge.ff=false) so every gated tip stays addressable from main.

DoD checklists

mechanical = a hook or verify-dod enforces it; judgment = a reviewer decides, and the gate verifies the judgment happened against exactly this diff. Where quality can't be mechanized, the mechanical check is that the judgment happened: a PASS note bound to the diff by diff_sha256.

Design → build

UI work carries a design, and the design and the build share one epic: a Working Unit lands the closed design (Tier-3 judges it at that merge, check 9), a later Working Unit builds it and cites what it built from. Nothing rendered changes without an answer on the record — which design, or why none — so the rule has three halves and all three are mechanical.

A UI-rendering fileNot one
any non-test .tsx under ui/src/, at any depth — screens, registry components, anything composed of them .ts logic and data modules · .test.tsx siblings · index.css (the tokens live in ui/tailwind.config.js) · everything outside ui/src/
HalfRuleRefused at
Upstream · added
a new surface names its design		 a WU whose diff adds a registry component (a file under ui/src/components/ carrying @tier) or a screen (a non-test .tsx under ui/src/ outside the collection) writes design.implements: [{path, blob, built: [<the files>]}] in its cr/v3 note. The blob pins the bytes read, not the filename; the path must resolve at the tip or — when the tip no longer ships it — at its last state reachable from the tip, with the pin matching that state (DEC-28); it must name a design artifact, and — if it is a design run — be archived. An added surface may only be cited: there is no reason that excuses one gate check 9, at the WU merge
Upstream · touched
an edit answers for itself		 every other UI-rendering file in the diff is cited the same way, or named by design.undesigned: [{path, why}] — an empty reason is not a reason. The declaration is the reviewer's statement of fact, bound to diff_sha256, not a waiver the builder grants itself; a silence is refused because a silence has always read as a pass (DEC-15). Every declaration is billed at the epic gate, so an epic that designed nothing says so in its own receipt gate check 9, at the WU merge
Downstream
no unbuilt design survives its epic		 every component design the epic added resolves to a roster entry at the epic tip, or the epic's cr note records design.dropped: [{path, why}] — an empty reason is not a drop. The roster counts screens as well as @tier components, so a screen design resolves where it was built. A design file is retired into the code's TSDoc when built (DEC-16), dropped on the record when not, and never left standing components·unbuilt, at the epic merge

UI work happens inside a Working Unit. The accounting lives on the cr/v3 note, and a standalone commit has none — so a commit that touches a UI-rendering file outside a WU is refused at commit level, whatever else it carries.

When the build and its design come apartWhat is owed
an unforeseen small change while building one sentence — no design run, no new artifact: the file is named under design.undesigned with why it needed none. The gate never demands a design for an edit; it demands an answer
the build amends the design it was handed nothing to remember — the amended file is a design artifact in that WU's diff, so check 9 re-judges it on the merge that lands it and the cited blob is the amended one
a surface nobody designed, found mid-build the build WU carries its own design, gated identically — a design WU and a build WU at once

Nothing judges the build against its design. The gate answers is there a design, and is it this one — never whether the code honoured it (DEC-25). The pointer is a mechanical check, not a judgment.

Waivers

A required test layer may be consciously skipped: integration: { waived: "<why>" } replaces count ≥ 1 at any level. The gate accepts a waiver mechanically (present, non-empty reason); whether it is justified is a review question — an unjustified waiver is a review finding. Vocabulary: waived = judged unnecessary, reason recorded, reviewable · exempt = a rule says no evidence is needed (docs/infra-only diffs — unless the diff carries a design artifact, which is a docs-only deliverable).

Manual review — a human sign-off, path-derived

Some changes must not land without a human's explicit OK. The requirement is derived mechanically from the diff's paths and the gate level — never from anything an agent asserts — and is not waivable: required means a listed authoriser is recorded.

The signature goes last — the tree settles before a human is asked (DEC-27)

Every binding on a tip carries the diff it was made against: cr/v3 pins diff_sha256, mr/v1 pins the result report's bytes. So any tree change after a binding orphans it — a fix, a forgotten test, a doc edit — and the cost is another review and another human signature. The order is therefore not a preference:

#StepWhy it comes first
1the work, its tests, its docs, the result reporteverything that changes the tree
2test/v2 + doc/v1 on the tipwriting the receipt is the act that carries adding the test and settling the docs — a missing receipt means the tree may still move
3cargo xtask preflight — Gate 0 plus the notes the review reads — then the code-review skill → cr/v3 PASS, diff-boundindependent judgment, so the human signs something already checked; the preflight is the last point where a red suite or a malformed note is still repaired for free (DEC-43)
4cargo xtask mr confirmthe first binding that costs a person; it goes last
5merge --no-ffthe gate re-checks every note against the final diff

Enforced, not merely documented: mr confirm refuses steps 2–3 missing, and refuses before the signing prompt — so the human is asked once, at the right moment.

Rule-bearing docs are gated at commit time — reviewing after the commit exists is too late, and a git note can't hang on a commit that doesn't exist yet — so the authoriser travels in the message: cargo xtask mr commit -m "<msg>" --as <id> appends a Reviewed-By: <tier> <id> trailer and the commit-msg hook refuses any T0/T1-touching commit that lacks one. WU/epic tips carry the record as a note: cargo xtask mr confirm (a wizard — args pre-answer its prompts; level/tip/target are inferred from the branch and the result report from the single tracked docs/work/*-result.html / archived candidate, or --report). Both check the identity against .mr-allowed (tiers email/username/key) — a local, gitignored trust store provisioned per machine by mr setup, never committed (DEC-10). The check runs independently of the docs/infra exemption — an always-required WU or epic still needs its note even when its diff is exempt from test/cr/doc.

A key entry (key: <identity> <ssh-pubkey>) makes the sign-off unforgeable (E-MRSIG · DEC-9): authorisation then requires an SSH signature only the human's hardware can produce, verified offline against the listed public key. What is signed per level: a rule-bearing doc commit is git-native SSH-signed (gpgsig header — the message stays clean; verified via git verify-commit at pre-push, because the commit-msg hook runs before git signs); a WU/epic tip's mr/v1 note carries a signature over the recomputed base..tip change-hash plus the attested result report's sha256 — sign-what-you-read (DEC-10): the note records the report's path + hash, a WU report re-hashes against the tracked file at the tip, and an epic report (archived by gate time, DEC-3) survives as the signed hash, re-verifiable offline forever. Amending the tip, or forging the report claim, breaks the signature at gate check 8. cargo xtask mr setup is the one-command wizard: it probes what the machine offers (on a Secure-Enclave Mac it compiles and installs the bundled trawler-signer, whose Touch ID sheet names the authorised action via TRAWLER_SIGN_REASON), accumulates the chosen methods in .mr-allowed, and points user.signingkey at the single active key.

The guarantee is per-entry. Identity-only tiers (email/username) remain listed-authorised — and agent-forgeable — as a migration convenience; a key-backed identity must sign, and claiming a weaker tier in the trailer does not dodge that. Unforgeability holds only for a .mr-allowed whose entries are all key lines (DEC-9) — and only on the machine holding that list: it is local config, like the hooks themselves; a fresh clone verifies nothing until mr setup recreates it (DEC-10).

Every schema carries the same identity block — identity never rides on branch names: epic: E-CAP · wu: E-CAP.W2 (WU work only) · branch: … (informative). Standalone commits omit epic/wu. Query by identity: cargo xtask dod list --epic E-CAP.

The chain is tamper-evident: notes attach to commits, reviews pin the diff bytes. Amending or rebasing a gated branch orphans its notes — the next gate goes red by itself. Notes sync to origin automatically on push (pre-push hook). The receipt is written only by the gate tool and only on green, and is never blind-trusted: any tip can be re-verified at any time, offline.

The gate — cargo xtask verify-dod

cargo xtask verify-dod wu   wu/<epic>/<slug>      # target inferred from the name, or --target
cargo xtask verify-dod epic epic/<slug>           # target defaults to main
cargo xtask verify-dod commit <sha>               # standalone commit check
cargo xtask verify-dod hook <wu|epic>             # merge-hook mode: tip = MERGE_HEAD, target = HEAD
cargo xtask verify-dod range <old> <new>          # pre-push mode: standalone commits in a pushed range
cargo xtask preflight wu|epic <tip> [--target <ref>]  # the review's first step: gate0 + the notes the review reads, before any finder spawns
cargo xtask mr commit -m <msg> --as <id>          # T0/T1 doc commit: append a Reviewed-By trailer (identity must be listed)
cargo xtask mr confirm <wu|epic> <tip> --as <id> [--report <path>]  # mr/v1 note attesting the result report
cargo xtask dod list [--epic E-CAP]               # query receipts
cargo xtask debug serve [--port 48027]            # live browser view of the note trail (epic→WU→commit)

Walk-error waiver — the surgical override that isn't --no-verify
      (DEC-8). When the epic walk (check 7) turns red on
      a seam it can't classify — a live cross-epic integration, or any future topology the discriminator
      doesn't yet recognise — do not reach for --no-verify, which skips
      every gate. Waive that one seam, on the record, by adding an entry to the epic
      tip's cr/v3 review note:

      
walk_waivers:
  - seam: <seam-sha, exactly as the walk printed it>
    why: "<why skipping this seam's re-check is safe>"

      
A non-empty why turns that seam's failure into a visible waived line; every
      other seam and every non-walk check still runs, and the still-red seam's fix line names
      this exact edit. It rides cr/v3 because a walk waiver is a review judgment, and because
      cr/v3 is diff-bound — a moved main re-validates the review and the waiver with
      it, so it can't silently outlive its diff. Manual review (check 8) is never waivable this way.
      An unjustified waiver is a review finding, like any other waived.

    


    
Who judges


    
Every judgment above is a run of the code-review skill
    (.claude/skills/code-review/), and it opens with a mechanical refusal rather than a
    judgment: cargo xtask preflight runs Gate 0 and the notes the finders read
    (DEC-43), so a red
    suite or a malformed note stops the run before an agent is spawned. Then five fresh-context finders
    (one rubric dimension each) plus a sixth — the design finder — whenever the diff carries a design
    artifact, one adversarial verifier per finding that tries to refute it, verdict,
    and the cr/v3 note. The triggering session orchestrates but never judges its own diff;
    finders read the tip's test/v2 and doc/v1 notes so waivers and distillation
    claims get judged — and the work's plan and result docs
    (work-planning standard) as inputs, so delivered-vs-planned and
    the substance behind a green checklist get judged too. On FAIL the triggering session fixes and re-reviews until PASS. The gate only
    verifies a PASS exists for exactly this diff — the review machinery can evolve without touching the
    gate.
