Testing Standard

The permanent, project-wide rule for how Trawler is tested: each unit of work carries a mandatory kind of test — Epic → e2e, Working Unit → integration, Commit → unit.

Draft v5 · 2026-07-05 · Trawler

Why this is a standard, not a suggestion

Every line of Trawler is written by an AI agent and no human reads the diff before it lands. The tests are the reviewer that catches the off-by-one, and the executable spec the feature is written against. So: if a behaviour isn't tested it isn't guaranteed; every documented quirk becomes a named regression test so it can't silently return; and the suite itself is audited by mutation testing. This document binds all of that to the way work is decomposed — it applies to every feature, present and future.

The charter — work maps to a test level

All work decomposes into three nested levels, and each carries a non-negotiable test obligation scoped to exactly what it delivers. Lower levels never substitute for higher ones: each tests what only it can see.

    E --> W2["Working Unit"]
    W1 --> C1["commit"]
    W1 --> C2["commit"]
    W2 --> C3["commit"]

    W1 -. "MUST have" .-> IT1["integration test — WU contract"]
    W2 -. "MUST have" .-> IT2["integration test — WU contract"]
    C1 -. "MUST have" .-> UT1["unit tests — all code in commit"]
    C2 -. "MUST have" .-> UT2["unit tests"]
    C3 -. "MUST have" .-> UT3["unit tests"]
The decomposition tree and its test obligations.
LevelDefinitionMandatory testDone-gate
Epic e2e A big, user-visible feature — the largest unit of planning. End-to-end test covering the full epic flow. Not complete until the e2e passes, every WU is done, and each documented quirk has a named regression test.
Working Unit integration A slice of an epic with a clear, bounded scope and one explicit requirement; independently shippable. Integration test(s) covering the WU's contract. Not merge-ready until its requirement is written down (one testable sentence) and an integration test asserts it; any new wire contract is snapshot-locked.
Commit unit The smallest coherent increment; a WU is built from one or more. Unit test(s) covering all code the commit adds or changes. Rejected if it adds/changes code with no unit coverage, or if fmt/clippy/coverage-floor gates fail.

Levels compose, they don't substitute. A green e2e never excuses a missing WU integration test, and a WU test never excuses unit tests on its commits — coverage is additive. When a WU is genuinely one small commit, both obligations may be met together, but both must be met explicitly.

The three layers

What each test kind is in this project — stable across all epics; only the subject changes. Effort concentrates at the bottom, where correctness weight and change frequency are highest.

flowchart TD
    E2E["E2E · per EPIC · few, high value
real client → whole system → real dependency"]
    INT["INTEGRATION · per WORKING UNIT
a component/endpoint at its real boundary"]
    UNIT["UNIT · per COMMIT · the bulk
pure functions & branches + all-input invariants"]
    E2E --> INT --> UNIT
Widest at the bottom: most confidence comes from cheap unit tests on every commit; a focused integration layer proves each WU's contract; a deliberately thin e2e layer proves each epic's full flow.
LayerJob & boundary — may touchLives in
Unit One function/type/branch in isolation. Fabricated inputs; no sockets/fs; private items fair game; a runtime only if the code under test is async. Inline #[cfg(test)] mod tests beside the code.
Integration A WU's contract at its real boundary — public crate surface, an in-process router (tower::oneshot), a seeded Store, temp-dir fs. No full product. tests/<subsystem>.rs (public API only).
E2E An epic's full flow through the running system on ephemeral ports: real client → real transport → local test dependency. Asserts external behaviour and internal fidelity. tests/e2e_<epic>.rs + shared tests/common/.

The testing contract

Five rules every test obeys at every level; a test that breaks one fails review (mechanically, via the CI gates).

RuleMeaning & enforcement
DeterministicSame input → same result. No sleep() as synchronization; assert presence of durations/timestamps, never exact values; seed randomness.
HermeticNo public network, no shared global files. Ephemeral ports (:0); filesystem tests use tempfile, never repo paths; local test servers only.
Behaviour, not implementationAssert observable contracts (JSON a client sees, bytes forwarded) so behaviour-preserving refactors stay green. Test names read as specifications.
Invariant-firstProperties that must hold for all inputs get a proptest generator, not three hand-picked cases.
Fast & isolatedEach test owns its state and runs in parallel; the unit layer is milliseconds. cargo nextest gives per-test process isolation.

Repository layout

flowchart TD
    src["src/*.rs — inline #[cfg(test)] mod tests (unit + property, per COMMIT)"]
    tests["tests/ — integration crate, public API only"]
    tests --> int["<subsystem>.rs — integration, per WORKING UNIT"]
    tests --> e2e["e2e_<epic>.rs — one per EPIC"]
    tests --> common["common/ — builders, test servers, test CA, proxy client"]
Unit tests sit beside the code (private access, fast). Integration & e2e live in tests/ and see only the public surface — the same view a real embedder has, keeping the public API honest.

CI gates

Merge is unattended, so a red gate blocks it: every push runs fmt, clippy -D warnings, the full test suite and a coverage floor; mutation and dependency/advisory audits run on a schedule; the same fast gates also run locally as git hooks via cargo-husky. Beyond these mechanical gates, marking work done also requires a test manifest note the workflow judges against the Done-gate.

Testing DoD — the test manifest note

MUST — every finished change writes its test manifest as a YAML git notes entry on its tip (schema below); cargo xtask verify-dod judges it against the charter Done-gate at every merge (see the workflow standard). No manifest ⇒ the work isn't done.

schema: test/v2               # manifest format version
level: commit                 # commit | working-unit | epic — sets which layer the charter requires
epic: E-CAP                   # identity block — present for epic/WU work, omitted on standalone commits
wu: E-CAP.W2                  # working-unit level only
branch: wu/capture/pagination # informative label; the ids are the truth
tests:                        # per layer: how many + what they cover (facts, checked against the diff)
  unit:
    count: 42
    covers: "decision table + byte round-trip; ring accounting, filters, eviction; decode round-trips; view JSON"
  integration:                # omit a layer block entirely if it wasn't touched
    count: 7
    covers: "control API list/get/body/stream (tower::oneshot); CA generate-then-reload"
  e2e:                        # a required layer may instead be consciously waived — reviewed, never free
    waived: "why no test is needed at this layer"

The gate requires the level's mandatory layer (commit ⇒ unit, working unit ⇒ integration, epic ⇒ e2e) to show count ≥ 1 or a non-empty waived reason; waiver justification is judged in review. v1 notes predating the workflow standard remain on old tips and are never re-gated.
