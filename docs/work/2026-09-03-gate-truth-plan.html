E-GATETRUTH — the gate tells the truth

Three deferred E-DFLOW problems: a rule pair that makes a legal note impossible, and two places the gate refuses correctly but names the wrong cause.

Draft v1 · 2026-09-03 · Trawler · T3 epic plan · E-GATETRUTH

Intent

E-DFLOW closed green but left three defects in the gate and its tooling, all of the same shape: the gate's verdict is right and its explanation is wrong — or, in one case, no correct note can be written at all. The first is a blocker-in-waiting: DEC-16 (retire a design once built) and DEC-25 (a new surface must cite the design it was built from) contradict each other, so the first epic to add a registry component under a cr/v3 note cannot produce a note the gate will accept. The other two cost real time in W12 — three debugging rounds on a commit that had already succeeded, two wrong diagnoses on a merge whose signature was valid — because the message sent the reader somewhere the fault was not. Now, because the next UI epic hits the blocker on its first component, and because a gate that misdirects erodes the trust the whole DoD model rests on.

Hình 1 — P1: both roads out of the citation are refused. DEC-16 removes the only path a citation may name; the reason-based escape hatch is closed by design.
Why E-DFLOW did not hit P1. Its 25 components landed under cr/v2-era seams. check_handoff downgrades the check to DESIGN_SCHEMA for a cr/v2 note, and the epic walk filters that class out (xtask/src/gate.rs:894). A fresh cr/v3 note gets DESIGN, which is not filtered.

Use-case requirements

A process epic — it delivers no UC-* behaviour and changes none. Nothing user-visible in the proxy or the UI moves. What changes is the workflow's own contract, so the truth lands in T2 decisions and the T1 process docs instead: the meaning of a design citation after retirement (a new decision record superseding the P1 half of DEC-25), the roster's worktree scope (extending DEC-10 rather than reversing it), and the link-integrity predicate as a stated verify-doc obligation in work-planning. The workflow standard's "design → build" table is rule-bearing text that P1 will contradict once fixed, so it is edited under a Reviewed-By trailer as a T1 rule change.

Expected result

Checkable by a reader who was not here:

#Observable afterHow to check
1 An epic that adds a registry component, retires its design per DEC-16, and writes a cr/v3 citation passes check 9 and the epic walk. A gate test builds exactly that history (design added → built → design deleted → cr/v3 note) and asserts green. It reds against today's code.
2 A citation naming a path that never existed, or pinning a blob no commit ever held, is still refused — the fix widens where a citation may resolve, never whether it is checked. Negative gate tests for both, asserting the refusal survives.
3 mr commit on a succeeding commit prints no error:; on a failing one it prints git's stderr without echoing the message body. Integration test on a temp repo: assert exit 0 + no error:; assert a forced-fail case names the real cause and omits the body.
4 verify-doc reds a doc whose relative href resolves nowhere in the tree, and stays green on archived-doc and docs/.archive/ links. Unit tests per case; a run over today's docs/ is green (the three known dead links are already gone or get fixed here).
5 A merge whose mr/v1 signer is absent from the running checkout's roster reports that, naming the signer and the roster path — distinct from a signature that fails against a listed key. Gate test asserting the two messages differ and each names its own cause.

Non-goals

  • Making .mr-allowed tracked. DEC-10 gitignored it deliberately — locally mutable, and a tracked roster is a tempting diff target. P3 improves the diagnosis; any move to share the roster must argue against DEC-10 on its merits and is out of scope here.
  • Judging a build against its design. DEC-25 holds: the gate asks is there a design, and is it this one, never whether the code honoured it. P1 must not smuggle in a content check.
  • Reversing DEC-16. Keeping design files standing after build would "fix" P1 by reintroducing the drift DEC-16 exists to prevent.
  • A general docs link-checker — external http(s) links, anchors into other docs, and image assets stay unchecked. P2b resolves relative file hrefs only.
  • Any change to proxy, capture, store, or UI runtime code. No src/ or ui/src/ behaviour moves in this epic.

Working units

E-GATETRUTH.W1 — decide what a citation means after retirement

The decision record for P1, and only that: a T2 decision fixing what design.implements resolves against once DEC-16 has retired the file, chosen among the three candidate directions (resolve against history · cite the TSDoc that now carries the contract · a design.retired variant carrying the last-known blob plus the retiring commit). Includes the T1 edit to the workflow standard's design→build table, which today states the tip-resolution rule the fix changes. No gate code.

E-GATETRUTH · P1 · supersedes the citation-resolution half of DEC-25; leaves DEC-16 intact.

A numbered decision record in docs/decisions/ stating the chosen semantics, the two rejected alternatives with why, and the exact predicate W2 must implement. docs/workflow.html and the decisions index reflect it. The T1 edit carries a Reviewed-By trailer (rule-bearing doc, DoD-C).

none — first WU; W2 depends on it.

E-GATETRUTH.W2 — implement the citation predicate

Change check_citation (xtask/src/gate.rs:609) to W1's decided predicate so a retired design can still be cited, while a fabricated path or an unpinnable blob is still refused. Carries the regression history that would have caught P1: a fixture epic that adds, builds, and retires a component under a cr/v3 note.

E-GATETRUTH · P1 · implements W1's decision.

Expected results 1 and 2 hold. The gate is green on the legal history and red on both negative cases, with a message naming which half failed.

E-GATETRUTH.W1 (the predicate must be decided before it is coded).

E-GATETRUTH.W3 — the gate names the cause it actually found

Both misdirection defects, together because they are one fault in two places. P2a: mr_commit checks whether HEAD moved before reporting failure, and the error path prints git's stderr alone instead of re-echoing the commit message. P3: when an mr/v1 note carries a signer the local roster does not list, tip_authorised's caller says exactly that — naming the signer and the checkout's roster path — distinct from a signature that fails against a listed key.

E-GATETRUTH · P2a + P3 · no rule changes, message and control-flow only.

Expected results 3 and 5 hold. A git log is no longer needed to learn that a commit succeeded, and a roster gap no longer reads as a bad signature.

none — independent of W1/W2; may land in parallel.

E-GATETRUTH.W4 — verify-doc resolves the links it ships

A verify-doc predicate resolving every relative href against the tree, with the two known wrinkles handled: an archived doc may reference other archived docs, and links into docs/.archive/ are expected to be unresolvable from a clean checkout. The ad-hoc check run by hand in W12 is the prototype. Fixes any dead link it finds in today's tree.

E-GATETRUTH · P2b · extends the work-planning standard's verify-doc obligations.

Expected result 4 holds. The DEC-13 class of defect — a T2 record pointing at a source file that never existed — is mechanically impossible to ship again.

none — independent; may land in parallel with W1–W3.

Open questions

#QuestionProposed default
1 Which P1 direction does W1 choose? Resolve against history.
