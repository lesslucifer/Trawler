Full text (baseline, for reference)

The original prose version — reasoning inline but wall-shaped. Kept only so you can confirm the driver table lost nothing.

The design frame. General design principles (state handling, a11y, spacing scale) live once in the rulebook (W3); everything here is case-specific and overrides a general principle on conflict.

User & context. A developer mid-debugging — task-focused, scanning fast, comparing many flows across a session, keyboard-heavy, desktop dark-theme app.

Ranked goals (ordering = hierarchy): G1 Triage — know what + whether-ok at a glance; owns the top. G2 Debug — read the bodies; the bulk. G3 Reproduce — copy as curl; subordinate.

Content priority (high → low): outcome/status + method + URL › bodies › headers › timing / protocol.

Qualities: Q1 scannable · Q2 dense but legible · Q3 terminal-like · Q4 calm · Q5 trustworthy (raw truth, no lossy prettifying without a toggle).

Constraints: C1 narrow column — wrap, never overflow. C2 content wildly variable — empty ↔ multi-MB, in-flight/streaming (overrides the generic "handle states" principle). C3 fit the app shell.

Success criteria: SC1 outcome <1s · SC2 header without scrolling past a body · SC3 never widen for the URL · SC4 in-flight never looks broken.

Non-goals. No edit/replay · no diffing two flows · no hi-fi polish.
