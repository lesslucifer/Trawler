Why a new run and not an amendment to run 10

Run 10 is data-status="archived" and green. Its stages are not wrong so much as answered about a different screen: four of the five things a design run reads as substrate changed underneath it, and the close step's own rule — ① re-pin the rulebook, and a receipt whose pin no longer matches is receipt·rulebook-stale — is exactly the condition it is now in. Re-opening an archived run to re-pin it inverts that step. The cheaper-looking path is also the one the flow forbids.

What this run reads, and what it may not assume

Every contract it designs against is built and merged — this is the first of the epic's two design-bearing WUs with no designed-ahead dependency. The run reads the endpoints from src/api/routes.rs and src/api/mod.rs, the refusal wording from src/api/curl.rs, the screen from ui/src/App.tsx, ui/src/FlowList.tsx and ui/src/Layout.tsx, and modality from ui/src/ProxyCloseDialog.tsx — never from the epic plan's prose and never from run 10's account of any of them.

Run 10 is substrate, not authority. Where this run reaches the same answer it says so and cites it; where it reaches a different one it must say which stage changed and why, in the review list. An answer that silently flips is the failure mode a second run has that a first run does not.

What the run has to answer

#QuestionWhy it is not obviousStage that owns it
Q1 Where do three new controls live on a header carrying a text field, two dropdowns, a status field and a count? Run 10's trailing cluster was sized against four plain boxes. A Select opens a popup, so the trailing edge now neighbours something that overlays; and Field's @avoid line — never let it grow to fit content, because the fields share one row — is a constraint on the row this cluster joins. choose-before-act still binds the ordering. Layout
Q2 Does the clear confirmation reuse ModalShell, extend it, or propose the registry entry run 10 asked for — and who owns it? The thing exists and is good: focus trap, Esc with a defaultPrevented guard so a Select popup's Esc is not the dialog's, backdrop, focus return to the invoker, initial focus on the action rather than the ✕. It is also screen-local by an explicit warrant that this run's second and third caller directly contradict. Promoting it is a registry change, and the run may propose but not perform one. Elements · Interaction
Q3 How is an imported flow marked in a 30px six-column row, with no new column? The row is unchanged since run 10 (110px 70px 180px 1fr 70px 90px), so the constraint holds — but data-ink-first refuses a badge that informs nothing on the overwhelmingly common captured case, colour-plus-text refuses a tint alone, and DEC-34 now bounds what a fixed-height row may do to a value it cannot fit. Elements
Q4 How is a curl command pasted, and where does the refusal land? Nothing in the registry accepts multi-line free text — Field is single-line by contract and a browser-copied command is multi-line with backslash continuations. The refusal is now a real string from a real endpoint, so absence-names-itself and display-equals-payload can be judged against what the server actually returns. Elements · Interaction
Q5 What does each control say while it is working, and what does it say at the end? Button's @states is explicit: no loading state of its own — a slow action needs the disabled control and a progress line, both halves or neither (fork D4). ProxyCloseDialog now ships a worked example of that fork, so the question is whether this screen follows it or has a reason not to. Interaction
Q6 Which of run 10's answers does this run keep, and which does it overturn? A re-run's specific duty. Q6 is not a design question — it is the honesty check that makes the other five readable, and it lands in the review list where a reviewer can see what moved without diffing two archived files. review
