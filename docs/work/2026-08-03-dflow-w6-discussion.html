The mandate, and the two things that moved under it

Epic plan, W6: "Apply W4 findings to the rulebook — add/remove/retag rules, sharpen ids and hard/soft tags." That was written when the rulebook's job was to be read. Two things changed it. W5 turned the collection into code, so the KB's vocabularies section is now a stale second copy of ui/tailwind.config.js — its own rule says "code wins", and code now exists. And round 1 moved the 12 hard-rule predicates into this WU. W6 settles each rule and writes the check that enforces it.
Why settle-then-check in one WU is the right shape, not scope creep. W4 ended by proving the same point the hard way: three times an agent broke a rule it had just written, which is why that WU ended with a checker instead of another paragraph. A rule settled in W6 and checked in W7 spends a whole WU in the state this epic exists to abolish — written down, believed, unenforced. And the four blocked predicates were already going to force W7 to re-read every ruling made here.

D6 · The rulebook binds the collection too answered — round 1

"Collection as well." Finding 4's binds: screen · component · both axis is added, and the component half now points at real code — 22 built components, not design files. That has a consequence worth stating plainly, because it is the one place this answer costs something:

bindsJudged againstChecked whenExample
screenthe design run's artifactsa design runvisual-weight-follows-goals — only a Frame ranks goals
componentui/src/components/ + its design filea design run and a component changegenerous-targets — IconButton's hit area is the component's, not the screen's
botheach at its own levelbothcalm-microcopy — a component's default string and the screen's override
What this exposes. A component-bound rule is only honestly enforced if something checks it when a component changes — and today nothing does. The collection has 226 unit tests asserting each component's own contract, and one integration test asserting the collection is a vocabulary; neither knows the rulebook exists. So D6 has a tail: does the collection gain a rulebook check? Recommendation: yes, but the cheap form — extend the existing collection.test.tsx rather than build a second gate, asserting the component-bound predicates that are statically checkable over the built components (token usage, hit area, mono for wire data). That reuses a test that already walks all 24 exports. The alternative — a design run being the only place a component rule is checked — means a component can drift for a whole epic between runs.

D7 · The two unvalidated imports — elaborated, and my default was wrong

Correction. Round 0 said "two runs, zero Tune calls → kill both." That was drawn from run #2's finding 15 without reading run #3's receipt. Run #3 marks both rules satisfied with real citations, and progressive-disclosure drove that run's largest divergence from the shipped code. The kill verdict does not survive the evidence.

What "principle import" means: the Seed column marks a rule as extracted (a W1/W2 citation — the codebase already made this decision) or import (an established design principle with at most one Trawler sighting, admitted on faith). The lifecycle table commits: "imports that pull no weight are W6 kill candidates." This is that audit. Here is every trace both rules left:

D8 · Test levels — no waiver available now

Round 0 proposed one integration test on the assumption W6 was docs-mostly. D5 removed that assumption: this WU ships twelve predicates in xtask/src/doc.rs, so it carries the full commit + WU load, and W4's own precedent sets the bar (every check mutation-proved on the real doc, not just against fixtures).

LevelWhat
unit commitPer predicate: one green case and one red per way the rule can be broken — the shape W4's 13 tests already use. Plus the config parser: an unreadable/renamed tailwind.config.js must fail loudly, never silently pass every token rule.
integration WUThe bounded contract, three parts: the checker parses the revised KB · every slug cited by an existing run doc still resolves (the slug-immutability guarantee, mechanically proved — this is what makes D7's deprecation-not-rename safe) · hard rules: 13/13 actually prints.
regressionThe two archived runs must still pass. Twelve new predicates over run #2 and run #3 is this WU's real acceptance test: any predicate that reds correct, reviewed, shipped work is wrong. W4 shipped data-status="archived" for exactly this, so it must be exercised rather than trusted — a predicate that reds an archived run is caught here, not after.
collectionPer D6's tail: collection.test.tsx extended with the statically-checkable component-bound rules.
e2ewaived: "flow e2e is W7 per the epic plan" — same as W4 and W5.
The risk this WU actually carries. Not "will the rules be right" — it is that twelve predicates written against two archived runs will over-fit to them. Both runs are the only design artifacts that exist, so a predicate can pass both and still be wrong about the third screen. The regression row above is necessary and not sufficient; the honest mitigation is that each predicate checks the rule, not the run — and where that cannot be written, the rule is not ready and stays unchecked with the gap printed, exactly as W4 did with the twelve.
