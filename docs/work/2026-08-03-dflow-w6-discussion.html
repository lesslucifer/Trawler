The mandate, and the two things that moved under it

The ruling — a closed vocabulary answered — round 2

"We only accept our listed tokens, for both spacing and colour. Other tokens like syn- or method- are not allowed — they must use the listed tokens only. Extending the list requires careful human review."

This is stricter than any option D2 or D3 offered, and it collapses them into one decision: the vocabulary stops being open. Both forks are answered by it, so their option tables below are superseded and kept only for the record.
Sub-decisionRuling
Chromatic tokensBanned. zero-accent becomes absolute: chromatic colour is ok + warn, nothing else. The 5 method-* and 3 syn-* tokens are deleted from the config; MethodLabel reverts to ink tokens.
Where the list livesui/tailwind.config.js is the source of truth; the KB mirrors it and links it. A token is legal because it is defined there — Tailwind's inherited defaults are not. "Careful review" is the ordinary code review of the config diff.

Structural exceptions: a suppression pragma answered — round 3

Asked on the round: "for structural values that can break the rules, can we have a pragma / comment to suppress the rule on them?" Yes — and it is better than the blanket structural exemption I recommended. A category exemption ("allow fr, auto, calc") legalises a whole shape of value forever and cannot tell a genuine grid template from a lazy escape. A pragma makes each exception individual, attributed, and greppable.

Blanket structural exemptionSuppression pragma
Scopeevery value of that shape, foreverone line
Reviewableinvisible — nothing marks the exceptionappears in the diff; a reviewer sees each one
Countablenogrep gives the exact debt list
Can it hide a leak?yes — calc(100% + 5px) passes as "structural"no — it is still an exception, just a declared one
The form, following this repo's own conventions. Two precedents exist and agree: setup.ts carries // TODO [UI_DEFER] (E-DFLOW.W5, r3·22): …, and the DoD gate accepts waived: "<why>" where an empty reason is not a waiver. So: 
// design-allow: grid-cols-[auto_1fr] — a grid template, not a size; no token form exists
Rules, all enforced by the predicate itself:
Applies tothe next line only — never a file or a block, so it cannot silently widen
Names the valuethe suppressed class is written out; if the line changes, the pragma stops matching and reds
Requires a reasonnon-empty text after —, mirroring waived:. No reason = not a suppression = red
Cannot suppress a sizea pragma over a bare […px]/[…rem] value is rejected — py-[5px] can never be pragma'd away, because a token is always the right answer there
Is countedthe gate prints the live total, like hard rules: n/13 — so suppressions are visible debt, not a silent hole

Against the 9 real escapes this gives a clean split — and note it is stricter than the structural exemption would have been, because min-w-[132px] and max-h-[184px] can no longer hide behind a category:

EscapeVerdict
grid-cols-[auto_1fr] · grid-cols-[18px_1fr]pragma grid templates — but the 18px must first become theme(spacing.step-marker), so only the template shape is suppressed
top-[calc(100%+4px)]pragma a positioning expression; the 4px should reference a token inside the calc
py-[5px] · text-[11px] · border-[1.5px] · min-w-[132px] · max-h-[184px]must become tokens pragma is not available — all five are sizes

And min-w-0 / left-0 answered — round 3

Asked: "so how do we handle them for now?" I looked at all eight usages rather than assuming, and they turn out not to be a spacing question at all:

UsageWhereWhat it is
min-w-0Notice · Select · StatusLine · StepListThe flexbox overflow idiom — a flex child defaults to min-width:auto and refuses to shrink, so text overflows instead of wrapping. This line is what makes wrap-not-truncate physically work.
p-0 m-0 gap-0Button · StepListResets of a browser default (<ol>'s padding, <button>'s padding).
left-0SelectAn anchor — "flush to the left edge" in an absolute position.
Ruling: zero is not a spacing value, so it needs no pragma and no list entry. A spacing scale answers "how much space?"; every usage above answers "none" or "reset this". Removing a browser default is not picking a value off a scale. The predicate therefore treats 0 as always-legal for spacing, position and sizing utilities — one clause, no exceptions to maintain, and it matches how Tailwind itself models it (spacing.0 = "0px" ships in the default scale, not as an opt-in).

The alternative was worse: adding 0: "0px" to the config's spacing list would work mechanically, but it invites the reading that zero is a design choice to be justified — and it would put eight pragmas or eight list-lookups in front of the flexbox idiom that wrap-not-truncate depends on.
One thing this exposed: Select uses min-w-full, which comes from Tailwind's minWidth scale — not from spacing. Closing spacing alone does not close minWidth, maxHeight, width and their siblings, each of which carries its own inherited scale. The config migration has to close every size-bearing scale, not just the four named in the ruling — otherwise w-96 and max-h-64 stay legal and the vocabulary is only half shut.
What this does to the WU's shape. W6 was already "settle the rules + build 12 predicates". The ruling adds a third leg: a config migration and a component change — theme.extend → theme, 8 tokens deleted, MethodLabel reverted, 7 spacing usages and 5 arbitrary sizes re-expressed. That is real ui/ work with its own tests, in a WU the epic plan scoped as a rulebook revision. Worth naming now rather than discovering in the plan.
