W6 step ⓪ — the sweep

Every size-bearing scale enumerated against the real config, every class in ui/src/ classified against it, and the keyword-vs-value ruling confirmed against actual usage. The plan's site counts were estimates carried from an earlier draft; these are measured. Three of them are wrong, and one changes step ②'s worklist materially.

Evidence · 2026-08-03 · Trawler · T3 (docs/work/) · wu/design-flow/revise-rulebook · plan: W6 plan step ⓪

Verdict

The ⓪ gate passes: the scale list is exhaustive, and the keyword ruling holds. 119 theme scales resolve; the project defines tokens in six; the discriminator "does a theme scale govern this prefix?" splits the real tree cleanly with no per-class exceptions. The relationship-keyword ruling was checked against all 31 of its real sightings and every one is a relationship or a reset, never a magnitude. But the plan's measured counts are stale — four corrections below, one of which adds ~19 sites to step ②.
Correction, added after the first draft of this doc: the class enumeration below was NOT exhaustive, and the method that produced it was unsound. The first pass scanned string literals at className= sites only. This codebase's dominant idiom is the opposite — classes live in module-level constants and lookup maps (BASE, FRAME, TONE, METHOD_COLOR, DOT_CLASS) that are interpolated in later, so their literals sit nowhere near a className=. 41 classes were missed.

How it was caught, and the method that should have been used from the start: build the CSS (npx tailwindcss) and read the emitted selectors. Tailwind scans its own content globs, so the built stylesheet is ground truth for what classes exist — 242 emitted, against the scanner's 205. Any bespoke scanner must be diffed against it, never trusted alone. Full reconciliation below.

The one that matters: text-method-get · -post · -put · -delete · -patch were invisible to the scanner — the exact five tokens step ① deletes and step ② must re-express in MethodLabel. A lint rule built on the scanner's design would have missed the primary deletion this WU exists to make.

⓪ᵇ The discriminator, run over the real tree

200 distinct classes across 34 production .tsx files (tests excluded). A class is in scope iff its utility prefix maps to a key in the resolved theme — mechanical, no allowlist.

KindCountExamplesVerdict
No theme scale governs it — structural, state, alignment 56 absolute flex grid truncate uppercase items-center justify-between sr-only animate-spin whitespace-pre tabular-nums text-center out of scope There is no value in absolute to pick wrongly.
Scale-bearing — a spacing / size / colour / type value was chosen 144 px-2 w-64 text-chrome gap-1 z-20 max-h-64 rounded-card in scope The only classes the rule judges.
The prefix alone is not the discriminator — three prefixes are overloaded and must be resolved by value. The plan's "prefix maps to a theme key" rule is right in spirit but under-specified, and getting it wrong produces exactly the false positives it was designed to avoid:

text- spans three things — text-chrome (fontSize), text-ink (colour), and text-center/text-left/text-right (alignment, no scale at all). A naive prefix match reds the alignment trio. · border- spans width (border, border-t), colour (border-hairline) and the border-none reset. · outline- and font- likewise.

The lint rule in ②ᵃ must classify on the resolved (prefix, value) pair, not the prefix. Recorded here because it is a correctness requirement on the rule, not an implementation detail — and it is the single most likely source of false positives in the whole check.

⓪ᵉ The computed-className finding

29 computed sites, not 7. The plan's feasibility argument rested on "only 7 of 206 are computed className={…}; the other ~96% are plain literals". The real figure is 29 of 235 (12%).

The strategy still holds — every one inspected holds its classes as string literals inside the expression (template literals with interpolated maps, e.g. ${TONE[tone]}, ${FRAME[frame]}, ${METHOD_COLOR[verb]}, and the maps themselves are literal objects). Reading literals inside the expression gets them right. What changes is the rule's obligation: at 12% the "report unresolvable fragments rather than silently pass" path is not an edge case — it is a routine path that needs its own RuleTester case, and the interpolation boundary must be handled (a naive scan of a template literal yields junk tokens like ${TONE[tone]}, ?, : as if they were classes).

Net effect on the numbers. The off-list worklist is essentially unchanged — nearly every missed class resolves to a project token, so ②'s re-expression surface stands, with the text-method-* five restored to it (they were always in the plan; the sweep simply failed to re-confirm them). What does change is the distinct-class count and the split: the population is ~224 authored classes, not 200, so the 144/56 figure is itself provisional and must be recomputed by the ②ᵃ rule against the oracle before it is quoted into DEC-17. Binding requirement on the ②ᵃ lint rule: it must resolve classes held in module-level constants and lookup maps, not only literals at className=. That is the majority idiom in src/components/, and it is invisible to the naive approach. Its RuleTester suite needs a case for it, and npm run lint's coverage should be reconciled against the built CSS at least once.

Gate

⓪'s gate — "the list is exhaustive, not the six obvious ones" — is met, on its own terms. The gate is about scales, and that half is exhaustive by construction: the 119 come from resolveConfig, Tailwind's own resolution, not from a scan. 22 carry inherited values reachable from real classes; six are named for closure plus lineHeight/letterSpacing/zIndex/outlineWidth/outlineOffset. The keyword ruling is confirmed against all 31 sightings, not assumed.

The class enumeration is a different claim and a weaker one. It is now reconciled against the built CSS and no longer rests on the scanner alone — but the exact 144/56 split is provisional until the ②ᵃ rule recomputes it, and it must not be quoted into DEC-17 before then. Ready for ① (which depends only on the scale list and the ruling, both solid), carrying two binding requirements into ②ᵃ: the overloaded-prefix rule and the constant/lookup-map requirement.
