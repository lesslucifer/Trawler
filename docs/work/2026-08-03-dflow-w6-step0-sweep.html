⓪ᵇ The discriminator, run over the real tree

200 distinct classes across 34 production .tsx files (tests excluded). A class is in scope iff its utility prefix maps to a key in the resolved theme — mechanical, no allowlist.

KindCountExamplesVerdict
No theme scale governs it — structural, state, alignment 56 absolute flex grid truncate uppercase items-center justify-between sr-only animate-spin whitespace-pre tabular-nums text-center out of scope There is no value in absolute to pick wrongly.
Scale-bearing — a spacing / size / colour / type value was chosen 144 px-2 w-64 text-chrome gap-1 z-20 max-h-64 rounded-card in scope The only classes the rule judges.
The prefix alone is not the discriminator — three prefixes are overloaded and must be resolved by value. The plan's "prefix maps to a theme key" rule is right in spirit but under-specified, and getting it wrong produces exactly the false positives it was designed to avoid:

text- spans three things — text-chrome (fontSize), text-ink (colour), and text-center/text-left/text-right (alignment, no scale at all). A naive prefix match reds the alignment trio. · border- spans width (border, border-t), colour (border-hairline) and the border-none reset. · outline- and font- likewise.

The lint rule in ②ᵃ must classify on the resolved (prefix, value) pair, not the prefix. Recorded here because it is a correctness requirement on the rule, not an implementation detail — and it is the single most likely source of false positives in the whole check.

⓪ᵉ The computed-className finding

29 computed sites, not 7. The plan's feasibility argument rested on "only 7 of 206 are computed className={…}; the other ~96% are plain literals". The real figure is 29 of 235 (12%).

The strategy still holds — every one inspected holds its classes as string literals inside the expression (template literals with interpolated maps, e.g. ${TONE[tone]}, ${FRAME[frame]}, ${METHOD_COLOR[verb]}, and the maps themselves are literal objects). Reading literals inside the expression gets them right. What changes is the rule's obligation: at 12% the "report unresolvable fragments rather than silently pass" path is not an edge case — it is a routine path that needs its own RuleTester case, and the interpolation boundary must be handled (a naive scan of a template literal yields junk tokens like ${TONE[tone]}, ?, : as if they were classes).
