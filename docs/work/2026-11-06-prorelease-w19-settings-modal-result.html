How

flowchart LR
  E["menu · Help · tray · open_settings"] --> R["lifecycle::request_dialog: queue the request"]
  R --> M["reopen_main (raise, or rebuild)"] --> V["emit dialog-requested"]
  V --> P["page: take_dialog_requests → queue"]
  P --> S{"quit check or keep ask up?"}
  S -- yes --> W["wait"]
  S -- no --> D["ModalShell: SettingsDialog / AboutDialog"]
  C["Close Window (own menu item)"] --> T["topmost(): close the top dialog, else close_window"]
The quit request's flag + event pattern, reused: a window still being built takes the request on its first read.

Removed

The settings and about windows; capabilities/about.json; settings from default.json and from the e2e capability; the page marks (page.ts); Settings' saved size and place (its windows.json record is no longer written; an old one is ignored); the native Close Window item.

Deviations

Onboarding is a screen, not a dialog, in this build, so Settings opens over the setup screen rather than waiting for it (the owner's Q5 list named it). A quit over Settings hides it and a cancel brings it back on its first page (the plan said "finds Settings again"; the page is not kept). The epic moved during the build (W5 merged) and was merged in; W5's screenshot spec addressed the settings window and was rewritten, S11 re-shot. Two pre-existing e2e defects surfaced: background-off read General's update switch as a third switch (fixed in the spec), and inspect-window-v2's JWT decode fails on the unchanged epic tip too (not this WU).
