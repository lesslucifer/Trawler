E-ONBRVP.W17 — wording and display: Android emulator

W12's pattern and W13's help rule on the Android emulator. adb reaches every emulator running, and a Google APIs image answers su, so the shell can install, route, open the address and start an emulator. Each task leads with a button, keeps its command as the other way, and names the Settings path Android 15 actually shows.

v2 · 2026-11-01 · Trawler · T3 WU plan · E-ONBRVP.W17 · branch wu/onboard-revamp/android-emulator-wording · epic plan · depends on E-ONBRVP.W12 · E-ONBRVP.W8
Every point is ruled (the owner, 2026-11-01: "1. all · 2. one for both as other screens · 3. no confirm · 4. most recent · 5. no design"). Every finding and both hand-ins are taken. Q1, Q2, Q3 and Q5 are A, and Q4 is B: the AVD used last gets the button. There is no design run, so each rendered file the build touches is declared undesigned on the design note, with that ruling as its reason. The WU adds no component and no screen, so none needs a citation. I found the findings by reading the android-sim reels, which I filmed again on all three hosts at the epic tip (fccdd1fe), and the source of its guide. I also tried each step on a throwaway Android 15 emulator (Google APIs image, API 35) against a throwaway CA and a local HTTPS server. The emulator, its AVD, the CA and the server are all deleted. Your Pixel_7_API_35 AVD was not touched.

Requirement

On the Android emulator, each state of the setup screen leads with the one thing to do next. That thing is a button wherever the shell can do the step through adb, and its command stays as the other way, naming an adb the user can run. Every word names one thing one way, matches what Android 15 shows, and is true of what the screen read. Where a step stays by hand, a button opens its screen and the rest is path parts. What explains shows only on request (W13's R1). A test holds each rule.

Part 3 — routes and media (the epic's Q11)

#The step todayProposed routeRuling
I1 Trust: save, push, then eight taps in Settings. install in the emulator, offered only where the store read answered (trusted or absent), which means su answered. On every running emulator, the shell pushes the live certificate's DER, copies it as su into the user store under its subject hash (system:system, 644, restorecon), and sends TRUST_STORE_CHANGED so an open Chrome trusts it. The store reading, not the click, then shows done — trusted in Pixel 7 API 35. A failure says what failed and opens do it by hand.take
I2 Route: paste a loop into a terminal. route the emulator: settings put global http_proxy 10.0.2.2:<port> on every running emulator, as the shell user. The proxy reading shows done.take
I3 Task 3: copy the marked address into Chrome. open it in the emulator: am start -a android.intent.action.VIEW with the marked address on every running emulator. The shell builds the URL and checks the mark, as for the Simulator. Its ?: A new emulator's Chrome shows Welcome to Chrome first: tap Use without an account, and the address opens.take
I4 No emulator running: nothing to press. open <AVD>: the shell reads the AVD folder (ANDROID_AVD_HOME, else ~/.android/avd) and picks the AVD whose hardware-qemu.ini is newest, the one used last (Q4 B). The button names it by its display name, and starts it, detached, with emulator -avd. The start command sits under do it by hand. With no AVD, the step says to create one in Android Studio's Device Manager.take
I5 No su (a Google Play image): the push, then the full Settings path. send it to the emulator: the shell pushes trawler-ca.cer to Download on every running emulator and opens More security & privacy. Then the path parts are Encryption & credentials → Install a certificate → CA certificate → Install anyway → trawler-ca.cer.take
I6 Ways back: a sentence each. Certificate: open Trusted credentials (the User tab), then W2's path parts. Proxy: stop routing the emulator, which sets :0 on every running emulator, shown once task 2 reads done, as This machine's reversal is. The quit dialog keeps the command through routeUndo.take
M1 — No media. Every step is a button, or path parts on a screen a button opened.take
