E-GATETRUTH.W4 — verify-doc resolves the links it ships

Nothing checks whether a doc's links point at anything. Four shipped dead in W12 alone, and all four sat in docs verify-doc refuses to open — it reads data-artifact, and a decision record declares none. This WU makes a relative href a checked property of the file rather than of its artifact type, so the class becomes mechanically impossible.

WU plan · 2026-09-04 · Trawler · T3 (docs/work/) · wu/gate-truth/link-integrity off epic/gate-truth @ 8d11ff1 · epic plan · W3 result · E-GATETRUTH.W4

Requirement

verify-doc reds a doc carrying a relative href that resolves to nothing in the working tree, naming the href and the doc, and it asks this of every .html file it is handed — governed or not — except one whose data-status is draft. A link into docs/.archive/, an absolute URL, a bare #anchor and a mailto: are not link-checked; no other verify-doc verdict changes.

Why nothing caught the four

verify_html_against reads the doc's data-artifact and returns Verdict::Ungoverned the moment there is none — before any predicate runs. A decision record declares no artifact type, and neither does a plan doc's prose body. Both dead-link classes the epic cites lived in exactly those docs, which is why a hand audit found them and 35 green verify-doc runs did not.

The predicate

One question per href, asked of the file the doc sits in. The doc's own directory is the base; the answer is whether <dir>/<href minus its fragment> exists.

Rows 4 and 5 are the epic plan's two archive wrinkles. Row 3 is the one that makes them wrinkles at all: an archived doc is red when named by its old live path and green when named by its .archive/ one, which is exactly the difference between a link that rotted and a link that was deliberately pointed at the archive.

Which docs it asks

The check is a property of the file, not of its declared type — so it runs before the data-artifact read that ends Hình 1 early. The one exception is a draft: the standard gives an author an explicitly silent surface to iterate on, and a link to a doc not written yet is the normal midpoint of writing a set of docs, not a defect.

This narrows a stated promise, so it is a rule change. work-planning's hook table says "drafts and ungoverned docs stay silent". After this WU that sentence is true of the checklist checks and of drafts, and false of ungoverned docs — a dead link is a dead link whatever the doc declares. The T1 edit says so in those terms and carries a Reviewed-By trailer per DoD-C.

Non-goals

  • No external link checking. https(s) targets stay unchecked — epic non-goal; the tree cannot answer for the network and a test that asks would not be hermetic.
  • No fragment resolution. foo.html#bar is checked for foo.html only. Whether #bar exists inside it is a second predicate with its own failure modes; epic non-goal.
  • No src, no images. The predicate reads href. Asset integrity is a separate question and the epic excludes it.
  • No history resolution. Unlike W2's citation predicate, a link is asked of the working tree only — the reader who clicks it has a checkout, not a rev-list. An archived target is repaired by rewriting the link as text, not by resolving it at an older commit.
  • No new gate check. Authoring time, per epic open question 4; the DoD gate gains no check id and the receipt is unchanged.
  • No hook change. Both hooks already run verify-doc and already act on exit 1 — the PostToolUse hook on every .html write, the Stop hook over every doc under docs/. They pick the predicate up for free, which is why the T1 edit is to the standard's text and not to .claude/.
  • No fixes to today's tree. The epic plan allowed for repairing dead links found here; a hand audit of all 42 docs found none — the four were fixed by hand in W12 and E-GATETRUTH.W1–W3. The result doc records the audit so the claim is checkable.
