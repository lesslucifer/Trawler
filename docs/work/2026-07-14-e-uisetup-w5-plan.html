E-UISETUP.W5 — Proxy auto-revert

Tear the system proxy back down cleanly so Trawler never leaves the machine pointing at a dead proxy. A symmetric unset_proxy command runs W3's per-OS turn-off, exposed as a manual "stop routing" control and as auto-revert on clean quit, gated on a we-set-it marker so it only ever reverts a proxy Trawler set — plus crash reconciliation at the next launch.

Draft v1 · 2026-07-14 · Trawler · T3 WU plan · epic: E-UISETUP · needs: W3 (off-commands + set marker) · W4 (launch path)

Requirement

A symmetric unset_proxy Tauri command runs the native turn-off of whatever W3's set_proxy switched on (macOS networksetup -setwebproxystate off / -setsecurewebproxystate off per enabled service in one elevation; Windows ProxyEnable=0 + the WinINET refresh). It is gated on a we-set-it marker — a small file written when set_proxy succeeds, deleted when unset_proxy succeeds — so a revert only ever touches a proxy Trawler set, never a proxy the user configured themselves. The command is exposed three ways: (1) a manual "stop routing through Trawler" control that turns the proxy off without quitting (and setting it again turns it back on); (2) auto-revert on clean quit via a Tauri window-close / exit hook; (3) crash reconciliation at launch — a marker present on the next launch means a previous run set the proxy and died before reverting, so that launch clears the stale self-set proxy (coordinated with W4's launch self-test). The unfixable tail — the app killed for good with no relaunch — is called out, not solved from inside a dead process (that needs an OS-level watchdog, out of scope). No core / API change: the off-commands run locally in ui/src-tauri, same boundary as W2/W3.

Maps to

Epic E-UISETUP.W5 — the teardown half of the UC-5 onboarding contract: the epic's consent, never silent rule makes turning setup off as first-class as turning it on. Reuses W3's native set path (set_proxy_commands, parse_services, the elevation wrapper, the WinINET refresh) and its off-step vocabulary (proxyOffSteps already documents the exact commands per client); adds the symmetric native builder and the marker those steps never needed as text. Integrates with W4's launch path — reconciliation runs on the same startup the self-test already owns. Local-OS capability only; no new endpoint, no core change (DEC-12 holds).

Design

W3 already builds and runs per-OS elevated argvs from fixed templates and writes the WinINET refresh; W5 is the mirror image plus one persistence fact — the marker. The teardown reuses every piece of W3's machinery; the only genuinely new question is "did we set it?", and the answer is a single file whose presence is the whole signal.

stateDiagram-v2
  [*] --> Launch
  Launch --> Reconcile: marker present?
  Reconcile --> Cleared: yes → unset_proxy, delete marker
  Reconcile --> Ready: no
  Cleared --> Ready
  Ready --> Set: set_proxy ok → write marker
  Set --> Off: manual "stop routing" / clean quit → unset_proxy, delete marker
  Off --> Ready
  Set --> [*]: hard kill (no revert — unfixable tail, marker survives)
  [*] --> Launch: next launch reconciles the stale marker
The marker is the single source of "Trawler set this proxy": written on set, deleted on unset, and the one thing a fresh launch reads to detect a crash-orphaned proxy.

The marker — presence is the whole signal

A zero-content file in the OS temp dir (std::env::temp_dir().join( "trawler-proxy-set"), the same temp-dir pattern W2 uses for the CA bytes). It is written after set_proxy's commands all exit 0, and deleted after unset_proxy's do. Its existence means "a Trawler run switched the system proxy on and hasn't turned it back off" — nothing more is stored, because the off-commands re-derive everything they need at run time (macOS re-queries -listallnetworkservices; Windows just flips ProxyEnable). This is the laziest correct marker: no serialized state to version, no stale service list to reconcile, presence-or-absence and done.

Why temp, not app-data. Temp survives a process crash (the crash tail we must handle) without threading a Tauri AppHandle path through the pure command builders. The one residual case — the OS clears temp between a crash and the next launch — leaves the proxy set with no marker to reconcile from; that collapses into the same unfixable tail the epic already calls out (a self-set proxy no live process can see), not a new gap. The marker guarantees the common crash-then-relaunch case, which is the one worth guaranteeing.

The native off-builder — mirror of W3's set

unset_proxy_commands(os, services) sits beside set_proxy_commands in setup.rs, same signature minus host/port, same shape of output (a Vec<Vec<String>> of argvs):

OSset_proxy (W3)unset_proxy (W5)
macOS one elevated osascript running -setwebproxy / -setsecurewebproxy per enabled service one elevated osascript running -setwebproxystate off / -setsecurewebproxystate off per enabled service (same parse_services + shell_quote, keeps the saved address, matches proxyOffSteps("macos"))
Windows reg add ProxyServer + ProxyEnable=1, then WinINET refresh reg add ProxyEnable=0, then the same internet_set_option_refresh() (keeps the saved address, matches proxyOffSteps("windows")), unelevated
otherNoneNone — guided-only, same as set

The unset_proxy command validates nothing from IPC (it takes no arguments — host/port are irrelevant to a state-off), runs the argvs exactly as set_proxy does, surfaces the OS tool's stderr on failure, and deletes the marker on success.

The three exposures — one command, three callers

ExposureWhereWhat fires unset_proxy
Manual "stop routing" Onboarding.tsx set-proxy body (auto-capable host only) A control shown once the proxy was set this session: click → invoke("unset_proxy"). Re-running Set system proxy turns it back on (symmetry). Guided clients keep their existing text proxyOffSteps fold — unchanged.
Confirm on quit closeConfirm.ts — the webview's onCloseRequested Revised in build (see the W5 result). The plan first put this on a silent WindowEvent::CloseRequested Rust hook; a bare elevation prompt at quit is confusing and declining it strands the user. So the close is intercepted in the webview and gated on the real system status (proxy_status), not a session flag: ours ⇒ prevent + ProxyCloseDialog Remove (unset_proxy) / Keep (clear_proxy_marker); foreign / none ⇒ info-only notice (a device elsewhere may still point here) with a durable "don't show again"; dismiss cancels.
Cmd-Q / menu Quit net lib.rs — RunEvent::ExitRequested Added in build (review finding). macOS Cmd-Q / menu Quit go through [NSApp terminate:], which never fires onCloseRequested and can't be cancelled to show a dialog — so the confirm above is skipped on that path. A synchronous revert_if_marked() here guarantees the machine is never left on a dead proxy; it is a no-op after a consented Remove/Keep.
Crash reconciliation lib.rs — app setup hook, on the W4 launch path At startup, if the marker is present, a previous run set the proxy and never reverted → run the off-commands and clear the marker (off the main thread), so the fresh launch begins from a clean slate. The hard-crash tail nothing got to answer.

The launch path uses the marker-gated revert_if_marked() helper (present ⇒ run off-commands ⇒ delete marker; absent ⇒ no-op); the quit path reads the same marker via proxy_is_set and routes the user's choice through unset_proxy or clear_proxy_marker. Every revert is gated on the one marker, so it can never touch a proxy Trawler didn't set.

The unfixable tail, named not solved. If the app is force- killed and never relaunched, no Trawler code runs to revert, and nothing inside a dead process can. Reconciliation covers crash-then-relaunch; the terminal case (gone for good) is a known limit that would need an OS-level watchdog — explicitly out of scope for this WU and this epic.

Test plan

Same layering as W2/W3: the pure builders and the marker gate are unit-tested in the standalone src-tauri crate; the quit-reverts journey is the e2e add.

LevelWhereAsserts
unitsetup.rs (Rust) unset_proxy_commands("macos", …) is one elevated osascript with -setwebproxystate off + -setsecurewebproxystate off for every service, single-quoted, address untouched. unset_proxy_commands("windows", …) writes ProxyEnable=0 and reuses the InternetSetOption refresh, unelevated (no RunAs). None on linux. The marker gate: revert_if_marked is a no-op when the marker file is absent and runs-then-deletes when present (temp-file roundtrip, no elevation needed for the presence check).
e2eui/e2e/specs/ + harness The quit-reverts path: the manual "stop routing" control is present in the set-proxy body and invokes the command; and the lifecycle wiring is exercised end to end in the real Tauri window. See the waiver — the OS-level proxy write/read is elevation-gated and not hermetic, so e2e proves the wiring and control surface, and the actual argvs are the unit contract.
Waiver (judged at review), inherited from the epic. The native proxy-off, like W3's set, needs OS elevation / a real system proxy store and is not hermetically runnable in e2e — the off-command builders and the marker gate are unit-tested, and e2e proves the control + lifecycle wiring. Reverting a real system proxy on the CI host would mutate the machine, which the hermetic-test rule forbids; by design, not a gap.

Done when

  • A manual control turns the proxy off (and setting it again turns it back on) without quitting.
  • Quitting the app reverts a proxy it set (clean-close hook), and does nothing if it set none.
  • Relaunch after a crash detects the stale we-set-it marker and clears the self-set proxy.
  • A revert only ever touches a proxy Trawler set — every path is gated on the marker.
  • unset_proxy builder + the marker gate unit-tested; the quit-reverts / control wiring covered in e2e. Gates green headless: vitest + cargo test (src-tauri) + clippy pedantic + cargo xtask ui build.

Non-goals

  • Reverting a proxy Trawler didn't set — the marker gate forbids it; we never touch a user-configured proxy.
  • The gone-for-good tail — app killed and never relaunched; needs an OS watchdog, out of scope.
  • Auto-revert of the CA trust — trust is longer-lived and its removal stays guided (W2's removalSteps); only the proxy auto-reverts.
  • A persisted store or new API endpoint — the marker is a single presence file in temp, not a config surface; DEC-12 (no core change) holds.
  • Reverting guided (non-auto) clients — Linux/Firefox/devices keep their existing text off-steps; auto-revert is only for what Trawler auto-set (macOS/Windows).
