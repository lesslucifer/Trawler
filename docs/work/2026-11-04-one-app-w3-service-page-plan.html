E-ONEAPP.W3 — the Capture service page

Settings… (⌘,) opens a page that shows the capture service's state, ports and live log and can restart it. When the window's core stops answering because the core exited, the window offers the same restart.

v1 · 2026-11-04 · Trawler · T3 WU plan · E-ONEAPP.W3 · branch wu/one-app/service-page · epic plan · depends on W2 · design run the Capture service page

Requirement

The app menu's Settings… (⌘,) opens a Capture service page that renders the supervisor's CoreState (starting · running with pid, start time and both ports · exited with its code or signal · attached with its address), streams the core's log as it arrives, and offers restart, which first warns that the captured list is cleared. The attached state shows no restart. When the core is owned and has exited, the main window's "isn't answering" state offers that same restart.

Mapping

E-ONEAPP · UC-SVC (new) · UC-4 (the not-answering restart) · expected #10 · owner rulings Q12 (no automatic restart) and Q14 (restart only, no stop). It renders W2's contract, ui/src/coreService.ts, and adds no core API. W4 owns the quit copy, and W5 drives this page end to end (J2).
