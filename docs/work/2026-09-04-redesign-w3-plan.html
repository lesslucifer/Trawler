E-REDESIGN.W3 — design the flow list and the app shell

The epic's first screen design run: one artifact covering FlowList, the App header/filter bar and Layout — six stages, five closing lists, archived closed. It designs a surface W2 partly wired ahead of it, and judges that wiring rather than inheriting it.

WU plan · 2026-09-04 · Trawler · T3 (docs/work/) · wu/redesign/flow-list-shell → epic/redesign · format: design run · rulebook: design-rules-index @ aeff5b0 · builds in W4

Requirement

Design — not build — the flow list and the app shell as one design run at docs/work/2026-09-04-flow-list-shell.html, carrying all six stages (Frame · Layout · Elements · Interaction · Draft mockup · Tune) and all five closing lists (receipt · capabilities · proposals · blocked-on · review), so that every element of FlowList.tsx, App.tsx's header and Layout.tsx resolves to a registry reuse/extend/propose verdict judged against its @use/@avoid, every soft rule in the rulebook carries a receipt verdict with evidence, and the run closes verify-doc-green and archived — leaving W4 a design it can cite by blob and build from without making a single design decision of its own.

The three questions this run must actually answer

Everything else in the run is method. These are the calls the screen genuinely does not have yet — each is a live question the plan deliberately leaves to the run, not a conclusion it pre-writes.

hard rule · wrap-not-truncate

Four cells truncate today

FlowList.tsx:78-82 puts truncate on time, method, host and path. The rule reads "no truncate/ellipsis/nowrap on payload elements" and binds at Elements · Draft mockup; host and path are wire payload in a fixed-height virtualized row.

The run resolves it on the record — a wrapping scheme, a column-priority scheme, a scoped propose, or an honest violated/blocked receipt with its reason. Not pre-decided here.

soft rule · visual-weight-follows-goals

The column widths encode a hierarchy nobody declared

110px 70px 180px 1fr 70px 90px gives path all the slack and status 70px. The Frame's goal ranking is what decides that, and the Frame does not exist yet.

If the top goal is scanning failures, the shipped weighting is upside down. The run's Frame must state the job — log correlation, live watching per the epic plan — and the Layout/mockup must then match it or explain itself.

soft rule · empty-states-orient · absence-names-itself

One sentence for several absences

Today: one raw <p>, "no flows yet — send traffic through the proxy". But the list can be empty for distinct reasons — nothing captured yet, versus a filter that matches nothing. Field's @avoid already routes the second one: "an unmatched filter is an empty list, explained by Notice at the list".

Two causes must not share one sentence. The run enumerates every way this zone can have nothing to show and gives each its own words.

data-item="frame"		A driver table — driver → why → therefore → on this screen with a ✓/✗ pair per row, grouped Goals/Constraints/Qualities, under the six density predicates (mean cell ≤12 words, longest ≤40; mean pair ≤24, longest ≤36; ≤3 <p>, longest ≤60). 2 · Layout
data-item="layout"		An annotated ASCII sketch of the shell's zones with a priority note each, and the overflow line naming every unbounded zone's cap and its owner — the list (ring-capped, virtualized), the detail pane (its own scroll), the header (pinned, never scrolls). This line is overflow-declared's whole check.
3 · Elements
data-item="elements" + data-map		A placement/composition tree plus one row per distinct component, each carrying tier · verdict · placement in one cell, a ≤14-word gist over a <details class="why"> that traces the @avoid cleared and the @use landed in, a reference ASCII shape, and states by reference. Every mention carries data-key. The T3 row breaks down to its lower-tier parts. data-wire on every payload element, data-order beside the collection row.
4 · Interaction
data-item="interaction"		A use-case table, each row grounded in a Frame goal, responses as zone → delta lines with UNCHANGED spelled out where not-changing is the decision, and a keyboard path per row (keyboard-parity is checked per row). The real cases: watch traffic arrive, narrow by filter, select a row, dismiss the detail, re-enter setup. Row selection has no keyboard path today — the row is a div with an onClick; the run must name one or propose it.
5 · Draft mockup
data-item="mockup"		A real build that mounts the real components from window.Trawler via specimens.bundle.js — every reuse/extend mounted, never drawn (mockup·hand-drawn). Screen-owned: the grid, the row assembly, the header row, the zoning. Stateful toggle across the states Interaction named — at minimum populated ⇄ empty. Zero colour literals in the doc's own CSS.
6 · Tune
data-item="tune"		A before/after table, both cells drawn in <pre class="tb">, every row citing a soft-rule slug, and a why stating whether it loops back to Layout. tune·drawn reds a row with fewer than two drawn cells, no slug, or prose instead of a table.
The closeReceipt (YAML: the rulebook blob, then every one of the 17 soft slugs in rulebook order with a verdict from the enum and one clause of evidence) · capabilities (every Given answered — used, deliberately unused, or blocked) · proposals · blocked-on · review. Then step ① re-pin, ③ green, ④ data-status="archived" — in that order.

A design WU adds no code, so the pyramid's three levels have nothing to assert against. The waivers rest on the E-DFLOW.W9 precedent the epic plan cites — the WU "touches no product code or screens" — and are stated here rather than taken silently.

What could go wrong

RiskHandling
The run ratifies W2's wiring instead of judging it. The path of least resistance is six reuse rows and a fluent receipt — exactly the "complete, fluent and false" failure Tier-3 exists to catch.Each pre-wired element's why must trace a real @avoid line, and the run states explicitly where it would have chosen differently. The method field is the live test case: Field's @avoid names "a choice among known options (that is Select)", and HTTP verbs are a known closed set. A run that does not engage that line has not judged the fit.
The template is unproven. No screen run has ever been written; the eleven items, the density predicates and the mount rule have only ever been checked against the flow spec's own example.Expect sharp edges and treat them as findings for the gate, not obstacles to work around — the epic plan's standing instruction. Edits are batched: one pass, verify-doc once, batch residuals, verify again. The norm is edit twice, verify twice — never twelve cycles.
The mockup hand-draws a component. A drawn component in correct utilities is a fork no class check can see; mockup·hand-drawn is the only thing standing between this run and a silent divergence.Build the bundle first (cargo xtask ui specimens) and mount from window.Trawler. Screen-owned is the grid, the row assembly and the zoning — nothing that has a registry entry.
The run designs through the detail seam. Layout's aside is on screen whenever a row is selected, and it is tempting to design its contents.The seam is declared, not designed — the shell owns the region, its width and its scroll; W5 owns what is inside. A zone note and an overflow line, nothing more.
The Frame restates the rulebook. "Use tokens", "be accessible", "calm microcopy" are all already bound — a Frame full of them holds nothing case-specific and fails Tier-3's "is a driver case-specific or a restated rule".Every driver must land on a concrete, falsifiable ✓/✗ pair about this screen. The density predicates enforce brevity; the reviewer enforces substance.
A stale rulebook pin. W2 deliberately deferred a rulebook row to W11 precisely so the screen runs pin an unchanged substrate — but the pin is still re-checked at close.Step ① of the close: re-run git hash-object docs/design-rules/design-rules-index.html and compare against the receipt. If it moved, both halves of the close re-open. receipt·rulebook-stale is the alarm.
