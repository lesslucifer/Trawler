Manual Review — design & epic plan

A human sign-off gate in the workflow. This epic builds the whole enforcement skeleton — path-derived requirement, the commit-message carrier, the mr/v1 note, the gate check, the walk — with identity-only authorisation (username / email). The unforgeable, hardware-backed cryptographic signature is a deliberately separate follow-up epic (E-MRSIG, on the roadmap) that swaps only the auth check. Draft — nothing implemented.

Draft v5 · 2026-07-06 · Trawler · T3 work doc

Scope of this epic — read first. Authorisation here is an identity assertion: a username or email listed in .mr-allowed. Because an agent knows the user's identity, it can produce it — so this epic's guarantee is a forced stop + an audit trail of who signed, not cryptographic proof. That is intentional: the hard, agent-unforgeable signature needs its own design discussion and ships as E-MRSIG. What this epic delivers is the entire surrounding machinery, built so E-MRSIG only has to replace "is this identity allowed?" with "does this signature verify?".

The strategy — three rules, two carriers, one authoriser

Manual review is required by the level and the diff's file paths — never by anything the agent asserts about necessity. When required, an authorised human's identity must be recorded: in the commit message at commit level, in the mr/v1 note at WU/epic level.

Level / gateRequired when…Authoriser recorded in…Blocked at…
Committhe commit touches docs (is_doc)the commit message (an mr trailer)commit-msg hook — the commit is refused
WU merge → epicthe WU touches UI (is_ui, deferred to E-UIFOUND)the mr/v1 note on the tipthe merge gate
Epic merge → mainalwaysthe mr/v1 note on the tipthe merge gate

Why the commit message for docs. Reviewing after the commit exists is too late — you want the commit prevented without a human OK, and a git note can't hang on a commit that doesn't exist yet. So the authoriser travels in the message: the commit-msg hook sees the staged diff touches docs/, requires an mr: <identity> trailer whose identity is in .mr-allowed, and refuses the commit otherwise. (In E-MRSIG this trailer carries a signature seeded by the change hash — the diff, which exists pre-commit via git diff --cached and recomputes after as parent..commit; the carrier is designed for that now, it just holds an identity today.)

How the gate decides it's required

is_doc(path) = path.starts_with("docs/")
is_ui(path)  = <deferred to E-UIFOUND — the embedded web UI's asset paths>

commit  requires mr  ⇔  diff.any(is_doc)
WU      requires mr  ⇔  diff.any(is_ui)
epic    requires mr  ⇔  always

The check runs independently of the docs/infra exemption: a docs-only commit is exempt from test/cr/doc notes but still needs an mr trailer — like the epic tracked-doc check (DEC-3) that fires on otherwise-exempt tips. When not required, nothing changes for that tip.

The authoriser — identity in .mr-allowed

One committed file lists who may sign off, by identity. The gate/hook checks the recorded authoriser is a listed one — nothing more, this epic.

# .mr-allowed
email:    vu.luu@workforceoptimizer.com
username: vuluu
# (E-MRSIG later adds a `key:` tier — a public key — for unforgeable signatures)

Mechanical test: the identity in the trailer / note is present in .mr-allowed. Optionally the hook also checks it equals the commit's committer identity — a weak sanity tie, still agent-controllable. The point today is that the recorded name is a known, accountable person and that the agent had to stop and ask; the file also seeds the trust anchor E-MRSIG will harden.

"Never automatically" — this epic vs. E-MRSIG

This epic (identity)

The gate/hook is mechanical (identity present & listed?), but the human-only part is procedural: the failure message and workflow.html instruct the agent to stop and get real confirmation, and never self-authorise. Enforced by honesty + the forced pause, like the rest of the DoD honesty layer.

E-MRSIG (crypto)

Replaces the identity check with a signature verify against a hardware-backed key. Then "the agent cannot produce it" becomes true, not asked. Everything else in this epic — rules, carriers, hook, gate check, walk — stays exactly as built.

The gate/hook error is explicit, both epics:

FAIL  8·manual-review   commit <sha> touches docs with no valid mr authoriser
      fix -> A HUMAN must review this and confirm. The AI agent MUST NOT self-authorise.
             After the user has reviewed and said yes:
               cargo xtask mr commit -m "<msg>" --as <email|username>      # doc commit
               cargo xtask mr confirm <wu|epic> <tip> --as <email|username>  # WU / epic
             The identity must be listed in .mr-allowed.

The evidence — message trailer & mr/v1 note

No status/waived — manual review is not waivable: required means a listed authoriser is recorded. Both carriers hold the same small identity record; the schema leaves room for the signature E-MRSIG adds.

## commit level — a message trailer (one line):
docs: revise capture use-case

mr: email vu.luu@workforceoptimizer.com          # E-MRSIG: append the change-hash signature here

## WU / epic level — the mr/v1 note on the tip:
schema: mr/v1
level: working-unit          # working-unit | epic
tip: <the gated tip>
tier: email                  # email | username  (which .mr-allowed tier matched)
signer: vu.luu@workforceoptimizer.com
date: YYYY-MM-DD

Below: the epic-plan checklist items, filled from the strategy above.

Intent

Add a human sign-off checkpoint to the DoD workflow so changes to human-facing surfaces cannot land silently: doc commits are refused at commit time unless the message names a listed authoriser; UI WUs and every epic are refused at merge unless the tip's mr/v1 note names one. The requirement is derived mechanically from the diff's paths. Authorisation this epic is identity-only (username / email) — a forced stop and an audit trail; the unforgeable cryptographic form is the follow-up epic E-MRSIG. The value now is the complete, correct machinery and a clean seam for that hardening.

Use-case requirements

A process/tooling epic — it changes the workflow standard, the gate, and the hooks, not the Trawler proxy product, so it touches no product UC-*. Its contract is the workflow itself: workflow.html (T1) gains manual review as a path-derived check across the commit and merge gates; a decision record captures the design and records the E-MRSIG deferral. The roadmap already carries E-MRSIG and the E-UIFOUND/is_ui dependency. T2 target is docs/decisions/.

Expected result

After this epic: (1) a commit-msg hook refuses a commit whose staged diff touches docs/ unless the message carries an mr: <identity> trailer with an identity listed in .mr-allowed. (2) cargo xtask verify-dod fails a UI WU merge (once UI paths exist) and every epic merge lacking a valid mr/v1 note, with an explicit human-confirmation instruction stating the agent must not self-authorise. (3) .mr-allowed supports email/username tiers, the matched tier recorded on the note. (4) cargo xtask mr commit|confirm --as <id> write the trailer / note after checking the identity is listed. (5) Verification is offline in the hook/gate; a valid authoriser makes the gate green and records the check in dod/v1; the walk re-verifies doc-commit trailers and merge-tip notes. (6) workflow.html reflects the change and a decision record explains it, including the E-MRSIG boundary.

Non-goals

No cryptographic signatures, hardware keys, or key setup (all E-MRSIG). No waivers (manual review is not waivable). No manual_review manifest flag (path-derived). No change to test/v2, the plan docs, or testing-strategy.html. No rejected status — absence of a listed authoriser is the rejection. This epic does not claim agent-unforgeability; that is E-MRSIG's job and is stated plainly wherever the mechanism is documented.
