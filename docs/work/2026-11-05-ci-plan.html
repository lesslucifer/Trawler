E-CI — a CI workflow on main: macOS, a signal and not a gate

A one-WU infrastructure epic. It puts .github/workflows/ci.yml on main, so that E-PKG2.W2 can dispatch Windows and Linux runs on its own branch.

v1 · 2026-11-05 · Trawler · T3 epic + WU plan (collapsed) · E-CI · E-CI.W1 · branch epic/ci off main 398f6dfe · WU wu/ci/ci-yml · from the owner's rulings Q17 and Q19 on 2026-11-05-packaging-v2-plan.html (E-PKG2), and the owner's go-ahead on 2026-11-05

Intent

Nothing outside this Mac has ever built or tested Trawler. E-PKG2.W2 has to bring the app up on Windows and Linux in GitHub Actions, and GitHub can dispatch a workflow on a branch only once the workflow file exists on the default branch. This epic lands that file with one job, macOS, the platform that is green today. It runs on every push to main and by hand on any branch. Why now: E-PKG2's W2 and W3 wait on it (Q19), and the owner chose to unblock them this way.

Local gates stay the only gates (DEC-42, DEC-74). CI reports, it does not refuse.

Requirement

.github/workflows/ci.yml runs on a push to main and on workflow_dispatch, and on nothing else. Its one macOS job installs the UI's packages from the lockfile, then runs cargo clippy --workspace --all-targets --all-features -- -D warnings and cargo test -p trawler -p trawler-ui, with read-only repository permissions.
