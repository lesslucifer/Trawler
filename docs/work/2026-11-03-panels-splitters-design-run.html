Design run: the splitters and the column handles

The flow list and the detail pane, with the list/pane split, the headers/body split and the five fixed columns each sized by the user between two tokens.

Design run · round 1 on 2026-11-03, closed (archived) · Trawler · T3 (docs/work/) · E-PANELS.W2 · branch wu/panels/splitters-design · epic E-PANELS · WU plan · component: Splitter (design retired into its TSDoc, DEC-16) · within DEC-67

Mockup

Live: drag the line between list and pane, the line under the headers, or a tick between two column labels. Each one also takes Tab, then the arrows (Shift for a larger step), Home / End; a double-click restores its default. The frame is the real window size, scaled to fit. The buttons below the frame force one state at a time.

overflow: app header pinned. flow list: rows scroll vertically, capped by the capture ring; when the list is narrower than its row (Σ tracks + 92 + path-min) the rows and the label row scroll sideways together, labels pinned to the top (Q8). list/pane splitter and headers/body splitter are bounded: 1 px lines, no content. detail pane: never scrolls as a whole. identity and flow line pinned, one row each. headers scroll inside a ceiling of the pane's height (the share, zone-min…zone-max). body takes the rest and scrolls inside itself (DEC-32).

Payload is mono: each row's cells (api.example.com, path, time, method, status, duration) and the header values. The splitters carry no payload.

A dragged value is user state between two tokens, never a design magnitude (DEC-67). Splitter A's live maximum is min(pane-max, window − 1 − list-min). When that falls below pane-min, pane-min wins and the list scrolls sideways.
