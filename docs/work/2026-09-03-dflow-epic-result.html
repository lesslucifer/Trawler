E-DFLOW — epic result

A design system and harness by which AI agents design UI consistently and verifiably: a component registry in code, an enumerable rulebook, a six-stage flow, and a three-tier gate that refuses a design which skipped a rule. Eight runs proved it; the last one measured what it costs.

Epic result · 2026-09-03 · Trawler · T3 · epic/design-flow → main · 12 Working Units

Outcome

The epic promisedWhat shipped
A T1 process doc — the staged flow and its per-stage artifacts docs/design-flow.html, with docs/component-design.html beside it for components. Both were written in W1–W2 and lived in docs/work/ until W12 promoted them — the promise was kept last, not first

A harness enforcing three tiers, emitting a receipt, red/green like the DoD gate Tier-1 cargo xtask verify-doc (mechanical completeness + the hard predicates + receipt coverage) · Tier-2 the run's own receipt · Tier-3 the design dimension of the code review (DEC-24), pinned by design-scope and recorded in a cr/v3 note
The flow run once to a passing, receipted design Eight runs, not one — two hand-runs, five on shipped screens, and one greenfield on a function that does not exist yet (the E-REPLAY composer)
A flow e2e (fake user + fake agent) proving the plumbing end to end xtask/tests/e2e_design_flow.rs, feature-gated design-e2e — 4 tests, green at the tip
