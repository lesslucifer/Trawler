Requirement

Each of This machine's tasks reads, on every host, the most accurate state something on this machine verified: the probes read the exact certificate Trawler uses and the proxy the system actually uses. Where no probe can read, the app's own request is what settles the task, and no promise is made that nothing can keep. A test holds each reading.

M1 · macOS · WindowsThe core keeps its CA in ca/ under the folder it started from. Start it from another folder and it makes a new CA with the same name. The old one is still trusted, so task 1 reads "✓ done — installed and trusted", yet every HTTPS request fails. Task 3 then says "this Mac trusts Trawler's certificate, so it comes from another device", which is false. Checked on this Mac: verify-cert passes for the live CA and fails for a new CA with the same name.The shell gets the live CA, as "Set up this Mac" already does, and checks that exact certificate. macOS verifies the live CA itself. Windows looks for its thumbprint. W2's result listed this as a follow-up.take
M2 · macOSYou double-click the file (the "other ways" route) and skip "Always Trust". Task 1 reads "not done — the certificate isn't trusted", the same line as when nothing is installed. The screen cannot tell you that the one thing left is the trust setting.The probe reports three readings: trusted, installed but not trusted, not installed. Task 1 reads "○ not done — installed, not trusted" for the middle one. The copy is matched to the live CA by its bytes, so no new dependency is needed.take
M3 · macOSThis Mac lists six network services: Ethernet, Thunderbolt Bridge, Wi-Fi, iPhone USB, Tailscale, WFO VPN. You are on Ethernet and run the manual step, which sets Wi-Fi. The probe finds Wi-Fi's proxy and reads "✓ done — this Mac routes through Trawler", but nothing is routed. The same false done shows when only the HTTP proxy is on and HTTPS goes direct.Read scutil --proxy: the proxy settings macOS actually applies, from the service in use (VPNs included). The HTTPS proxy decides the task. It takes 5 ms, against 270 ms for the service-by-service read.take
M4 · WindowsIn Internet Options you untick "use the same proxy for all protocols". The server becomes http=127.0.0.1:7420;https=127.0.0.1:7420, which the probe cannot read, so task 2 reads "can't check here" (and see M5). A certificate imported into your user store, not the machine's, reads "not done" although Edge and Chrome trust it.Read the https= entry of a per-protocol list. Check the user root store as well as the machine's (M1's thumbprint, both stores). Not reproducible here: the argv and parsers are unit-tested, as W2 did for -60007.take
M5 · Linux · any failed readOn Linux you set the proxy and run the curl. Task 2 reads "◐ can't check here — this machine's first request confirms it", and it still reads that after the request arrives. Nothing can ever settle it: only the probe counts for This machine's proxy, because the curl names the proxy itself, and Linux has no probe. The matrix test pins that line in every traffic state. The same happens on a Mac or PC whenever the probe fails to read.The "make a request to example.com" button's request goes through the system proxy, so it is the one request known to prove this machine's route. It carries a marker in its URL (Q4). A captured, decrypted request with the marker settles task 2 (and task 1, M6) wherever the probe cannot conclude: "✓ done — this machine's request reached Trawler". Until then the line promises only what can keep it: "◐ can't check here — the request button in step 3 confirms it". A probe that concludes still outranks it (DEC-33). This is a rule change, so it becomes DEC-62.take
M6 · LinuxYour phone is still pointed at Trawler from yesterday. You open setup for This machine on Linux and do nothing. The phone's background traffic decrypts, and task 1 reads "✓ done — a request decrypted". Task 3's remedy then says "this machine trusts Trawler's certificate". Neither is known.Only a probe, or this machine's own request (M5), settles This machine's certificate. Any other device's decrypt still counts for task 3 ("capturing traffic") and for the success line, as today. Cost: a curl alone no longer settles task 1 on a host with no trust probe. Q1 A covers most of those hosts.take
M7 · LinuxA Linux user sees "can't check here" on both tasks until they act, although both answers are readable on the machine.Two read-only Linux probes, which your Q8 ruling allows. Trust: the system CA bundle holds the live CA's exact bytes (Debian/Ubuntu and Fedora paths; anywhere else unknown). Proxy: GNOME's gsettings, mode manual with the HTTPS host and port; anywhere else unknown. They match the two commands the Linux guide gives.by Q1

That is true, but the request went straight past Trawler, and nothing says so.The note reports the route: "example.com answered through Trawler", "the request reached Trawler and didn't decrypt" (a tunnel to example.com opened after the click, with no marked flow), or "example.com answered, but not through Trawler". It still never turns a task done by itself (DEC-56).take

The live "capturing traffic" line and the success line keep their 30 s window, and the dot keeps its 3 minutes (DEC-61).by Q3
M10 · macOS · WindowsEvery time you come back to the window, both lines flash "⟳ checking" for about 0.3 s and "Set up this Mac" is disabled while they do. You did not ask for a check.A re-read on focus keeps the dated reading on the lines. Only the "checked 14:02" row shows it is checking, and the lines change only if the answer changes. "check again", the first read and the read after an action still show "checking" on the lines.take
