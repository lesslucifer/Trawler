E-EXPORT.W6 — build the controls

The three doors the API already has become three acts a user can reach: one ⋮ trigger at the header's trailing edge, the acts as words inside a menu, a modal ask in front of the destructive one, and a paste target that takes a curl command or a .har file — built from design run 11, cited to it.

v2 · 2026-09-08 · Trawler · T3 WU plan · E-EXPORT.W6 · epic plan · design run 11 · W9 result

Requirement

In the native app, the flow list's header carries one ⋮ trigger whose menu offers export as har…, import… and clear…; export writes the filtered capture through the OS save dialog under the filename the server names and claims nothing when the dialog is cancelled; import opens a modal that takes either a chosen .har file or a pasted curl command and renders a refusal as the server's own sentence, verbatim; clear asks first in a modal titled with the count it will remove, focused on cancel, and the emptied list says capture cleared rather than no flows yet; an imported row carries a ↑ mark in its time cell; and the list refills from the bus — including the cleared event the client did not previously listen for.

The contract calls this WU makes

Question the run leaves to the buildCall, and why
How does a second screen use ModalShell without minting a registry entry? Lift it to its own module under ui/src/, outside components/. Exporting it from ProxyCloseDialog.tsx would make the new screen import from a sibling screen — the shape the collection exists to prevent, and the shape the run names. A module of its own is neither that nor a registry entry; the promotion the run proposes stays the collection's to perform.
F wants initial focus in the textarea; ModalShell focuses [data-opener="true"] button. Widen the marker lookup to any focusable inside the marked element, and to the marked element itself when it is focusable. The marker keeps its name and every existing call site keeps its behaviour — the run's "a per-caller placement of the existing marker, not a rule ModalShell must special-case".
Where does the refusal's text come from? The response body, verbatim. All four doors throw an Error whose message is the server's sentence, and the surface renders error.message. The client never rewords and never adds a prefix — display-equals-payload, and the reason W7 wrote those sentences for a paste target.
What tells the list it is empty because it was cleared? A clear that succeeds arms a flag in App; the flag disarms as soon as rows return or the filter moves. Not derived from the event, because useFlows deliberately collapses every event into one refetch, and not persisted, because the absence is about what just happened.
Does the slot show importing… when the dialog already says so? Yes. The run's TonedText row lists all three states of the one slot, and the dialog's mute Notice is the in-flight line for the surface that has focus. Two zones, two facts about the same transfer, neither inferable from the other while a modal covers the header.
The cross-year timestamp that still overruns cell 1 by 7.2px. Not fixed here, and not silently inherited either: the run's second blocked-on is carried forward to the flow-detail run with the reason unchanged. Widening cell 1 again would be paid out of PATH, which the Frame already calls tight — a whole-grid call this WU has no design for.
