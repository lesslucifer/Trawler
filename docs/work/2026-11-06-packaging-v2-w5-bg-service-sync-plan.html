E-PKG2.W5 — what E-BGSVC added works from the installed app and survives an update

The update quits through the quit request a windowless app can answer, the login item is guarded and travels inside the bundle, and the Linux AppImage and tray notes are taken.

v1 · 2026-11-06 · Trawler · T3 WU plan · E-PKG2.W5 · branch wu/packaging-v2/bg-service-sync off epic/packaging-v2 (7a008d7e, main merged in) · epic plan · Q14 · DEC-77, DEC-82, DEC-84, DEC-86

Requirement

An installed Trawler with keep capturing on installs an update the same way a windowed one does: Install reopens the main window, runs DEC-64's check through the quit request, stops the windowless core, swaps the app and relaunches with the same arguments. A quit that cannot open its window drops the update. The login item's agent ships in the updater archive, so the registered entry survives. On macOS 11 and 12 the login item reads unavailable instead of panicking. An AppImage's autostart entry names the AppImage file, and the Linux release notes say how to reach a tray-less app.

What E-BGSVC left for this epic

#FoundChange
G1Install closed the main window. Windowless, there is none: close_main_window exited without installing. With keep capturing on, a close leaves the app running and the staged update waited for some later quit.update::stage_and_quit stages and calls lifecycle::request_quit (⌘Q's path, which builds the window when needed). quit_app ends through update::end, which installs a staged update; menu::close_main_window is deleted.
G2A quit request whose window cannot open keeps nothing pending, but a staged update stayed.That branch also drops the staged update (DEC-82: a pending update never outlives its quit).
G3minimumSystemVersion is 11.0, and SMAppService exists from macOS 13. On 11/12 Settings → General's read reaches agentServiceWithPlistName and objc2 panics: "class SMAppService could not be found".AgentService::new returns None below 13 (NSProcessInfo isOperatingSystemAtLeastVersion, a safe call), so the place is absent and the existing unavailable refusal answers. macOS 11 stays supported. The release notes say open at login needs macOS 13.
G4Linux AppImage: the autostart entry records current_exe(), a mount gone after reboot.login_item::program_at_login takes an absolute $APPIMAGE on Linux. The updater replaces that same file, so the entry stays valid across updates.
G5A tray may build where no StatusNotifier host shows it. The app would then be windowless with no visible icon.Recorded, not detected. The Linux notes say GNOME needs the AppIndicator extension and that opening Trawler again brings the window back (single instance, DEC-77 rule 6).
G6DEC-84's crate: package verifies the agent plist in every .app (E-BGSVC), but nothing proved the updater archive carries it, and CI never ran its tests.package_bundle asserts the .app.tar.gz lists the plist. ci.yml's three test steps add -p trawler-login-service (an empty lib off macOS), and ci_workflow pins it.

The update, windowless

flowchart LR
  I["Install (dialog)"] --> D["download + verify sig"]
  D --> S["stage_and_quit: Pending ← update"]
  S --> Q["request_quit: reopen main, emit quit-requested"]
  Q -- "window cannot open" --> X["drop request + update · keep running"]
  Q --> C["closeConfirm: DEC-64 check"]
  C -- cancel --> K["quit_cancelled drops update"]
  C --> A["quit_app → update::end"]
  A --> E["core.stop · install · restart (same args)"]
One path whether the app had a window or not. A ✕ that ends the app reaches the same update::end.
