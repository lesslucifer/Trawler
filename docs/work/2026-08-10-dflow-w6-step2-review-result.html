The two real defects

① Same-named locals collided

The rule followed identifiers by name across the whole file and kept only the last one. Two functions each holding const cls = … meant one was never checked.

Fix: keep every declaration, not just the last.

false-negative only no existing class changed verdict

② The /step half was never checked against its own scale

The step was tested against one global opacity list instead of the scale its own base draws from.

Fix: per-base modifier list from Tailwind's own metadata.

renders unstyled the exact failure the rule exists to catch

The one rule that decides every row below: a /step is only legal if it belongs to the scale its own base draws from. The old rule asked one question — “is step in the opacity scale?” — no matter what the base was.

“Nothing at all” means nothing — not even the base. rounded-full/wash does not fall back to rounded-full. Tailwind matches the whole token or nothing, so the element loses its rounding entirely and renders unstyled with no error anywhere.
text- is a colour prefix and a size prefix at once. The plan and the run doc both wrote that the split checks “each half against its own scale”. The code never did that for the modifier half. The fix also widens the vocabulary — text-body/loose sets a line height, is perfectly legal, and used to be reported as a bad opacity step.
