E-EXPORT.W2 result — a capture leaves as HAR

GET /flows/export serves the filtered capture as HAR 1.2, delivered as planned: the export selects what the listing lists by construction, and every body Trawler never captured says so in the file.

v1 · 2026-09-04 · Trawler · T3 WU result · E-EXPORT.W2 · WU plan · epic plan

Outcome

Delivered, against the requirement as written. A new src/api/har.rs projects a Flow onto a HAR 1.2 entry and GET /flows/export serves the whole filtered capture as one document. All six of the WU plan's observables hold:

Contract calls the plan left to the build

CallMadeWhy
how the filter is shared between the two endpoints two Query extractions over the same query string — FilterQuery and PagingQuery — rather than a FilterQuery nested in ListQuery under #[serde(flatten)] the plan asked for one shared filter definition and flatten was the obvious shape, but serde_urlencoded — which axum's Query uses — cannot deserialize a flattened struct from a query string: it made every unparameterised GET /flows a query rejection, caught immediately by the pre-existing list_flows_orders_and_filters. Two extractions get the same single definition, because serde_urlencoded ignores keys a struct does not declare. The constraint is recorded in FilterQuery's doc comment so the next endpoint does not rediscover it.
redirectURL's wire spelling an explicit #[serde(rename)] beside the struct's rename_all = "camelCase" HAR spells it redirectURL; camelCase alone produces redirectUrl, which no HAR reader looks for. Found by the field-mapping unit test, which is exactly the kind of silent wire-shape error the WU's snapshot obligation exists to catch.
an uncaptured request body postData omitted entirely, with bodySize: -1 carrying the fact HAR's postData has no shape for "a body existed but was not captured" — it has no size field of its own and its text is required. An empty text would claim the request had no body. So the honest reading of what HAR can express is an absent postData plus the unavailable body size. The response side keeps the full four-state vocabulary, because content does have a size and an optional text.
the snapshot's nondeterministic fields startedDateTime and the creator's version normalised before the assertion the testing contract forbids asserting exact timestamps, and pinning the crate version would redden the snapshot on every release. Both are asserted for presence and shape in their own tests instead.

Deviations

None from the WU plan's contract. Every row in its field mapping and body mapping shipped as written, and all four of its stated calls (no limit/cursor on the export; /flows/export before /flows/{id}; a response-less flow omitted; no body decoding) hold.

Two mechanism choices differ from what the plan assumed, both recorded in the calls table above and neither a change of contract:

  • the shared filter is two query extractions, not a #[serde(flatten)] member — the plan's phrasing implied the latter, which serde_urlencoded cannot do. The plan's actual requirement (one definition, so the two endpoints cannot drift) is met.
  • an uncaptured request body omits postData rather than carrying a reason comment. The plan's body table specified the four-state vocabulary against content/postData jointly; HAR's postData cannot express it, and this is the narrowest honest representation. The response body — where every capture-path skip actually occurs — is unaffected.

Deviation from the epic plan: none. W2's summary block, its dependency ("none — independent of W1") and its expected result are as planned; questions 2 (the export is never paged) and 7 (insta joins here) shipped as settled. One dependency the plan did not name — form_urlencoded — was added and is justified above.

The review round

Five isolated finders over the WU diff, plus adversarial verification of every candidate. 11 candidates, 6 refuted, 5 real — all nits, and the three that were worth fixing were fixed rather than waived. The design dimension did not run: cargo xtask design-scope reports no design artifact and no rendered file in the diff, so the cr/v3 note carries no design: section.

DimensionRaisedOutcome
correctness 3 1 real, fixed. HAR sanctions -1 for entry.time but requires timings' three phases to be non-negative, and an unmeasured duration propagated -1 into wait. Unreachable from the capture path — store.rs assigns response and duration_ms atomically under one lock from a single call site — but Flow::duration_ms is a public field, so W3's importer reading an entry with time: -1 would construct exactly this state and export it back as invalid HAR. Fixed with a named regression test first (proved to fail without the fix), and the validity proptest strengthened to assert phase non-negativity — the gap that let it through was that the property checked the phases were present, never that they were legal. Two refuted: a literal + in a query decoding as a space is real behaviour but not a defect (the wire-exact URI is preserved in request.url, queryString is a derived convenience DEC-30 excludes from round-trip fidelity, and W3 reads url); an untested malformed filter on the export is byte-identical pre-existing axum extractor behaviour, verified by running both endpoints.
altitude 1 refuted on the architecture, 1 real nit fixed. Moving the body-reason token mapping onto NotCapturedReason would push wire vocabulary down into the domain model, against the separation FlowView's own doc comment states. But the code comment claimed the tokens were reused from BodyRec::state, which structurally cannot produce too_large/read_error — it returns the coarse not_captured. The comment now names the real source (BodyView's reason), which is what DEC-30 said all along.
efficiency 4 1 real (already-deferred), 3 refuted, all by measurement at the shipped 256 MB default cap rather than by inspection. The export's ~200 ms of synchronous projection and serialization is the same execution-context pattern list_flows and get_flow already use, on a work-stealing multi-threaded runtime — not a new class of problem. The absence of a rate limit is pre-existing on a loopback-only surface where GET /flows is already documented as deliberately unbounded. The real one is the peak-memory multiple, which the epic plan already defers — and the review's measurement corrected this report's own claim that the ring cap is the ceiling: it is roughly 4× the cap, and the follow-up row now says so.
reuse · simplification 1 · 3 1 real, fixed (both dimensions found it independently): rfc3339 was defined byte-identically in har.rs and view.rs, so the wire timestamp format had two definitions. Now one, api::rfc3339, shared by both projections. Refuted: collapsing the three {name, value} HAR structs (HarCookie is forward-looking — HAR's optional cookie attributes are exactly what it will grow) and collapsing FilterQuery into FlowFilter (which would force serde into the store layer). The verifier also independently confirmed the WU's load-bearing claim: both handlers take the same Query<FilterQuery> and convert through the same From, so the export and the listing cannot select different sets.

Round 2 re-reviewed the fixed tip and found five more nits, four of them one real miss: the timings fix introduced an exception to an invariant three places still asserted — HarTimings' own doc comment, UC-6's sentinel sentence and DEC-30's round-trip row all said the phases sum to the total, which stops being true when the total is -1 and the phases are zeroed. All three now state the exception and why HAR forces it. The fifth: the replacement comment on not_captured_comment over-generalized, attributing all three tokens to BodyView::NotCaptured's reason when streaming is that enum's variant tag rather than a reason value — reworded to claim only what is true. Round 2 also moved rfc3339 from api/mod.rs (which otherwise holds only router composition and the CORS layer) into view.rs, beside the projections that use it. Round 2 independently re-verified all three round-1 fixes, including that the new regression test fails without its fix.

Two nits were accepted rather than fixed, and are recorded as waivers on the cr/v3 note: the three structurally identical HAR list-element structs (kept distinct because the spec gives them different optional fields), and the per-body owned String in encode_body (unavoidable inside serde's data model without a hand-written streaming Serialize, and an export is not a hot path).

Follow-ups

ItemWhere it belongs
Nothing consumes the export yet — no UI control, and no client but curl. Not this WU: E-EXPORT.W5 designs the capture-management controls and W6 builds them, including the save dialog through the Tauri layer.
not_captured_comment's three reason tokens are now a wire contract that W3's parser must read rather than re-spell. E-EXPORT.W3, whose parser is defined against this projection. Pinned here by the snapshot and by the per-variant unit tests, so a re-spelling turns red.
Cookie attributes (expires, httpOnly, path, …) are not parsed out of Set-Cookie into HAR's optional cookie fields — the header itself is preserved verbatim, so nothing is lost from the file. Recorded in DEC-30 as a stated non-preservation, not debt: HAR's cookie attributes are optional, and omitting an optional field is honest where guessing it would not be. New work only if a real reader is found that needs them.
A large capture is serialized into one in-memory response, and its peak memory is a multiple of the ring's byte cap rather than bounded at it. Already the epic plan's deferred row (streaming a cap-sized export, deferred at plan review — revisit when a real capture proves the one-shot response too heavy). Quantified by the review: at the shipped 256 MB default cap, an export of binary bodies peaked at roughly 4× the cap, because the cloned flows, the base64-expanded document and the serialized JSON are all live at once. The deferred row covers it — response streaming is the fix that also caps the memory — but the ceiling is that multiple, not the cap, and this row says so rather than implying the cap bounds it.

No debt discovered. No test layer skipped beyond the recorded e2e waiver.
