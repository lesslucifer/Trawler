The one contract this step adds: data-wire

Three rules turn on which elements render a verbatim payload. That is a fact about content, and no static reader can recover it from markup — so the mockup declares it.

WrittenMeans
data-wire="<what it is>"this element renders a verbatim payload — it must be mono, and it must wrap
data-wire="collection"on a catalog row: this component renders a captured collection, so it owes an ordering
data-wire="none"this screen renders no payload at all. The n/a path the rulebook already grants, said out loud

Silence is not the third answer. An unmarked mockup reads as correctly typed when nobody looked — the same silence capabilities·answered and elements·map already refuse.

Two honest limits, named rather than papered over

LimitWhat was chosen, and why
A shared prefix reds under both rules that own it. text-pink-500 answers to colour-tokens-only and type-tokens-only at once An illegal class is illegal in both scales, and nothing in the string says which one it meant to be. The alternative is a precedence rule, and a precedence rule silently exempts whichever rule loses. Two truthful failures beat one arbitrary one. The visible cost: an outline width like outline-1 reports under the colour rule, because outline- is a colour prefix
zero-accent is narrower than it reads. With the config closed, no legal class can name a colour outside the chromatic set — the membership test is satisfied by construction What it still owns is the value written past the config: an inline chromatic colour, which the vocabulary rule reds as untokenised and this one reds as chromatic. That is a real and separate statement, and it is the honest remainder rather than a predicate pretending to more
