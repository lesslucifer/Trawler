E-CODEX.W1 — every door a Codex session goes through

Four links over the canonical Claude artifacts, one payload-tolerant hook script, and the parity tests that make a copy fail instead of drifting.

Draft v1 · 2026-09-11 · Trawler · T3 WU plan · E-CODEX.W1

Requirement

A Codex session started anywhere in this repository — main worktree or any linked worktree, repository root or a subdirectory — reads the tracked T0 rules, discovers every repository skill with the bytes the gate pins, and receives the same verify-doc verdict a Claude session receives for the same edit, each artifact reached from exactly one tracked source.

The four doors

#Canonical (tracked)Codex doorMechanism
1 CLAUDE.md — the T0 rules AGENTS.md symlink (git mode 120000); replaces the untracked copy that already differed at line 80
2 .claude/skills/ .agents/skills symlink of the repository skill root, so a skill added to .claude/skills/ needs no second step
3 .claude/settings.json .codex/hooks.json symlink, plus harness-neutral command strings — the one place a link alone is not enough
4 .claude/hooks/ .codex/hooks symlink; verify-doc-post.sh additionally learns the Codex payload shape
The hook command, stated once. Both command strings become root=$(git rev-parse --show-toplevel 2>/dev/null || echo "$CLAUDE_PROJECT_DIR"); bash "$root/.claude/hooks/<script>" — the active worktree's root when git can answer (Codex's documented recommendation, and correct in a linked worktree or a subdirectory launch), Claude's project variable as the fallback when it cannot. No absolute path survives in the config, so the definition is the same string in every worktree and Codex's trust hash stays stable across them.

Expected result

#DoorObservable afterHow to check
1 T0 One file carries the rules; the second name is a link to it. git ls-files -s AGENTS.md prints mode 120000 and CLAUDE.md's blob hash; readlink AGENTS.md prints CLAUDE.md.
2 Skills Every repository skill is discoverable at the path Codex scans, with the bytes the gate pins. readlink .agents/skills prints ../.claude/skills; each .claude/skills/<name>/SKILL.md reads identically through .agents/skills/ and carries name + description.
3 Hook config Both harnesses load one definition set, valid from any worktree. The two paths canonicalize to one file; its only top-level key is hooks; no command contains the repository path; the command string run from a worktree root and from a subdirectory both resolve the script.
4 Hook scripts One script tree, so a fix cannot land in one harness only. readlink .codex/hooks prints ../.claude/hooks; each script reads byte-identically through both paths.
5 Payload parity A Codex edit is judged by the same contract as a Claude edit. A tool_name: apply_patch payload writing a red ready doc exits 2 with the same problem blocks the file_path payload produces; green, non-HTML and vanished targets are silent; a multi-file patch reports every red doc it names.
6 Drift alarm The arrangement cannot quietly become a copy. The parity tests red when AGENTS.md is a regular file, when a skill exists on one side only, or when the two harness configs stop resolving to the same commands.
