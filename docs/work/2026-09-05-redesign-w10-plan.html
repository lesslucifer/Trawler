Three changes below the screen

StepStatusView.short — closing the [UI_DEFER] marker

StatusLine renders status.message and its anatomy caps it at ~40 characters, a fragment not a sentence. Four of the sixteen verdicts exceed that (101, 116, 63, 63) and the two error verdicts interpolate without bound. StatusLine's @avoid forbids the call site shortening a domain message, and the [UI_DEFER] marker at setup.ts:187 assigned the short form to setup.ts itself, deferred "until the screen that consumes StatusLine". W10 is that screen.

StepStatusView gains short beside message; message is unchanged, so nothing else that reads it moves. The design specifies all sixteen values verbatim — they are copied, not invented. The four long verdicts split: the verdict keeps the fragment, the remedy moves out into a Notice.

StatusLine — tone the message, not just the glyph

The component tones the glyph through TonedText and renders the message ink-mute in every verdict, so ok and warn read identically at a glance and the only channel carrying the difference is a 9px glyph. The change lands in StatusLine.tsx's own file — "never re-decide what a component owns" makes this an extend, not a call-site override. Muted stays muted; only ok and warn gain colour, so colour-plus-text still holds with the glyph as the second channel. StatusLine reads short.

Clipboard — confirm and error where there is silence

Onboarding.tsx:270 and :302 call navigator.clipboard.writeText unguarded: no optional chaining, no .then, no feedback. A rejected write is silent and a missing API throws. CopyText already owns confirm-at-point (~2s "copied") and the guarded call — adopting it closes both defects without new code.

One deviation from the design, recorded

W10 builds Checkbox itself. Design run #9 proposes Checkbox as a T1 registry entry and rules the work "its own WU, not W10", because a design run resolves elements and does not design components. Its blocked-on table states: "W10 cannot build the dialog's remote mode from this run alone — it needs the component first, or it builds a local checkbox and the propose is lost."

Decision (author's call, at plan time): W10 builds the registry entry rather than inserting a component WU ahead of it, so the dialog's remote mode lands complete and the propose is not lost to a screen-local control.

What this costs, stated so W11 need not discover it: the entry ships without a component design file behind it, unlike Field/StatusDot/ Disclosure, which W1 designed and W2 built. Checkbox will therefore have no roster entry to cite, which the epic's expected result ("every component design the epic added has a roster entry") asks for. W11 either back-fills the design file or records the exception. W10's cr/v3 note states the same thing so the reviewer judges a declared deviation, not a silent one.

The contract the design states for the entry is built as given: the states, and the label-inside-the-hit-target rule.

The build-local composition

modal-shell — scrim, panel, focus trap, focus return to the invoker on dismiss, Esc, backdrop click. Its only state is open (mounted conditionally); Esc, backdrop and ✕ all cancel the quit. It stays build-local by warrant: no registry entry owns modality, and generalising a Dialog from the app's only dialog would encode this dialog's two-mode shape as though it were general — a sample of one. A second dialog re-opens the question. This is what earns the design's focus-returns-to-origin slug, receipted blocked there because it was unowned until now.

What could go wrong

RiskMitigation
Rewriting onboarding.spec.ts selectors hides a real regression behind a green e2e. Keep the spine — the same user journey, the same assertions about outcomes; only the selectors move. Diff the spec's assertion list before and after and confirm it is unchanged in substance.
Disclosure is uncontrolled (DEC-21), so a failed action cannot drive open. Pass defaultOpen, and let the host branch on "collapsed or not at all" — Disclosure always discloses (fork D4). Unit-tested.
The short field silently diverges from the design's sixteen values. The unit test asserts them literally against the table above.
Building Checkbox here leaves an unrostered registry entry. Declared in the deviation callout and in cr/v3, so W11 inherits a known item rather than a surprise.
