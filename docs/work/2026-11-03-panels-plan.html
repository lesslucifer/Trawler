E-PANELS — epic plan

Every split, every flow-list column and every window the app opens can be resized by the user, and comes back the way they left it.

v3 · 2026-11-03 · ready: every open question ruled · Trawler · T3 (docs/work/) · branch epic/panels · WU branches wu/panels/<slug>

Intent

The app's layout is fixed today: the detail pane is the pane token (520 px), the headers zone is capped at zone-cap (35 %) of the pane, and the window always opens at 1440×800 wherever the OS puts it; the flow-list columns are fixed tracks (160 70 180 1fr 70 90). A reader with a long cookie wants a wider pane; a reader scanning paths wants a narrower one; nobody can choose, and every relaunch forgets the window. This epic makes each split and each fixed column draggable and keyboard-resizable within designed bounds, and persists split sizes, column widths and window geometry locally, so the layout a user sets is the layout they get back. It reverses DEC-36's rejection of a draggable split — the three things that rejection said the shell lacked (a stored preference, a drag affordance, a minimum on both sides) are exactly what this epic builds.

Use-case requirements

UCChange (contract-level)
UC-4The native app's layout is user-sized: the list/pane split can be dragged or keyboard-stepped within designed bounds; the flow-list columns can be dragged or keyboard-stepped within per-column bounds; the window reopens at its last geometry. A saved layout that no longer fits (smaller monitor, a file whose shape the app no longer reads) falls back to defaults rather than restoring something broken.
UC-5Inside the flow detail, the headers/body split is user-sized; the body stays the zone that takes the remaining height. The pane's chosen width is the width every flow opens at.
UC-8The composer occupies the same pane and so inherits the pane width; nothing composer-specific is added.

Expected result

#Observable after the epic
1Dragging the list/pane splitter changes the pane width; it never goes below pane-min, above pane-max, or narrower than the list's minimum allows.
2The splitter is focusable (role="separator", aria-valuenow/min/max); arrow keys step it, Home/End jump to its bounds, and the reset gesture returns the default — keys registered in the keyboard-conventions vocabulary.
2aEach column handle behaves the same horizontally: the track never goes below its minimum or above its maximum, path never below path-min; the label and the cells it names stay aligned at every width.
3The headers/body splitter behaves the same, vertically, with the body keeping its minimum share.
4Quit and relaunch: the pane width, headers share, column widths and window size/position/maximized state are what they were.
5A missing, corrupt or unrecognised-shape layout.json yields the default layout and no error surface; a window saved onto a monitor that is gone opens on a visible one.
6Shrinking the window clamps the pane so the list keeps its minimum; growing it back restores the user's width, not the clamped one.
7Double-clicking a splitter or column handle restores that one default; "Reset layout" (placement per the design run) restores every default in one act.
8curl still sees everything: no layout state goes through the core or the control API (DEC-12).

Non-goals

  • Reordering, hiding or adding flow-list columns — widths change, the column set and order do not (see Q9).
  • Docking, tabbing, detaching or rearranging panels — sizes change, the arrangement does not.
  • Resizable modals (ModalShell dialogs) — they stay content-sized.
  • Syncing layout across machines or storing it in the core.
  • The inspector windows themselves — E-INSPWIN owns them.

JourneyAsserts

Columnsdrag the host handle past both ends → host track equals its min / max, path never below path-min; each label's left edge equals its cells' left edge; double-click the handle → 180.

Broken savewrite a corrupt / wrong-shape layout.json before launch → defaults, no error notice.

The launcher removes layout.json before and after the run, like the notice markers, so no run inherits another's layout. Off-monitor restore is unit-level only (W5) — a real second monitor is not hermetic; that is the stated waiver for that row.

Open questions — all ruled (review rounds 1–2)

#QuestionDecision
Q1Seam with E-INSPWIN: who provides window-geometry persistence for its inspector windows?E-PANELS provides the mechanism (W5, keyed by window label); whichever epic lands second adopts the other's — if E-INSPWIN lands first, W5 retrofits its windows.
Q2Where does layout persist?Shell-side layout.json in the app config dir (beside the notice markers). Not localStorage: it is per-origin, so dev and bundle would keep separate layouts and the e2e could not clear it from outside.
Q3Is a size saved once for the app, or once per window?
WhatSavedSo
pane width, headers share, each column widthone value each, for the whole appevery flow opens at the same pane width; an inspector window showing a flow detail (E-INSPWIN) uses the same headers share as the main window; changing it in one place changes it everywhere
window size / position / maximizedone record per window labelthe main window and each inspector window each reopen where they last were
Q4Is the saved layout versioned?No version field. A file that does not parse into the current shape gives the whole default layout.
Q5Do flow-list columns count as "panels"?Yes — column widths are in this epic (W4).
Q6Reset affordance — where?Double-click a splitter or column handle resets that one; a "Reset layout" act resets all (placement is W2's).
Q7May a panel collapse to zero?No — min bounds only; closing the pane stays "deselect the flow".
Q8DEC-36 records a known defect: below 1132 px with the pane open, the rows scroll sideways and the label row does not, so labels and cells come apart. Column resizing touches exactly that row. Fix it here?Yes — the label row moves into the rows' horizontal scroll container, so labels and cells move together at any width. It is the same file and the same template W4 already rewrites.
Q9Columns in scope means widths only, or also reorder / hide?Widths only. Reorder and hide change the arrangement, which this epic keeps fixed; a later epic if wanted.
