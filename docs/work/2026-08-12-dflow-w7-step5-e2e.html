Two runs through this, one compliant and one that breaks a hard rule. Nothing is stubbed below the test: the real binary, the real node oracles over a real component collection, real git, and the real merge hook doing its own branch dispatch.

The assertion that carries the test

The plan asked that "every stage must yield its artifact or the test fails at that stage, not at the end". The form that gives that teeth is a set equality, re-checked after every write:

After stage n, the run is red for exactly the stages not yet written — no more, no fewer.

Both directions are a real failure. Fewer means the flow went quiet: a half-written run that asks for nothing has stalled, and the agent has no next move. More means the harness refused a stage that was not wrong — a prompt for work the flow has not reached, which is the "misleading prompt" the requirement names. A weaker assertion — "the red mentions the next item" — passes on both.

What it found

Neither hole was visible from the code. One shows up only when a run is partial, the other only when a Working Unit's whole deliverable is a design — and every fixture in the suite until now was a complete run inside a code-bearing WU.

① A predicate prompting five stages ahead
Wasat the Frame stage, with no mockup written and none due for four more stages, mono-for-wire-data·undeclared reds: "the mockup marks no payload element and does not say it has none"
Why it is wrongit asks the agent to fix a mockup that does not exist. Its three siblings inside check_hard_rules already wait for the stage that answers them — overflow for the layout, keyboard parity for the interaction, states for the elements. This one did not, for no reason beyond its scan being doc-wide
Nowthe demand for a marking waits for the mockup item; the marking rule itself still reads the whole doc, because a payload can be marked outside the mockup and the wrapping half scans every class
Blast radiusnone a finished run always has a mockup item — it is one of the eleven — so no complete run changes verdict. The only behaviour that moves is a mid-flow run's message

② Tier-3 skipped on exactly the diffs it exists for

A design is a docs-only deliverable. The gate exempts a diff that touches no code — the rule that lets an incidental doc edit through without notes. A design Working Unit writes a run doc, or a set of component design files, and no code at all. So the exemption was handing the design dimension precisely the diffs it was built to judge, and 9·design could never fire on them.

The e2e hit it on its first green attempt: a design-bearing tip carrying a cr/v2 note merged clean, reporting "exempt — docs/infra-only, gate not required". The rule is now code_changed || designs, sitting beside 6·run-closed, which was already answerable at the merge for the identical reason: the Working Unit that carried the design is ending.

This was not hypothetical. Re-running the epic gate found one landed seam that the old rule had let through — 8173f47, the E-DFLOW.W2 merge. It landed component-design-base.html and 14 component design files — the entire registry the three later runs design against — with no cr note on the tip at all. Not a stale review, not a review that missed something: no review. Its test/v2 note says why in its own words — "design/docs-only WU" — which is exactly the claim the new rule refuses.

The waiver this costs, and why it cannot self-date

One entry, at the epic merge. Step ④ paid zero because a cr/v2 note says in its own bytes that it predates the design dimension — the grandfather rule is the artifact itself. That trick does not reach here: the W2 seam has no cr note at all, so there is no schema string to read and nothing on the seam that dates it. A date cutoff would be the only alternative, and step ④ ruled that out for the reason it always fails — it cannot tell a note written before the rule from one written badly after it.

Applied where the other three are, in the epic's own cr note when the code review writes it (walk() runs only at Level::Epic; merging a WU into the epic does not walk, so nothing is blocked meanwhile): 
walk_waivers:
  - seam: 8173f4721f...

W2 landed component-design-base.html and 14 component design files with no cr note, exempt as docs-only; the exemption no longer covers a design-bearing diff. Waived only because the seam is immutable — the files it landed are reviewed by every WU that has touched them since, and W9's fresh-screen run is the standing check on the roster itself"
Running total: four. Step ③ predicted this and attached a number — a dozen by the epic merge means the walk's verdict has become mostly waiver. Four of a dozen, with ⑥ still to go.
