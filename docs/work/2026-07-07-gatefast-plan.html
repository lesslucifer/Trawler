E-GATEFAST — epic plan

Cut the agent wall-clock to land a change — measured at 45–106 min active per gate-heavy epic — by removing turns from the land-a-change loop, without weakening what the gate proves. Four WUs, sequenced by measured payoff and risk.

Plan v1 · 2026-07-07 · Trawler · T3 epic plan · solution discussion

Intent

Landing a Working Unit or epic is slow, and the transcripts say precisely where the time goes: not the gate script — cargo xtask verify-dod is 4–19 s per epic (<0.5% of active time; it only shells out to git and date, no compile, no AI) — but the agent turns spent resolving the gate. Measured across three gate-heavy epics (discussion §Measured budget): main-loop model generation (hand-authoring notes/docs, fixes, re-prompts) is 32–56% of active time; the code-review fleet is a stable ~25%, re-run from scratch on every trivial delta via the cascade; doc distillation is a ~10–15% slice of the model-gen bucket. This epic attacks those specific sinks. The load-bearing constraint is DEC-2: receipts are recomputed, never blind-trusted — so every cut here is a caching/scoping problem under that invariant, never a relaxation of it. A wrong cache that reports green for an unverified tree is worse than a slow gate. Full analysis and the per-candidate reasoning live in the solution discussion.

Use-case requirements

None — E-GATEFAST is a process/tooling epic on the DoD workflow gate and the code-review skill; it touches no product use-case (no UC-*). The contracts it changes are the workflow-gates decision record (DEC-2, the recompute-don't-trust invariant), gate.rs/notes.rs, and the code-review skill. The epic's truth distills to a new DEC.

Expected result

  1. C4 (W1) — note + doc skeletons. An xtask subcommand emits the test/v2 + doc/v1 note skeletons and the governed plan/result doc skeletons from the diff, with all file-accounting pre-filled; the agent fills only judgment (counts, intent, waivers). Hand-authoring and its schema/accounting re-tries — the largest (main-loop) bucket — collapse.
  2. C1 (W2) — incremental Gate 0. The review's Gate 0 (fmt+clippy+nextest) is skipped when the reviewed tip SHA is unchanged since the last green Gate 0, keyed off a git note (decided). It must invalidate on any tree change — a stale "green" can never slip through. The ~10% cargo bucket, today paid 2–3×, drops toward one verify.
  3. C6 (W3) — faster review model, measured. A recorded A/B of the finder/verifier fleet on a faster model (e.g. Sonnet) vs Opus, comparing found/verified/escaped counts, yields a defensible decision on whether — and for which role — to switch. Verifiers (narrow, single-claim) are the safer candidate than finders.
  4. C2+C3+C5 (W4, spec-first) — scoped re-verify & right-sized finders. A precise, mechanical definition of a "provably-safe delta" (docs-only, or an empty delta from a base-advance) lets a trailing fix re-bind the diff hash and re-run only what it touches — not a full 5-finder + N-verifier sweep — and lets the finder set scale to diff shape with a floor. The definition is the whole risk and is specced and discussed before code.
  5. Invariant frozen. A genuinely ungated change, a stale/absent receipt, or a tree that was never verified still turns the gate red — unchanged from today. Each WU carries a regression test that pins this.
  6. Every WU proven and signed off. Each WU delivers a wu-result report carrying a measured time-saved figure, and merges only after owner manual review (mr/v1 on every WU) — see the per-WU close protocol below.

Non-goals

  • Relaxing what the gate proves. No shortcut may let ungated work reach main; no cache may report green for a tree it did not verify. DEC-2 holds; this epic only caches/scopes under it.
  • Optimising verify-dod itself — proven noise (<0.5%). Out of scope.
  • Removing the manual-review human stop (S6) — real but bounded, by design, and not an agent-time target.
  • Cutting review dimensions below a safety floor — C5 right-sizes with a floor; it never trades coverage on a real code diff for speed.
  • A timing assertion inside the hermetic suite — wall-clock is non-deterministic, so the automated e2e/integration tests prove behaviour (shortcuts fire exactly when safe, never when not), never a timing threshold. The time-saved measurement the owner requires lives in each wu-result report as a recorded before/after figure (see the close protocol above), reviewed manually — not as a flaky test.

Working Units

Four WUs, sequenced C4 → C1 → C6 → C2+C3+C5 (owner decision): the two safe, independent wins first, then the measured model experiment, then the coupled high-care loop cut last. Each carries its own WU plan doc before its code; W4 is explicitly spec-first.

Per-WU close protocol (owner directive). Every WU in this epic ends with three things before it can merge: (1) a governed wu-result report (outcome · deviations · evidence · distillation · follow-ups); (2) a measured time-saved figure recorded in that report — a before/after on a representative land-a-change flow (e.g. transcript wall-clock or an xtask timing of the affected step), reconstructed the same way as the baseline budget, so the saving is a real number, not a claim; and (3) owner manual review — an mr/v1 sign-off is required on every WU here (not just ui/ WUs), and the owner reviews the result report before it. The WU is closed and merged only after that confirmation.
E-GATEFAST.W1

Note + doc skeleton generation (C4)

Add an xtask subcommand that, from the current diff scope, emits the test/v2 + doc/v1 note skeletons and the governed plan/result doc skeletons — every docs/ path in the diff pre-accounted, tiers pre-classified, schema fields pre-stubbed. It reuses what gate.rs/notes.rs/doc.rs already know (the diff, the tiers, the schemas). The agent fills only judgment: test counts, waivers, intent prose. It generates; it never authors intent or blind-passes the gate.

E-GATEFAST · C4 → sinks S4 (hand-authored notes) and S5 (governed plan/result docs); hits the #1 (main-loop) bucket and the doc-distillation slice.

Running the subcommand on a real diff produces notes that pass verify-dod checks 1 & 6 with no hand-editing of file-accounting, and doc skeletons that satisfy the verify-doc data-item checklist as drafts. A missing or phantom docs/ path in the generated doc/v1 is impossible by construction. Judgment fields are left as explicit TODO stubs, never fabricated.

none — independent and safe; lands first.

E-GATEFAST.W2

Incremental Gate 0 via green-tip note (C1)

Cache the last-green Gate-0 tip SHA in a git note (decided over a per-worktree file: survives, queryable, composes with the existing test/cr/doc receipt refs). The code-review Gate 0 and the main-loop build path consult it: if the working tree's tip is byte-identical to the cached green SHA, skip fmt+clippy+nextest; otherwise run and, on green, update the note. Any tree change invalidates — the cache stores the SHA, never a verdict divorced from it.

E-GATEFAST · C1 → sink S1 (review re-runs from scratch); recovers the ~10% cargo bucket paid 2–3×. Under DEC-2: correct invalidation is the load-bearing requirement.

Unchanged tip ⇒ Gate 0 skipped and the run proceeds straight to finders; any tree mutation (code, test, or a whitespace edit) ⇒ Gate 0 re-runs in full. A stale or forged green note never yields a skip on a tree that differs. Ref name and whether it syncs to origin like the other note refs decided in the WU plan.

W1 — additive on landed state; sequenced after it, no code coupling.

E-GATEFAST.W3

Faster review model — measured A/B (C6)

Make the finder/verifier subagent model selectable in the code-review skill, then run a recorded A/B on one representative epic's diff: the fleet on a faster model (e.g. Sonnet) vs Opus, comparing found / verified / escaped finding counts and wall-clock. Decide per role — adopt for verifiers (narrow, single-claim, adversarial) and/or finders only if the quality delta is acceptable. A finder's wall-clock is partly tool I/O (git diff, file reads), so the speedup is expected to be partial.

E-GATEFAST · C6 → sink S1 (review fleet cost). Owner directive: "set a WU for this verify."

A written verdict backed by the A/B numbers: which role(s) switch model, the measured speedup, and the found/verified/escaped comparison proving no coverage regression. If quality drops on finders, the WU adopts the faster model for verifiers only (or neither) and records why — a null result is a valid, defended outcome.

W1, W2 — sequenced after; no code coupling. Independent experiment.

E-GATEFAST.W4

Scoped re-verify & right-sized finders — spec-first (C2 · C3 · C5)

The coupled, high-care loop cut, combined per owner decision because right-sizing (C5) and scoped re-verify (C2/C3) share the same "what did this delta actually touch?" mechanism. Spec-first: the WU begins with a precise, mechanical definition of a "provably-safe delta" (docs-only; empty delta from a base-advance; the open question of any safe code subset) and a finder-sizing heuristic with a floor — discussed and agreed before implementation. Then: a trailing safe delta re-binds the diff hash and re-runs only affected finders instead of the full sweep; the finder set scales to diff shape.

E-GATEFAST · C2+C3 (scoped re-verify / stale-base tolerance) + C5 (right-size finders) → sinks S2, S3, S1; the dominant cascade cost.

A docs-only or empty-delta post-review change re-verifies in seconds instead of a full 6–12 min sweep; a real code delta still forces the full sweep (too-loose "safe" reopens the R2 hole — the definition is the deliverable's crux and is frozen by regression tests). A small diff spawns a right-sized finder set, never below the floor.

W1, W2, W3 — lands last; sequenced after all, and gated on its spec being agreed before code.

E2E test plan

One hermetic e2e (temp repo, ephemeral ports/tempfiles, local only — in the existing gate/hook suite, tests/dod_hooks.rs or xtask/tests/dod_gate.rs; the implementing WU picks) walking the whole faster-loop flow and proving every shortcut fires only when safe:

  1. C4: generate notes + doc skeletons from a seeded diff → verify-dod checks 1 & 6 pass with zero hand-editing of accounting; injecting an extra/absent docs/ path is unrepresentable.
  2. C1: gate a tip green → re-run with an unchanged tree ⇒ Gate 0 skipped; mutate one byte ⇒ Gate 0 re-runs; hand-forge the green note onto a differing tree ⇒ no skip (the recompute-don't-trust check).
  3. C2/C3/C5: after a green review, a docs-only trailing commit ⇒ scoped re-verify passes without a full sweep; a trailing code commit ⇒ full sweep forced; a two-line diff ⇒ right-sized finder set, never below floor.
  4. Invariant (spans all WUs): a genuinely ungated seam / stale receipt still turns the gate red — the R2 guardrail holds end-to-end.

C6 is validated by its recorded A/B artifact rather than a suite assertion (a model-choice decision, not a behaviour). Each WU additionally carries its own integration test for its bounded contract, and each commit its unit test — additive, never substitutive. No waivers intended at any level.

  • docs/workflow.html — note the skeleton-generation subcommand in the land-a-change flow, and the scoped-re-verify behaviour on trivial deltas.
  • code-review skill — the incremental Gate 0 skip, right-sized finder fleet, and the per-role model selection (infrastructure markdown, updated in-place).
  • This plan, the solution discussion, and the per-WU plan/result docs → distilled into the above, then git rm'd to docs/.archive/ (DEC-3) before the epic merges to main.

Open questions

  • C1 cache location — DECIDED: git note. Remaining WU-plan detail: the ref name (e.g. refs/notes/greentip) and whether it syncs to origin like the other note refs.
  • C2/C3/C5 "provably-safe delta" definition — deferred into W4 by design (spec-first). Docs-only is the easy case; whether any safe code subset exists, or any code change forces a full sweep, is discussed when W4 starts. Too-loose reopens the R2 hole — this is the epic's highest-care call.
  • C6 scope — decided by W3's A/B. Whether the faster model is adopted for verifiers only, finders too, or neither is an outcome of the measured experiment, not a pre-commitment.
