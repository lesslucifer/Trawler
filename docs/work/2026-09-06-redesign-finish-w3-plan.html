E-RFINISH.W3 — the benchmark, then the three performance costs

E-REDESIGN named three costs and refused to fix any of them at a merge seam with nothing to show a fix helps. This WU builds the measurement first and commits it, then pays each cost against a recorded before number — and reverts any fix the benchmark cannot show helping.

WU plan · 2026-09-06 · Trawler · T3 (docs/work/) · wu/redesign-finish/perf-bench → epic/redesign-finish

Requirement

A committed benchmark measures the three named costs before any of them is edited, and each fix is kept only on a recorded improvement against it — pnpm bench from ui/ and cargo xtask ui bench both run the same suite, covering TimestampText's per-row moment construction on a virtualized re-render, useFlows's host merge over a refreshed list, and the character-rendered members' byte-size report on an over-cap body; each of the three carries a before and an after number in the WU result, and every existing unit test for the touched modules passes unchanged, which is the proof that only cost moved.

The three costs, verified in the tree

The benchmark

Vitest already runs the front end at every level, and it ships vitest bench (tinybench) — so the suite needs no new dependency, no new runner and no new config file, and it reuses the jsdom environment the component tests already prove out.

PieceWhat it is
ui/bench/*.bench.tsone file per cost, matched by Vitest's default benchmark include; outside ui/src/ so it is not a code path the DoD gate or the design accounting reads
pnpm benchvitest bench --run — the ui/ entrypoint
cargo xtask ui benchthe repo entrypoint, alongside build/dev/e2e: pnpm install then pnpm bench, same as every other ui subcommand
fixturesgenerated in-process from a seeded counter — no network, no files, no Math.random; the same list of flows and the same body text every run, so two runs differ only in timing
A benchmark is not a test and does not join the suite. Wall-clock numbers are not deterministic, so pnpm bench stays out of pnpm test and out of every gate — it is a tool the WU result quotes. What the gate sees instead is the unit and integration layers below, which assert the cost's disappearance deterministically (a spy counts calls; a call count is the same on every machine).

The three fixes

Cost 1 · TimestampText

Remember the now, remember the string

The two “now” moments become one pair of local day/year boundary instants, computed once and reused until the wall clock leaves the cached day — an isSame(now, "day") is a numeric range test, not an allocation.

Then the formatted string is memoized on (format, timestamp), keyed to that same day generation so a midnight crossing cannot serve yesterday's answer. A virtualized list re-rendering the same thirty timestamps on every SSE event then parses each one once, not once per event.

format="relative" is never memoized — its whole contract is that it changes while the input does not.

Cost 2 · useFlows.merge

Keep the set, and stop parsing what was already parsed

The accumulated host set survives across refreshes instead of being rebuilt from the array each time, and merge asks for the host alone rather than calling toRow, whose path half it discards.

The new URL() parse is memoized on the URI's scheme-and-authority prefix — a cheap slice — so a refresh over 5 000 flows drawn from a handful of hosts parses a handful of URIs. The map is bounded and cleared wholesale on overflow; correctness never depends on a hit.

Cost 3 · byteLength

Count the bytes without materialising them

byteLength keeps its signature and its answer and loses its allocation: UTF-8 length is arithmetic over code units — 1, 2 or 3 bytes, and 4 for a well-formed surrogate pair — so the count is a scan with no array behind it.

A lone surrogate is the one place the two implementations could disagree; TextEncoder emits U+FFFD (3 bytes) for it and so must this. That is a property test, not a hand-picked case.

Expected result

  • pnpm bench from ui/ and cargo xtask ui bench from the repo root both run the same three benchmark files and print an ops/sec figure for each.
  • The WU result carries three before/after pairs, each quoted from a run of the committed benchmark, with the before taken at the benchmark's own commit — before any src/ edit existed.
  • Every existing unit test for TimestampText, TextRenderer, FormRenderer, useFlows and body passes unchanged — no assertion is relaxed, retimed or deleted to accommodate a fix. A fix that needs a test edited to stay green is a behaviour change and is reverted.
  • A spy-based test proves each cost is gone rather than merely faster: the timestamp of a re-rendered row is parsed once, not once per render; a second refresh over the same hosts parses no URI; and an over-cap body is never handed to TextEncoder at all.
  • Any fix whose benchmark shows no improvement is reverted, and the WU result records the number that condemned it — a reverted fix is an outcome, not a failure.

Test plan

LevelWhat asserts what
Unit
per commit

Commit 1 (benchmark) — xtask/src/ui.rs: ui bench is a recognised subcommand and ui bench --forever is a usage error, in the same shape as the two subcommand tests already there.

Commit 2 — the day/year boundary helper: a timestamp inside today's local bounds is same-day, one a millisecond either side is not; the cached boundary is recomputed once the clock leaves it (fake timers, never sleep). Memo: two renders of the same timestamp yield one moment parse, a relative render is never served from the memo, and the memo is abandoned across a day boundary.

Commit 3 — host extraction returns exactly what new URL().host returns (port kept, default port dropped, userinfo stripped, IPv6 bracketed, an opaque URI → empty), and a repeated authority is served from the memo; the memo's overflow clear loses no host from the accumulated set.

Commit 4 — byteLength agrees with TextEncoder over ASCII, 2-, 3- and 4-byte code points, an empty string, a lone high surrogate, a lone low surrogate and a well-formed pair; and a property test over generated strings, since “agrees with TextEncoder for all inputs” is an all-input invariant and the surrogate cases are exactly where a hand-picked list stops.
Integration
the WU contract

One file, ui/src/perf.test.tsx, asserting the WU's own sentence at the seam each cost lives on — the cost is gone and the render is unchanged, which is the pair the requirement claims:

  1. The list. Render FlowList over a fixed set of flows, re-render it the way an SSE refresh does, and assert the moment parse count does not grow with the number of re-renders — while the rendered time cells are string-identical before and after.
  2. The feed. Drive useFlows through two refreshes over the same list with a spy on the URL constructor, and assert the second refresh parses nothing — while hosts holds exactly the same values it holds today.
  3. The pane. Render TextRenderer and FormRenderer over a body past TEXT_MAX with a spy on TextEncoder.prototype.encode, and assert no call receives the untruncated body — while the cut marker's two sizes are the exact strings the pre-fix implementation produced, captured as literals in the test.

Deterministic and hermetic by construction: call counts and rendered strings, no timing assertion anywhere. The benchmark is the tool that says how much; these say whether.
E2E waived — the epic's e2e is W10's, and it proves the three use-case contracts. This WU moves no contract: an e2e that could see a difference here would be asserting a duration, which the testing standard forbids at every level.

Outthe virtualizer's window size, the debounce interval, and the shape of GET /flows. Tuning the amount of work asked for is a different question from making the work cheap, and only the second one was deferred to this WU.
Outreplacing moment. TimestampText's @tier contract names it, and swapping a parser is a behaviour change wearing a performance costume — this WU stops calling it needlessly, which is a different thing.

What could go wrong, and what stops it

RiskGuard
A memo serves a stale clock string across midnight.The memo is keyed to the day generation it was filled under; a unit test crosses the boundary with fake timers.
A hand-written UTF-8 count disagrees with TextEncoder on some input.A property test over generated strings, plus the lone-surrogate cases named explicitly — the one input class where the two could ever differ.
A cheap host parse gets an edge case wrong and a host silently vanishes from the filter.The memo caches the result of the real new URL() parse; nothing is parsed cheaply. The slice only decides whether the parse is needed.
A fix looks good and does nothing.It is reverted, and its number goes in the result. That is the discipline the epic plan wrote this WU to add.
