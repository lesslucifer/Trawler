The arithmetic Q1 turns on

A negative number is not a narrow column — it is the row's fixed tracks overflowing their box. The row region is overflow-auto and the column-label row above it is not, so below that width the labels and the cells they name scroll apart, and Layout's own overflow line ("C has NO horizontal scroll") stops being true. That threshold is shipped, not introduced here: at 380 it is 992, and the app declares a minimum of 800. Widening the pane raises it to 1132. The run states the number and escalates the fix rather than paying for the pane by narrowing a column the epic's non-goals put out of scope.

What the width buys is on the other side of the same identity. DEC-32 clamps a long header value to three lines with more/less under its name, so the pane's width is not how tall a cookie is — it is how much of one is legible before the reader has to act. Field (status)
T1		 A · filter bar
reuse
The near-miss was the contract, not the control.
why

The first pass reached this verdict too, and left it resting on the wrong leg. Its per-key table already ruled "Field, but not a Select either: the useful query is a class (4xx), which neither control expresses" — a verdict about what the API could not serve, which is why it went to that run's blocked-on list as one of three options rather than closing. Read that way, Field survived only because nothing better was expressible; the moment W5 makes 4xx expressible, that argument expires and the Select question is open again.

So this run re-asks it on the control's own terms, and Field wins on a second, durable leg: a Select can offer only what its caller passes, and the caller can pass only what capture has already seen — the same accumulation hosts uses. But filtering for a 404 before any 404 has arrived is the debugging act: set the filter, then reproduce. A control that cannot express an unobserved value cannot serve this key. The set is not knowable, so @avoid's "a choice among known options" never applies here — and it still will not after W5, which is the part the first pass's reasoning could not promise.

Lands in @use "any free-text entry … Pass value + onChange + aria-label; pass width through className". Clears @avoid "validating, debouncing, formatting or restricting what is typed" — and the shipped call site does not: inputMode="numeric" (App.tsx:232) is a keypad hint over a field that must now accept a letter. It goes. Width moves w-field-sm → w-field (80 → 128px) so the placeholder is not itself truncated; the header wraps before it clips, so the cost is the bar's second line at a narrow window, never a hidden control.

What the field accepts: 404 (unchanged) or 4xx (W5). Anything else is a stated rejection at the list, its own absence — never the silent frozen list App.tsx produces today for status=abc.

reuse — unchanged
It answers "is this set up", not "is the app hearing back".
why

A tempting move this run rejects: making the dot warn when the API stops answering. Its three states are a capture lifecycle — broken is "setup incomplete or capture never proven", and an unreachable core is neither; the proof that capture works remains a true historical fact. Folding transport into the same disc would make one indicator mean two things and leave the user unable to tell a CA that was never trusted from a core that just died.

@avoid "deriving the status from app phase inside the component" is why this is even a screen-level question: dotStatus() owns the mapping (DEC-20), and a screen may not re-decide it. The band is the second indicator, and the two are read together: the dot is the standing answer, A′ is the live one.
