push-reads-proof — pre-push reuses Gate 0

A push pays for a suite run only when this checkout has not already proven the exact tree being pushed.

v1 · 2026-11-05 · Trawler · T3 WU plan · E-GATEPAR2.W2 · epic plan · W1 plan

Requirement

pre-push pipes its refspec lines to cargo xtask gate0 push, which proves every pushed tree: when every pushed sha carries the tree of a clean checked-out HEAD, it runs the marker-aware Gate 0 on this checkout; any other pushed tree is proven in a scratch detached worktree before the push leaves, and a red proof refuses the push. Deletions and refs/notes/* carry no build tree and need no proof. The range check and the notes sync stay.

The scratch worktree skips the tracked post-checkout (its seeder walks the process tree to find a source); gate0 push seeds directly from the checkout it runs in. The scratch lives under target/ so it is git-ignored, on the same volume for copy-on-write clones, and wiped by cargo clean.

Expected result

  • A push right after a green merge (clean tree, pushed sha = HEAD) spawns no fmt, clippy or test process and prints gate0 skipped … (<key>).
  • A push of HEAD with a dirty worktree, or of a sha whose tree is not HEAD's, runs Gate 0 in a scratch worktree at that sha; the scratch is gone afterwards.
  • A red proof exits non-zero with the refusal line; nothing reaches the remote.
  • A push of only deletions or notes runs no Gate 0.
  • The verify-dod range check and notes sync behave as before.
