The freshness gate — answering "how to stop the agent faking it"

Your instinct is right, and it's the reason to drop the stored hash. Any "stored hash == hash(folder)" check is forgeable — the agent computes hash(folder) and pastes it, index still stale, gate green. A value the agent writes can never enforce the agent. Fix: store nothing. The gate regenerates from the code and diffs. 
flowchart LR
  SRC["ui/src/components/*.tsx
TSDoc = truth"] --> GEN["xtask gen-index
(deterministic)"]
  GEN --> IDX["index (committed,
generated file)"]
  IDX --> GATE{"gate: re-run gen-index,
git diff vs committed?"}
  GATE -->|"differs"| RED["❌ stale — run gen-index"]
  GATE -->|"identical"| GREEN["✅ fresh"]
Same pattern as Cargo.lock freshness / verify-doc: the gate produces the comparison value by re-running the generator over the real .tsx sources — the agent never supplies it. Hand-edit the index → the diff catches it. There's no hash to paste. Regenerate-and-diff, not trust-a-stored-value.

Optional: a hash may cache "is it stale?" for a fast local hint, but it is never the gate — the gate is always regenerate + diff. Generator + gate build in a later WU / W7; W2 only specifies them.
