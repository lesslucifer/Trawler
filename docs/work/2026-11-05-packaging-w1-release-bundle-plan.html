E-PKG.W1 — one version, a release-only bundle, cargo xtask package

The artifact every later WU ships: one committed version, a front-end bundle that can never be the e2e one, and one command that builds and ad-hoc signs the host's installers.

v1 · 2026-11-05 · Trawler · T3 WU plan · E-PKG.W1 · branch wu/packaging/release-bundle off epic/packaging · epic plan

Requirement

cargo xtask package builds the host's installers from one committed version ([workspace.package] version), from a front-end bundle marked release whatever bundle ui/dist held before, and on macOS leaves an ad-hoc-signed Trawler.app and .dmg that pass codesign --verify --deep --strict and whose binary captures under a launcher's environment.

(2) an e2e-flavoured ui/dist and VITE_E2E=1 in the environment, then xtask package --profile package-test: the dist is release; the .app passes codesign --verify --deep --strict; a .dmg exists; the .app's binary, run with env_clear, launchd's PATH, a temp HOME and cwd / as --core on ephemeral ports, prints the ready line and a request through its proxy to a local origin is in GET /flows
e2e—waived at this level: the epic's e2e_packaging (W6) installs and drives this artifact; W1 is its build step
Why the integration test is feature-gated. Both cases run a full Tauri build of the app and a bundle, minutes each; in the default suite every gate0 would pay that. They follow the hook-tests precedent: compiled by every clippy --all-features, run explicitly with cargo test -p xtask --features package-tests --test package_bundle, recorded in the WU result. Where the epic's own packaging e2e runs is W6's to settle.
