E-GATEBM.W1 — target-reachability discriminator

Teach the epic-gate seam walk to skip a back-merge of history already on the gate target, while still gating every genuine forward WU seam.

v1 · 2026-07-07 · Trawler · T3 WU plan · epic plan · solution discussion

Requirement

In the epic-gate seam walk's three-parent arm (gate.rs), skip a merge seam whose merged-in parent (p2, the WU tip) is already an ancestor of the gate target — a back-merge of landed history is not a net-new WU seam and must walk clean, while a forward seam (whose tip carries commits absent from the target) must still be gated.

Mapping

E-GATEBM · R1 (recognise integrations of already-gated history that reach the target), R2 (preserve the genuine forward-seam gate — satisfied by construction: a forward seam is never an ancestor of the target), R4 (record the discriminator rationale and the rejected #1 symmetric-ancestry alternative in the workflow-gates DEC — done at epic distillation).

Expected result

  • The gate target ref is threaded into walk(); the three-parent arm keeps the existing p2 ⊑ mainline self-history check and adds p2 ⊑ target.
  • A stale epic that has back-merged an up-to-date target walks clean — the spurious 7·walk·1·notes … no cr/v2 note line on the integration seam is gone.
  • A genuinely ungated forward WU seam merged into the epic still turns the walk red — unchanged from today.

Test plan

  • Unit (gate.rs #[cfg(test)]): the discriminator predicate — a helper that classifies a (p2, mainline, target) triple as skip/gate — proves skip fires when p2 ⊑ target and does not fire for a diverged forward tip. Covers the code this commit adds.
  • Integration (xtask/tests/dod_gate.rs): the WU's bounded contract on a real temp repo — (a) an epic that back-merged an advanced main walks green; (b) an epic with a genuinely ungated forward WU seam still walks red on that seam (the R2 guardrail). No waivers intended.
