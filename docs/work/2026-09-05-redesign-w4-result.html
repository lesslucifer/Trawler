E-REDESIGN.W4 — the flow list and shell, built from a design it never argued with

The first build WU to read a screen design and implement it without deciding anything of its own. Every row cell renders through the component that owns its value, the two absences have their own sentences, and the row a keyboard could not reach is a listbox. The review found three real defects — all in the build, none in the design.

W2 had already exercised the harder case (a design its own WU deleted, resolved through history per DEC-28); W4 is the ordinary one — a design that stays on disk, so the blob resolves at the tip.

The review — three real defects, all of them the build's

Five finders, then one fresh verifier per candidate. What matters about the shape of the result: every surviving finding was a place the build failed to follow the design, and none was a place the design was wrong. The reuse dimension returned empty — the row cells match their components' @use/@avoid contracts exactly.

FindingWhy it was realFix
A hardcoded proxy address. The empty state named 127.0.0.1:7420 as a literal. Found independently by two finders. api.ts's own comment forbids it in as many words — "configurable, never hardcoded in component code" (DEC-12) — and App.tsx already resolves the address and threads it to Onboarding. Under VITE_TRAWLER_PROXY the list would have named one address while onboarding named another. Calls defaultProxyAddr(), the same resolver as everything else. The test asserts against the resolver, not a literal, so it cannot re-freeze.
A convention applied to a third of its subjects. The design's wire-markup line asks for data-wire on all six payload cells, data-wire="collection" + data-order on the row region, and data-wire="none" on the header's chrome. Two of six had it. A marking convention applied partially is worse than one not applied: it reads as complete. This was a straightforward failure to implement a line of the design the build had claimed to follow. All six cells, the region and the header row now carry their attributes.
The scroll-into-view was untested. Every keyboard test used the same three-row fixture, which fits the mocked 600 px viewport whole — so the virtualizer never windowed, and the mechanism could have been deleted with the suite green. The sharpest finding, because the mechanism exists specifically so the keyboard path is not nominal — the exact risk the plan named and W3 pre-authorized as a W4 finding. Its own safeguard had no test. A 200-row test drives the selection past the rendered window and asserts the virtualizer is asked to follow at every step. See D3 for what it can and cannot prove.

Three candidates were refuted and are recorded because finder quality should stay visible: that TimestampText adds per-render cost (the pre-WU code was equally unmemoized and the component is design-mandated by name); that selectedIndex/toRow per-render work is a regression (both bounded by the virtualized window, and toRow's call site predates this WU); and that move(delta) ignoring its sign with nothing selected is misleading (it is the design's stated Select convention — either arrow lands on the first row — and both directions now have a test).

The filter controls — the one open question the owner settled

W3 escalated the method/status filters to blocked-on with three options and picked none, because "two of the three fixes change a contract outside the screen". The owner settled it during this build, and the answer is not uniform across the three keys — which is exactly why the design refused to guess it.

KeyServer matchNowWhy not the same as its neighbour
methodeq_ignore_ascii_case — exact Select, nine verbs The design's own option (a), legal today: a closed set matched whole. Select's @avoid "two to four options" is cleared at nine. Each option renders through MethodLabel, so the tone in the dropdown is the tone in the column. This was the worst case — typing GE returned an empty list indistinguishable from no traffic.
hostcontains, case-insensitive Select, every host seen Beyond what the design contemplated (it had kept host as a Field on the grounds that "a partial host is the point"). The owner took the trade: partial matching is no longer expressible here, and the free-text key still covers it. Options are accumulated rather than derived — see the note below.
status== Some(u16) — exact Field — unchanged, deferred Deliberately not converted. A dropdown of seen codes is buildable, but the useful query is a class (4xx) and FlowFilter.status is a u16 — so neither control expresses what a user actually wants. Deferred to a later epic to design the interaction rather than half-converted now; the reason is marked at the call site.
Host options are accumulated, not derived — and that is load-bearing. flows is the server-filtered list, so building the options from it would shrink them to the one host already chosen the moment you chose it, stranding the user with no way back. useFlows keeps every host capture has seen instead, which a unit test pins directly: after narrowing to one host, the other must still be offered.

Clearing. Select's @avoid rules out a clear affordance — "nothing returns to unselected once chosen" — so a filter that must be clearable needs an answer inside that contract. An "any" option at the top is one: a real choice that happens to mean no filter, rather than a control the component forbids.

Deviations

#DeviationWhy
D1 The header gained flex-wrap, which the plan did not list. Writing Layout's zoning comment surfaced that the design's overflow line says zone A "wraps to a second line before it clips" and the code had no flex-wrap — so the comment as written would have described behaviour the file did not have. Making the code true was the smaller change than making the comment lie; it is the design's own stated rule, not a new decision.
D2 FlowList gained a filtered prop. The design requires the list to tell its two absences apart, and only App knows whether a filter is active — the list receives an already-filtered array and cannot distinguish "nothing captured" from "nothing matched". The alternative, reading the filter inside the list, would put data-layer knowledge in the row region.
D3 The scroll-into-view test asserts the request, not the result. jsdom implements no scrollTo, and the virtualizer's scroll is exactly a scrollElement.scrollTo call — so under jsdom the window provably cannot follow. The test asserts the virtualizer is asked at every step including past the window's edge, and its comment says so plainly rather than implying more. That the browser then honours the request is the e2e's assertion, driving real keys against the real WebKit window.
D4 The truncation stayed. Not a deviation from the design — the design's own recorded verdict. host and path truncate because a virtualized fixed-height row cannot wrap, the full value lives on the row's title and in the detail pane, and the missing rulebook clause is W11's. The test asserts both halves, so a later well-meaning "fix" that drops the title fails rather than passes.
