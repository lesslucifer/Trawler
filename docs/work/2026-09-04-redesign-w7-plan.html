E-REDESIGN.W7 — design run: the body viewer

The epic's largest run. Nine registry members, six body kinds, seven zone states, two mutually exclusive switches — put through the six-stage flow so W8 can wire a pane that states its truncation, dispatches xml for real, and copies exactly what it shows.

WU plan · 2026-09-04 · Trawler · T3 (docs/work/) · wu/redesign/body-viewer → epic/redesign · flow: design-flow · rulebook pinned aeff5b0f · registry: 27 entries

Requirement

Design — not build — the flow's six stages over BodyViewer.tsx, landing as one closed run doc that resolves all six body kinds to the BodyRenderer family members, both switches to SegmentedControl, the truncation statement to CutMarker and all seven zone states to Notice — each with a reuse/extend/propose verdict traced to the entry's own @use/@avoid, a receipt covering all seventeen soft slugs against rulebook aeff5b0f, and a mockup that mounts the real components from specimens.bundle.js — so that W8 has a Tier-3-judged design to cite by blob, and the three UC-5 defects the epic charges to this screen have a designed answer rather than an improvised one.

Two shape decisions taken up front

Both were open going in; both are recorded here so the run does not re-litigate them mid-stage, and both remain falsifiable at Elements by the @avoid trace.

Layout · the control row

Two SegmentedControls, one row

Leg (request|response) and mode (decoded|raw) are both always-visible mutually exclusive view switches — SegmentedControl's @use names both of these two cases by name. So both are literal reuse, side by side, with copy and save pushed to the row's end by choose-before-act.

The rejected alternative — promoting leg to a Section variant="band" — is plausible (Section's @use does name "a two-leg panel's leg level") but W5 owns the panel's zoning, and two runs claiming the leg seam is the conflict this decision avoids. Recorded at Elements as a considered fork, not silently dropped.

Interaction · the empty states

All seven zone states, tabled

bodyNotice already returns five distinct absences — empty · streaming · not-captured-too-large · not-captured-read-error · no-response-yet. The pane has two more the current code renders as unstyled <p>: in-flight and fetch-failure.

absence-names-itself demands "two causes never share one sentence", and Notice's @use claims "BodyViewer's five absences" explicitly. Designing only five would leave the receipt's satisfied unearned on the two states nobody wrote words for. No retry affordance — that is a new user-facing capability, which the epic's non-goals forbid.

This WU adds no code, so the pyramid's three levels have nothing to assert against. The waivers rest on the E-DFLOW.W9 precedent the epic plan cites for exactly this case — the WU "touches no product code or screens" — and are named here rather than taken silently.

What could go wrong

RiskHandling
The run re-decides what a member owns. Nine members with dense contracts, and the flow's sharpest rule is "never re-decide what a component owns" — restating HexRenderer's dump format or CutMarker's size form is the natural failure mode of a run this size.The States column is filled by reference only, citing the member. A run that re-lists a member's states has produced a fork no class check can see; Tier-3's design dimension is pointed at exactly this.
The mockup draws instead of mounts. Nine renderers is a lot of mounting, and a plausible-looking <pre> in correct utilities passes the eye.mockup·hand-drawn reds any reuse/extend element that is not mounted. What legitimately stays stubbed is named in advance: a member's internals — the CodeMirror surface, the live clipboard, the renderer dispatch itself (DEC-26).
An @avoid hit gets smoothed over. The most valuable output of Elements is a member refusing the job — and the cheapest thing to do with one is to write reuse anyway.An @avoid hit is recorded as a propose or a blocked-on entry, never argued past. The flow is explicit: "forcing a component past its @avoid line is a propose, not a reuse". Two candidates are known going in — the raw-mode dispatch (rawKind returns only text|hex, so raw mode has no xml/json surface) and ImageRenderer's no-copy rule interacting with the shared control row.
The seam with W5 drifts. W5 designs the panel that contains this pane, and both runs are open against the same epic with no ordering between them.This run treats the panel as given and designs inward from the pane's own zone — the reciprocal of W5's "declares the seam, does not design through it". Any zoning this pane needs from the panel is a blocked-on entry naming W5, not an assumption.
A needed token does not exist. Nine renderers, a checkerboard, three syntax roles — DEC-17 leaves no room for a literal.The three syn-* roles and the chromatic set already ship. A value the config genuinely lacks is a config change handed to W8 as blocked-on — "a value that has no utility needs a named token in the config, not a literal here". Never a hex escape in the mockup.
The toolchain is not on PATH. verify-doc is the per-write gate, and this worktree's ~/.cargo/bin is empty — the stable toolchain lives unlinked under ~/.rustup/toolchains/.Verified working with ~/.rustup/toolchains/stable-aarch64-apple-darwin/bin prepended to PATH; ui/node_modules installed and the specimens bundle built. An environment note, not a design finding — but a run whose gate never fires would be the worse failure.
