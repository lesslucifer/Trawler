Requirement

Every quit Trawler can intercept asks first while this machine routes through Trawler. The dialog states only what it can verify about this machine and Trawler's proxy, and offers to stop only a proxy that routes through Trawler. It shows the other-devices notice only when a device could be routing here now. It is one frame whose button gives way to its outcome, and its by-hand steps are each platform's own. A test holds each rule.

Part 1 — when it asks, and what it claims

#What goes wrong todayProposed fixRuling
D1 ⌘Q quits without asking (reproduced). So do the app menu's Quit, the Dock's Quit and logging out. A Mac user's usual way to quit leaves the machine routed through a proxy that is about to stop. E-UISETUP.W6 accepted this in July, believing nothing could catch it. UC-ONBOARD still promises the opposite. Per Q1. A: the app menu's Quit becomes Trawler's own item on ⌘Q. It asks the window to close, so ⌘Q runs the same check as ✕. The Dock's Quit and logging out still send terminate:, which tao cannot cancel. UC-ONBOARD names that gap, and a roadmap row keeps it.—
D2 Linux always hears "No proxy is set on this machine." Quit reads no proxy on Linux, so the reading is unknown, and unknown is handled as the remote case. A GNOME proxy pointing at Trawler gets a sentence saying none is set. A macOS service that fails to read does the same. Turning the proxy off from the dialog cannot work on Linux either. Quit reads GNOME's proxy on Linux, as setup's proxy task does. An unread proxy gets its own sentence: Trawler couldn't read this machine's proxy, with the steps. Where the shell cannot turn the proxy off (Linux), the dialog shows the command instead of a button that can only fail.—
D3 Someone else's proxy is treated as Trawler's problem. A work proxy reads foreign, stops every quit, and offers turn it off. Quitting Trawler does not change that proxy, and turning it off can take away the internet it provides. It asks on every quit, with no way to stop it. Meanwhile this machine's own LAN address at Trawler's port also reads foreign, though it routes here. Per Q2. A: a proxy that does not route through Trawler is not this dialog's business, so that quit goes on to the other-devices check. A proxy at Trawler's port on any of this machine's own addresses reads ours.—
D4 The other-devices notice shows when no device can be routing here. It appears on every quit that finds nothing set on this machine, until it is dismissed for good. Another device can reach Trawler only while reach is armed (DEC-55), and an emulator only while its proxy points here. A notice that is nearly always irrelevant teaches its don't show this again, and then it stays silent on the day it matters. Per Q3. A: the notice shows only when a device could be routing here now: reach is armed (the core's /reach), or a running emulator's proxy reads ours (W8's adb reading). Otherwise the quit goes through.—
D5 The stake is tied to the window, not the proxy. "Leave it on after quitting and your internet may stop working" and "once Trawler closes": the proxy is the core, a separate process that this quit does not stop. When the core is already not answering, the machine has no internet through it now, and the dialog says "may". The stake names the proxy: This machine sends its web traffic through Trawler. Once Trawler's proxy stops, it has no internet until you stop routing through Trawler. While the core is not answering: Trawler's proxy isn't answering, so this machine has no internet through it now. Final words come from the design run.—

Part 2 — shape and wording

#What goes wrong todayProposed fixRuling
S1 A dead button (the roadmap row). After a successful turn-off whose window stayed open, turn it off stays on screen, disabled, beside "you can quit safely". Frame B's ruling: the button gives way to its outcome. quit remains alone in the same corner, with focus on it.—
S2 A second dialog body (the roadmap row). The remote mode returns its own ModalShell tree. Frame B's ruling: one frame with sentences worded per mode. The remote mode drops the button and gains the opt-out.—
S3 Two names for one act. Setup's reversal reads stop routing through Trawler and names the half it performs (UC-ONBOARD). The dialog says turn the proxy off, turn it off and the proxy is off for the same unset_proxy. Its progress line asks for a prompt on Windows, where turning the proxy off writes the user's own settings and shows none. Per Q4. A: the dialog uses setup's words. The button reads stop routing through Trawler, the title asks stop routing through Trawler before quitting?, and the outcome says this machine no longer routes through Trawler. The prompt is mentioned on macOS only.—
S4 The by-hand steps fork from setup's. The dialog keeps its own seven targets (proxyTargets.ts). Android's step names a path stock Android lacks (W10's C3), and there is no iPhone target, though both phones are platforms setup routes here. In the remote mode the picker defaults to this host's OS, the one machine the notice has just said is clean. Per Q5. A: the dialog's steps are the platforms' own undo steps from setup.ts, picked by platform. The default is this machine wherever this machine is the subject, and in the remote mode the device the reading found (the emulator) or the last platform set up. Each fix W3–W10 made then reaches the dialog by construction.—

#QuestionProposed

Quitting Trawler changes nothing for that proxy, so there is nothing to ask. B interrupts every quit to say so. C offers an act that can break the machine's internet.
