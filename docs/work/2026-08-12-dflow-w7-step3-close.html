② The review record — finding 29, the last open flow-spec finding

Two reviewer instructions in run #2 moved the Layout sketch, two catalog rows, two use-cases, the mockup, four receipt rows and the cross-check — and the run doc reads as if the stages had produced all of it. Tune is the run's own stepping-back; the cross-check compares runs. Nothing recorded that a human overrode the design and what the override cost.

ColumnAnswered howWhat the check refuses

what it moved the run's own item names — frame · layout · elements · interaction · mockup · tune · receipt · capabilities · proposals · blocked-on — or nothing "the reviewer changed things". The vocabulary is the artifact's own, so the column cannot drift from what a run contains. nothing is a real answer: an instruction argued and refused is provenance too, and a schema that cannot express it teaches runs to omit the row
the contract it hit a cited <code>: a rule slug, a component's @use/@avoid, a decision record — or taste an uncited cell. taste is deliberate and load-bearing: it distinguishes the reviewer overrode a contract from the design had latitude there, and the first is the signal worth keeping

Kept separate from the Tier-3 verdict, per the W7 discussion: one is provenance, the other a judgment. Merging them loses the provenance half.

③ Closing — where the enforcement had to sit

Three homes were possible. The measurement that decided it: a run mid-design is legitimately red for days, so any working-tree sweep holds the suite hostage to work in progress.

HomeRuling
a unit test — "every run is archived or green" refused already ruled out in W6: it reds the whole suite for the duration of every live run
a close command that archives after verifying not built the user's call. It would own the step but force nothing; the step's failure mode is skipped, and a command nobody is required to run does not fix a skip
the merge — 6·run-closed built the first moment the tree is answerable for the run: the Working Unit that carried it is ending. A run still mid-design across a merge declares data-status="draft" — unfinished, which is a different claim from closed, and one the epic gate later refuses to leave in the tree at all
Read the declaration, never the string. The flow spec and two W4 plans quote data-artifact="design-run" inside a <code> block. A substring scan — the first thing tried while measuring — called all three of them runs and would have gated every doc that explains the contract. The gate reads the same tokeniser the predicates read, and a test pins it on both surfaces.

Does not assert— that every run is archived. That is the merge's job, and a run being designed right now must not red the suite

The old test's weakness was structural: it was the same "somebody remembers" that left run #3 open, one layer down. Its new form cannot go stale, and the vacuity guard is what keeps it from degenerating into "archived docs are silent", which is true by construction.
