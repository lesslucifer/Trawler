W1 · hook-sync — installed hooks are the tracked hooks

Git runs the hooks in the checked-out tree, never a stale copy, and every gate refuses a checkout where it would not.

Draft v1 · 2026-11-05 · Trawler · T3 WU plan · E-GATEPAR.W1 · epic: E-GATEPAR plan

Requirement

cargo xtask hooks install sets core.hooksPath to the relative .cargo-husky/hooks, every tracked hook is executable, and each gate entrypoint (verify-dod, gate0, lint, preflight) in a tree that ships .cargo-husky/hooks/ refuses with exit 1 and the line cargo xtask hooks install when core.hooksPath is unset, points elsewhere, or a tracked hook is not executable.

Expected result

  • After cargo xtask hooks install, editing a tracked hook changes what the next git commit runs — no build, no reinstall — in the main checkout and every linked worktree.
  • In a checkout without core.hooksPath (or with it pointing elsewhere), cargo xtask lint / gate0 / verify-dod … / preflight … print the refusal and cargo xtask hooks install, exit 1, and run nothing else.
  • A tracked hook that loses its executable bit is refused by the same check, by name.
  • This machine: core.hooksPath set once in the shared repo config — all worktrees switch at once.
