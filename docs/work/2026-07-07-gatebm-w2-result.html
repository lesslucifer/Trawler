E-GATEBM.W2 — result: walk-error waiver valve (R5)

The epic gate now suppresses a single walk seam failure via a recorded, per-seam entry on the tip's cr/v2 note — not the blanket --no-verify.

v1 · 2026-07-07 · Trawler · T3 WU result · WU plan

Outcome

Delivered against the requirement. CrNote gained an optional walk_waivers: [{seam, why}] field and a walk_waiver_for(seam) resolver that matches by sha prefix and requires a non-empty why. The walk loads the tip's cr note once and routes every seam failure through record_seam: a match records a visible WAIVE line and drops the failure; otherwise the failure is pushed with its fix extended to name the exact git notes --ref=cr waiver edit and warn off --no-verify. Report gained a waived channel surfaced in format_report.

Deviations

Two refinements beyond the literal plan, both in-spirit. (1) The valve was wired for every walk seam class — three-parent WU seams, standalone commits, and octopus merges — not only WU seams, since R5 explicitly insures against "any future topology the walk can't classify". (2) Seam matching is sha-prefix-tolerant (a short sha in the note matches the full seam sha and vice-versa), so an agent can copy the abbreviated sha the walk prints straight into the waiver.
