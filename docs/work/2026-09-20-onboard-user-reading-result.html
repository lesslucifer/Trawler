Deviations

#DeviationWhy
1Six commits, not the plan's seven. The words and the screen landed as one They are one change. setup.ts and verdicts.ts hold the sentences Onboarding.tsx renders, and every task's title, state and promise moved together. Splitting them would have landed a commit whose tests assert sentences the screen does not render, which is a red suite dressed as a boundary
2The single install certificate button left, and install_ca with it. The plan did not foresee a deletion It was reachable in no state of the screen the design renders. This machine is the only platform whose certificate store the trust probe answers for, and it is also the only one the combined action covers — so the button's condition (trust is probed here AND no combined action) is empty by construction. An #[tauri::command] nothing can call is dead code and unreviewed surface both, so the handler, the registration and the front-end prop went together. The reading round had already named the successor: what it replaced stays reachable inside the manual disclosure, which is where the steps now are
3The end-of-setup sentence names the device only on this machine. The copy table names it unconditionally A decrypted request proves Trawler is capturing and never says which device made it — the run's own still open blocked-on row, and the reason F21 exists. The copy table's row is written under a this-machine mockup; carrying its last three words to a phone would put back the attribution W4 removed. This machine is the one platform where the two readings cannot differ, so it keeps the full sentence and every other platform drops the clause
4The probe's shape changed, which touched the quit dialog's seam — closeConfirm.ts reads .status off the same answer One read, both readers. The alternative — a second command asking the OS the same question a second time — puts two readings of one setting in one screen. The quit dialog's behaviour, markup and copy are unchanged; only the shape of the answer it destructures moved, and the epic's non-goal is the dialog, not the probe it calls
5The primary action is named for the host. Set up this Mac on macOS, Set up this PC on Windows The copy table is written under a macOS mockup. Rendering this Mac on a Windows host is the same class of false sentence the P0 set removed, so the noun comes from the host the app detected — the one place it already names itself in the tiles
6Three resolvers left with the lead they worded — screenVerdict, stepsLeftHere and stepsDetail All three existed to word the screen's lead sentence, which F1 removes. W4's note says W5 "keeps the resolver, which is where the count comes from"; the amended mockup has no element that grades this machine's setup, so keeping them would leave an exported, tested resolver nobody reads — a claim nobody makes. The count's evidence is in W4's result, and a screen that wants one again can re-derive it from two probes
7The mockup's own left-edge class is not in the vocabulary. Its pl-9 renders unstyled The aside under the tasks takes the task body's left edge by repeating TaskStep's own template — an empty marker column and the same gap — rather than a 46px value the closed spacing scale has no token for. Same geometry, no escape pragma, and the alignment cannot drift from the component it is aligning to
