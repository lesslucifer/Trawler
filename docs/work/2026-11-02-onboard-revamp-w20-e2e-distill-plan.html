How the emulator counts an unmarked request (deviceTraffic, nextClearReadings, newestRead) Only inside a clear span: from one reading of this machine's proxy that lands off or pointing elsewhere, to the next one's send. Each reading waits for every probe, adb's emulator_readings among them, and a quiet read is skipped while one is in flight. So a slow adb, or a proxy reading other than off or another, keeps the request from countingG1
The e2e launcher (wdio.conf.ts) and the harness's front (front.rs) The e2e window talks to the core directly. The walkthrough's window talks to the front, which forwards everything and answers /reach itself, arming an address without binding it. So with the window on the front, a spec can arm an address with no native dialog and no LAN listener, which is the reason the spec gives for not driving the reach platformsJ3 · Q1
A marked request: markOf, REQUEST_URL in route.rs, Config A mark counts only on a captured https://example.com/?trawler-check=… row. Through the proxy the core resolves example.com itself, and Config has no resolver override, so a hermetic marked request needs a core change.
