One plan text did not survive contact, and it is the plan's, not the rulebook's. ③ was scoped to write zero-accent as "the simplest rule in the book: chromatic colour is ok and warn". It is written as eight members. Step ② already moved it to five when the verb tones proved to be a palette gap rather than a deletion; ③ adds the three DEC-11 syntax tones for the same reason and with more force — they were being painted the whole time. The rule's shape is what the ruling asked for: no exception list, no scope carve-out, one membership test against the config. Only the cardinality is different, and the count was never the point.

Two different switches, sharing the word raw, one of them wearing the other's name. Found while writing the lexicon entries finding 9 asked for, because writing three definitions forces the question the two artifacts never had to answer together.

Ruled: raw | pretty is correct and the build is what changes. Deferred, and deliberately not skipped. A rulebook step that quietly edits UI copy is a rulebook step nobody can trust, so the fix does not happen here — but a deferral with no home is a drop. It has three: the lexicon states the ladder (wire bytes → decode → raw → pretty) so the fix has something to be correct against · the rulebook says where a live violation goes carries the ruling · and the deferred backlog owns it until an epic absorbs it. The rule that catches it meanwhile is one-term-per-concept, which now cites this as a live example on its own row — a soft rule earning its place by naming a real defect rather than a hypothetical one.

The sweep ② handed over — 63 scales were open, not one

Step ② closed fontWeight and left ③ a debt: "an open scale is invisible to the rule by construction; ③ owes a sweep for any other scale ① left open." Measured by generating the class list twice, once with each scale emptied, and intersecting with what ui/src/ actually authors:

63

8

of them actually drawn from — animation cursor flex flexShrink gridColumnStart gridRowStart listStyleType transitionProperty

54

latent — open, and nothing in the tree touches them. Now red on sight rather than silently legal

The fix is one line of definition, not 63 config entries. Legality was "a class Tailwind can emit"; it is now "a class Tailwind can emit from a scale the config declares". So the config declares the 8 in use, at exactly the members the code draws from, and the other 54 need no entry at all — anything drawn from them reds. That is the fontWeight defect fixed at its root instead of one scale at a time: duration-500, animate-bounce and font-bold all red now, and each has a RuleTester case.

The last pass: the T2 carries rules, this doc carries the case history

What ③ hands to ④

Every hard rule now says what its predicate must check, in the words the predicate will implement — the two that were blocked on content (overflow-declared's granularity, spacing-scale's floor) are settled, and the two that carry a known run defect (state-declarations must read the registry verdict, wire-order-preserved needs an n/a path) say so in the table itself. Three facts ④ must not re-derive: the chromatic set is eight and lives in the config, not five and not in the doc · the pragma's five rules are the rule's contract, already enforced by the lint rule and now documented identically · and 13/13 is the target because the hard list is deliberately frozen at 13 — the three rules ③ added went to the soft table for exactly that reason.

One thing ④ should treat as a warning rather than a fact: every correction in this WU so far — seven in the plan revision, three in ①, two in ②, two here — came from executing against the real artifact. Not one came from re-reading a document. A predicate written against the KB and never run over the two archived runs is the same bet that has now lost eleven times.
