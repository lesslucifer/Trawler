merge-proves-tree — the merge into main runs Gate 0 on the tree it creates

No merge commit reaches main unless the merged tree passes fmt, clippy and the suite in the checkout making it.

v1 · 2026-11-05 · Trawler · T3 WU plan · E-GATEPAR2.W1 · epic plan

Requirement

A merge into main — automatic (pre-merge-commit) or a conflicted completion (pre-commit with MERGE_HEAD) — runs cargo xtask gate0 merge on the merged working tree after verify-dod hook epic is green and is refused when it is red, while a merge into epic/* runs no Gate 0, and every check Gate 0 spawns runs with no GIT_* variable in its environment.

Expected result

  • A merge into main whose merged tree fails Gate 0 exits non-zero at the hook; main HEAD is unchanged and the output names git merge --abort and the back-merge.
  • A red verify-dod hook epic refuses before Gate 0 starts.
  • A merged tree this checkout already proved green is a marker hit — no fmt, clippy or test process.
  • A WU merge into epic/* spawns no Gate 0.
  • A check spawned by Gate 0 or lint sees no GIT_* variable, whatever the caller exported.
  • DEC-74 recorded and linked from workflow-gates.html and the decisions index.
