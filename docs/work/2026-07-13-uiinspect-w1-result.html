Outcome

The view-time decode chain in src/api/decode.rs now covers the full common set the inspector needs. Before W1 it un-gzipped/deflated and pretty-printed JSON only; ?decode=1 now also:

CaseBeforeAfter
content-encoding: brcompressed bytes → hex garbagedecompressed via the brotli crate, reusing the shared decompress() + MAX_DECODED_LEN zip-bomb guard
non-UTF-8 charset=shown as UTF-8 → mojibaketranscoded to UTF-8 via encoding_rs before any pretty step
XML / HTML bodyone unbroken lineindented via quick-xml, mirroring JSON pretty

Chain order: decompress → transcode → pretty (JSON or XML). Every step is identity-on-error, so a body that fails any stage renders as its input, never an error. View-time only over unchanged raw bytes — no new endpoint, capture untouched; the broadened contract reaches curl and the web shell too. The requirement sentence ("extend decode_body to add brotli, charset→UTF-8, XML pretty alongside gzip/deflate + JSON, keeping the guard and identity fallback, no new endpoint") is met in full.

Deviations

Two, both from the code-review round; neither changes the requirement or contract:

  • brotli pinned to 8, not 7. The plan named the brotli crate without a version. brotli = "7" compiled a second copy alongside the 8.0.4 already pulled transitively via hudsucker → async-compression. Bumped to "8" to unify onto one copy — smaller binary, no API change.
  • XML pretty via quick-xml. The plan left the XML implementation open; a hand-rolled indenter can't correctly handle comments/CDATA/attributes/entities, so a streaming reader/writer is the honest call. Malformed / unclosed markup falls back to raw via a depth check plus quick-xml's default check_end_names (an explicit redundant assignment was removed in the review fix).

New crates: brotli, encoding_rs, quick-xml.
