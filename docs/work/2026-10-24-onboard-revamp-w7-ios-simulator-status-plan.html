Requirement

The iOS Simulator's certificate and try tasks read only what is the Simulator's — its own trust store, or its own marked request — so this Mac's traffic never turns them done, a refusal on this Mac never blames the Simulator, and "You're set up" shows only on the Simulator's proof. Each command finds the file the save step wrote, reaches every running Simulator, and its removal removes Trawler's root. A test holds each rule.

Part 2 — steps that cannot be done as written

As in W5 and W6, each of these leaves a task waiting for a request that the step, as written, can never produce, or says something false.

#What goes wrong todayProposed fixRuling
C1The trust command names a bare trawler-ca.pem. The save step opens a dialog that saves wherever the user points it. A terminal opens in ~, so the command fails with "no such file" (reproduced). This machine's commands on macOS, Windows and Linux name the bare file too.Once the file is saved, the command names the path the save returned, quoted. Before a save, it names ~/Downloads/trawler-ca.pem, and the save dialog opens in Downloads. Who gets this: Q2.take
C2booted picks one Simulator, silently. With two running, the command trusted the one booted last (reproduced). It may not be the one the user is looking at, so ③ never decrypts.The command trusts every running Simulator: for d in $(xcrun simctl list devices booted | grep -Eo '[0-9A-F-]{36}'); do xcrun simctl keychain $d add-root-cert <file>; done. With S1's probe, ① names any running Simulator still missing the certificate.take
C3The removal removes nothing. simctl keychain booted reset exits 0 and leaves Trawler's root in the trust store, through a reboot (reproduced). So both halves of its warning, "clears everything in it, not only Trawler's root", are wrong.The removal step is the one that works: "Erase that Simulator: Device → Erase All Content and Settings. It wipes everything in it." The keychain reset command goes. Alternative: Q3.take

Questions

#QuestionProposed · ruling
Q1What reads ①? A a shell-side probe (epic Q8): for each running Simulator (device.plist state 3), does its TrustStore.sqlite3 hold Trawler's CA? It reads with /usr/bin/sqlite3 -readonly and adds no dependency. Unread wherever no Simulator runs or the file is not there, and then the marked request settles ①. · B the marked request only, DEC-63's mechanism, with no new probe A. It is the most accurate reading available, and it re-reads, so the epic's carried-in rule ("a proof is not permanent") holds: an erased Simulator reads not done on the next tick. Risk: Apple does not document the path, so a runtime that moves it reads unread, never not installed. Ruled: A
Q2Who gets C1? A every guide where a save step comes before a command: the Simulator, and This machine on every host · B the Simulator only, with This machine left to W12 A, as W6's Q1 did: the same failure in the same code, fixed once. Ruled: A
Q3How is Trawler's root removed? A Erase All Content and Settings: supported, and it wipes the Simulator · B delete the one row from TrustStore.sqlite3 while the Simulator is shut down. This keeps everything else, but writes a file Apple does not document A. Reading an undocumented file can only misread. Writing one can damage the Simulator. Ruled: A
