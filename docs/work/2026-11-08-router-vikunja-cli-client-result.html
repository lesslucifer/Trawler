Outcome

Delivered against the requirement: init · show [--project] [--needs-owner] · read · put · create, the router token alone, every task-field write a whole-task read-modify-write.

put facetCallBatched?
--done/--undone, --descriptionone POST /tasks/<id> carrying the whole task read at the startyes — one write for both fields
--commentPUT /tasks/<id>/commentsown endpoint
--relationPUT /tasks/<id>/relations per relationno bulk endpoint exists
--assignee/--unassignPUT …/assignees · DELETE …/assignees/<uid>split: …/assignees/bulk exists but the router token is refused it (401)
--label/--unlabelPUT …/labels · DELETE …/labels/<lid>split: …/labels/bulk refused to the token too (401)

Order is fixed whatever the flag order — comment → relations → task fields → assign → label → unlabel → unassign — so one put is the protocol's ask (label lands last) or its close (label off before the assignee). Adds already present / removals already absent are skipped and said: Vikunja answers those with 8001 / 4021 / 403 otherwise.
