E-PAGES.W4: pages.yml, the workflow that builds and deploys the site

One pinned GitHub Actions workflow: build target/site from the tree and releases/latest, deploy it to GitHub Pages; a hermetic test holds its shape.

v1 · 2026-11-08 · Trawler · T3 WU plan · E-PAGES.W4 · branch wu/pages/deploy off epic/pages · epic plan E-PAGES (the workflow shape, router checklist, owner settings)

Requirement

.github/workflows/pages.yml builds the site with cargo xtask site build reading releases/latest (never the event payload) and deploys it to GitHub Pages: triggers push to main, release published (skipped when pre-release), workflow_dispatch; contents: read at the top, pages: write + id-token: write on the deploy job only; every action pinned by full SHA with a version comment, equal to release.yml's pin where both use it; persist-credentials: false; environment github-pages; concurrency group without cancel-in-progress; no actions/configure-pages (the base URL is the xtask constant); a hermetic test xtask/tests/suite/pages_workflow.rs asserts those properties; actionlint clean.

Flow

flowchart LR
  E1(["push: main"]) --> IF{"release event and prerelease?"}
  E2(["release: published"]) --> IF
  E3(["workflow_dispatch"]) --> IF
  IF -- "yes" --> SKIP["build + deploy skipped"]
  IF -- "no" --> B["build (contents: read): checkout · toolchain 1.99.0 · gh api releases/latest · cargo xtask site build --out target/site · upload-pages-artifact"]
  B --> D["deploy (pages: write, id-token: write) · environment github-pages · deploy-pages"]
