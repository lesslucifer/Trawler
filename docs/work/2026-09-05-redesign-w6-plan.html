E-REDESIGN.W6 — build the flow detail

The panel a user lands on after clicking a row, rebuilt from W5's closed design: four zones split by scope, one leg selector in the pinned identity row, every header value a copy target, a curl action whose payload is never rendered, and the two keyboard promises the design receipted as blocked — Esc dismisses, focus returns to the row's list.

WU plan · 2026-09-05 · Trawler · T3 (docs/work/) · wu/redesign/flow-detail-build → epic/redesign · designed by W5's design run · W5 plan · W5 result · DEC-31

Requirement

Build — citing W5's design run by blob, not re-deciding it — a FlowDetail whose pinned identity row carries MethodLabel · StatusPill · a SegmentedControl selecting the leg · DurationText · an IconButton close; whose unlabelled flow line carries the URI as CopyText, the versions line and a CopyButton reading copy as curl; and whose two leg-scoped Sections — Headers (a wire-order table of KeyValueRows, Notice when the leg sent none) and Body (one BodyViewer given the selected leg) — both follow that one selector, with the pending panel a Notice — so that the panel holds exactly one model of "which leg", opens on request always, copies any header value or the URI on click, confirms and reverts its curl copy instead of sticking on "copied", closes on Esc, and returns focus to the list that opened it.

What the design left to this WU by name

the panel's state · DEC-31

Leg is a useState in FlowDetail, default "request"

Passed to the header table and to BodyViewer. The shipped per-flow rule (flow.response_body ? "response" : "request") is not reintroduced: a request always exists, and it is what the user clicked a row to identify. App already remounts the panel per selection (key={selectedId}), so a new flow opens on request without extra code.

blocked-on · Interaction

Esc dismisses the panel

A keydown listener on document for the panel's lifetime — not on the panel's root — because the keyboard path that opens it (Enter on the list) leaves focus on the list, outside the panel. Ignored when the event is already defaultPrevented: Select claims Esc that way for its popup. The quit dialog does not, so a dialog-and-panel Esc closes both; recorded as a follow-up for W10, whose screen the dialog is.

blocked-on · focus-returns-to-origin

Focus returns to what opened the panel

The panel records document.activeElement when it mounts — the list's listbox, whether the row was clicked or entered — and focuses it again on close, by ✕ or Esc, if it is still in the document. No list API, no change to FlowList; the panel owns its own exit.

T3 locals the run sanctioned

Header table · versions line

Both build local, waive reuse per the tier model, each recorded in the run with why no entry fits. The header table is the <dl> grid (~8 lines, its existing design-allow pragma kept) plus the branch to Notice; the versions line is HTTP/1.1 → HTTP/2 as one muted mono line, data-wire="protocol-version", the arrow only when a response version exists.

Not in scope

No change to any registry member or to BodyViewer — components are consumed exactly as they ship; a member that needs a change is a finding, not an edit. No KeyValueTable component — the run considered and declined it; a third pair-grid tenant may reopen it. No eviction notice (the Frame's Not given; nothing raises the event). No timing breakdown, no replay, no next/previous flow. No zebra on header rows (Tune 6). No change to the quit dialog's own Esc handling (W10's screen). No Gallery.tsx deletion — that is W11.

What could go wrong

RiskHandling
The build re-decides what a member owns. The natural failure here is a second confirm timer, a hand-rolled focus ring on the close, or a tone resolved at the call site. The screen passes raw values (method, status, duration_ms) and holds no confirm state. Anything visual it adds is layout: the pinned/scroll split, the grid, the flow line's flex row.
The existing tests encode the old layout. Two W8 integration tests and one W8 e2e assert two body panes on the page at once; the App tests and one e2e assert a rendered curl text. Rewritten, not patched, and each deleted assertion maps to a design line (DEC-31, Tune 7). A suite kept green by keeping the old layout is the failure mode.
Esc has other tenants. Select closes its popup on Esc; the quit dialog cancels on Esc. The panel ignores a defaultPrevented Esc, which is how Select claims it. The dialog does not prevent default, so both would close — a W10 finding, recorded, not fixed here in a file this WU has no design for.
The e2e origin's request carries few headers. A reqwest client through the proxy sends accept and host; content-type is a response header. The request-leg assertion uses accept; content-type is asserted after selecting the response leg — which is itself the new contract.
Clipboard under WebDriver. A real write fails or prompts, which is why curl was asserted as DOM text — text this WU removes. Replace navigator.clipboard with a recording stub via browser.execute before the click; assert the recorded payload. If the WebView refuses the override, fall back to the copied label and keep the waiver wording.
Focus return races the unmount. Focusing the origin after onClose has unmounted the panel is fine; focusing something the panel contained is not. The origin is read once at mount, before any element in the panel can take focus, and focused only if still connected.
The toolchain is not on PATH. This worktree's ~/.cargo/bin is empty and ui/node_modules is present. ~/.rustup/toolchains/stable-aarch64-apple-darwin/bin prepended; verified. An environment note, not a finding.
