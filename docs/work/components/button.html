Button T1

Plain labelled action button — the primitive two other components' contracts already point at, and the registry does not have.

Component design · proposed · 2026-07-26 · E-DFLOW.W4 · T3 (docs/work/components/) · proposed by run #2 · fixes finding 30 · owner W5

Identity & frame

Why it exists: IconButton's @avoid redirects word-labelled actions to "CopyButton or a plain button" — naming a component the roster does not contain. CopyButton's @avoid rules out "anything that is not a copy action". So the first non-copy, non-glyph action the collection met (retry) had nowhere to land. It stayed invisible for four zones because a read-only detail panel has almost no actions that are not copies — the gap is structural, not incidental.
TierT1 Primitive — generic action affordance, no business logic → in the collection
Tenantsretry and close in the detail panel's three load failures (zone E) · retry in BodyViewer's proposed fifth state · every future form, dialog or confirm the app grows
Exists todaynowhere — and that is the finding. Run #2 had to style its zone-E buttons at screen level because there was nothing to compose
Made of— (T1 primitive). Third sibling of CopyButton and IconButton: Button is the base case — a label and a handler. The other two are that plus a clipboard, or that minus the label.
DriverDesign consequence
① it must not read as a fourth button styleidentical chrome to CopyButton — same border, radius, padding, family, size, and interaction tones. The visual difference between "copy" and "retry" should be the word, nothing else
② it owns no effect (unlike CopyButton)no confirming state, no error state. The caller's handler owns the outcome; a retry's result is a new panel state, not a button state
③ zero chromatic accent (Warp DEC-11, zero-accent)no filled/primary variant. Hover and focus are ink-toned; ok/warn stay reserved for status
④ calm, dense panel (data-ink-first)hairline border at rest and nothing else — the border is what makes a bare word read as a button, and it is the whole of the chrome
⑤ touch target (WCAG 2.5.8)min-height:24px — the floor IconButton cites. Padding, not margin: the whole box is interactive
⑥ its most common host is a failure statemust survive being the only interactive element on screen, next to warn-toned text, without competing with it — settled in D2

Present because the slot must exist for the shapes to match, documented as rarely earned so it does not become the default.
No primary variant, no filled style. zero-accent leaves nothing to fill a button with — ok and warn are status colours, and a warn-filled "retry" would state that retrying is the danger. Emphasis comes from which actions are offered at all: zone E's eviction case shows only close precisely because retry can never succeed there. Choosing the actions is the hierarchy; painting one of them is not.
No confirming state, no loading state. CopyButton confirms because it owns the clipboard write and nothing else on screen changes. A Button's handler changes the zone — a successful retry replaces the Notice with content, which is the confirmation. A spinner belongs to the zone doing the work, not to the button that started it. Adding either would make this T2.

Five states, and they are CopyButton's five minus confirming and error — the two it owns because it owns the clipboard. Same values throughout; the only deliberate divergence is the rest label tone (ink-body vs CopyButton's ink-mute), argued in anatomy ②.

Forks — settled here, confirm or push back

D1 · chrome — clone CopyButton's box, don't design a new one

settled ✓
Identical border, radius, padding, family and size. Side by side, the only difference is the word — which is correct, because the only difference is the word. A second button box would make the collection teach that copies and non-copies are different kinds of thing.
rejected
A distinct, slightly heavier box so actions read as more consequential than copies. Rejected: it invents a weight hierarchy the rulebook does not have, and every screen would then need to decide which of two boxes an action deserves.

D2 · a button inside a warn Notice stays ink-toned

settled ✓
⚠ trawler is not responding
Ink-toned, unchanged. The warn belongs to the message; the button is the way out, not part of the problem. Keeping exactly one warn element per failure means the eye lands on the sentence first — which is the one that says what happened.
rejected
⚠ trawler is not responding
Warn-toned inside a warn Notice. Tempting for cohesion, but it doubles the alarm and reads as "retrying is dangerous". Also collides with CopyButton's s-error, where warn on a button genuinely means this button failed.

D3 · label tone at rest — ink-body, one notch above CopyButton

settled ✓
ink-body
ink-body. A Button is usually the only way out of the zone it sits in; CopyButton is a convenience beside content that is already readable. visual-weight-follows-goals — weight follows what the zone is for.
rejected
ink-mute
ink-mute, exact CopyButton parity. Simpler rule, and one fewer divergence to remember. Rejected because the panel's only recovery action would then be the quietest text in the zone.
Open for W5: whether a destructive tone is needed later (clear the capture ring, delete a flow). Deliberately not designed here — the app has no destructive action today, and zero-accent means the answer would have to be a word ("clear all"), a confirm step, or a warn carve-out. Designing it against a hypothetical would settle it wrong; recorded so the first real tenant reopens it rather than inventing a variant.

 * @tier T1 — generic action affordance, no business logic

Use / avoid

✅ Use

Any action that needs a word and is not a copy — retry, close, save, submit, and every form or dialog the app grows. This is the primitive IconButton's @avoid already sends you to. Prefer one lowercase verb; the label is the accessible name.

🚫 Avoid

Copy actions — CopyButton owns the clipboard write and the confirm that follows it. Actions whose glyph is unambiguous in place (close ×, save ↓ in a dense bar) — IconButton is more compact and already the convention there. Reaching for emphasis: there is no primary variant, so express importance by offering fewer actions, not louder ones. And never warn-tone it inside a warn Notice (D2).

Off-scale, disclosed: py-[3px], px-[9px], gap-[5px] and the 11.5px label are below spacing-scale's 8px floor and off the type scale. They are not a new liberty — they are CopyButton's confirmed values, cloned deliberately per D1, and the same contradiction finding 14 already records. Named here so a new component does not quietly enlarge the breach: W6 settles the floor, and this file moves with CopyButton, never independently of it. The one value chosen rather than inherited is min-h-6 (24px) — a WCAG floor, not a spacing choice.
