DurationText T1

A flow's elapsed time — formats a raw duration (unit prop, default ms) to a human-readable string and holds its column slot blank while the flow is still in-flight.

States

327 ms
fast — below 1 000 ms; mute tone, integer ms. No tinting — calm palette rule
1.8 s
slow — 1 000 ms and above; mute tone, one decimal in the scaled unit (s / min / h / d). Same visual tone as fast — the user reads the number, not a traffic light
000 ms
pending / in-flight — value === null; invisible fixed-width placeholder holds the slot. No "…" spinner — calm; the value arrives when the flow completes
Deliberate non-states:
  • No hover / focus / active. DurationText is read-only — it carries no interaction affordance and owns none of those states.
  • No live-ticking counter. The registry seed explicitly warns against a live counter while in-flight — calm; the slot stays blank. A real-time elapsed ticker creates churn re-renders for zero debugger value; the captured value is what matters.
  • No empty state. A null value is the pending state, not an error. There is no condition where the component is rendered with no valid slot.
  • No error / failed state. Duration is a derived field; if the flow failed to complete, duration_ms stays null and the pending state applies.

Forks — settled here, confirm or push back

D1 · unit strategy settled: largest unit ≥ 1 — ms / s / min / h / d, one decimal
999 ms→999 ms  ·  1000 ms→1.0 s  ·  60000 ms→1.0 min  ·  5400000 ms→1.5 h

Chosen: the largest unit that keeps the value ≥ 1, always one decimal in the scaled form. The capture granularity is wall-clock milliseconds — not sub-ms. Showing "1 842 ms" above 1 s (or "127.4 s" above a minute) forces mental arithmetic; the scaled read is the natural one. One decimal (not two) because the proxy does not claim sub-100 ms precision — .toFixed(1) is the honest precision. Extended past s on review (manager): long flows — streaming, SSE, large exports — are real in a debugging proxy and the same arithmetic burden applies at every rung.

alt: always ms rejected
1842 ms→1842 ms

This is what ships today (flow.ts:50). "1842 ms" vs "327 ms" requires the eye to parse digit-count before magnitude — that is the shipped regression this component fixes.

alt: two decimals (1.84 s) rejected
1842 ms→1.84 s

Claims 10 ms precision the proxy does not guarantee. Wall-clock capture via tokio adds overhead that can vary by tens of ms. Two decimals is false precision.

D2 · fast/slow tinting settled: no tinting
327 ms
1.8 s

Both fast and slow render in mute tone. Warp's zero-chromatic-accent rule: ok/warn are reserved for status outcomes (HTTP 2xx vs 4xx/5xx) — the one exception the proxy needs. Tinting duration "slow = warn" bleeds the warning signal into an informational datum. The user reads the number.

alt: warn for slow (≥ 1 s) rejected
327 ms
1.8 s

The threshold that makes a request "slow" is application-specific — this component cannot know it. Hardcoding 1 s as the warn boundary is a design judgment that belongs to the screen, not the primitive. If the product ever adds configurable SLO thresholds, a T2 wrapper handles the mapping.

D3 · pending display settled: invisible fixed-width placeholder
000 ms
(no visible text — slot held)

Invisible placeholder string "000 ms" holds the column width. Transparent text, not empty string. The list row grid does not reflow when the response arrives and fills the slot.

alt: "…" pending indicator rejected
…

"…" is the StatusPill's in-flight indicator (status unknown), which is a different semantic — the status is unknown until the response arrives. Duration unknown is not the same as status unknown; conflating the two makes the list noisier. StatusPill shows "…"; DurationText holds blank.

alt: empty (collapse the slot) rejected

This is what ships today (flow.ts:50 returns ""). The duration column collapses to zero width for in-flight rows and then widens — the row reflows. In a virtualised list (FlowList.tsx uses @tanstack/react-virtual with ROW_HEIGHT = 30) this causes a height recalculation. Fixed-slot avoids it entirely.

D4 · input unit settled: unit prop, default "ms" (revised on review)
value 90, unit "s"→1.5 min  ·  value 250→250 ms

Chosen: value + optional unit ('ms' | 's' | 'min' | 'h' | 'd', default 'ms'). Manager decision, revising the first draft's ms-only stance. Input normalizes to ms at the prop boundary (one multiplication) before the single format path runs — the input unit never picks the display unit, the ladder does. The 'ms' default keeps both current tenants unchanged: they keep passing duration_ms as-is.

alt: ms-only input rejected — overruled in review

The first draft settled ms-only because both tenants pass duration_ms straight from the API types and no other unit exists in the system today. Review requires unit support for future callers; the optional prop costs one lookup-and-multiply and leaves existing call sites untouched.

 * @tier T1 — duration→human formatting only, no business logic
 * @anatomy right-aligned muted numeric text, tabular-nums, mono · input normalized to ms (unit prop, default "ms") · unit scales: integer ms below 1 s, one decimal in the largest unit ≥ 1 above (s / min / h / d) · invisible fixed-width placeholder while in-flight

Use / avoid

✅ Use

Any place a flow's elapsed time appears: the list duration column, the detail panel identity bar. Pass duration_ms directly from the API type.

🚫 Avoid

A live-ticking elapsed counter while the flow is in-flight — DurationText is calm. Tinting by speed threshold — that is a T2 wrapper concern. Rendering arbitrary non-flow durations that have different precision semantics.
