KeyValueRow T1

One wire key/value pair — muted name, mono value; the value is a CopyText: click grabs it whole, drag-select still takes a part.

Component design · confirmed 2026-07-23 · review round 1 addressed · E-DFLOW.W2 · T3 (docs/work/components/) · registry: W2 seed · was: HeaderRow

Identity & frame

Why it exists: without a shared component, the name/value visual contract (fixed column, wrapping value, typography split) drifts across every callsite — and every callsite re-decides how a value gets copied. KeyValueRow pins both: the display:contents grid shape that already ships (FlowDetail.tsx:23) and one grab contract for values — whole via a CopyText click, partial via native selection. Named generically (review 2026-07-23, was HeaderRow): the same row serves headers, trailers and decoded form fields.
TierT1 Primitive — display + value click-copy via CopyText, no business logic → in the collection

Deliberate non-states:
  • No row hover stripe. The value cell's hover is CopyText's, scoped to the cell; a row-wide tint would fire on every row as the user drags to select — visual noise across 30+ rows, and there is no per-row tint in the zero-chromatic-accent palette (frame ⑤). Fork D3 settles this explicitly.
  • No row focus state. The value cell is CopyText's tab stop (role="button", its own focus ring); the row and name cell add none.
  • No empty / error state. A row with an absent value is not rendered — the parent (HeaderTable) decides when to show "none"; KeyValueRow never renders a missing value.
  • No disabled state. The row is always either shown or absent; there is no partially-available row.

/**
 * KeyValueRow — one wire key/value pair; muted name, value is a CopyText (click copies whole, selection stays native).
 * @tier T1 — display + value click-copy via CopyText; no business logic
 * @anatomy two-column grid (display:contents inside parent): name (muted, nowrap, mono, inert) · value (CopyText: body tone, break-all, mono, never truncated)
 * @use any wire key/value line: request/response headers, trailers, decoded form fields
 * @avoid editable forms (that is Field) · data needing sort/filter · standalone full-value fields with no name column (bare CopyText)
 * @states rest · hover/focus/confirming on the value cell (CopyText's states) · drag-selecting (native; the guard fires no copy)
 * @madeof CopyText (value cell)
 */

Use / avoid

✅ Use

Any wire-level name/value line: request headers, response headers, HTTP trailers, decoded form body fields. Three or more of these in a block → HeaderTable wraps them with the parent grid and its copy-all action.

🚫 Avoid

Editable key/value pairs — that is Field. Data that needs sorting or filtering — KeyValueRow has no interaction surface beyond the value copy. A standalone full-value field with no name column (URI, flow id) — that is a bare CopyText. Single label/value in UI chrome (non-wire) — plain styled spans are cheaper.
