TonedText T1

A short value or message carried in one of three semantic tones — the primitive two contracts already name, the roster never had, and the app has been shipping under another component's name.

Identity & frame

Why it exists: this is not a proposal — it is a dangling contract. StatusPill's @madeof line reads TonedText, and its @avoid routes callers away by name and tier: "a toned value that is not an HTTP status — use TonedText (T1)". Fork D4 recorded the split and promised "registry follow-up on confirmation: add TonedText under T1". The confirmation landed; the row did not. Two independent runs then hit it from opposite directions — run #2 by reading StatusPill, run #3 by needing it three times in the zone that carries a screen's whole verdict. A contract that names a component the vocabulary lacks is worse than a gap: it reads as available.

DriverDesign consequence
① it must know nothing (T1, and the whole point of D4's split)no mapping, no formatting, no null handling, no default tone. Tone is required and passed in; children render as given. Every branch a caller might want belongs in the T2 above it
② the three tones are the app's existing vocabulary, not a new oneok · warn · muted — the same StatusTone the shipped code declares (flow.ts) and the same StepTone the setup domain returns (setup.ts:189). One union, three members, already in two places; this component does not widen it
③ zero chromatic accent (Warp DEC-11, zero-accent)ok and warn are the scheme's two sanctioned exceptions; muted is ink-family, not chromatic. Three tones is the ceiling — a fourth would need DEC-11 reopened, not a prop added
④ colour is never the only channel (colour-plus-text)the component cannot satisfy this alone — it renders whatever text it is handed, in a tone. The second channel is the caller's: StatusPill's text is the status code, StatusLine's is a glyph + words. Stated in @avoid rather than enforced, because a T1 that inspects its children is not a T1 (fork D2)
⑤ its tenants sit in dense scan columnsfont-mono + tabular-nums, inherited size. Tabular figures keep a status column's digits aligned down a list; mono keeps a value from reflowing when it changes. Both are shipped values (components.tsx:25), not new choices
⑥ pure display — it is never the interactive thinga <span>. No hover, focus, or active states; no handler prop. When a toned value must be clickable, the affordance wraps it (CopyText, Button) — the tone does not become a button

A helpful default here would be wrong in one of the two tenants and unremovable in both.

States

200tone: ok
ok — text-ok #4cc38a. The positive outcome; DEC-11's first sanctioned exception
404tone: warn
warn — text-warn #e5484d. Something needs attention; DEC-11's second
301tone: muted
muted — text-ink-mute #aea69c. Neutral, unknown, or in-flight. Ink-family: costs no colour
Three states, and every one of them is its tone prop — that is the whole state machine. Deliberately absent:
  • no interaction states (hover · focus · active · disabled) — a <span> is not focusable and owns no handler (driver ⑥). A toned value that must be clicked is wrapped by CopyText or Button, which bring their own five states.
  • no empty state — children are required. A caller with nothing to show renders nothing, or renders its own placeholder: StatusPill's "…" for a pending status is StatusPill's text, passed in as children.
  • no in-flight state — "waiting" is a muted tone plus whatever the caller writes ("…", ⟳ Installing…). Giving the primitive a spinner would put timing logic in a T1.
  • no transition — the tone switches instantly. A fading status is a status you can misread mid-fade, and DurationText's @avoid already bans live animation in a scan column for the same reason.

/**
 * TonedText — a short value or message in one of the app's three semantic tones; the tone channel with the meaning removed.
 * @tier T1 — tone in, text in, span out: no mapping, no formatting, no state. The base StatusPill and StatusLine are made of
 * @anatomy inline mono span with tabular-nums at inherited size (components.tsx:25) · tone → text-ok / text-warn / text-ink-mute, a three-key lookup and nothing else · children rendered as given · no background, border, radius, padding, role or title

 * @madeof —

Use / avoid

✅ Use

Any short value whose meaning is carried by tone and which is not an HTTP status: a precondition verdict (StatusLine's glyph + phrase), a toned count, a health word. Pass a resolved tone and the text; the component adds a colour and a mono frame, nothing more. Also use it as the base when building a new T2 that owns a mapping — that is what StatusPill does, and the reason this primitive exists.

🚫 Avoid

An HTTP status — StatusPill owns 2xx/4xx/5xx, the "…" for pending, and the reason phrase. A toned sentence, especially with an action beside it — that is Notice (Inter, secondary line, action slot). Colour as the only signal: pair the tone with a glyph or a word, per colour-plus-text (D2 — stated here, enforced by review). Anything interactive: wrap it in CopyText or Button rather than growing states here. And never re-resolve a tone at a call site that already has a T2 for it.
