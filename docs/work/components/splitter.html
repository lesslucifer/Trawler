Splitter T1

A line between two zones that the user drags, or steps from the keyboard, to size one of them between two bounds.

Component design · 2026-11-03 · Trawler · status: draft, awaiting confirmation · proposed by the splitters' design run (E-PANELS.W2) · built by E-PANELS.W3 · retires into the TSDoc on build (DEC-16)

Identity & frame

Without it every resizable split repeats the same pointer capture, clamp, key handling and ARIA by hand, and one of them is bound to drop the keyboard path.

Anatomy

#PartSpecWhy
1line1 px, bg-hairline at rest, bg-ink-mute when active. Along the split's whole lengthit replaces the border the two zones already shared, so at rest the screen looks unchanged
2hit bandthe line plus grip-reach (4 px) on each side, transparent, above both zones (z-sticky). The cursor is col-resize or row-resize9 px is reachable and still covers no control in either zone. Both zones keep at least 16 px of padding
3focus ringoutline-focus outline-ink-mute outline-offset-focus-inset on the band, keyboard focus onlythe ring every focusable member carries, kept inside the band so neither zone clips it

A column handle is the same component with the gap between two label cells as its band (12 px, w-3), and its line is only as tall as the label row.

Behavior

Anatomy is what you see; behavior is what it does.

RuleExampleSpecWhy
dragpane 520 → drag 40 px left → 560pointer capture on press. value = start + dir × Δpx × perPx, clamped. The whole document shows the resize cursor and selects no text until releasestart-relative, so a pointer that overshoots a bound and comes back picks up where it crossed
directionsplitter A: right = narrower panedir: +1 when moving along the axis grows the value, −1 when it shrinks itthe value is the caller's zone size, whichever side the zone sits on
keys← on splitter A → pane +8the arrows along the axis move the line 8 px, with Shift 48 px. Home goes to min, End to max, Enter calls onResetthe arrows are spatial (the line goes where the arrow points); Home and End follow the value, as ARIA's separator does
resetdouble-click → 520double-click or Enter calls onReset. The caller supplies the defaultQ6
commita drag of 300 moves → 1 writeonChange on every move; onCommit once on release, a key step or a resetthe caller saves on commit only, never mid-drag
bounds movewindow shrinks under a pane at maxa max below value renders at max and does not call onChangethe clamp changes what is shown, never what is saved (E-PANELS expected result 6)

Use / avoid

Use

A boundary the user may move, where both sides keep a minimum and the value is saved by the caller: the list/pane split, the headers/body split, a fixed column's boundary.

Avoid

Collapsing a zone (closing the pane is deselect the flow) · a boundary nobody sizes, which stays a border-hairline · a value with known options, which is SegmentedControl or Select.
