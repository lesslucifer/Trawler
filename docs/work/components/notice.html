Notice T1

One sentence explaining why there is nothing to show, why something failed, or that a zone is working — with the action that actually helps, when one exists.

Identity & frame

Why it exists: the roster has no absence/failure renderer, yet two confirmed components already draw one privately and disagree about it — HeaderTable's .ht-none is Inter 12px upright, BodyViewer's .body-pane .notice is mono italic. Every flow detail panel shows both at once. Run #2's failure state would have made a third private copy, which is what turned a styling wart into a component proposal: a third copy settles nothing, and the fourth is already implied.
TierT1 Primitive — renders a sentence at a tone; owns no domain knowledge → in the collection
TenantsHeaderTable empty + pending · BodyViewer's five absences (incl. the W5 fetch-failed state) · the flow detail panel's three load failures (zone E) · the setup screen's capture-is-working zone (tone="ok", D4) · every future "nothing here / it broke / it is working" surface
Exists todaytwice, privately and inconsistently: .ht-none (HeaderTable) and .body-pane .notice (BodyViewer) — marked CONFLICT: in specimen.css
Made ofButton (T1) in the optional action slot — nothing else. Sibling of neither button primitive: Notice is a message that may carry an action, not an action.
DriverDesign consequence
① one renderer, three tones W5 · D4tone="mute" (absence — normal, expected) · tone="warn" (failure — something broke) · tone="ok" (a standing positive outcome — the zone is working). Not a fourth: transient confirmations of an action still belong at their control (confirm-at-point), and a toned value is TonedText's job, not a sentence's
② it renders a sentence, it does not decide whichno reason enum, no built-in copy. The caller passes words. A component that owned the wording would need a case per absence and would still be wrong for the next one
③ absence ≠ instruction (empty-states-orient, run #2 finding 16)the action slot is optional. "not captured — too large" has no next action, and inventing one is a lie
④ tone is never the only channel (colour-plus-text)warn carries ⚠ and ok carries ✓, each and its toned text; the sentence itself names the failure or the outcome. Remove the colour and nothing is lost. Mute carries no glyph — absence is the default, not a signal
⑤ it is a sentence, not a card (data-ink-first)no border, no background, no panel chrome. It sits inside whatever zone already has an edge
⑥ calm, lowercase, blames nobody (calm-microcopy)the component enforces nothing about wording, but the specimen is the reference the tenants copy

Forks — settled here, confirm or push back

D1 · family — Inter upright, not mono italic

settled ✓
no response yet
Inter, upright. mono-for-wire-data gives mono to bytes that crossed the wire; a notice is chrome about their absence. Inside a body pane the switch is also the clearest possible signal that what you are reading is not the body.
rejected
no response yet
Mono italic (BodyViewer's current drawing). Keeps the pane's baseline grid, but makes the panel show two absence families at once and leans on italic mono at 12px — the least legible pairing on the surface.

D2 · scope — one component for absence AND failure, not two

settled ✓
empty body
⚠body unavailable
One component, tone prop. They are the same shape — a sentence, an optional cause, an optional way out — and the boundary between them moves: "not captured" is an absence, "could not load" is a failure, and BodyViewer's fifth state sits between. Two components would force each tenant to pick, and finding 24 is what happens when tenants pick.
rejected
EmptyState + ErrorState
Two components. Reads tidier in a roster and is how most systems do it. Rejected: it duplicates the entire anatomy for one changed colour, and the first component to need "absence, but you can retry" (BodyViewer's fifth state) has to choose a parent arbitrarily.

D3 · the action is a slot, not an onRetry prop

settled ✓
⚠could not load this flow — 500
action?: ReactNode. The three zone-E failures need close / retry / both, chosen by why the fetch failed — knowledge the panel has and this primitive must not. A slot also keeps Notice free of any Button-specific API.
rejected

Named handlers. Guarantees consistent button order and wording, which is real. Rejected because it hard-codes the two actions we happen to need today, and the third tenant either adds a third prop or renders its own row anyway.

Three tones: ok · mute · warn. ok carries a ✓ glyph on the same rules as warn's ⚠ (same tone as the text, aria-hidden, the sentence carries the meaning). Everything else is unchanged — no border, no background, optional detail, optional action.

Why this reverses the "no third tone" driver: the driver said "a notice is never an outcome", which was true of every tenant the read-only panel had. Run #3's setup screen has a zone whose entire content is a standing outcome — capture is working — and the roster has nothing else that renders one. The choice was: permit it here, fork Notice, or invent a badge. Forking duplicates the whole anatomy for one colour, which is the argument D2 already won; inventing a badge adds a component whose shape is identical to this one.
rejected
two tones; positive outcomes have no component
Keep ok out, on confirm-at-point. The rule is real but it is about confirmations of an action — a transient acknowledgement belonging at the control that triggered it, which is why CopyButton owns its own and why this file still @avoids them. A zone that says "capture is working" is not confirming anything the user just did; it is describing the zone's current state, for as long as it holds. That is precisely what Notice is. Rejected because the rule it leaned on does not reach the case.
The boundary that keeps ok from spreading. Three tests, all of which must hold — otherwise the answer is still not Notice:
test✓ Notice ok✗ something else
is it standing, or transient?"trawler is capturing" — true until it stops"copied" after a click → confirm-at-point, the control owns it
is it a sentence about a zone, or a value?a zone that would otherwise be blanka toned value in a row or table → TonedText / StatusPill
is it the zone's whole content?zone C is this sentence and nothing elsea green dot beside a live list → the list's own status renderer

In particular ok does not make Notice a status renderer. Run #3's Frame required zone C to look unmistakably unlike the probe status lines directly above it — a Notice sentence and a StatusLine verdict are different shapes on purpose, and giving Notice a third tone must not blur them. zero-accent is satisfied the same way warn is: ok is one of the two sanctioned status tones in the palette, used transiently or sparsely, never as decoration.

The card this file compiles down to — carried verbatim as the component's TSDoc when built (code-as-truth):

/**
 * Notice — one sentence explaining an absence or a failure, with the action that helps if one exists.
 * @tier T1 — renders a sentence at a tone; owns no domain knowledge
 * @anatomy Inter 12px sentence at ink-mute, ink-warn or ok · ⚠ glyph at warn, ✓ at ok, none at mute (aria-hidden; colour is never the only channel) · optional detail line, always ink-mute, 11.5px · optional action slot 8px below, aligned to the sentence not the glyph · no border, no background, no panel chrome
 * @use any zone that has nothing to show and must say which nothing it is (empty · pending · capped · not captured) · any zone whose load failed · any zone whose whole content is a STANDING positive outcome (tone="ok" — "trawler is capturing") — HeaderTable empty/pending, BodyViewer's five absences, the detail panel's load failures, the setup screen's capture-is-working zone
 * @avoid transient confirmations of an action (use confirm-at-point at the trigger — CopyButton owns its own; tone="ok" is for a STANDING outcome, not an acknowledgement) · a dismissible message (dismissing leaves the blank zone this component exists to prevent) · a toned value rather than a sentence (that is TonedText, or StatusPill for an HTTP status) · a status verdict with a glyph+name+message shape (that is StatusLine) · wrapping a notice in a card or panel of its own
 * @states not interactive — no rest/hover/focus. Renders: mute bare · mute + detail · warn + ⚠ · warn + detail · ok + ✓ · ok + detail · any tone + action slot
 * @madeof Button (T1) — in the action slot only
 */

Use / avoid

✅ Use

Wherever a zone would otherwise be blank, wherever a load failed, and wherever a zone's whole content is a standing positive outcome (tone="ok" — D4). The sentence must name which state this is — "none" (empty set), "awaiting response…" (unfinished), "not captured — too large" (over cap), "no longer captured" (ring eviction) are four different sentences and must never collapse into one. Pass an action only when it can actually succeed.

🚫 Avoid

Transient confirmations of an action — those are inline at their trigger (confirm-at-point), and CopyButton already owns its own; tone="ok" is for an outcome that stands, not an acknowledgement that fades. Anything dismissible or auto-hiding: Notice describes the zone's current state, so hiding it means lying about the zone. A toned value instead of a sentence — TonedText renders that, or StatusPill for an HTTP status; a glyph·name·message verdict is StatusLine's shape, and run #3's Frame requires the two to look unalike. And never wrap it in a bordered card — data-ink-first; it lives inside a zone that already has an edge.
