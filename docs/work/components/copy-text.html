CopyText T1

A displayed value the user grabs whole — click copies it verbatim. Canonical exemplar of the component-design format — new component files copy this structure.

Component design · confirmed 2026-07-22 · updated 2026-07-23: KeyValueRow values adopt CopyText · E-DFLOW.W2 · T3 (docs/work/components/) · registry: W2 seed

Identity & frame

Why it exists: grabbing a whole value is frequent in a debugging proxy (URI → curl, id → grep), and hand-selecting a long wrapped mono string is multi-step and silently error-prone — native selection alone fails that.
TierT1 Primitive — display + click-copy, no business logic → in the collection
Tenantsrequest URI today · flow id, CA fingerprint later (W1's "URI text", generalised) · every KeyValueRow value cell (review 2026-07-23)
Exists todayno — flow.uri is a plain <p> (FlowDetail.tsx:81)
Made of— (shares the ~2 s confirm convention with CopyButton — one shared hook, not composition)
DriverDesign consequence
① whole-value grab is frequentone click copies the entire value
② display must equal payload (trust)verbatim, never truncated — shown and copied are the same string
③ calm, dense panelno added chrome — the value itself is the affordance
④ partial takes must survivenative selection preserved; copy is guarded
⑤ verify without looking awayconfirm inline at the click point, ~2 s

States

rest — body tone, hairline dotted underline
hover — ink, underline strengthens to mute · native tooltip "click to copy" · cursor stays the I-beam (honest: the text is selectable; never pointer — not a link)
focus — 1 px mute outline (zero-chromatic-accent rule: focus is ink-toned, never colored)
confirming — ~2 s; re-click restarts; value change resets instantly (CopyButton convention). Click it — this swatch is the live component, so the state is entered the way a user enters it, not painted on
drag-selecting — native selection wins; releasing a non-collapsed selection fires no copy. Try it — drag across part of the value
No empty / disabled state. A value that is absent isn't rendered as a CopyText — the screen omits the field. Nothing to copy → the component doesn't exist.

The card this file compiles down to — carried verbatim as the component's TSDoc when built (code-as-truth):

/**
 * CopyText — a displayed value the user grabs whole; click copies it verbatim.
 * @tier T1 — display + click-copy, no business logic
 * @anatomy value verbatim (mono, wraps, never truncates) · dotted underline, I-beam cursor kept (un-link-like on purpose) · transient "copied" chip
 * @use full-value fields grabbed whole: the request URI, a flow id, every KeyValueRow value
 * @avoid prose · showing anything but the exact payload · explicit copy actions with their own label (that is CopyButton)
 * @states rest · hover · focus · confirming (~2 s, resets on value change) · drag-select passes through to native selection
 * @madeof — (shares the confirm convention with CopyButton via one hook)
 */

Use / avoid

✅ Use

Full-value fields grabbed whole: the request URI, a flow id, a CA fingerprint. The value cell of every KeyValueRow (headers, form fields — adopted on review 2026-07-23; the selection guard keeps partial takes native). Anywhere the user's intent is "give me exactly that".

🚫 Avoid

Prose. Explicit copy actions with their own label — that's CopyButton. Showing anything but the exact payload.

Template rule — the specimen no longer scales down, because it is no longer re-implemented. It is deleted: the specimen imports the component, so the 2 s timeout, the ok tone swap and the selection guard you exercise above are the shipped ones. The scale-down rule still applies to a component too expensive to instantiate in a doc (a hex grid over a large body), but it is no longer about cost of re-implementation — nothing is re-implemented.
