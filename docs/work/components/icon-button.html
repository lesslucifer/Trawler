No confirming state. IconButton fires a handler — the caller owns the result state. CopyButton has a confirming state because it owns the clipboard write; IconButton delegates everything to the caller. A save action's progress (if any) belongs to its parent screen, not this primitive.
No loading / in-flight state. An async operation triggered by the button (save, export) may need a loading indicator, but that indicator belongs on the parent screen — this primitive stays stateless. Adding a spinner prop would make it T2 (business logic). If a tenant needs it, propose a SaveButton (T2) that composes IconButton.

Forks — settled here, confirm or push back

D1 · hover treatment — ink-toned only, no chromatic ring

settled ✓
→
mute → ink + soft bg wash. Rest is muted, hover shifts to full ink + 7% ink bg — no ring, no color. Consistent with the zero-chromatic-accent rule (tailwind.config.js:5): ok/warn are status colors only.
rejected
ink at rest + accent ring on hover. Introduces chromatic accent that Warp DEC-11 deliberately excludes. The rest-ink approach also makes the glyph always prominent — removes the calm/dense benefit.

D2 · at-rest border — none

settled ✓
no border at rest
Borderless at rest. Background and border appear only on hover/focus. Matches the close × in the shipped header (FlowDetail.tsx:69–76): no border, muted glyph only at rest.
rejected
Hairline border at rest (CopyButton style). CopyButton carries a visible border because its label ("copy") needs the button frame to read as a button. IconButton's glyph is self-contained — the border adds chrome without aiding recognition.

D3 · hit area size — 28 × 28 px

settled ✓
↓
28×28
28 × 28 px default, optional size prop overrides. 28 exceeds WCAG 2.5.8 minimum (24×24) and fits naturally in the sub-bar height — no row height change needed. Overrides must stay ≥ 24 px (the WCAG floor).
rejected
↓ glyph-only (~14px)
Glyph-size target only. The shipped close × at FlowDetail.tsx:69 has no explicit padding — its hit target is the glyph alone. Fails WCAG 2.5.8 and is painful on touch. This design fixes it.
Glyph source — settled by review: the component ships a small named-glyph registry — glyph="close" → ×, glyph="save" → ↓ (Unicode, extended one entry per new tenant) — and children stays the escape hatch for custom nodes (Unicode or SVG). If a project-wide SVG icon system ships later, the registry swaps internally with no API change.

The card this file compiles down to — carried verbatim as the component's TSDoc when built (code-as-truth):

/**
 * IconButton — bare-glyph button; compact affordance for icon-only actions (close, save, collapse).
 * @tier T1 — generic action affordance, no business logic
 * @anatomy 28×28 px hit area by default, size prop overrides (padded beyond the glyph) · glyph from built-in registry (glyph="close"|"save") or custom children · muted glyph at rest, ink+soft-bg on hover/active · 1px mute focus ring (ink-toned, zero chromatic accent) · native title tooltip, defaults to the glyph name
 * @use icon-only triggers unambiguous in place: close ×, save ↓ — wherever the glyph alone carries the action
 * @avoid actions with no fitting glyph (word label carries it better — use CopyButton or a plain button) · primary actions (no visual weight at rest)
 * @states rest (muted glyph, no bg) · hover (ink + 7% bg wash) · focus (1px mute outline) · active (ink + 13% bg) · disabled (35% opacity, not-allowed, no tab)
 * @madeof —
 */

Use / avoid

✅ Use

Icon-only triggers that are unambiguous in place: close ×, save/download ↓, collapse/expand. The glyph must be self-explanatory in context — the tooltip confirms, it does not substitute. Use when the button must be compact (sub-bar, dense header) and a word label would waste space.

🚫 Avoid

Actions with no fitting glyph — use a labelled button or CopyButton instead (the W1 curl lesson: "copy as curl" failed as an icon). Primary actions that need visual weight — a plain styled button or filled button gives more presence. Multiple-state results (clipboard confirm, progress) — those belong to a T2 widget (e.g. CopyButton for copy, a SaveButton for async save) that composes IconButton rather than replacing it.
