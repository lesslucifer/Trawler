Disclosure T1

The collapse primitive — a summary line that reveals a slot. It owns the twist, the target and the keyboard; it decides nothing about what it hides.

Identity & frame

Why it exists: Section's @avoid already routes here — "a Section that needs to collapse (put the disclosure inside the slot instead)" — and names a thing that does not exist, so the instruction currently resolves to "hand-roll it". Which is what happened: three raw <details> in one file (Onboarding.tsx:134, :188, :276), each repeating the same cursor-pointer text-ink-mute summary and each getting the browser's default triangle. The do-nothing answer keeps them, and it fails twice over: the summary styling is copy-pasted three times with nothing keeping it in step, and every one of them inherits a disclosure triangle the app never chose — a piece of chrome from outside the closed vocabulary, invisible to every check because it is a UA default, not a class.
TierT1 Primitive — summary line, twist, target, keyboard, and a slot. No business logic, and it never inspects what it hides. This answers the epic plan's open question: T1, slot-based, the host owns what is inside and whether it starts open
TenantsOnboarding's ManualPanel — the manual-setup fallback, opened automatically when an action fails (Onboarding.tsx:123-139) · "Remove the certificate later" (:188) · "Turn the proxy off later" (:276). Three tenants in one file today, which is what makes it a component rather than a one-off
Exists todayas three raw <details>/<summary> pairs, no shared component. ManualPanel (:123) is the closest thing to one, and it is a screen-local wrapper whose real job is the conditional — collapsed or not at all
Made of— (the leaf). Native <details>/<summary> is the element (fork D1); the twist glyph and the summary chrome are this component's
DriverDesign consequence
① what it hides is secondary, never absentthe summary is always visible and always reads as pressable. progressive-disclosure: the default view is the scan level, depth is one explicit act away — so the closed state must make clear that there is depth, which is what the twist glyph is for
② its host decides the initial state, and sometimes forces it opendefaultOpen is a prop, because ManualPanel opens itself when an action fails (open={state === "failed"}, Onboarding.tsx:167) — the app's one case of a disclosure that reacts to state. The component never derives this
③ the app must own its own chrome (DEC-17)the UA triangle is suppressed and replaced with a › that rotates — a glyph the vocabulary chose. A default nobody picked is the one kind of drift the closed-vocabulary lint cannot see, because there is no class to read
④ zero chromatic accent (DEC-19)the summary is ink-mute at rest and ink on hover — the same two-step ink lift Button and Field use. No colour, no underline, no link styling
⑤ it sits inside a step the user is readingopening pushes content down rather than overlaying — the opposite of Select's popup (whose driver ⑥ says the reverse), because here the revealed content is the next thing to read, not a choice to make and dismiss
⑥ keyboard-complete (keyboard-parity)Enter/Space toggles — the rulebook's "activate the focused element" binding, inherited free from native <summary> (fork D1). Focus stays on the summary through the toggle, so a keyboard user is never dropped into revealed content or out to <body>
⑦ touch target (WCAG 2.5.8)the whole summary row is the target, full width, at min-h-control — not the glyph, and not just the words. generous-targets: the target could be bigger for free, so it is

Boundary — Disclosure vs Section

These are the two "a label above some content" components, and Section's @avoid is the reason this one exists. The line has to be crisp, because reaching for the wrong one produces a screen that looks right and drifts on the next edit.

Disclosure (this)Section
content ishidden until asked foralways visible
the label isa control — pressable, focusablea heading — h2/h3, inert

nestingallowed but unused; no depth cap of its owncapped at two levels (variant="band", never nested)

They compose, and the direction is fixed. Section's @avoid says a Section that needs to collapse puts the disclosure inside the slot — so a Disclosure may live in a Section's content, and a Section must never live in a Disclosure's summary. That keeps the heading outline stable whatever is open: a collapsed Disclosure hides content, never a heading. No edit to Section is needed — its @avoid line becomes true the moment this component exists, which is the whole point of the phantom-redirect class of bug this epic closes.

Deliberate non-states.
  • No disabled. No tenant, and a disclosure that cannot open is content that should not have been rendered. Adding it later is additive; guessing it now is DEC-21's "a mode with no tenant".
  • No empty state. A Disclosure with nothing in its slot is a caller bug, not a state — the host renders no Disclosure at all, exactly as StepList declares for its own empty case.
  • No loading. Its content is passed, never fetched; a host awaiting content renders a Notice in the slot.
  • No overflow cap. Unbounded content is the host zone's to cap (see anatomy 3) — clipping a step list mid-step would be worse than a long page.
  • No transition on the content. B4 — only the twist moves.

Forks — the contested decisions

D1 · Native <details>, or a div + state?

settled — native <details>/<summary>
<details><summary>…</summary> free: focus · Enter/Space · aria-expanded · find-in-page
Every a11y behaviour driver ⑥ needs, correct by construction and impossible to regress. Browsers also expand <details> for find-in-page, so a user searching for a step in the manual panel finds it — a capability a div version silently loses.
rejected — div + useState
<div role="button" tabIndex={0} …> hand-written: keydown · aria-expanded · aria-controls
Why it lost: it buys one thing — a controlled open prop — at the cost of re-implementing four behaviours the platform already has, and B1 shows no tenant wants that prop. The three shipped call sites are all native today and all correct; replacing correct platform semantics with hand-written ones is a regression wearing a refactor's clothes.

D2 · One rotating glyph, or two glyphs?

settled — one glyph, rotated
›closed
›open
The shape is constant, so only the angle carries the state — and the label never shifts, because the glyph's box is a fixed w-glyph either way. One character to render, one transform to animate.
rejected — ▸ / ▾ swap
▸closed
▾open
Why it lost: two glyphs with different advance widths and different vertical centres, so the label nudges sideways and the row's baseline shifts on every toggle. It also cannot transition — the swap is a jump — and it re-introduces the filled triangle that fork D3's whole point is to get rid of.

D3 · Suppress the UA marker, or live with it?

settled — suppress it, draw our own

Its size, colour, gap and shape are decided outside the closed vocabulary (DEC-17) and differ per engine, and no lint can see it, because there is no class to read. It is the cheapest possible drift and the hardest to detect.

Disclosure always discloses. The screen keeps the one line that encodes its rule — "when we cannot automate the step, the manual steps are primary" — which is domain knowledge, not chrome.

Why it lost: it deletes three lines from one screen and buys a component that, in one of its two modes, is not a disclosure at all — no summary, no twist, no toggle. Every reader of the registry then has to learn that "Disclosure" sometimes means "nothing". The right shape for that conditional is an if in the screen, and it is already written.

/**
 * Disclosure — a summary line that reveals a slot; the app's one collapse primitive.
 *
 * @tier T1 — summary chrome, the twist, the hit target and the slot. No business logic, and it never inspects what it hides
 * @anatomy native <details>/<summary> (fork D1 — focus, Enter/Space, aria-expanded and find-in-page come free) · the UA marker suppressed (list-none + ::-webkit-details-marker) and replaced by a › in a fixed w-glyph slot that rotates 90° when open · full-width summary row at min-h-control, ink-mute lifting to ink, wash-hover across the row · the slot adds mt-chrome-y and nothing else — no padding, border, indent or height cap
 * @use any secondary content a screen offers but does not lead with: manual setup steps, a "remove it later" remedy, an advanced block. Pass the label and the content; pass defaultOpen when the host has a reason to start it open
 * @avoid a labelled zone whose content is always visible (that is Section — and a Section that needs to collapse puts one of these inside its slot, never the reverse) · a mutually exclusive view switch (that is SegmentedControl) · a "collapsed or not at all" conditional — Disclosure always discloses; the host branches (fork D4) · a controlled open/onToggle pair: the native element owns the state and no tenant needs to override it (DEC-21) · animating the content height, capping it, or scrolling it — only the twist transitions, and unbounded content is the host zone's to cap · a caller-supplied glyph or variant
 * @states closed (ink-mute, twist 0°) · open (ink, twist 90°, slot in flow — it reflows, never overlays) · hover (wash-hover across the whole row) · focus (the shared 1px ink-mute outline; focus never moves on toggle). No disabled, empty or loading state — an empty slot is a caller bug, and a host awaiting content renders a Notice in the slot
 * @madeof — (the leaf: native <details>/<summary> is the element, the chrome is this component's)
 */

Use / avoid

✓ reach for Disclosure when…
  • content is secondary — offered, not led with (manual steps, a later remedy)
  • you have a short label and a block, and the block should start hidden
  • a Section needs to collapse — put one of these in its slot
✗ reach for something else when…
  • the content is always visible → Section
  • it is a switch between two views of the same thing → SegmentedControl
  • the zone has nothing to show and must say which nothing → Notice
  • you want it to sometimes not collapse at all → branch in the screen (D4)
  • you want it to overlay rather than push → that is Select's popup, a different component and a different driver

One vocabulary gap, and it is W2's to close. The twist needs rotate-90 and transition-transform; ui/tailwind.config.js declares transitionProperty with only colors, and declares no rotate scale at all — and under DEC-17 an undeclared scale means the class resolves to nothing. So rotate-90 and transition-transform are not legal today and neither is a literal an escape can excuse. Blocked-on: W2 adds rotate: { 0: "0deg", 90: "90deg" } and transform to transitionProperty — two named members, exactly the tenants this component needs, per DEC-17's "a value that has no utility needs a named token in the config". Nothing else in this file needs a token that does not exist.
