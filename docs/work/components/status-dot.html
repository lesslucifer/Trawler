Identity & frame

Why it exists: StatusPill's @avoid redirects to it by name — "proxy connection health — StatusDot" — and there is no such component. The do-nothing answer is to let the header keep a hand-rolled tinted <button> (components.tsx:38), and it fails on the thing that makes this element unusual: it is the only control in the app that is simultaneously a status readout and a navigation affordance. Nothing in the registry covers that pairing, and the two halves have contradictory instincts — a status is display (StatusPill is explicitly non-interactive), a nav control is a button. Left hand-rolled, the pairing stays undocumented, and the next person to touch the header has to re-derive why a status is clickable.
TierT2 Widget — it owns the DotStatus→tone map and the DotStatus→title-text map, exactly as StatusPill owns status→tone and its reason phrase. Business logic in, full display out → in the collection
TenantsApp's header, in both phases — the only tenant, and it is on screen 100% of the time the app is open (App.tsx:110 onboarding, App.tsx:139 proven). One tenant, but an unavoidable one
Exists todayui/src/components.tsx:38 — a <button> with a DOT_CLASS record and a title from COPY.dotTitle (onboardingMachine.ts:87). The tri-state semantics, the tone map and the titles are all shipped and all correct; what this design adds is the accessible name, the hit target, and the contract that says why it is clickable
Made ofTonedText is not its base (fork S2) — this renders no text. It is a <button> wrapping a tinted disc; the button chrome is Button's frame="bare" shape="square" shell, the way IconButton composes it
DriverDesign consequence
① it answers "is Trawler working?" at a glance, alwaysit sits first in the header, before the wordmark, in both phases. A 10px disc is the smallest thing that reads as a state light; it is deliberately not a word, because the answer must be readable in peripheral vision without being read
② it is also the only way back into setupit is a real <button> with a hit target far larger than the disc (driver ⑦), not a tinted <span>. This is the pairing the registry has no other case of, and the reason it cannot be StatusPill or TonedText (both non-interactive by contract)
③ three states, and the middle one is not a tonebroken and connected land on warn/ok. checking is not "neutral" — it is "we do not know yet", and DEC-19 grants it no token, so it reads ink-mute. That is the tri-state claim: the state set is connection lifecycle, not severity (see the boundary below)
④ colour cannot be the only channel (colour-plus-text)a 10px disc with no text is colour alone — the rule's plainest violation. So the second channel is mandatory and carried by the accessible name + title, which state the verdict in words: "not capturing yet — click to set up". data-status carries it a third time for tests. This is the component's load-bearing a11y decision
⑤ zero chromatic accent (DEC-19)the three fills are bg-warn, bg-ink-mute, bg-ok — closed-set tokens carrying their fixed meanings. No fourth state, no pulse, no glow
⑥ its meaning must not drift between the two phasesthe same dot, same map, same component in onboarding and in the proven app. The phase resolves the status (dotStatus(), onboardingMachine.ts:62) and the component renders it — the component never reads app state
⑦ touch target (WCAG 2.5.8)the disc is 10px (spinner); the button is min-h-control min-w-control — 24px square, the floor Button, IconButton, Select and Field all cite. The shipped version has no such padding — its hit target is the 10px disc (fork S3)

The tri-state claim — why DotStatus is not StatusTone

The epic plan predicted this is where a rulebook line gets forced, so the claim is argued rather than asserted. Both types have three members and both currently map onto the same three colours — which is exactly why a reviewer should suspect they are the same type wearing two names.

DotStatus (this)StatusTone
membersbroken · checking · connectedok · warn · muted
the axis islifecycle — where a connection has got toseverity — how good an outcome is
orderingtemporal: checking precedes the other two, always. You cannot be connected before you have checkednone — ok and warn are alternatives, not a sequence
the middle member means"not known yet" — a transient that resolves on its own"nothing to say" — a terminal state (a 3xx is muted forever)
can a caller pick one?no — it is derived from the phase by dotStatus()yes — TonedText's whole API is the caller passing a tone
if a fourth arrivesplausible: reconnecting, paused — lifecycle sets grow with the protocolclosed by DEC-19 — a fourth tone is deliberately left for the first tenant to reopen
Verdict: distinct types that happen to share a palette today. The tell is the middle member. checking→ink-mute and muted→ink-mute render identically and mean different things: one says "ask me again in a moment", the other says "this will never be interesting". Collapsing them would make checking a caller-suppliable value, and a caller could then render connected while the app is still checking. Keeping them separate is what makes dotStatus() the single authority — the same reasoning DEC-20 uses to let StatusPill absorb status→display while StatusLine refuses raw inputs.
Proposal — for the rulebook, not for this file to land. The chromatic meanings table maps each token to a fixed meaning and an owning component. If this design is confirmed, ok and warn gain a second owner (StatusDot connection lifecycle) alongside StatusPill/MethodLabel, and ink-mute gains its first entry as the not-yet-known channel. Recorded here as a proposal — the rulebook is frozen input for a run and grows at distillation (DEC-14). The epic's distillation plan already reserves the row.

Behavior — what the parts do

Anatomy is what you see; behavior is what it does. Two of the three rules below are about what the component refuses to know.

phase "checking" → checking
phase "onboarding" → broken
phase "proven" → connected
↑ dotStatus(), onboardingMachine.ts:62
The caller resolves; the component renders
B1 · it takes a resolved status and never derives one
spec
props are status: DotStatus and onClick. It reads no phase, no flow list, no connection count
why
driver ⑥ and DEC-20: the map from app phase to lifecycle state is a function of app state the domain already resolves, so it stays in dotStatus() — the same line StatusLine draws when it refuses raw inputs. What the component does own is the two maps that are pure functions of DotStatus: the fill and the words
"not capturing yet — click to set up"
title · aria-label · data-status="broken"
Three channels for one verdict — only one of them is colour
B2 · the verdict is always in words
spec
every state supplies a phrase, rendered as both title (hover) and aria-label (assistive tech), from COPY.dotTitle. data-status carries the raw state for tests. There is no state without a phrase
why
driver ④ — colour-plus-text binds both surfaces, and a bare tinted disc is the rule's clearest breach. The phrases are already written and already correct (onboardingMachine.ts:87); this design's addition is aria-label, which the shipped version lacks — title alone leaves the button nameless to a screen reader, so today it announces as "button"
"capturing — click to run setup again"
→ clicking a green dot still opens setup
Clickable in every state, including the good one
B3 · it is never disabled
spec
all three states are clickable and dispatch the same event (re-invoke). No disabled state, no state in which the action is unavailable
why
driver ②: it is the only route back to setup, so a state that disables it is a state with no way back. The connected phrase says so explicitly — "click to run setup again", not "capturing" alone — because labels-add-context wants the label to carry the fact the context does not state, and "this green thing is still a button" is exactly that fact

States

not capturing yet — click to set up
broken — bg-warn. Setup incomplete, or capture has never been proven
checking…
checking — bg-ink-mute. Transient: the launch self-test is still resolving. Not a tone (see the claim above)
capturing — click to run setup again
connected — bg-ok. A decrypted HTTPS flow has been seen
hover
hover — bg-wash-hover behind the disc. The disc's own fill never changes on hover
focus
focus — the shared 1px ink-mute outline at 2px offset, inherited from Button's shell
Deliberate non-states.
  • No disabled. B3 — the only exit from a broken setup must never be closed.
  • No pulse or blink on checking. motion-informs: the animation would carry no information the muted fill does not, and the state typically lasts one request. A spinner here would also read as a fourth thing, next to StatusLine's real in-flight spinner.
  • No loading or error state of its own. It renders a status; failing to determine the status is what checking already is.
  • No fourth state. reconnecting/paused are plausible futures (see the tri-state table) but have no tenant, and DEC-21 is explicit that a mode with no tenant is deferred, not built.
  • No count, no badge. The flow count lives beside it as its own text (App.tsx:178); attaching it here would give one element three jobs.

Forks — the contested decisions

S1 · One element for status and navigation, or two?

settled — one element, both jobs
Trawler
The thing that tells you setup is broken is the thing you press to fix it. One target, zero extra chrome, and the affordance is discoverable exactly when it is needed.
rejected — a dot plus a settings button
Trawler
Why it lost: two elements for one concern, and the gear is dead weight in the connected state that is 99% of the app's life. It also separates the alarm from its remedy — data-ink-first: strip the gear and nothing is lost, because the dot can carry the press.

S2 · Is it made of TonedText?

settled — no; a bare button + a tinted disc
TonedText renders text in a tone — "tone in, text in, span out". This renders no text at all, and its colour is a background, not a color. Composing it would mean passing an empty string and overriding the one property it exists to set.
rejected — TonedText, like its two siblings
●
Why it lost: StatusPill and StatusLine are both @madeof TonedText, so the symmetry is tempting. But rendering the disc as a ● glyph makes its size a function of the font, its vertical alignment a per-browser accident, and its shape a typeface's opinion. The disc is a shape, and TonedText's tone maps to text-* — a channel this component does not use.

S3 · Keep the shipped 10px hit target?

settled — 24px button around a 10px disc
24 × 24
The disc stays 10px — driver ① wants it small. The button grows to the app's 24px floor with transparent padding, exactly as IconButton does. generous-targets: the target could be bigger for free, so it is.
rejected — the disc is the button (ships today)
10 × 10
Why it lost: this is components.tsx:38 verbatim — a 10px target where the app's own floor is 24px, failing WCAG 2.5.8 by 14px on the one control that must never be hard to hit. W2 must not copy the shipped class string.

S4 · title only, or an accessible name too?

settled — both, same phrase
title="Not capturing yet — click to set up" aria-label="not capturing yet — click to set up"
Sighted hover and assistive tech get the same verdict from the same source. Driver ④'s second channel only counts if it reaches everyone.
rejected — title alone (ships today)
title="Not capturing yet — click to set up" announced as: "button"
Why it lost: title is not reliably an accessible name and is unreachable by touch and keyboard. An empty button whose only content is a coloured div announces as "button" — colour-plus-text satisfied for sighted users and breached for everyone else. This is a real defect in the shipped component, found by this design.

/**
 * StatusDot — capture health as one disc, and the app's only way back into setup.
 *
 * @tier T2 — owns the DotStatus→fill map (broken=warn, checking=ink-mute, connected=ok) and the DotStatus→phrase map that gives every state its words; status in, full display out. The phrases come from COPY.dotTitle, the status from dotStatus() — it derives neither
 * @anatomy a 24×24 bare-square button (Button's frame="bare" shape="square" shell — the app's hit floor, WCAG 2.5.8) wrapping a 10px rounded-full disc (spinner token) whose background carries the state · the disc is aria-hidden; the button's aria-label and title both carry the verdict in words · data-status carries the raw state for tests
 * @use the app header's capture indicator — the single tenant, on screen in both the onboarding and proven phases. Pass a resolved DotStatus and the handler that re-invokes setup
 * @avoid an HTTP status (use StatusPill) · a precondition's verdict with a name and message (use StatusLine) · a toned value that is text (use TonedText — this renders a shape, and its colour is a background, not a color) · deriving the status from app phase inside the component (dotStatus() owns that, DEC-20) · a caller-supplied phrase, tone or size — each is the component's, per state · disabling it in any state: it is the only route back to setup, so a disabled dot is a dead end · rendering it as a bare span or a ● glyph, which loses the hit target, the accessible name, or both
 * @states broken (bg-warn — setup incomplete or capture never proven) · checking (bg-ink-mute — the launch self-test is still resolving; a lifecycle transient, NOT StatusTone's terminal muted) · connected (bg-ok — a decrypted HTTPS flow has been seen) · hover (wash behind the disc; the fill never changes) · focus (the shared 1px ink-mute outline). No disabled, loading, error or fourth state, and no pulse on checking — motion would carry nothing the fill does not
 * @madeof Button (T1) with frame="bare" shape="square" — element, focus ring, radius, hit floor and keyboard come from the shell, the way IconButton composes it. NOT TonedText, unlike its two status siblings: there is no text to tone
 */

Use / avoid

✓ reach for StatusDot when…
  • you are rendering the app header's capture indicator — the one tenant
  • you have a resolved DotStatus and the handler that re-opens setup
✗ reach for something else when…
  • it is a flow's HTTP outcome → StatusPill
  • it is a precondition with a name and a reason → StatusLine
  • it is a short toned value → TonedText
  • a zone has nothing to show and must say which nothing → Notice
  • you want a second dot somewhere else → there is exactly one; a second means the state set has a new axis, which is a propose, not a reuse
