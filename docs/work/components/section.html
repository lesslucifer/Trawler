Section owns no interactive states. No hover, focus, active, disabled, loading, or empty state of its own — the seed card explicitly records "states: none of its own". Any state visible inside a Section belongs to its child. This is what it means to be layout chrome.
No collapsible state. The HeaderTable's "collapsible headers" disclosure (from the W2 roster seed) is owned by HeaderTable, not by Section. Section never collapses — if a group of content needs to collapse, a disclosure element wraps that content inside the slot. Section is unaware of it.

F2 · last-Section hairline settled: consumer removes it

Every Section carries border-b; the consumer (the scroll-container parent) uses overflow:hidden on the outer shell to clip the last hairline, or the last Section is passed a prop or class override. The simplest contract: Section always has the separator, and the outer panel clips or the last child overrides. The shipped code's outer overflow-auto div serves as the clip boundary; the last border-b disappears at the scroll edge.

alt: Section auto-detects last sibling rejected

Using :last-child CSS or JS to suppress the bottom border internally. Fragile if a sibling is conditionally rendered and becomes last; the component would need to know about its siblings' rendering — that is coupling that belongs outside.

F3 · heading element settled: <h2> inside <section>
Request

<section> root + <h2> heading. Each Section is a landmark region; a screen-reader user can navigate between panel zones by heading. The shipped code uses <section> + <h2> (FlowDetail.tsx:7–12). Heading level is fixed at h2 — Section always sits one level below the panel's h1-level identity.

alt: heading level as prop rejected

A level prop (h2/h3/h4) would be needed only if Sections nested — which they must not (see No nesting rule and seed card avoid line). YAGNI: the constraint removes the need for the prop.

/**
 * Section — titled grouping container; heading + spacing + hairline separation, no logic.
 * @tier T1 — layout chrome only; heading typography and hairline rhythm would drift per call site without it
 * @anatomy uppercase-muted heading (Inter xs, letter-spaced) · transparent content slot (no overflow, no layout) · hairline bottom border between siblings
 * @use every labelled zone of a detail or settings screen: request, response, headers, body panels
 * @avoid unlabelled grouping (plain spacing does it) · nesting a Section inside another Section · a Section that needs to collapse (put the disclosure inside the slot instead)
 * @states none of its own — all interactive states belong to slot children
 * @madeof —
 */

Use / avoid

✅ Use

Every labelled zone of a detail or settings screen: "Request", "Response headers", "Body", any titled region where the heading + hairline + padding rhythm must hold consistently across sibling zones. Current tenants: the five <Section> calls in FlowDetail.tsx:80–116.

🚫 Avoid

Unlabelled grouping — plain py-3 spacing does it. Nesting a Section inside a Section — the heading hierarchy collapses and padding doubles. Any group that needs to collapse or toggle visibility — put the disclosure element inside the content slot instead; Section itself never collapses. A page-level heading — <h1> belongs to the panel's identity bar, not here.
