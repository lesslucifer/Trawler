CopyButton T1

A labeled button that copies a derived, invisible payload and confirms inline — the payload is not shown; the label says what you will get.

Component design · confirmed 2026-07-23 · 2026-07-22 · E-DFLOW.W2 · T3 (docs/work/components/) · registry: W2 seed

States

Deliberate non-states. No loading/in-flight state — the write is synchronous enough that a spinner would flash. No empty state — disabled covers "nothing to copy"; the component is not rendered when the section is absent.

Forks — settled here, confirm or push back

D1 · confirm form: label-swap vs chip settled: label-swap
click ▸ ~2 s ▸

Label-swap wins: the shipped FlowDetail.tsx:101 pattern already uses copied ? "copied" : "copy" — the label IS the confirm slot. Zero reflow: the button width stays fixed at the longer of "copied" / original label (pick the wider, pad the narrow). The button shape never changes, the confirm lands exactly where the click was.

CopyText uses a chip — why not here? CopyText's confirm chip appends after the value text; removing it and swapping the value would hide what was just copied — that's why CopyText settled on a chip (CopyText fork D2: "swapping the value hides what was just copied"). CopyButton's value is NOT displayed, so the label-swap has no "hiding" cost — swapping "copy curl" → "copied" loses nothing, because the curl was never the button's text. The chip would add DOM outside the button boundary; the swap is cleaner here.

alt: chip after the button rejected
copied

Appending a chip outside the button is DOM outside the hit zone — reflows the sub-bar, adds a second element to manage, and makes the button narrower than needed while the chip floats. The label-swap keeps everything inside the button.

alt: toast rejected

A distant toast breaks the "verify without looking away" frame driver. Not considered further.

D2 · icon: include or omit settled: optional, caller-controlled

The curl use-case in W1 explicitly dropped glyph-only because no glyph fits the action unambiguously (registry seed, IconButton card). With the label mandatory, a leading ⧉ is additive chrome — acceptable but not required. Caller decides; label-only is the default.

alt: icon-only (no label) rejected

The payload is invisible — the label is the only payload identifier. Icon-only collapses that identity. W1 lesson: "actions with no fitting glyph — the word carries it instead". CopyButton must always show the label.

Exception — visible payload (manager review 2026-07-23, BodyViewer): when the payload is rendered directly adjacent to the button (BodyViewer's pane shows exactly what copy delivers), the invisible-payload premise doesn't hold, and icon form — ⧉ with mandatory tooltip + aria-label, confirm as a ✓ ok-tone glyph swap — is allowed (body-viewer.html anatomy ④).

D3 · payload prop shape: value vs getPayload settled: value (eager) is the default; getPayload (lazy) optional

The shipped curl case pre-computes curl at render time (FlowDetail.tsx:51 — const curl = toCurl(flow)) and passes it directly. Most uses will follow this pattern. A lazy getPayload: () => string escapes expensive computation on every render without breaking the reset-on-change rule (key the reset on a stable identity token instead). Both are acceptable; value is the primary API, getPayload is the escape hatch.

D4 · scope: copy-specific vs generic "flash a state" button settled: copy-specific; the generic mechanic is the shared hook

(Manager review 2026-07-23: the temporarily-switch-state logic could serve non-copy buttons — make the component generic?) The generic piece is real: timed state swap, timer restart on re-trigger, reset on input change, width stability, aria-live. But that piece is already factored as the shared confirm hook CopyText uses (Made of) — the hook IS the generic layer. What sits above it is copy-only and would not survive generalisation: the clipboard write, the "copied"/"failed" vocabulary, and the payload-transparency rules (label names the invisible payload, never icon-only, stale confirm resets on payload change). A generic component could not mandate any of those — each caller would reinvent them, which is exactly the ad-hoc drift frame driver ② exists to prevent.

alt: generic FlashButton (onAction + flash labels); copy = one caller deferred — no non-copy tenant

Every tenant today is a copy action (Identity § Tenants). Extracting a generic FlashButton now is speculative generality with a real cost (weaker contract, per-caller conventions) and no user. The escape path stays cheap: when a non-copy transient button appears, lift the shell + hook into FlashButton and make CopyButton its thin wrapper — no caller changes, no design rework here.

The card this file compiles down to — carried verbatim as the component's TSDoc when built (code-as-truth):

/**
 * CopyButton — labeled button that copies a derived payload and confirms inline; payload is not displayed.
 * @tier T1 — clipboard write + timed label-swap, no business logic
 * @anatomy compact bordered button · label (names payload) → "copied" (ok) or "failed" (warn) for ~2 s → reverts · optional leading icon (label always present — icon-only allowed only when the payload is rendered adjacent, e.g. BodyViewer: ⧉ + tooltip, ✓ confirm — fork D2)
 * @use any one-click copy affordance where the payload is derived/invisible: copy-as-curl, copy body, copy all headers (payload serialised by HeaderTable)
 * @avoid showing a value the user grabs verbatim (that is CopyText) · icon-only form · anything that is not a copy action · serialising the payload itself (the parent owns press logic)
 * @states rest · hover · focus · active · confirming (~2 s, restarts on re-click, resets instantly on payload change) · error ("failed", warn tone, ~2 s, same timer rules) · disabled (nothing to copy)
 * @madeof — (generic ~2 s flash mechanic in one shared hook with CopyText; copy contract lives here — fork D4)
 */

Use / avoid

Use

Any one-click copy where the payload is derived or invisible: copy-as-curl (panel zone B) · copy body (BodyViewer) · copy all headers (HeaderTable sub-bar — HeaderTable serialises the payload, this button just writes it). Anywhere the label names the payload class and the value is not shown verbatim.

Avoid

A value that IS displayed verbatim and the user grabs whole — that is CopyText (the displayed string is both the affordance and the payload). Actions that are not clipboard writes — use IconButton or a plain button. Never icon-only when the payload is invisible — the label is load-bearing for payload identity (icon form is allowed only when the payload is rendered adjacent — fork D2 exception, BodyViewer).
