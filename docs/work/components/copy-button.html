CopyButton T1

A button that copies a derived payload and confirms inline. Labelled by default — the label says what you will get, because the payload is not shown. Icon-only where the payload is shown beside it (fork D2b).

Component design · confirmed 2026-07-23 · contract fix E-DFLOW.W5 2026-07-27 (forks D2 and D4 reopened in place — the icon form's exception and size, and the box now composed from Button; W5 plan) · 2026-07-22 · E-DFLOW.W2 · T3 (docs/work/components/) · registry: W2 seed

Identity & frame

Why it exists: a debugging proxy generates derived payloads (curl, body, headers) users must copy in one act — without this, ad-hoc confirm logic gets reinvented per site.
TierT1 Primitive — clipboard write + timed confirm swap on a composed Button shell, zero business logic → in the collection. Composing another T1 does not raise the tier: no domain knowledge enters, and the roster already has T1s made of T1s (Notice holds a Button in its action slot)
Tenantslabelled form: copy-as-curl (FlowDetail.tsx:96 — the curl string is never rendered, so the label is the only payload identifier). icon-only form (D2b): copy body (BodyViewer chrome bar ×2 — the pane below shows the payload) · copy all headers (HeaderTable sub-bar ×2 — the rows below are the payload; HeaderTable serialises, this writes)
Exists todayinline in FlowDetail.tsx:96–103 and BodyViewer.tsx — not yet extracted
Made ofButton (T1) in both forms — tone="mute", plus shape="square" for the D2b icon form; the element, its five states, focus ring, disabled treatment, radius, hit floor and keyboard all come from the shell · the shared "flash a state for ~2 s" hook (with CopyText). This component adds the copy contract: the clipboard write, the copied/failed vocabulary, and payload transparency — fork D4

States

rest — muted text, hairline border
hover — ink text, mute border (strengthens, ink-toned — zero chromatic accent)
focus — 1 px mute outline (ink-toned, not colored — zero-accent rule)
active — tinted fill, ink text (press-down acknowledgment; brief)
confirming — ok-tone text + border, label "copied", ~2 s then reverts. Only on successful write.
error — warn-tone text + border, label "failed", ~2 s then reverts. Only on failed write (review 2026-07-23).
disabled — 38% opacity. Only when there is nothing to copy (e.g. body not yet captured).

The icon-only form (D2b) carries the same seven states at 24 px square. Only the two transient ones look different, because there is no label to swap:

rest — ⧉ glyph, muted, hairline border. The payload is the pane below it; title + aria-label carry the name the label would.
confirming — glyph swaps ⧉ → ✓ at ok tone, ~2 s, same timer rules as the label swap. No width change: the box was already square.
error — glyph swaps to ⚠ at warn tone, ~2 s. The aria-live announcement is what carries "failed" to a screen reader — the glyph alone never states the outcome.
Deliberate non-states. No loading/in-flight state — the write is synchronous enough that a spinner would flash. No empty state — disabled covers "nothing to copy"; the component is not rendered when the section is absent.

Forks — settled here, confirm or push back

D1 · confirm form: label-swap vs chip settled: label-swap
click ▸ ~2 s ▸

Label-swap wins: the shipped FlowDetail.tsx:101 pattern already uses copied ? "copied" : "copy" — the label IS the confirm slot. Zero reflow: the button width stays fixed at the longer of "copied" / original label (pick the wider, pad the narrow). The button shape never changes, the confirm lands exactly where the click was.

CopyText uses a chip — why not here? CopyText's confirm chip appends after the value text; removing it and swapping the value would hide what was just copied — that's why CopyText settled on a chip (CopyText fork D2: "swapping the value hides what was just copied"). CopyButton's value is NOT displayed, so the label-swap has no "hiding" cost — swapping "copy curl" → "copied" loses nothing, because the curl was never the button's text. The chip would add DOM outside the button boundary; the swap is cleaner here.

alt: chip after the button rejected
copied

Appending a chip outside the button is DOM outside the hit zone — reflows the sub-bar, adds a second element to manage, and makes the button narrower than needed while the chip floats. The label-swap keeps everything inside the button.

alt: toast rejected

A distant toast breaks the "verify without looking away" frame driver. Not considered further.

D2 · which forms exist settled: two forms — labelled (default) · icon-only under the adjacency test reopened W5 · r2·27 · r2·28 · r3·17 · r3·21
labelled — icon optional

Labelled is the default form. The curl use-case in W1 dropped glyph-only because no glyph fits the action unambiguously (registry seed, IconButton card). With the label present, a leading ⧉ is additive chrome — acceptable, not required. Caller decides; label-only is the minimum.

D2b · icon-only form settled: allowed when the payload is adjacent
24 px square · tooltip + aria-label mandatory · ✓ confirm

The adjacency test — the whole condition, in one sentence: the icon form is allowed only when the payload the button copies is rendered on screen beside the button. Then the label is not load-bearing, because the content itself names what will land on the clipboard. Tenants: BodyViewer's chrome bar (the pane below shows exactly what copy delivers) and HeaderTable's sub-bar (the rows below are the payload). Confirmed by manager review 2026-07-23.

Size: 24 px square — generous-targets' documented floor, and the value BodyViewer's own chrome-bar spec row already carries (size=24). Not IconButton's 28 px: this is a CopyButton, not an IconButton, and 28 px would break the chrome bar's single-line rhythm. Not the 22 px both W4 runs reached for — that is under the floor and was never anything's specified value (see the drift note below).

Mandatory with the icon form: a title tooltip and an aria-label naming the payload ("copy body", "copy all request headers"); the confirm is a ✓ ok-tone glyph swap for the same ~2 s as the label-swap, with identical timer rules.

alt: icon-only anywhere rejected
payload nowhere on screen

When the payload is not rendered — copy-as-curl, where the curl string is assembled and never shown — the label is the only payload identifier and icon-only collapses that identity. W1 lesson: "actions with no fitting glyph — the word carries it instead". This is the case the flat @avoid line was written for, and it stays rejected.

Why this fork was reopened (W5, D5 — edited in place). The exception above was settled in July but recorded only inside the rejected card, while @avoid read "icon-only form" flat. Two design runs read the @avoid line — which is where the flow instructs fit to be judged, and what elements·avoid-cited checks — and both shipped a wrong form while citing this file: run #2 (findings 27, 28) and run #3 (findings 17, 21). Both also borrowed BodyViewer's private 22 px .ibtn, because no canonical drawing of the icon form existed anywhere. The three fixes: the exception now lives in a settled card, @avoid carries it inline, and the size is one named value. A contract whose exceptions live outside the lines the gate reads is unenforceable by construction (W5 D6).

Run #3's finding 21 is the sharper lesson and is not fixed by this fork: that run put the icon form beside a command the user reads and copies verbatim, which @avoid's first clause already excluded — that is CopyText's job. Adjacency permits the icon form; it never overrides the CopyText boundary. Both clauses must pass.
D3 · payload prop shape: value vs getPayload settled: value (eager) is the default; getPayload (lazy) optional

The shipped curl case pre-computes curl at render time (FlowDetail.tsx:51 — const curl = toCurl(flow)) and passes it directly. Most uses will follow this pattern. A lazy getPayload: () => string escapes expensive computation on every render without breaking the reset-on-change rule (key the reset on a stable identity token instead). Both are acceptable; value is the primary API, getPayload is the escape hatch.

D4 · scope: copy-specific behaviour on a shared shell settled: copy-specific contract · the box is Button · the timer is the shared hook reopened W5 — the deferred lift, resolving as this card predicted

the deferred alternative, now landed resolved W5 — Button is the tenant

This card previously deferred a generic FlashButton for want of a non-copy tenant, and wrote its own escape path: "when a non-copy transient button appears, lift the shell + hook into it and make CopyButton its thin wrapper — no caller changes, no design rework here."

That tenant appeared. Button was proposed in W4 (run #2's finding 30) for the first non-copy action the collection met, and it was specified as "CopyButton's box exactly". So the lift is not a new decision — it is this deferral resolving exactly as written, with one correction: the shared piece is the shell, not a flash mechanic. Button carries no timer and never flashes; the hook stays where it was.

Why it could not wait for the build: the two files had already drifted on three values (border alias, padding, active wash) while both claiming to be identical — see Button § tokens. Two descriptions of one box drift silently; that is the same defect class as r2·24, and composition is what makes "identical" structural instead of aspirational.

Use / avoid

Use

Any one-click copy where the payload is derived or invisible: copy-as-curl (panel zone B) · copy body (BodyViewer) · copy all headers (HeaderTable sub-bar — HeaderTable serialises the payload, this button just writes it). Anywhere the label names the payload class and the value is not shown verbatim.

Avoid

A value that IS displayed verbatim and the user grabs whole — that is CopyText (the displayed string is both the affordance and the payload). This boundary is checked first and the icon form never overrides it: run #3 put an icon CopyButton beside a shell command the user reads and copies whole, which is CopyText's case (finding 21). Actions that are not clipboard writes — use IconButton or Button. Icon-only when the payload is not on screen — the label is load-bearing for payload identity; the icon form is allowed only under D2b's adjacency test (the payload is rendered beside the button: BodyViewer's pane, HeaderTable's rows), at 24 px with tooltip + aria-label.
