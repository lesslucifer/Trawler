Forks — settled here, confirm or push back

F1 · absolute vs relative time settled: absolute default · relative opt-in
14:07:52

Absolute HH:MM:SS default (chosen). A debugging proxy is used side-by-side with server logs, terminal output, and system clocks. Absolute time reads directly against those; "2 m ago" requires the user to subtract from now. Relative time IS supported — format="relative" (State S6) — for surfaces where recency matters more than log correlation; it is opt-in per callsite, so its 10 s re-render tick is confined to the surfaces that ask for it.

alt: relative as the default rejected
3 minutes ago

As a list-wide default, relative times require mental arithmetic to correlate against a log, re-render on a timer for every visible row, and become ambiguous after a few hours ("2 h ago" is less useful than "10:07"). Rejected as the default; available only as the explicit format="relative" mode. No hybrid default (relative for recent + absolute after threshold) — a branch point without gain for a debugging tool.

F2 · millisecond display settled: default truncates · custom format shows them
14:07:52
raw: 14:07:52.381 → shown: 14:07:52

Seconds only by default (chosen). The 110 px list column (FlowList.tsx:9) fits exactly 8 chars at the current font size; adding ".mmm" pushes to 12 chars. Ordering within a sub-second burst is preserved by list insertion order (server-side capture order), not by sub-second display. Truncate (floor to second), never round — rounding could display a time 1 second ahead of the real event. A surface that genuinely needs ms is the custom-format case: format="HH:mm:ss.SSS" (State S5) — no new fork required.

alt: milliseconds in the default (HH:MM:SS.mmm) rejected
14:07:52.381

12-char output exceeds the 110 px column at current font size. The column would need to widen, pushing host and path columns or triggering truncation. Sub-second burst ordering is already communicated by list row order — ms in the default adds width without a gain. Covered by the format prop where needed.

F3 · local vs UTC timezone settled: always local
14:07:52
system clock: UTC+2 → "14:07:52" (local)

Always local (chosen — confirmed). Trawler is a local desktop proxy; the user's shell, server logs, and browser dev tools all display in local time. A UTC display would require conversion before correlation, which is the opposite of the log-correlation frame driver. Local applies to every mode — the default, custom format strings, and relative all render from the local clock; there is no UTC prop and none planned.

alt: UTC (always suffix "Z") rejected
12:07:52Z

UTC forces the user to add their offset before matching a local log line. Useful only if target servers always log UTC and users never use local tooling — not the case for a general desktop proxy. Rejected outright — always local, no UTC mode or preference.

F4 · 12 h vs 24 h settled: 24 h default · 12 h via custom format
14:07:52
not "02:07:52 PM"

24 h default (chosen). Server/proxy logs are universally 24 h. An AM/PM suffix adds 3 chars to the output, breaking the 8-char stability contract and the 110 px column. The pinned HH:mm:ss moment format string overrides any locale that defaults to 12 h. A surface that truly wants 12 h is the custom-format case: format="hh:mm:ss A" — no new fork required.

alt: locale default (may be 12 h) rejected
02:07:52 PM

The current toLocaleTimeString() call (flow.ts:44) has no options — on a US-English locale it may produce "2:07:52 PM", which is 11 chars with variable leading-zero behavior. Column unstable; format unfamiliar for log correlation. Rejected as the default; covered by the format prop where needed.

F5 · date library — moment vs native Date settled: moment
moment(timestamp).format('HH:mm:ss')

moment (chosen — manager direction). One parser/formatter covers all three modes: lenient parsing of ISO 8601 / epoch ms / Date, format-token rendering for the default and custom strings, and fromNow() for relative — nothing hand-built. New UI dependency (ui/package.json has no date library today). Note: moment is upstream-maintenance-mode; if that ever matters, dayjs shares the same format-token API and the swap is confined to this one component.

alt: native Date + Intl rejected
Intl.RelativeTimeFormat + hand-rolled units

Zero-dependency, but three hand-built pieces: Date.parse accepts fewer input shapes than moment, custom formatting would mean inventing a token syntax for the format prop, and relative mode needs hand-rolled unit selection around Intl.RelativeTimeFormat. Rejected in favor of the one dependency.

Use / avoid

✅ Use

Anywhere a point-in-time label reads against external logs or the system clock: the list time column, the flow detail overview. Pass the raw value (flow.started_at, an epoch, a Date) — no caller-side formatting. When the default doesn't fit a surface, pick a mode via format: a moment format string, or "relative" where recency beats correlation.

🚫 Avoid

Relative time as the list-column default — format="relative" is opt-in per surface, never the default (F1). UTC display — always local, in every mode (F3). A timestamp the user wants to copy whole — wrap TimestampText in CopyText for that. Live-ticking elapsed time or duration-since-start — that is DurationText.
