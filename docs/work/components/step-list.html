StepList T1

Ordered manual instructions — a numbered list with a free slot per step. The registry's first instructional component, and it exists because the collection had none at all.

Component design · draft — awaiting confirmation · 2026-07-27 · E-DFLOW.W5 · T3 (docs/work/components/) · proposed by run #3 (in PreconditionRow) · fixes findings 3 · 9

Identity & frame

Why it exists: finding 9 — the registry has no instructional component at all, and the gap is structural rather than incidental. All 16 files were extracted from a read-only detail panel that never asked the user to do anything, so the vocabulary can render wire data in six ways and cannot render "do this, then this". KeyValueRow misses on both axes (no ordinal, and its @avoid targets wire data); CopyText @avoids prose outright; Notice is one sentence with at most one action. Any screen that instructs — setup, an error with a remedy, a migration — starts from zero. This is the file that stops that.
TierT1 Primitive — an ordered list with a slot per step. It renders what it is handed, in order, and decides nothing → in the collection
Tenantsthe setup screen's manual instructions per target — 6 trust targets × 2–4 steps (guidedSteps, setup.ts:69) and the proxy-off reversal steps (proxyOffSteps) · any future remedy, migration, or "do this on your device" sequence
Exists todaythe content ships as string[] per target (setup.ts:36–67); the rendering is inline in Onboarding.tsx. This component is the render side, and the data feeding it is already there and unit-tested
Made of— (T1 primitive). Deliberately not @madeof CopyText: a step's content is a caller slot, and a command inside one is a CopyText the caller composes (fork D1). What the component owns is the ordering and the marker column
DriverDesign consequence
① the order is the meaning — a certificate install done out of order failsa real <ol> with visible numbers. Not bullets, not a bare stack: the ordinal is content, so it belongs in the markup a screen reader announces
② a step is prose or a command or both — run #3's steps interleave themone free ReactNode slot per step, no shape imposed. The component never decides what a step contains, which is exactly what keeps it T1 (fork D1)
③ commands must never be truncated or reflowed (instructions-are-commands)the step body is min-w-0 and wraps; nothing in the component sets truncate, white-space:nowrap, or a max-height. Run #3's longest is 330 characters and it must survive whole
④ these are read while the user looks away at another windowgenerous 10px between steps, 1.55 line-height, and the marker column aligned right against the text — the reader loses their place and must find it again. Density loses to re-findability here, unlike the panel the other 16 components came from
⑤ calm, ink-first (data-ink-first, zero-accent)numbers in ink-mute, body in ink-body, no box, no background, no rule between steps. Two ink tones and nothing else — the instructions are the content, not a card
⑥ the user is following, not being told offno state per step: no checkmarks, no "current step" highlight, no progress. StatusLine above owns whether the goal is met; the list is a reference, and the app cannot observe which step you are on (fork D2)

Why no existing component fits

Run #3 checked the roster before proposing — this table is that check, and it is also the proof that finding 9 is structural. Every near-miss fails on the same axis: nothing in the vocabulary has an ordinal.

CandidateNearest fitWhy it misses
KeyValueRowa two-column list of pairsno ordinal, and its @avoid names wire data as its subject. "1." is not a key, and a step is not a value
CopyTextthe command inside a step@avoids prose explicitly. It is the right component for one step's command — which is why it appears inside this one's slot (D1), not instead of it
Noticea message with an actionone sentence, at most one action, and about a zone's state. Four ordered instructions is not a notice about anything

SegmentedControl—mutually-exclusive selection. Steps are neither exclusive nor selectable

spec10px vertical gap, uniform. No rule, no divider, no zebra, no background, no border, no padding around the list. The list contributes no box of its own. why10px rather than the panel's usual tight rhythm because these are read while looking at another window (driver ④): the gap is what makes "which one was I on" answerable at a glance. Uniform rather than proportional to content length, so the column reads as a sequence of equals. No box because the host already provides one — a card around instructions inside a PreconditionRow inside a Section is three nested frames for one list (driver ⑤).
No copy affordance of its own. A command in a step is a CopyText the caller passes in — that component owns click-to-copy and its confirm chip, and run #3 confirmed that pairing (finding 21: no command on the setup screen carries a separate copy button, because CopyText is the affordance). If StepList also offered copying, two components would own the same gesture on the same text.
No nested StepLists, no sub-steps. A step whose content is a StepList produces "2." followed by "1.", which is unreadable and unspeakable. If a step needs sub-parts they are prose within the one slot, or the sequence is wrong and needs flattening — every real tenant in setup.ts is flat. Stated in @avoid; nothing in the component prevents it, and nothing should need to.

One state, and the absences are the design:
  • no empty state — a target with zero steps does not render a StepList; the host omits it. Run #3: 5 of 7 targets have steps and the 2 automated ones show them too ("the steps are one act away"). An empty-list placeholder would be a component apologising for a call the caller should not have made.
  • no per-step done/current state — the app cannot observe whether you opened Keychain Access, so a checkmark would be a claim it cannot support, and a "current step" highlight would be a guess (driver ⑥, fork D2). Whether the goal is met is StatusLine's, from a real probe.
  • no progress indicator, no step count — "step 2 of 4" adds a number that the numbers already say.
  • no interaction states — the list is not focusable and owns no handler. Interactive content inside a step brings its own states (CopyText's, Button's).
  • no collapsed/expanded state — disclosure belongs to the host (PreconditionRow decides whether its body is open, from which precondition is unmet). A list that could hide itself would compete with that.

Forks — settled here, confirm or push back

D1 · a free slot per step, not a {text, command} shape

settled ✓
steps={[<>Run:<CopyText …/></>, "Or double-click…"]}
  1. Run:certutil -addstore …
  2. Or double-click the file.
ReactNode[]. Run #3's real steps are prose, prose-plus-command, a path with arrows, and a caveat about Android 7+ — four shapes in one target's list. A free slot fits all four and keeps the component T1: it renders children in order and inspects nothing. Section's content slot works exactly this way.
rejected
steps={[{text:"Run:", command:"certutil …"}]}
A structured step — {text, command?}. Tempting: it would let StepList render the CopyText itself, so no call site could forget the copy affordance. Rejected — it makes the component own which parts a step has, so the first step that is neither (a Settings path, a caveat) needs a third field or an escape hatch, and owning "commands get CopyText" is business logic. That is a T2, and the screen would still need the free case.

D2 · no per-step completion — not even optional

settled ✓
  1. Save the certificate.
  2. Run the trust command.
✓trusted — the goal, probed
Plain steps; the verdict lives above in StatusLine. The app cannot observe which step you did — only whether the CA is now trusted. One honest probed verdict beats four unverifiable ticks, and run #3's Frame already ruled that a tick lies in most real states.
rejected
  1. ✓ Save the certificate.
  2. Run the trust command.
An optional done flag per step. Familiar, and free when unused. Rejected: the flag has no truthful source — nothing in setup.ts observes per-step progress — so the first caller would drive it from a click, which records "I read this", not "this is done". A component whose prop can only be filled with a guess should not have the prop.

D3 · always numbered — no unordered variant, no auto-unnumbering at one step

settled ✓
  1. The iOS Simulator uses the host Mac's trust store.
Always an <ol>, always visible numbers. A one-step list still reads "1." — it is a sequence of one, and the ordinal tells the reader nothing is missing above it. Keeps the component's contract exactly one sentence long, which is why it stays a primitive.
rejected
  1. The iOS Simulator uses the host Mac's trust store.
ordered={false} · or drop the number at length 1
An ordered prop, or hide the number when there is one step. A lone "1." can look pedantic. Rejected: an unordered variant makes this the app's generic list component, competing with plain markup for something no tenant asked for; and length-dependent rendering means the same data shows a number or not depending on the target — the surprise costs more than the pedantry. A single step with no ordinal is prose, and a caller wanting that renders prose.
Open for review — the reversal case. proxyOffSteps (setup.ts) is the "to undo:" sequence, and run #3 placed it in zone D as instructions too. Whether an undo sequence wants a visually quieter treatment (smaller numbers, muted body) or is simply a StepList in a differently-labelled Section is not settled here: run #3 rendered it as an ordinary list and nothing broke, so a variant would be speculative. Recorded because the second tenant is the right place to answer it, and because a variant prop added later is cheaper than one added now and unused.

API + registry TSDoc

PropTypeRequired
stepsReactNode[]✅ requiredone entry per step, rendered in array order — prose, a CopyText, or both stacked (the slot is a column with a 6px inner gap). Never inspected; never truncated. An empty array is a caller error: the host omits the list instead
classNamestringoptionalpass-through for layout only — never for colour, family, size, or the step gap

Two props, one of them required, and no variants: no ordered (D3), no done (D2), no start, no compact. The array index is the key and the ordinal — steps are static content, never reordered or filtered at runtime.

The card this file compiles down to — carried verbatim as the component's TSDoc when built (code-as-truth):

/**
 * StepList — ordered manual instructions: a numbered list with a free slot per step.
 * @tier T1 — renders the steps it is handed, in order, and decides nothing about their content
 * @anatomy a real <ol> · 18px right-aligned marker column, Inter 11px ink-mute tabular ("1." · "2.") so every step body shares one left edge · one ReactNode slot per step, Inter 12px ink-body at 1.55, min-w-0 and wrapping (never truncated — a cut command is a broken command), stacking its children with a 6px gap · 10px between steps · no box, background, rule or padding of its own
 * @use any ordered sequence the user performs by hand — a certificate install, a device setting, a remedy, a migration. Pass a command step as a CopyText inside the slot
 * @avoid a single unordered statement (that is prose, or Notice if it is about a zone's state) · wire data key/value pairs (use KeyValueRow) · nesting a StepList inside a step, or sub-steps of any kind — flatten instead · adding a copy affordance: a command step is a CopyText, which already owns click-to-copy and its confirm · rendering per-step completion or a current-step highlight — the app cannot observe it; the probed verdict belongs to StatusLine above · truncating, clamping or scrolling a step
 * @states rendered — the only state. No empty state (a host with no steps renders no list) · no per-step done/current, no progress count, no interaction states, no collapsed state (disclosure is the host's)
 * @madeof —
 */

Use / avoid

✅ Use

Any sequence the user performs by hand where order matters: installing a certificate on a device, changing an OS setting, undoing a proxy, following a remedy after a failure. Pass each step as a node — prose, a CopyText for a command, or prose then command stacked. This is the component finding 9 says the registry lacked, so it claims the whole instructional category, not just setup.

🚫 Avoid

A single unordered statement — that is prose, or Notice if it is about a zone's state. Wire data pairs — KeyValueRow. Nesting, or sub-steps: flatten the sequence. Adding your own copy button beside a command — CopyText is the affordance (finding 21). Showing per-step completion or a current step — the app cannot observe either, and the goal's real verdict belongs to StatusLine. And never truncate or clamp a step: instructions-are-commands, and the longest real one is 330 characters.

Off-scale, disclosed: gap-2.5 (10px between steps), gap-2 (8px marker→body), gap-1.5 (6px inside a step), the 18px column and the 11px marker are all off spacing-scale's 8px grid or the type scale — except the 8px one, which is exactly on it. The same contradiction finding 14 records across the collection; W6 settles the floor and this file moves with the sheet. Two values are argued rather than inherited and should be reviewed as design, not drift: 10px between steps (driver ④ — deliberately looser than the panel's rhythm because these are read while looking away) and the 18px marker column (fits "10." at 11px tabular, so a ten-step list does not reflow).
