Identity & frame

Why it exists: the registry has no text input at all — 24 entries, not one of which accepts typing. KeyValueRow's @avoid already redirects to it by name — "editable forms (that is Field)" — naming a component nobody can open. That is the phantom this file closes. The do-nothing answer is a raw <input> per call site, and it fails at the thing the collection exists to prevent: the app's four filter inputs and Select's filter box would each own their own chrome, and the first one edited would drift — precisely how three copies of the tone map got into the tree.
TierT1 Primitive — a labelled box that renders what it is handed and reports what is typed. It never validates, never debounces, never formats, never decides what a value means → in the collection
TenantsApp's filter bar — four fields today (free text, host, method, status — App.tsx:145-176), each passing aria-label, placeholder and a width class · every future input: a saved-view name, a search box, a port override. Select's in-popup filter is not a tenant — see the boundary below
Exists todayui/src/components.tsx:9 — the legacy kit's only input, and one of the three things that kit still holds. It is a real precedent, and this design keeps its box, its focus behaviour and its placeholder tone; what it adds is stated in forks
Made of— (the leaf). Its box is Select's trigger box, which is Button's — one small-control chrome across the app (DEC-18), a shared vocabulary rather than a composition

Field vs Select — the boundary

Both are small boxes you interact with, both use the same chrome, and Select contains something that looks exactly like a Field. The line has to be drawn in this file because a build reaching for the wrong one produces a working screen with the wrong contract.

Select's filter box is not a Field, and must not become one. It looks like one (Select.tsx:173-186) and it is deliberately not the same element: it is borderless and sits inside the popup's own chrome, drawing its frame from the popup rather than carrying one. Wrapping it in a Field would give it a second border 2px inside a bordered popup, and would hand a caller control over a name the component has already fixed (aria-label="filter options", Select.tsx:176) — one of the several things Select deliberately does not let a call site reach. Recorded here so a later reuse-or-propose pass reads it as a decision, not an oversight.

Behavior — what the parts do

Anatomy is what you see; behavior is what it does. Field's behaviour is deliberately thin — the interesting rules are the ones about what it refuses to do.

States

rest · empty — hairline border, placeholder in ink-mute
rest · filled — value in full ink
hover — border lifts to ink-mute; same as focus by design (driver ④ leaves one channel)
focus — ink-mute border, native caret. No outline ring: the border is the ring
disabled — opacity-disabled (.38), out of tab order. No tenant today; declared because state-declarations requires it
Deliberate non-states — each is a refusal, not an omission.
  • No error / invalid. Fork F3 — nothing in the app can judge a filter wrong, and the empty result is explained by Notice, at the list, where the eye already is.
  • No loading. A text box has nothing to wait for; Select has isLoading because its options arrive late, and a Field has no options.
  • No empty state. Empty is the rest state — that is what the placeholder is for. This is the distinction state-declarations asks each component to make explicitly.
  • No confirming. Nothing is committed, so there is nothing to confirm (confirm-at-point has no trigger here).
  • No focus ring separate from hover. Both land on the same ink-mute border. Two distinguishable ink weights would be the alternative and the palette has no third step that reads at 1px.

Forks — the contested decisions

F1 · Does the app get a Field at all, or four raw inputs?

settled — a registry entry
One box, one accessible-name rule, one focus behaviour. KeyValueRow's @avoid gets a real target. Four call sites shrink to a width class each.
rejected — raw <input> per screen
Why it lost: it is what ships today, and the class string above is already 12 utilities long — copied four times in App.tsx via components.tsx:9. The moment a fifth input appears anywhere, nothing makes it match, and no check can see the divergence. This is the exact failure the epic exists to close.

F2 · Its own box, or Select's?

settled — Select's box, class for class
px-control-x py-control-y, rounded-button, border-hairline, text-control, min-h-control — the same five decisions Button and Select already made. DEC-18 is explicit that a new control composes the one box.
rejected — input-specific chrome
Why it lost: "an input should look inset, a button should look raised" is a real convention — and it produces the pair above, where two controls in one row disagree about radius, fill, padding and type size. DEC-18 was minted after exactly this drifted three token values while both files claimed identity. Weight is expressed in tone and in which actions exist, never in a second shape.

F3 · Does it own validity?

settled — no validity, ever
list below: "no flows match this filter"
The box stays neutral; the outcome is explained where the outcome is, by Notice. One place to look, and it is the place already being looked at.
rejected — warn border + message
not a number
Why it lost: three ways. It spends a chromatic token — warn means failure outcome, and a half-typed filter is not one (DEC-19 fixes each token's meaning). It fires while typing, so 4→40→404 flashes an error twice on the way to being right. And it needs a rule for what "valid" means in a filter, which no tenant can supply.

F4 · Is Select's popup filter this component?

settled — no, it stays Select-local
⌕
macOS
Borderless, inside the popup's own border, and named by Select itself (aria-label="filter options") rather than by whoever mounts it. It is a part of Select, like the caret.
rejected — reuse Field inside Select
macOS
Why it lost: a bordered box inside a bordered popup — two frames, 2px apart, for one control. It would also move the name out of Select's hands: the filter's aria-label is fixed at Select.tsx:176, and Field's contract (B3) requires the caller to supply one. Reuse that produces a worse screen is a propose in disguise; here it is simply "not a tenant".

Use / avoid

✓ reach for Field when…
  • the user types something you cannot enumerate — a host, a substring, a name
  • you have a value and a setter and want the app's standard box around them
  • the field is visually unlabelled and needs a real accessible name
✗ reach for something else when…
  • the value is one of a known set → Select (5+) or SegmentedControl (2–4)
  • the value is displayed, not entered → CopyText, or KeyValueRow with a name beside it
  • you want to tell the user their input is wrong → Notice, at the zone whose content is affected
  • you are inside Select's popup → that filter box is Select's own part (F4)
