EditSurface T2

The data window's whole-data surface for JSON, XML and text: every byte rendered, editable, foldable and searchable, with no cap.

Component design · 2026-11-03 · Trawler · status: draft, awaiting confirmation · proposed by the data window's design run (E-INSPWIN.W2) · built by E-INSPWIN.W3, extended by W4 (find, fold to depth) and W6 (the inset) · amended by the run's round 2 (2026-11-04) · retires into the TSDoc on build (DEC-16)

Identity & frame

Without it the window has nothing to edit in: SourceSurface is read-only by contract and TextRenderer is a capped pre, so a 2 MiB document could be neither changed nor read whole.

States

Not states: an error state (a parse failure is the caller's warn Notice above the surface; the surface keeps rendering the text) · empty (a 0 B payload is the screen's none region, the surface is not mounted) · a modified look (DEC-59: marking a value edited is the screen's, in words).

/**
 * EditSurface — the data window's whole-data surface: every byte of a JSON, XML or text document, editable, foldable and searchable, uncapped.
 * @tier T2 — owns the editor configuration (editable document, virtualised viewport, fold gutter, three-token highlight, find marks); the text, the one history and what a change means are the caller's
 * @anatomy line numbers (ink-mute) · fold gutter ▾/▸ with a "… N lines" wash-tint chip on a folded line · mono text-body document, syn-key/syn-str/syn-num, punctuation ink-mute, wrap on by default · find marks wash-select, current wash-active + 1px ink-mute outline · CodeMirror cursor and selection · an inset block under one line (the caller's node)
 * @use the data window only (DEC-68): its json / xml / text surface and a form shown encoded; read-only for a decoded result
 * @avoid the body pane or any surface showing captured evidence (UC-5: that is SourceSurface, read-only, and the line between them is DEC-68 rule 5) · keeping its own undo history: every change goes to onChange so the caller's one history holds it · reformatting, sorting or decoding inside it — those are the caller's steps, handed back as text · a cap or a cut marker: the data window has none (DEC-68 rule 7) · marking the document edited (DEC-59: the screen says so in words) · overlaying the inset on the lines below it: it is a block in the document
 * @states editable · read-only (selection, find and fold still work) · folded (view state) · with find marks · with an inset under one line. No empty, error or loading state
 * @madeof CodeMirror 6 (T0) — view, state, language, lang-json, lang-xml, search decorations
 */

Use / avoid

Use

Inside the data window: the working copy of a JSON, XML or text payload, a form shown encoded, and read-only for a decoded result in the peek.

Avoid

The body pane (SourceSurface, read-only, is the evidence) · a plain value that is one line (Field) · a form's pairs (FormTable) · binary (HexView).
