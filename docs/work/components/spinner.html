Spinner

The one thing in Trawler that moves: a ring that turns while a transfer the user started is still running.

Component design · 2026-09-08 · Trawler · retires into the TSDoc on build (DEC-16)

Why this exists

Two components already draw this ring inline — Select while its options load and StatusLine while a request is in flight — with the same six utility classes typed out twice. A third and fourth call site arrived with the capture controls, so the shape is now a vocabulary entry rather than a local detail, and the collection is where a vocabulary entry lives.

The rule this settles — motion-informs

Two design runs read motion-informs as a ban on spinners. That reading is overturned here.

Run 10 receipted it as "nothing animates; in-flight is a disabled control plus a static word, never a spinner or a bar", and run 11 carried the same verdict forward as "nothing animates, and nothing moves". Both went further than the rule they were applying.

What the rule saysWhat follows
"Motion and transience only communicate state change; nothing animates for decoration; transient feedback expires (~2 s)." Its reviewer question is "For each animation: what does it tell the user? 'Nothing' fails." The rule bans animation that says nothing. A turning ring says this is still running — the definition of a state change, and the one fact the user is waiting on. It answers the reviewer's question, so it passes.
The DON'T the rule ships is "hover glow, panels sliding for style". Decoration. A progress indicator is the DO side of the same rule, which is why the rulebook's own example of acceptable motion is a confirm chip that appears and expires.
The ~2 s clause governs transient feedback — an acknowledgement that must not linger. It does not govern a progress indicator, whose duration is the transfer's, not the designer's. An export of 73MB takes as long as it takes; a ring that expired after two seconds would report the opposite of the truth.

What the runs got right, and what is kept. Their real concern was a screen that twitches. That is preserved and is a constraint on this component: the ring occupies a fixed box, never displaces text, and never animates anything but itself. Run 11's "nothing moves" — the in-flight line swapping inside a fixed-width slot rather than displacing the row — stands unchanged. Only "nothing animates" is reversed.

The contract

FacetDecision
tierT1 — a shape with no business logic and no state; props in, span out.
anatomyA spinner-sized square span, fully rounded, a hairline border all round with the top edge inked to ink-mute so one arc reads darker than the other three, turning once per second, linear, forever. It does not shrink in a flex row.
accessible nameNone, and this is the decision most likely to be misread as an omission. The ring is aria-hidden because every sanctioned use puts it beside a line that already says what is happening in words — exporting…, importing…. A name here would make a screen reader say the same fact twice.
colourNone of its own. The inked arc is ink-mute, the neutral channel: a transfer in flight is not an outcome, and ok/warn would claim one.
sizeOne, from the spinner token. A second size is not offered until a second context needs one; spinner-lg exists in the config and has no caller.
statesOne. It turns. There is no rest, hover, focus or disabled state — a caller that wants it gone unmounts it.

Where it belongs, and where it does not

Use

Beside a word naming what is awaited, for an act the user started whose duration the app cannot predict: a transfer, a load, a request in flight. Always the second channel — never the only one.

Avoid

As the only signal that something is happening (the words carry it; this repeats it) · for work with a knowable extent, where a count or a proportion tells the user more · as a page-level or blocking overlay · anywhere the reason for the wait is worth a sentence, which is Notice's job · giving it an accessible name that restates its neighbour.
