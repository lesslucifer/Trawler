Component design — base spec & template

The file format an AI agent follows to design one component = one file, and the review loop that confirms it. Component-agnostic: the reusable method, not one design. Canonical exemplar: CopyText — copy its structure, replace its content.

Base spec · 2026-07-22 · Trawler · T3 (docs/work/) → promotion decided at W4 distillation · from E-DFLOW.W2 · sibling: design-flow-base (screens)

What this is

The per-component design format E-DFLOW.W2 converged on by piloting CopyText through live review rounds. A screen run's Elements stage names components; this file is where one of them actually gets designed — deeply enough that the build WU implements it without further decisions. The file compiles down to the component's registry TSDoc (code-as-truth): the doc is the long form with rationale and examples; the TSDoc is its usage summary; the generated index derives from that.

One file per component under docs/work/components/. The design is done when the reviewer confirms it, not when the author does.

Principles (apply to every section)

  • Example-first — the reader is not a designer. Every spec row carries a rendered example beside it (a swatch, a before→after pair, a timeline, a transcript). Terms alone fail review; this was the pilot's hardest-learned lesson.
  • Specimens render in app tokens. Every visual uses the real Warp palette (an .app-scoped variable block copied from the exemplar), never the doc palette — the reviewer judges what will actually ship.
  • Every spec has a why. Each anatomy part and behavior rule traces to a driver (identity & frame) or a shipped-code precedent (cite file:line). A spec that can't say why is a guess.
  • Spec-first, demo-last. The reader meets the reasoning before the toy: identity & frame → anatomy → behavior → states → forks → API — the live specimen closes the file.
  • Forks show their losers. A settled decision renders its rejected alternatives visually, each with the reason it lost. Review catches ride in the winning card (see the exemplar's cursor sub-fork).

The section contract

#SectionAnswersRequired form
1Identity & framewhat is it, why does it exist, where does it stand?one-sentence claim callout (what the do-nothing answer fails at) + fact table: tier + why · tenants · exists-today (code pointer or "no") · made-of + driver table, two columns: driver → design consequence, one line each
2Anatomywhat parts are on screen?annotated specimen (numbered badges) + one block per part: example swatch · spec · why
3Behaviorwhat rules do the parts obey?one block per rule: concrete example · spec · why. Opens by restating the split: anatomy = what you see, behavior = what it does
4Statesevery state it ownsswatch grid, each state pinned visually with a one-line caption · deliberate non-states called out (e.g. "no empty state — the screen omits the field")
5Forkswhich decisions were contested?per fork: settled card + rejected alternative cards, all with visuals; badges settled/rejected
6API + TSDocthe build contractprops table (minimal — every prop earns its row) + the registry TSDoc block the file compiles down to
7Use / avoidthe fit-first contracttwo cards: when reaching for it is right / wrong (name the component to use instead)
8Tokensmockup → build mappingtable: part → Tailwind classes, incl. any override the semantics force (see the exemplar's cursor-text note)
9Live specimendoes it feel right?interactive demo, last section — see the scale-down rule below
The specimen scales down, never away. Fully live when the behavior is cheap to re-implement in a doc (CopyText: ~20 lines). When it isn't — a collapsible JSON tree, a hex grid — a simplified sample stands in: static swatches plus explanation text, diagrams, or visualizations of the hard part. States stay visual either way; only the interactivity is negotiable.

File skeleton

docs/work/components/<kebab-name>.html   ← mint data-htmldoc-id · snapshot on create (htmldoc skill)

hero      <Name> <tier badge> · one-liner · status: draft — awaiting confirmation · link: registry seed
identity  claim callout (one sentence) + fact table (tier+why · tenants · exists-today · made-of) + driver table (driver → consequence)
anatomy   annotated specimen + part blocks (example · spec · why)
behavior  rule blocks (example · spec · why)
states    swatch grid + non-state callout
forks     settled + rejected cards, visual
api       props table + TSDoc block
fit       use / avoid cards
tokens    mockup → Tailwind table
specimen  live demo (or simplified sample) — last

Styling, the .app token scope (Warp palette values), the part-block grid, swatches, timelines, chips: copy them from the exemplar — don't reinvent per file. Headings and data-c blocks stay direct children of <main> (htmldoc diff rule).

How the file compresses to TSDoc

TSDocComes from
first linehero: Name — one-liner
@tieridentity: tier + the why
@anatomyanatomy parts, compressed to one line
@use / @avoiduse / avoid cards
@statesstates grid, names + the one timing that matters
@madeofidentity: made-of

Drivers, behavior details, forks, and tokens do not compress into TSDoc — they stay here as the rationale record. TSDoc is the usage summary an agent reuses from; this file is what an agent extends or re-litigates from.

The review loop

Draftauthor the file → snapshot → hand the path to the reviewer with the settled forks called out
Roundreviewer comments (htmldoc layer) → snapshot before edits → address each comment → resolve with a reply stating what changed → share ?diff=latest
Confirmreviewer says done → hero status flips to confirmed with the date. Only a confirmed design feeds the build WU

Provenance

Extracted from the CopyText pilot (E-DFLOW.W2) after three review rounds; the rounds live in that doc's snapshots. The format's review-driven rules — example-first, spec-first/demo-last, why columns, the specimen scale-down rule — all came out of those rounds, not theory. T3 until W4 validates the flow that consumes these designs; whether this becomes a T1 process doc (or a section of the promoted design-flow doc) is decided at that distillation.
