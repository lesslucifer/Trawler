E-EXPORT.W3 result — a capture comes back, marked

POST /flows/import reads a HAR 1.2 document back as flows marked imported, delivered as planned: the parser inverts the projection from inside the module that writes it, and a refused document changes nothing because nothing was inserted.

v1 · 2026-09-04 · Trawler · T3 WU result · E-EXPORT.W3 · WU plan · epic plan

Outcome

Delivered, against the requirement as written. src/api/har.rs gained the read side of the format — permissive Deserialize types and flows_from_har — beside the projection it inverts; Flow gained source: FlowSource; the store gained Store::import and a source filter; and POST /flows/import serves the whole thing. What shipped

FileChange
src/api/har.rs the read side, in the module that writes it: separate permissive Deserialize types (every member optional, unknown fields ignored), flows_from_har, and an ImportError whose every variant names the field at fault and, for an entry-level fault, its index. The whole document parses into a Vec<Flow> before the caller can touch the store, and the vector is reversed — the export writes newest-first, so file order would land a capture backwards in a newest-first ring. reason_token reads back exactly what not_captured_comment wrote, so the four-state vocabulary has one spelling rather than two.
src/flow.rs FlowSource (Captured | Imported), Flow.source, and Flow::imported() — the enum only; its wire tokens live at the API boundary, per the review. Flow::new still yields Captured, so the capture path and the recorder never learn a new field exists — asserted by a test, because a silent regression there would mismark every live flow.
src/store.rs Store::import — one lock for the whole batch, so a concurrent capture cannot interleave into the middle of an imported one and the batch stays a contiguous slice of the ring; then one eviction pass; then one RequestCaptured per flow plus ResponseCaptured only where the entry had a response. Also FlowFilter.source, matched exactly, and Store::max_bytes so the import route's body limit derives from the ring's own cap rather than a second copy of the number.
src/api/routes.rs import_flows; and FilterQuery gained source, which turned its From impl into a fallible into_filter — a filter value can now be wrong, where every previous field could only be unmatched. Both reading endpoints refuse an unrecognised value rather than serving a silently empty result.
src/api/view.rs source on both FlowView and FlowSummary — an added field on each, so the bare array and the paging envelope keep their shapes and W1's contract stays valid — plus source_token and parse_source, the provenance vocabulary's one home, beside the rfc3339 W2's review put here for the same reason. The domain enum stays wire-agnostic: nothing below this boundary needs the string form, because the store filters on the enum itself.
src/api/mod.rs the POST /flows/import route with a DefaultBodyLimit of the ring's cap; the CORS grant widened to GET, POST, OPTIONS; and the module's contract line updated from "inspect-only".
tests/api.rs seven integration tests over the real router, plus one edit: W1's the_unparameterised_listing_keeps_its_pre_paging_shape pins the summary row's exact field set and went red on source — which is the test doing its job. Its expected set gained the field; its purpose is unchanged.

Untouched: the capture path (capture.rs, recorder.rs), the event bus's variants, decode.rs, src/api/ui.html, all of ui/src/, and every pre-existing test assertion except the one field-set lock above. No UI-rendering file is in this diff, so the design→build accounting has nothing to answer for here. No new dependency.

Contract calls the plan left to the build

CallMadeWhy
the refusal's wire shape plain text, matching every existing refusal the plan said {"error": "…"} was "the shape W1's paging refusals already use". It is not — bad_request returns plain text, and has since before this epic. Introducing a JSON envelope for the new endpoint's refusals would have given the API two refusal shapes and made ?source='s refusal differ from ?limit='s on the same endpoint. Recorded as a deviation below.
the filter conversion From became a fallible into_filter a source value can be invalid, which no previous filter field could be (a bad host simply matches nothing). From cannot fail, so keeping it would have forced the parse into the store layer or a silent fallback to "no filter" — the latter being exactly the empty-listing failure the plan forbade. One conversion, still one definition, still shared by both endpoints.
the imported flow's SSE duration flow.duration_ms.unwrap_or(0) FlowEvent::ResponseCaptured.duration_ms is a u64 with no absence to express, and widening it would touch every subscriber for a field the listing already serves as null. A measured duration is carried through; an unmeasured one reports the 0 the event has always used for "nothing to say", and the flow itself still holds None.
a fractional time rounded, and clamped at u64::MAX HAR types time as a number, so a writer may emit 12.6. Truncating would silently lose the millisecond; an unchecked cast of an absurd value would wrap. Neither is a refusal-worthy fault in a file that is otherwise fine.
a foreign comment beside a measured zero Empty — the size wins the first cut keyed the empty case on comment.is_none(), which made any prose a foreign tool wrote turn a genuine 204 into a not-captured. The marker is what carries state; a comment that is not the marker carries nothing. Caught by a test asserting the wrong expectation, then corrected in both.
postData.mimeType deliberately unread the request's content type lives in its Content-Type header, which is preserved verbatim; postData only ever restated it. Reading it back would be a second source for one fact. Stated in the type's doc comment so the omission reads as a decision rather than an oversight.

Deviations

None from the WU plan's contract. Every row of its inversion table and its body table shipped as written, and all seven of its stated calls hold. Three differences from what the plan assumed, none a change of contract:

  1. The refusal is plain text, not a JSON {"error"} envelope. The plan asserted the JSON shape was already W1's convention; it is not, and the plan was wrong about the existing code rather than choosing a new shape. Following the real convention keeps one refusal shape across the surface. The plan's actual requirement — "refused with a status and a reason" — is met, and every refusal test asserts the reason's content rather than its wrapper.
  2. The CORS widening landed here, not in W4. The epic plan scheduled it with W4's DELETE, assuming that would be the first mutating method. Import is, so the grant became GET, POST, OPTIONS now and W4 adds DELETE to the same list. The plan predicted this deviation and it is recorded in DEC-31 as placement, not reasoning — a deviation from the epic plan, the only one.
  3. architecture.html was edited, and W2 predicted W4 would do it. W2's result left the T1 store/API line standing because an export adds a read. Import adds an ingest, so two T1 statements went false at once: the seam diagram's "the control API is purely a subscriber and reader — it never mutates capture state", and the invariant row's "read-only API bound to loopback". Both narrowed to what is now true. It is rule-bearing T1, so the commit carries a Reviewed-By trailer via mr commit.

One question the plan settled and the build confirmed rather than reopened: the parser lives in har.rs rather than a new import.rs. Nothing in the work argued against it — the two directions share the reason tokens, the version constant and the timestamp format, and a second module would have had to import all three.

altitude 5 1 real, fixed — the round's most consequential finding. FlowSource::as_str/parse put the wire tokens on the domain enum, and the verifier found the fact that settles it: nothing below the API boundary needs the string form, because FlowFilter holds the enum and store.rs compares enum values. Both functions' only non-test callers were in src/api/. Four refuted: the claim that the plan had specified view.rs and the placement was an unrecorded deviation (the plan never mentions the conversion's location at all — shipping it on the enum resolved an open question rather than deviating, and the result's "what shipped" table recorded it); FlowFilter holding a domain enum (consistent with matches already reading domain fields); the parser mutating Flow's public fields after Flow::new (a pre-existing in-tree pattern — test_support.rs does the same, and host is never stale because the request is complete before construction); and the architecture.html edit's accuracy, which the verifier confirmed.
efficiency 2 1 real, fixed. Store::import cloned each flow's request and response inside the ring mutex, while insert and set_response both clone before taking it — and the proxy's capture path contends on that same lock, so P2 ("critical sections stay minimal") applies to who is stalled, not who holds. Now cloned before the lock. The measurement corrected the finding's own framing: a verifier's synthetic benchmark reported a ~17× reduction in total hold, but measuring what a real capture actually waits gives ~44 ms versus ~49 ms on a 2048-flow batch — about 5 ms, because a contending capture queues behind the flows still ahead of it rather than the whole batch. Real, worth fixing, and smaller than first claimed. One refuted: decode_body's as_bytes().to_vec() where into_bytes() would move — true and compiles, but squarely the rubric's excluded "micro-optimization outside hot paths" on a one-shot import whose document is already buffered several times over.
correctness 3 0 real — all three refuted, and the finder independently confirmed the WU's load-bearing claims: the parse-before-store invariant is structurally enforced, the oldest-first reversal is genuinely exercised rather than tautologically validated, bytes do outrank a declared size, and no parsing path can panic. Refuted: import returning the accepted count rather than the post-eviction survivor count (UC-6 commits explicitly to "how many entries it took", DEC-31 accepts eviction as a designed cost, and a survivor count would be stale the moment a concurrent capture lands — differently arbitrary, not more truthful); a SystemTime::from panic path the fuzz generator cannot reach (empirically unreachable — time 0.3 without large-dates caps years at ±9999, and the extremes were run without a panic); and a params-only postData reading as not-captured (exactly what DEC-30's sentinel-not-invention rule requires — reconstructing wire bytes from parsed params would fabricate bytes never on the wire).
simplification 1 1 real, fixed (nit). response_body's fallthrough was two sequential decisions sharing a reason variable, the first with no else; it is now one match over (marker, size) with an arm per outcome. The verifier proved the single match compiles clippy-clean under this repo's pedantic settings, refuting the concern that it would reintroduce the match_same_arms warning an earlier iteration hit.
reuse 2 0 real, and the finder confirmed each load-bearing sharing claim: reason_token reads back exactly what not_captured_comment writes, HAR_VERSION and the timestamp format have one definition each, and Store::import shares Ring::evict and announce_evictions with insert. Refuted: seeded_store duplicating W2's har_fixture_store (extending that helper would churn the insta snapshot it feeds, and the two fixtures differ in methods, statuses and body directions, not just cosmetics); and extracting a shared Ring::push (the rubric's explicit "not its job: inventing new abstractions to force sharing" — three trivial statements carrying no invariant).

The lock fix ships without a regression test, deliberately. The testing standard wants a named regression test first for a confirmed finding, and three attempts were made: a lock-held-from-another-thread timing assertion, a concurrent-capture contention test, and a direct hold measurement. All three passed against the unfixed code — at any batch size a unit test can afford, a contending capture waits for the handful of flows ahead of it rather than the whole batch, so the two shapes are indistinguishable. A test that cannot fail is worse than no test, because it falsely implies the property is guarded; the fix is kept on structural grounds (it matches what insert and set_response already do) and the absence of a guard is recorded here instead of being papered over with a green assertion.

Follow-ups

ItemWhere it belongs
Nothing in the app can import yet — no control, no file picker, and the API client has no importHar. Not this WU: E-EXPORT.W5 designs the capture-management controls and W6 builds them, including the open dialog through the Tauri layer.
The source mark is on the wire but nothing renders it — an imported row looks identical to a captured one in both the app and the web shell. W5 answers how the mark appears in a row without adding a column; W6 builds it. The field is deliberately shipped first so the design has a real contract to design against.
W7's curl parser needs this WU's source marking and its refusal contract, and lands behind the same endpoint as a second format. E-EXPORT.W7. Pinned here by ImportError's Display and by the marking test, so a re-spelling turns red.
An import is held entirely in memory three times over — the request body, the parsed Vec<Flow>, and the ring's copy — so peak memory during an import is a multiple of the document size, and the route's limit is the ring's whole cap. The same class of problem as the export's, already the epic plan's deferred row (streaming a cap-sized export, revisited when a real capture proves the one-shot response too heavy). Streaming is the fix on both sides; the all-or-nothing contract is what makes a streamed import harder than a streamed export, and that is the design question the deferred row inherits.
An imported flow's ResponseCaptured event reports 0 when the file recorded no duration, because the event's field is not optional. Recorded here as a known narrowing rather than debt: the listing and detail views both serve the honest null, and widening the event would touch every subscriber for a fact they can already read. New work only if a subscriber is found that needs the distinction live.

No debt discovered. No test layer skipped beyond the recorded e2e waiver.
