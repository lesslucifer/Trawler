Design run: the data window's new kinds and find

The data window reads a kind from its bytes and says what decided it; html, javascript and css become kinds of their own; html gains a preview that runs nothing and loads nothing; find is typed the way the flow list's filter is.

Design run · closed 2026-11-05 after the owner's round 1 (accept all, one wording comment on E1) · Trawler · T3 (docs/work/) · E-INSPWIN2.W3 · branch wu/inspect-window-v2/data-window-kinds-design · epic E-INSPWIN2 · WU plan · component: ChipBox · within DEC-79, DEC-80 and DEC-76

Mockup

Live. Pick a payload with the buttons under the frame. In find, type ke to see the suggestions, take one with Enter or Tab, type a word and press Space to make a chip, Enter to step, Backspace on an empty draft to drop the last chip; try re:( + Space. Open ⋯ for reformat and the html view. Change the kind in the status bar. The frame is the window at 1200 px, scaled to fit.

overflow: window header, find bar and status bar pinned, each one row that wraps as the window narrows; the find bar's chips wrap onto a second row inside the box rather than scroll. surface: the one zone that scrolls, both ways, inside itself, uncapped (DEC-76 rule 7); in html's preview the frame fills the surface and scrolls inside itself. menus: the ⋯ menu, the kind picker and the find suggestions float over every other zone, one at a time.

Payload is mono: the surface, the chips and the draft. The status bar's words are ui. Highlighting for javascript, css and html is stubbed here (EditSurface ships json, xml and plain today; W6 and W7 add the three).
