Design run — About, Help and the version

Where a user on macOS, Windows or Linux finds which Trawler they run, under what licence, how to get help or report a problem, what Trawler sends out, and how to stop it asking for updates.

Every Help item lands in one of two places: the About window on the right page, or the browser. A browser that would not open lands on the About page with the address to copy.

Mockup

Mounted from the real ui/src/components/. The native menu bars and window title bars are drawn by the screen (the OS owns them; the build only names the items). Each button shows one state — read each alone, then combine the OS with any other.

overflow: help menu — five items (six off macOS), bounded · about window — fixed at pane wide, its height the page's, bounded · title bar — one line · pages — three names in a column, pinned · about page — logo slot, name, version, one licence line, three buttons, bounded; the version wraps, never cut · licences page — the notice is unbounded (every crate and package Trawler ships): it scrolls inside its own region, capped at body-max on the mockup and at the window's height in the build, one tab stop (scroll-a-region); the page title above it stays pinned · privacy page — a short statement, bounded; where the window is shorter, the page scrolls · settings general updates — one switch, one line, one version row and at most one notice, bounded.

Payload: the installed version (0.1.0-5), the bundled THIRD-PARTY-NOTICES.txt read verbatim, and an address the browser would not open (https://github.com/lesslucifer/Trawler/blob/main/GUIDE.md). Nothing else is wire data.
