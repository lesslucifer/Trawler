The worklist

⓪ The parser swap

Four functions read HTML by hand. Six code-review rounds each found a hole in them, and each fix revealed the next — the signal that they are one missing abstraction rather than six bugs. Every later step in this WU adds a predicate, and the measured price of not doing this first is one more round of it per predicate.

DoesNotes
Replace the four functions with a real HTML parser one small dependency. The house rule is "never add one for what a few lines can do" — six rounds of evidence say these are not a few lines. xtask today carries serde, serde_yaml and tempfile only
Turn the six known holes into tests an attribute quoted inside another attribute's value · a tag end found at a bracket inside a quoted value · re-syncing past a malformed tag and lending one element another's classes · quotes re-pairing across a fault · a legal title holding an escaped angle bracket · a snippet cut at a byte boundary mid-character
Keep markup·escaped's verdict a raw angle bracket in an attribute value stays red — round 8 refuted the argument for allowing it, and the pin says so

Gate: every predicate re-run over all three archived runs and the reds reproduce exactly — W6 recorded 49, of which 33 are real over 29 sites. A different number means the swap changed a verdict, which is the one thing it must not do.

④ Tier-3 — the design dimension of the code review

Once Tier-3 is named as the design-side cr/v2, hosting it elsewhere means re-implementing independence, freshness, binding-to-exact-bytes and merge-time enforcement, all of which already exist. So it goes where those already are.

PieceWhat it is
The design rubric a sibling to rubric.md: what a design finder looks for (soft rules and the new-component warrant only — Tier-1 owns all thirteen hard rules, so a second opinion on them is noise) and, as important, its exclusions
The finder activates when the diff carries a design artifact; loads the rulebook and the step-① registry oracle; reports findings or PASS, citing the exact slug — never a per-rule verdict table, which is Tier-2's job and would double it
cr/v3 the note gains a design section. The bump is for enforcement: without a field recording that the design dimension ran, a PASS on a design-bearing diff cannot be told from one where nobody looked at the design — silence reading as correctly typed is the defect this epic keeps rediscovering
verify-dod a design-bearing tip needs a cr/v3 whose design section is present. Existing cr/v2 notes on already-merged tips stay valid; only new tips are held to v3
The risk this step carries, named at planning. Tier-3 is an LLM judging prose rules; no unit test can assert that a judgment is correct. So its acceptance is calibration against known defects: run it over the three archived runs, where the real defects are already documented, and require it to surface them — run #3's wrong reuse (finding 21), run #2's false satisfied, the capability designed away that only the cross-check caught. A reviewer that passes a run known to be defective is not ready to judge a live one.

Waived in identical words by W1, W2, W3, W4, W5 and W6. Paid here.

AssertsHow

⑥ Hand over, then the human's run

D5 makes the fourth run the human's, which turns "usable by someone other than its author" from a courtesy into a deliverable. A harness only its author can drive would pass its own e2e and fail this.

  • The flow spec executable start to finish — the substrate-load command, the review invocation, the closing step, each named where a run is written.
  • Every red message says what to do about it. W6's round 9 is the precedent: a message that named a cause it could not know was itself the defect.
  • Then the run: the flow detail panel, through all three tiers, receipted — and mr/v1, the note no agent may write.
