E-UISETUP.W3 — result

The set-proxy onboarding step is live: on macOS/Windows one click points the system at Trawler (macOS one elevation prompt sets web + secure-web on every enabled service; Windows writes the per-user WinINET registry and refreshes running apps, unelevated), and a client selector shows the correct copy-paste snippet or guided steps for every other client — always visible, auto path or not. The proxy address is configuration (DEC-12), never hardcoded. The machine, stepper and status dot are untouched; proof stays W4's capture.

Outcome

Delivered as planned. Against the W3 requirement and its "done when":

  • Native set, Rust owns the command. ui/src-tauri/src/setup.rs — set_proxy(host, port) validates host against ^[A-Za-z0-9.-]+$ (elevated-shell injection guard; port is a u16 by type), then builds the exact per-OS argvs from fixed templates (set_proxy_commands): macOS → one osascript "with administrator privileges" compound script running networksetup -setwebproxy/-setsecurewebproxy for every enabled service (parsed from -listallnetworkservices via parse_services, single-quoted); Windows → two reg add HKCU writes (ProxyServer=host:port, ProxyEnable=1) + a fixed PowerShell InternetSetOption(39, then 37) refresh, no elevation; else None. Every argv must exit 0; the OS tool's stderr surfaces on failure. Registered as the app's second invoke_handler command.
  • Client selector + snippets everywhere, address from config. ui/src/setup.ts — proxySnippet (the one copyable command, null for GUI-only clients), proxySteps and proxyOffSteps as plain-text data for all seven targets (macOS/Windows/Linux-GNOME/Firefox/Terminal/iOS-Sim/Android), each carrying the real address. defaultProxyTarget defaults the selector to the detected host (other→terminal); splitProxyAddr splits host/port on the last colon. ui/src/api.ts — defaultProxyAddr() resolves __TRAWLER_PROXY__ → sessionStorage → VITE_TRAWLER_PROXY → 127.0.0.1:7420, mirroring defaultBaseUrl (DEC-12). No hardcoded port in component code.
  • Step body wired, machine untouched. Onboarding.tsx's set-proxy body renders the client selector, steps, a one-click Copy command on command-shaped snippets, and — only when selected == host && auto-capable — the Set system proxy button with local idle/running/done/failed state. Turn-it-off steps sit in a <details> fold that tracks the selector. App.tsx supplies setProxy = splitProxyAddr(defaultProxyAddr()) → invoke("set_proxy", {host, port}). done means only "the command exited 0"; nothing transitions the machine — W4's capture proves routing.
  • Gates green, headless. 70 vitest tests (7 files) · 13 cargo test units in the standalone src-tauri crate · clippy pedantic clean · cargo xtask ui build (tsc + vite) clean.

Deviations

  • macOS elevation is inlined in the builder, not W2's elevated_argv. The plan said "reuse the osascript wrapper"; the set path needs a compound && script covering every enabled service in one prompt, which the single-argv elevated_argv can't express. set_proxy_commands builds the osascript script directly — same "do shell script … with administrator privileges" shape, one password prompt, unit-tested.
  • Shared useAction hook + ActionButton, not a copied TrustCa body. Trust-ca and set-proxy both run idle→running→done/failed with an error and a survive-unmount step glyph. The two identical runners were factored into one useAction hook and one ActionButton in Onboarding.tsx; the action-state testids became <action>-status/-error (so trust-ca's is now install-ca-error). Behaviour and IPC surface unchanged.
  • Neutral action-state key. The lifted state uses a neutral running (was trust-ca's installing) so both steps share the hook and the failed-glyph path; the per-step note text differs (INSTALL_NOTE / SETPROXY_NOTE).
  • Failure wording is proxy-specific. W2's failure_message says "install failed" — wrong for a proxy write, so set_proxy surfaces the OS stderr with its own "couldn't set the proxy" wording rather than reusing that helper verbatim.
  • Windows refresh is a self-contained P/Invoke one-liner. InternetSetOption is called via an inline Add-Type DllImport in the fixed PowerShell command (SETTINGS_CHANGED=39 then REFRESH=37), so running WinINET apps pick the proxy up immediately — no external dependency, still unelevated (HKCU).
  • Terminal / CLI added as a first-class client. Beyond the epic's client table, the selector exposes a Terminal / CLI target (export HTTPS_PROXY/HTTP_PROXY) — the common case for curl/npm/scripts and the default for an undetectable host.
  • Off-steps ship here as text; automatic revert is W5. A stale system proxy pointing at a stopped Trawler breaks connectivity, so per-client turn-it-off steps are always visible (mirroring W2's removal fold). Doing the revert automatically (on quit / after a crash) and a manual "stop routing through Trawler" toggle are their own WU (W5), as agreed in review.
  • Code-review round. The multi-agent review flagged (and this WU fixed): a trailing-colon / :0 address split to port 0, which u16 and valid_host both accepted silently — set_proxy now rejects port == 0 at the trust boundary (unit-tested); proxySteps no longer claims a "one-click button above" the manual snippet (that button is hidden when the client selector differs from the detected host), splits the address once, and the macOS snippet names the Wi-Fi service explicitly with a note to change it for Ethernet; App resolves defaultProxyAddr() once per render. Refuted as non-issues: the Windows InternetSetOption refresh discarding its BOOL (the registry write — the state that makes the proxy live — is the exit-code-checked step; the refresh only shortens pickup latency) and a double-quote in a service name (fails closed with a clean Err, local-only).
