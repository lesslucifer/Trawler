E-ONEAPP.W2 — the app supervises its core

The app spawns its own binary as --core before any window exists, tells every webview where it listens, keeps its state and log, restarts it on request, and stops it on every quit.

v1 · 2026-11-03 · Trawler · T3 WU plan · E-ONEAPP.W2 · branch wu/one-app/supervised-core · epic plan · depends on W1 · realizes DEC-68 rule 8

Requirement

Launched with no TRAWLER_API, the app spawns current_exe() --core --lifeline on 7420/7421 with its CA in the app data directory. It shows a window only after the ready line, with the bound API address injected into every webview before first paint. If a port is taken, a native dialog names it and the app quits without a window. The app exposes the core's state and log tail as Tauri commands and events, restarts it on the same ports on request, and on every quit closes its stdin, waits, then kills it. A second launch focuses the first window. With TRAWLER_API set, the app attaches to that core and spawns none.

The core is spawned in setup, not in main, so single-instance sends a second launch away before it could hit a port conflict. Config windows are built before the setup hook (tauri::app::setup), so each config declares "create": false and the hook builds the window once the address is known.
