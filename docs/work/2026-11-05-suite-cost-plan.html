suite-cost — the suite costs its tests, not its structure

One integration-test binary per crate instead of 28, and no doc-test pass for a crate with no doc-tests — guarded so neither can drift back silently.

v1 · 2026-11-05 · Trawler · T3 WU plan · E-GATEPAR2.W4 · epic plan · push timing report

Requirement

Every workspace crate's always-on integration tests compile into one binary, suite, rooted at <crate>/tests/suite/main.rs with one module per former file; feature-gated targets (hook-tests, design-e2e, codex-e2e, debug-tests) keep their own. Each of the three libraries (trawler, xtask, trawler_ui_lib) sets doctest = false, and a guard test fails when a doc comment in any doctest = false library gains a fenced example rustdoc would compile. The non-ignored test count is unchanged.

The tests/suite/main.rs layout is Cargo's own auto-discovered form: no autotests = false, so a new top-level test file still runs (as its own binary) rather than being silently dropped.
Gate 0 runs nextest, which never runs doc-tests (W3 result). doctest = false pays off for plain cargo test; the guard is what keeps a runnable example from going unexecuted on every gate.

Expected result

  • cargo nextest list --all shows one suite integration binary per crate; feature-gated targets build only with their feature.
  • The non-ignored test count before and after is identical, and every test passes.
  • cargo test -p <crate> --doc runs no doc-test pass for any of the three libraries.
  • A runnable fenced example in a doctest = false library fails the guard with its file:line; text, ignore and foreign-language fences pass.
