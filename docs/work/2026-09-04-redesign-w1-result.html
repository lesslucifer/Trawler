What the review changed

Six finders, then a re-review of the corrections by fresh design and correctness finders. Eight candidates, six verified, none waived. Two were load-bearing arguments that reached a defensible conclusion by a route that was not true — the failure mode the design rubric names as a contract that is complete, fluent and false.

Round 1 — on tip 9a28f12, fixed in 08101f7

1 · Field's F4 argued from a false premise. It said Select's in-popup filter "carries no aria-label of its own because the listbox above it is already named". Select.tsx:176 has aria-label="filter options", distinct from the listbox's at :201. Found independently by the reuse and design finders. The conclusion survived on the double-frame grounds also given; the reasoning was rebuilt on what is true — Select fixes that name where Field's B3 requires the caller to supply one. Corrected in all four places, including the TSDoc @avoid.

2 · StatusDot's central claim was contradicted by its own cited authority. The tri-state argument turned on "checking is transient, muted is terminal". DEC-19 reads muted as "informational / non-terminal", and StatusPill's shipped @states files null/pending → "…" under it — so StatusTone already carries a not-yet-resolved case. Rebuilt on the axis that is real: authority. TonedText's whole API is a caller-passed tone, so collapsing DotStatus into it would make connected caller-suppliable and let a call site render green while the app is still checking; DotStatus has no caller-facing constructor, only dotStatus().

3 · The warrant skipped its nearest sibling. IconButton is cited four times as precedent but never run through a reuse-or-propose fork. Added as S2b: the Button shell is genuinely shared, but IconButton is a T1 contracted to hold no business logic, and extending it would return the tone map to the call site — which StatusPill's @avoid and DEC-20 both forbid.

4 · The plan and the test note named the wrong mechanism (see deviations).

Round 2 — re-review on tip 08101f7

Both re-reviewers independently confirmed all four corrections hold against shipped code. The design finder checked the rebuilt argument adversarially — verifying TonedText's caller-passed tone prop and the absence of any caller-facing DotStatus constructor — and judged it a genuine improvement rather than a second rationalisation.

One further nit, again in a note rather than the work: the test/v2 note listed dec-26-the-mockup-mounts.html among the files still loading tw-config.js, but that file names it in prose only. Exactly two carry a live script tag. Corrected on the tip.

Worth carrying forward: four of the six verified findings were in claims about shipped code, and two of those were in the git notes rather than the designs. A component design's factual assertions — file:line citations, quoted @avoid lines, token values — are cheap to write and cheap to check, and they were where the errors concentrated. The screen runs W3/W5/W7/W9 will make many more of them.
