E-RELFIX — a release-candidate tag runs green on every platform

Fixes what each rc tag run of release.yml shows red, until one run builds, smokes, signs and drafts all five targets.

Intent

v0.1.0-1 went red at the host check (E-RCFIX). v0.1.0-2 (run 42159698428) went red at Build · linux-arm64's --bundle-only: tauri-bundler's rpm writer passes the version verbatim and rpm refuses the - every numeric pre-release has; fail-fast cancelled the other four rows. Steps after a red step have never run on GitHub, so each tag run can surface the next first-run bug. This epic collects those fixes as parallel Working Units, cuts each rc tag on its own tip, and merges into main only after one tag run is fully green.

Working units

How a WU lands. The owner names a problem → its data-wu block is added here by a doc commit on epic/release-fixes → a worker branches wu/release-fixes/<slug> off the epic in its own worktree, writes its WU plan (docs/work/2026-11-06-release-fixes-w<n>-<slug>-plan.html) before code, then commits, test/v2 + doc/v1 notes, the code-review skill (cr/v5), its WU result, and stages cargo xtask mr confirm wu <tip> --target epic/release-fixes --report <result> and the --no-ff merge for the owner. WUs run in parallel; a WU branched before another merged merges the epic in first when they touch the same file. Version: each tag needs the next unused 0.1.0-N; exactly one WU per tag bumps it (W1: 0.1.0-3), and the tag log below names it.

W1 · rpm-prerelease — a pre-release ships no rpm, every row runs to its end, 0.1.0-3

cargo xtask package drops rpm from Linux's bundles when the shipped version has a pre-release (rpm refuses -; tauri-bundler 2.12.4 rpm.rs passes version_string() verbatim). release-manifest requires the two rpm keys only for a final. release.yml's build matrix is fail-fast: false. The version becomes 0.1.0-3. The steps after the failing one (bundle on each OS, smoke, sign, upload, flatten, manifest) are audited against tauri-bundler's source for the same class of first-run bug. DEC-86 follows.

End-to-end plan

The epic's e2e is a tag run of release.yml on the epic tip: all five build rows green (bundle, smoke, sign, upload), the release job's manifest and a draft release. No local session can host it; each WU's own e2e is waived to that run, and the epic closes only on a fully green one (its run id in the epic result).

Distillation plan

DEC-86 (rules and known limits) in each WU that changes a release rule; the roadmap's packaging row at the epic close (the first green rc); the epic plan, WU plans and results move to docs/.archive/ at the close.
