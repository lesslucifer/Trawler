E-GATETRUTH.W3 — the gate names the cause it actually found

Two places where the verdict is right and the sentence is wrong. mr commit calls a landed commit a failure and buries git's one useful line under the whole message body; check 8 reports a valid note signed by a key this checkout never met as "no valid mr/v1 note". After this WU each message names the cause the code found, and nothing about what is accepted or refused moves.

WU plan · 2026-09-03 · Trawler · T3 (docs/work/) · wu/gate-truth/name-the-cause off epic/gate-truth @ 917fff4 · epic plan · W2 result · E-GATETRUTH.W3

Requirement

mr commit reports success when and only when HEAD moved, and on failure prints git's own output without the commit message body; and check 8 (8·manual-review) prints a distinct message for each way an mr/v1 note fails to authorise — no note, an unreadable note, a signer the running checkout's .mr-allowed does not list a key for (naming the signer and the roster's path), and a signature that does not verify over base..tip — while the set of tips it authorises is unchanged.

Two fixtures have to reproduce W12, not a neighbour of it. P2a: git ignores a post-commit hook's exit status, so no hook can make a landed commit exit non-zero. The end-to-end quadrant is driven by running the xtask binary with a git shim first on its PATH that execs the real git and exits 1 after a commit — in the subprocess only, never the test process. The pure verdict function carries the quadrant at unit level regardless. P3: the test Repo helpers commit .mr-allowed; a second worktree of such a repo inherits the roster and the gap never opens. The worktree fixture must gitignore the roster before either checkout writes it — exactly the DEC-10 layout — or the merge lands and the test has proved nothing.
