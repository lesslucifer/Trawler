E-QUERY.W3 — build the query bar

One QueryBar of filter chips replaces the header's four filter controls. The list follows the chips, never a keystroke, and the chips come back after a relaunch.

v1 · 2026-11-04 · Trawler · T3 WU plan · E-QUERY.W3 · branch wu/query-bar/query-bar-build · epic plan · base 96e3e313 · built from the QueryBar design (docs/work/components/query-bar.html, retired into QueryBar's TSDoc by this WU) and the design run · rules from DEC-71

Requirement

The app header holds one QueryBar where the free-text field, the host and method dropdowns and the status field were. A draft becomes a chip only when it parses (Enter or Tab take the highlighted suggestion, Space takes the draft as typed), and a draft that does not parse stays and says why. The listing, export and clear are sent the chips as W1's parameters, and the list refetches only when a chip is added or removed. A refusal from the core marks the chip it names. ⌘F focuses the bar, and the chips survive a relaunch.
