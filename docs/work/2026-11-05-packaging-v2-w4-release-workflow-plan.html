E-PKG2.W4 — a v* tag builds every installer and a draft release

release.yml, plus the two xtask commands that make its smoke and its latest.json testable without GitHub.

v1 · 2026-11-05 · Trawler · T3 WU plan · E-PKG2.W4 · branch wu/packaging-v2/release-workflow off epic/packaging-v2 (348b9f68) · epic plan · Q1, Q4, Q5, Q16, Q18, Q20 · DEC-81, DEC-82, DEC-83, DEC-85

Requirement

Pushing a tag v<version> runs .github/workflows/release.yml. It fails before any build when the tag differs from the workspace version. It builds five targets with cargo xtask package (macOS universal, Windows x64 and arm64, Linux x64 and arm64), smoke-tests each bundle before uploading anything, and ends in a draft release holding every installer, every updater .sig, a latest.json naming every platform and install kind, and notes headed by each OS's first-open steps.

Choices the plan makes (defaults, owner may overrule)

#ChoiceWhy
C1Build with cargo xtask package, not tauri-action. The epic plan's sentence "through tauri-action" is superseded.DEC-81 rule 3: one command builds an installer, and it verifies the macOS signature. tauri-action would be a second build path outside that check.
C2New cargo xtask smoke [--universal] [--profile p]: locate the bundle, install it to a temp dir (macOS: the .app as built; Windows: NSIS /S /D=; Linux: --appimage-extract-and-run), launch its binary --core with a temp CA dir, send a request through the proxy to a local origin, require it in GET /flows and the CA on disk (J1), stop it, and require both reported ports bindable again (J4).The epic's e2e_packaging (J1 to J4 with the window) is W6. The release needs a smoke now, and it must be the same code the macOS packaging test runs, so package_bundle.rs calls xtask smoke instead of carrying its own copy.
C3New cargo xtask release-manifest <dist-dir> --tag v… --repo owner/name writes latest.json and notes.md into the dist dir.A latest.json merge in shell is untestable. In Rust the platform keys, installer kinds, signatures and the "every platform present" refusal are unit tests.
C4The draft is never marked prerelease by the workflow.releases/latest/download skips drafts and prereleases, so an rc the app must take by update has to be a plain release. The owner can tick prerelease on a draft that nobody should update to.
C5Trigger: tag push only; no workflow_dispatch.A dispatch has no tag to check against the version.
