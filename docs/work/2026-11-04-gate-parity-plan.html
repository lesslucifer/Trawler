Gate parity — the merge proves what the push will check

A merge that goes green must leave a tree the push accepts, and the push must not re-pay for proof the merge already bought.

Draft v1 · 2026-11-04 · Trawler · T3 epic plan · E-GATEPAR

Intent

Today main can take a green epic merge and then go red on git push: the merge gate checks only notes, while the suite first runs on the merged tree at pre-push — after the merge commit already exists on a merge-only branch. The hooks are also slow: pre-push runs the whole suite blind on every push, the installed hooks have drifted from their tracked sources, and the Gate 0 cache thrashes across worktrees. Fix the order (prove the merged tree at the merge), then the cost: a push takes 10+ minutes, and about 95% of that is waiting on per-launch executable assessment rather than running tests (push timing report). Reuse the merge's proof at the push, and make the remaining suite runs pay for tests, not launches. Now, because six epics run in parallel worktrees, so every landing combines content no gate has tested.

Move the suite's first contact with the merged tree from push to merge; the push then reads the merge's proof.

Use-case requirements

A process epic — it delivers no UC-* behaviour and changes no use-case contract. Its contracts are the workflow's gate/hook rules (workflow.html § Hooks, DoD-W/DoD-E) and decisions/workflow-gates.html.

Expected result

  • An epic merge into main whose merged tree fails fmt/clippy/suite is refused at the merge; no red merge commit ever reaches main. WU → epic/* merges keep today's notes-only gate.
  • A merge whose tree equals an already-green tree (the common --no-ff of an up-to-date branch) costs a cache lookup, not a suite run.
  • Pushing a ref whose tree is proven green locally skips the suite and says so (gate0 skipped … (<key>)); an unproven tree still runs it.
  • core.hooksPath points at the tracked .cargo-husky/hooks/, so an installed copy cannot drift; a checkout without it is refused with the one fix command.
  • Green proofs from one worktree survive another worktree's run on the shared target/.
  • A push of a tree the merge already proved spends no time in the suite; the hook prints the cache hit.
  • A gate whose machine has the launch-assessment penalty (C6) says so up front with the one fix line, instead of a 10-minute run or a false red.
  • The push-timing report's commands, re-run at W7, show per-check wall time before vs after on the same machine. The speed claim is measured, not asserted.

Non-goals

  • No change to what a note proves or to gate checks 1–9; the review / mr / dod chain is untouched.
  • No remote CI; this is local hooks only.
  • No sharding or test selection, and no test is removed: W6 changes how the suite is packaged, not what it checks.
  • No change to macOS security settings from code. The Developer Tools exemption is a user action the gate only detects and names.
  • Not splitting the shared target/ per worktree (decided — see decisions).

Working units

W1 · hook-sync — installed hooks are the tracked hooks

Make the tracked .cargo-husky/hooks/ the hooks that actually run via core.hooksPath → .cargo-husky/hooks/, set by cargo xtask hooks install and verified by every gate entrypoint (unset or elsewhere → refuse with the fix command). cargo-husky's copy-install is retired. Fixes C4.

E-GATEPAR · C4 · workflow.html § Hooks.

After W1, editing a tracked hook takes effect in every worktree with no rebuild; a missing core.hooksPath is loudly refused.

none — lands first so W2/W3's hook edits reach the machine.

W2 · cache-per-key — proofs survive a shared target

Gate 0 and lint markers become a set of keys (e.g. target/.gate0-green/<key>, bounded/pruned) instead of one file holding the last key. Fixes C5.

E-GATEPAR · C5 · DEC-54 (amended).

Two worktrees alternating gate0 runs each hit their own cache on re-run.

none — independent; W3/W4 rely on its cache hit rate.

W3 · merge-proves-tree — the merge gate runs Gate 0 on the merged tree

For a merge into main only, pre-merge-commit (and the conflicted-merge path in pre-commit) runs cargo xtask gate0 on the merge result in the working tree after verify-dod hook is green; red refuses the merge with an abort/back-merge instruction. WU → epic/* merges are unchanged. Fixes C1 + C2.

E-GATEPAR · C1, C2 · DoD-W/DoD-E "merge --no-ff" rows.

An epic → main merge that combines two individually-green epics into a red tree is refused before the merge commit exists; an up-to-date merge is a cache hit; a WU → epic merge runs no suite.

E-GATEPAR.W1 (hook must reach the machine), E-GATEPAR.W2 (cheap hits).

W4 · push-reads-proof — pre-push reuses Gate 0

pre-push calls cargo xtask gate0 (cache-aware) instead of a blind suite, when the pushed sha's tree is the checked-out clean tree; otherwise it proves the pushed tree (never skips an unproven sha). Keeps the range check + notes sync. Fixes C3.

E-GATEPAR · C3 · workflow.html § Hooks (pre-push).

Push right after a green merge: no suite run. Push of a dirty or non-HEAD ref: suite runs.

E-GATEPAR.W1, E-GATEPAR.W2.

W5 · launch-guard — a slow-launch machine is named, not endured

cargo xtask hooks install (W1) and the suite-running gates probe the machine once: link a fresh tiny binary and time its first launch. Above a threshold → refuse with the Developer Tools fix line (Q6). The verdict is cached per machine. cargo-nextest becomes a checked prerequisite and the serial cargo test fallback goes (Q7). Fixes C6 (machine side), C7.

E-GATEPAR · C6, C7 · push timing report F1, F3, F5.

On a machine with the Gatekeeper wait, the gate names the cause in seconds instead of a 15-minute run or a false red; without nextest, it refuses with the install line.

E-GATEPAR.W1 (the install entrypoint).

W6 · suite-cost — the suite costs its tests, not its structure

Cut what the suite pays around its tests. (1) doctest = false for each crate with zero doc-tests, plus a unit test per crate that fails when a doc comment gains a runnable example, so a doc-test is never silently dropped. (2) Integration tests consolidated to one binary per crate (tests/it/main.rs + modules, Q5); the feature-gated hook tests keep their own targets. (3) Re-measure with the report's run-5 script. Fixes C8.

E-GATEPAR · C8 · push timing report F6, F7.

On this machine, cargo test --all after a change drops from 67 s toward its 13–14 s of tests; fewer binaries to link also trims the 56 s compile; no test is lost (passed count unchanged: compare the before/after totals).

none: independent of the gate WUs; lands before W7 so the measurement includes it.

The epic e2e (below), a re-run of the push timing report's commands (before/after per check), a new DEC, and the T1 Hooks table update (via mr commit).
