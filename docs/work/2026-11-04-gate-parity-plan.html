Gate parity — each checkout runs its own hooks and builds its own code

Parallel worktrees must not run another branch's hooks or link another branch's build. Ship that first; the merge/push parity work follows as E-GATEPAR2.

v3 · 2026-11-05 · Trawler · T3 epic plan · E-GATEPAR · scope cut to W1–W3 for an early release

Intent

Seven worktrees work in parallel on one machine, and two shared pieces make each one run code it did not check out. Hooks: git runs copies in .git/hooks that cargo-husky installed once, so landed hook changes never reach the machine (C4). Build output: every worktree symlinks one target/, where a workspace crate gets the same artifact name in every checkout and the uplifted binaries (target/debug/xtask) have none, so a build, a test or a gate in one worktree can link or execute another worktree's code with no error (C9, met live in E-GATEPAR.W1). Fix both now and release early, so every worktree can back-merge main and stop corrupting the others. The merge-proves-tree and suite-cost work in the original plan is deferred unchanged to E-GATEPAR2.

Share only what is identical across checkouts (third-party crates, by copy-on-write blocks); everything a checkout's own sources produce stays in that checkout.

Use-case requirements

A process epic — it delivers no UC-* behaviour and changes no use-case contract. Its contracts are the workflow's hook rules (workflow.html § Hooks) and decisions/workflow-gates.html.

Expected result

  • core.hooksPath points at the tracked .cargo-husky/hooks/, so an installed copy cannot drift; a gate in a checkout without it is refused with the one fix command. W1 done
  • Every worktree has its own target/ directory; a build, test or gate in one worktree never reads or overwrites another's workspace-crate artifacts or binaries.
  • A new worktree's target/ starts as a copy-on-write clone holding only third-party artifacts: no extra disk at creation, no third-party rebuild, and the first build compiles only the workspace crates.
  • A gate in a checkout whose target/ is still a symlink to another checkout is refused with the one fix command.
  • The shared tree's disk use is measured before and after the one-time prune, in the epic result.
  • After E-GATEPAR is on main, each live worktree syncs with one documented sequence (back-merge, isolate its target/), then one repo-wide cargo xtask hooks install.

Non-goals

  • Everything in Deferred to E-GATEPAR2: merge-proves-tree, push-reads-proof, launch guard, suite cost, timing re-measure.
  • No change to what a note proves or to gate checks 1–9; the review / mr / dod chain is untouched.
  • No shared compiler cache service (sccache); APFS clones are the sharing mechanism. Non-APFS hosts fall back to a fresh, unshared target/.
  • No dev-profile change unless W2's measurement shows the leftover debug objects regrow after the prune.

Working units

W1 · hook-sync — installed hooks are the tracked hooks

Make the tracked .cargo-husky/hooks/ the hooks that actually run via core.hooksPath → .cargo-husky/hooks/, set by cargo xtask hooks install and verified by every gate entrypoint (unset or elsewhere → refuse with the fix command). cargo-husky's copy-install is retired. Fixes C4.

E-GATEPAR · C4 · workflow.html § Hooks.

After W1, editing a tracked hook takes effect in every worktree with no rebuild; a missing core.hooksPath is loudly refused. The repo-wide install waits for the sync (install refuses while a sibling worktree would lose a hook).
