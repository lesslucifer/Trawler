What lands — three components, and what each one fixes

Two of the three ship today in the legacy kit, and neither ships correctly. W1 found three defects in shipped code; this WU is where they stop being true. A build that copies components.tsx's class string reproduces all three.

T1 · ui/src/components/Field.tsx

Field — the app's one text input

Controlled box, required aria-label, no validation, no debounce, no width of its own.

Fixes: the legacy box is px-3 py-chrome-y where Select's trigger is px-control-x py-control-y — a 3px/1px divergence, invisible alone and obvious once a Field sits beside a Select. DEC-18 says the app has one small-control box; this takes Select's.

T2 · ui/src/components/StatusDot.tsx

StatusDot — capture health, and the way back to setup

A 10px disc inside a 24px bare-square Button shell; owns the DotStatus→fill and DotStatus→phrase maps.

Fixes two: the shipped hit target is the 10px disc, failing WCAG 2.5.8 by 14px on the one control that must never be hard to hit; and its title alone leaves the button nameless, so it announces as "button". Both are real defects W1 found by designing shipped code.

T1 · ui/src/components/Disclosure.tsx

Disclosure — the collapse primitive

Native <details>/<summary>, UA marker suppressed, a › that rotates 90°, a slot that adds a gap and nothing else.

Fixes: three raw <details> in Onboarding.tsx each inherit a browser triangle the app never chose — chrome from outside the closed vocabulary that no lint can see, because there is no class to read. Its three call sites are W10's to migrate; the component is this WU's.

The one vocabulary gap — a config change, not a literal

Disclosure's twist needs rotate-90 and transition-transform. ui/tailwind.config.js declares transitionProperty with only colors, and declares no rotate scale at all — and under DEC-17 an undeclared scale means the class resolves to nothing, silently. So both classes are illegal today, and W1 handed the fix forward as an explicit blocked-on:

ScaleAddWhy exactly these members
rotate{ 0: "0deg", 90: "90deg" }The twist's two positions and no others. A scale left open inherits Tailwind's full ladder and the lint rule cannot see into it.
transitionPropertytransform alongside colorsThe rotation is the state change (motion-informs); nothing else in the app transitions a transform.

DEC-17's rule is the shape of this: "a value that has no utility needs a named token in the config, not a literal here". Nothing else in the three files needs a token that does not exist.

The order is the decision — step ③ is gated on step ①, because ① is the only step that can lose data.

A design file is ~600 lines; the TSDoc block it compiles to is nine. The difference is the forks and the frame drivers — exactly the part nobody re-reads, which is why the file looks redundant once the code exists. Eleven fork cards across the three files (F1–F4, S1–S4 incl. S2b, D1–D4) get read for what still constrains future work; a fork that was purely local is recorded as a dead end, not preserved.

The epic's distillation plan already reserves the home: "a new decision record — why the app's one text input and one state dot are registry entries rather than screen-local". That record is where the surviving forks land, together with StatusDot's tri-state argument (the DotStatus-is-not-StatusTone claim) which W1 recorded as a rulebook proposal and this WU is the first point that can act on.

What could go wrong

RiskHandling
The first design.implements citation does not pass. The epic plan flags the path as untested — "no design.implements citation exists on any note, ever" — and names W4 as the probe. But W2 builds a component, so W2 is where the citation is first owed, and therefore where the sharp edges surface first. Run design-scope before writing the note and read what the gate demands. If it refuses something the flow spec claims is legal, that is a finding for the gate — captured, not worked around. The extra wrinkle here: the citation names a design file this same WU deletes, so the {path, blob} pair must resolve at the range's last state (DEC-28/DEC-29) rather than at the tip. If it does not, the finding is real and belongs in the result.
The build copies the legacy class string and silently reproduces all three shipped defects. Both design files warn about this in their own words — "W2 must apply this delta, not copy the legacy string", "W2 must not copy the shipped class string". Each defect gets a unit test that asserts the corrected value, so a copy fails rather than passes. The three are enumerated in the test plan above by design-fork id (F2, S3, S4) — a reviewer can check each one lands.
Retirement loses the forks. Step ③ is cheap and step ① is not, so the pressure is to delete and move on — which is exactly the failure DEC-16's order exists to prevent. The deletion and the decision record land in one commit, so a diff that removes ~1,400 lines of design without adding the record is visibly incomplete. The epic's distillation plan already names the record, so its scope is not a judgment call made under deletion pressure.
Two StatusDots and two Fields in the tree at once, one legacy and one registry, for the length of the epic — the ambiguity the epic exists to remove, temporarily doubled. Accepted and bounded: the legacy kit is not importable from components/, no screen changes in this WU, and the epic assigns each removal to the WU that migrates its call sites (legacy StatusPill → W4, the kit itself → W11). Deleting them here would mean rewriting App.tsx against an undesigned layout — which is W3's design and W4's build.
The tri-state proposal has nowhere to land. W1 recorded DotStatus-is-not-StatusTone as a rulebook proposal, and this epic's non-goals freeze the rulebook. The freeze is on the flow spec, rulebook and gate as inputs to a run; the distillation plan explicitly expects this row ("Expected for StatusDot's tri-state"). It lands as part of the retirement's decision record and the rulebook row at distillation, per DEC-14 — not as a mid-run rewrite.
