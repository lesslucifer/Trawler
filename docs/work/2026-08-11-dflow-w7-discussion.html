The forks

D1 · Is Tier-2 already shipped?

What Tier-2 is. The self-reflex tier: the agent that just produced the design writes a verdict on its own work, one row per soft rule, machine-read. It is the cheapest possible defence against the epic's animating problem — an agent that forgets a rule cannot produce a complete receipt, and Tier-1 reds an incomplete one. It is not a check that the verdicts are true; a fluent satisfied costs nothing to write, which is the entire reason Tier-3 exists.

Concretely, in a run doc today: 
rulebook: <blob sha>
soft:
  data-ink-first: satisfied — zone B draws no chrome the payload does not need
  calm-microcopy: inherited — StatusLine owns every message on this screen
  empty-states-orient: n/a — no zone can be empty here
seven verdicts are legal (satisfied · inherited · satisfied-via-proposal · blocked · n/a · violated · violated-inherited), every soft slug in the rulebook must appear, and a hard slug appearing is a red — a rule with a predicate is judged by the predicate, never by a hand verdict.

So the question is only whether that counts as the tier. My read: it does. It was built in W4 out of necessity — the run that needed a receipt is the run that exposed why — and the epic plan's Tier-2 sentence describes it exactly.

That is the W4 receipt, and Tier-1 already refuses an incomplete one W7 records the tier as complete and spends nothing on it. D2 · What is Tier-3, mechanically?

First, what Tier-3 judges — the design artifact, not the built code. Its subject is a design run doc (or a component design file): the same thing Tier-1 checks mechanically and Tier-2 receipts. It is the design-side answer to the rule the dev workflow already runs on — never judge your own diff. test/v2 is a note you write about your own work; cr/v2 is the independent one. Tier-2 and Tier-3 are that same pair, applied to design — which is what settles where Tier-3 lives.

The ruling answered — round 3

Tier-3 is a dimension of the code review, not a second review. Once it is named as the design-side cr/v2, hosting it anywhere else means re-implementing independence, freshness, binding-to-exact-bytes and the merge-time enforcement that already exist and already work.

QuestionRuledWhat it turns on
host the existing code-review skill — a design rubric and a finder that activates when the diff carries a design artifact the guarantees Tier-3 needs are the ones cr already provides. A separate skill would rebuild every one of them, and then need its own merge-time enforcement on top
receipt cr/v3 — the note gains a design section, which is why the schema bumps the bump is for enforcement, not tidiness: without a field recording that the design dimension ran, a PASS on a design-bearing diff is indistinguishable from one where nobody looked at the design. Silence reading as correctly typed is the defect this epic keeps finding. The field is required when the diff contains a design artifact
when before the design reaches development — unchanged a cr-hosted review runs at the merge of the WU that lands the design. That is the upstream gate if the design lands in its own commit ahead of implementation — which is exactly W8's stated default. Flagged as the one dependency: if W8 rules that design and implementation share a WU, the review fires after the code is written and the gate stops being upstream
What survives from round 2, and what I had wrong. The inline principle survives where it belongs: Tier-2's receipt stays in the run doc and dies with the file, which is correct — the self-reflex claim is part of the artifact. Tier-3's verdict is about a commit, and commits are permanent even when the files in them are later retired under DEC-16. So the note is right because the artifact is transient, not despite it — the same way cr/v2 outlives code that gets refactored away.

Two things I argued and withdraw. "The subject is a doc, not a diff" — the run doc is in the diff; what Tier-3 needs is a rubric and a conditional finder, not a second orchestrator. And the content pin I owed: unnecessary now, because a cr note binds to a sha, so an edit after PASS invalidates the review the existing way. Sweep row 11's rulebook pin still stands on its own merits.

Unchanged by the ruling: the Tier-3 verdict and finding 29's review closing item stay separate artifacts. One is an independent agent's verdict; the other records what a human reviewer's instruction moved and what it cost. Merging them would lose the provenance half.
