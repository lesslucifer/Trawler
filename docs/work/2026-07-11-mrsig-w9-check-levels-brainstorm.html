E-MRSIG.W9 — Check-Levels Brainstorm

Rebalancing where human sign-off lives: mr always at WU and epic tips, result reports made gate-provable, commit-level signing narrowed to rule-bearing files (T0/T1).

T3 brainstorm (ungoverned — not a plan/result artifact) · 2026-07-11 · E-MRSIG.W9 · branch wu/mrsig/check-levels

The driver

Since .mr-allowed went all-key (d434d6d), every docs/-touching commit costs a Touch ID — including T3 scratch like this very doc, which the agent cannot commit without you. Meanwhile the sign-offs that carry real meaning (a human read what a WU actually delivered) are only demanded for UI paths. The proposal is one coherent move, not three: shift human authority up to the WU/epic boundaries, where a result report gives the human something worth reading — and narrow the per-commit signature down to the files that configure the rules themselves.

Commit level — sign T0/T1 only

Why these paths: T0 and T1 are the files that configure the workflow the agent runs under — CLAUDE.md steers every session, and docs/workflow.html / testing-strategy.html / documentation-system.html / work-planning.html define what the gates demand. An unsigned edit there lets an agent weaken its own gates. T2/T3 are agent-synthesized records: their quality is already judged by the WU/epic reviews that read them, and — with the WU change below — every one of them now passes a human mr boundary anyway. Docs stay gated at commit time for T0/T1 exactly as DEC-9 argued (post-hoc review of a rule change is too late); T2/T3 lose the commit gate because they gain a boundary one.

Decided (manager comment): .mr-allowed leaves git — gitignored, local-only. The signature check is a local-machine concern (hooks and gates all run locally), so the key list is local trust config like the hooks themselves, not versioned content. This dissolves the gap found here (an agent adding its own key to the tracked list rode ordinary infra commits): a local file edit is the same trust boundary as editing a hook — the workflow forbids it, DEC-2/DEC-6 already accept that shape. Supersedes DEC-7's "adding a person to .mr-allowed is itself a tracked, reviewable diff". Consequence: a fresh clone verifies nothing until mr setup recreates the list; tests are unaffected (temp repos build their own).

WU level — mr always, result report gate-checked

mr always: drop the UI-only path derivation; a WU tip needs a listed mr/v1 note, not waivable, exactly like an epic tip today — check 8's level predicate changes, the mr-rules-table row changes, nothing else. Like the epic rule, it runs independently of the docs/infra exemption: a docs-only WU still ends with a human. The trade is honest: today you touch Touch ID once per doc commit; after, once per WU — fewer touches, each one attached to a readable deliverable.

Result report: the standard already demands a wu-result doc before the merge, harness-verified at authoring time — but "Relation to the DoD gates: none mechanically". At the WU gate the report is unproblematic to check: T3 archival happens at epic close, so the docs/work/…-result.html file is legitimately tracked at the WU tip. Options:

MechanismAssessment
adoc/v1 gains a result_report: <path> field; gate check 6 verifies the file is tracked at the tip, data-artifact includes wu-result, verify-doc greencheap, purely mechanical, proves existence only
bmr confirm becomes sign-what-you-read: the wizard names the report, records its path + sha256 in mr/v1, and the Touch ID signature covers change-hash + report hash; check 8 verifies bothcouples the two proposals — the mr means "a human read this WU's result"; tamper-evident on the report bytes

Decided: b, with a's file check folded in. b is what makes "mr always" worth its touch — otherwise the WU mr is a blind tap.

Epic level — the report-vs-distillation tension

The tension the ask names: DoD-E demands the epic result report, but gate check 6 refuses anything tracked under docs/work/ at the epic tip, and T3 archival moves every work doc to untracked docs/.archive/ before the merge. So at the exact moment the epic gate runs, the report cannot be in git — today it exists only as a working-tree file (see mrsig-w3-result.html, sitting untracked right now) and the gate can't prove it ever existed. Options:

MechanismAssessment
alineage proof: epic-tip doc/v1 must carry an archived entry declaring the epic-result artifact with distilled_to; check 6 extensionmechanical but weak — proves a note claims a report; the file lives outside git
bsign-what-you-read, same as WU option b: mr confirm epic names the report, mr/v1 records path + sha256, the Touch ID signature covers change-hash + report hash; the archive copy re-hashes offline foreverstrongest — the human attests the exact bytes read, and archival can't erase the proof because the proof is the hash, not the file's git status
ctrack the epic result on main (carve a one-file exception into check 6)rejected — T3 on main rots by definition; T2 is the distilled truth (documentation-system)

Decided (manager comment): b (a comes along free — the hash has to point at an archive path, which is the lineage). Epic mr count is unchanged; only its meaning upgrades from "authorised this tip" to "read the result report and authorised this tip", with TRAWLER_SIGN_REASON naming it on the Touch ID sheet.

Where this lands

Landed in W9 itself (manager direction at the result-report review: implement with tests, don't defer to a follow-up epic). The enforcement, its unit + integration coverage and the updated e2e shipped in this WU together with the T1 flip — workflow.html / work-planning.html changed in the same diff as the hooks they describe, honouring "T1 states what the hooks enforce now" without ever letting the two drift. One design point surfaced during implementation: the epic walk never re-judges a WU tip's mr/v1 — manual review is boundary-only at seams (the WU merge hook gates the seam when it is made), or W1–W8's noteless historical seams would have reddened every future E-MRSIG gate, and any fresh clone (empty local .mr-allowed) would redden everything; recorded as a DEC-10 choice, same shape as DEC-9's doc-commit rule. Full seam list and test evidence: the W9 result report and DEC-10.
