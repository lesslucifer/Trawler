E-SIMPWF.W8 — a round costs less on both axes

The round stops paying an adversarial agent for candidates that cannot change its verdict, and stops spending its clock on reads the orchestrator could do once. Finders are never merged and verifiers never batched — W6 measured both as work moved, not removed. What moves here is the pool the verifier stage is spawned for, the reads the finder makes, and the price of the judgment — and the round times itself, so both axes have a reading.

v1 · 2026-09-14 · Trawler · T3 WU plan · E-SIMPWF.W8 · wu/simpwf/round-cost off epic/simpwf · epic plan · W6 result — the numbers this plan is built on

Requirement

A review round completes end to end inside 300s on the slowest case of the corpus, and spawns strictly fewer verifier agents than the candidates its finders raise. The orchestrator runs git diff once and packs the diff plus the BASE and HEAD text of the files it changes into every finder prompt; Gate 0 runs concurrently with the finder stage; a finder returns only candidates carrying a falsifiable failure scenario and self-applies the rubric's exclusions against the BASE text it was handed; a candidate proposed nit is recorded and dispositioned without buying a verifier, and only blocker and important candidates are verified — each still by one fresh agent of its own, on a model the skill names. Finders are never merged and verifiers never batched, stated as a rule so the measurement that refused them is not re-bought. The round writes elapsed seconds per stage and candidates by severity into cr/v5's fleet: block, so both axes have a reading. Each lever is adopted or dropped on its own number against § the A/B: a lever that loses a real finding is dropped alone, and the WU is recorded measured-and-rejected only if none survives.

Read off every cr note in this repository on 2026-09-14 — 196 notes, 195 with a parseable findings: block — beside W6's per-agent readings.

The 70% is a pre-W4 number, and this plan does not spend it as if it were current. Of the 191 refuted candidates whose rationale a note records, 59 (31%) name a docs/ artifact and no code path — the class W4's code-only rule abolished outright. cr/v4 rounds refute 43%, but on 21 candidates, which is too small to carry a decision. The current refutation rate is unmeasured, and measuring it is this WU's first reading. The levers below are sized against what the pool is made of, not against a rate that has already moved.

One lever is dead before it is built: dedup. Across all 191 recorded refutations there are zero exact duplicates within a round, and W6 found none between its two finders either. Two finders raising one claim is not where the fleet's money goes, and nothing here collapses candidates before the verifier stage.

The levers, and what each one removes

W6 established the rule this WU obeys: a cut that moves work between stages buys nothing. Merging finders cost +354s of fixed reasoning per agent and made the stage 152% slower for a 38% token saving; batching verifiers halved tokens and multiplied the stage by 4.6. Every lever below removes work instead.

Arithmetic, stated as arithmetic. Over measured stage means: Gate 0 concurrent (−60s), the finder stage packed (219s → ~145s), the verifier stage unchanged in shape and parallel (110s) puts a round at ~255s; the pool shrinking by the nit share puts the verifier stage near ~310k tokens, before L7's price change. This is arithmetic over measured stages, not a measured round — and the tail, not the mean, is what decides whether a real round lands. That is exactly what the A/B is for.

What W6 proved about method, and what this WU does differently

W6's cut was refused by its own measurement, and then its control arm refused the measurement: four of five probes showed the incumbent fleet failing the same bar on a fresh run. A round's findings are a sample, not a fixed set the rubric determines. Three corrections follow, and they are requirements of this plan, not commentary on the last one.

W6's methodWhy it could not decideThis WU
Arm B run live, arm A read off historical notes The two arms were measured by different instruments on different days; the 5-probe control that replaced the second arm then failed the bar itself Both arms actually run, on the same cases, at the same bases, in the same session
The bar was every known-real finding is raised No configuration of this review passes it, including the one in production — so it discriminates nothing A paired rate: per case, arm B's verified known-reals ≥ arm A's, and no blocker or important that A raises is missed by B
One bundled cut, one stopping rule A single escape dropped the whole shape, instrument and all — and the instrument was the part worth keeping Per-lever adoption. The levers are independent and separately attributable; a lever that loses a finding is dropped alone

The instrument — the round times itself and counts what it did not verify

The note stays cr/v5. No existing field changes meaning, every new field defaults, and a note without stage_seconds is a round that did not time itself — the same discipline W6 landed for the block as a whole, where an absent block is a reading not taken rather than a measured zero. A bump would buy nothing and would cost every v5 note written between W6 and here.

fleet:
  finders: 5

  verifier_model: haiku-4.5     # what the judgment was bought on
  candidates:                   # the pool the finders returned, before verification

    correctness:    { found: 3, verified: 2 }

The A/B — three arms, because the levers fail differently

Five of the eight levers can lose a finding, and they lose it at different stages. One corpus run cannot attribute an escape across all of them, which is the trap W6 fell into. Each arm below isolates what it measures.

Arm 1 · the verifier stage, on labelled candidates already in the tree

No finders run. This repository already holds a labelled candidate set: 43 verified findings with their severity across 14 notes, and 191 refuted claims with the rationale that killed them across 29 notes. Each one is replayed through the new verifier — one fresh agent, the same prompt, the model L7 names — and its verdict compared to the recorded one.

ReadingBar
Agreement on candidates the incumbent verified as blocker or important Total. One real finding flipped to false-positive drops L7 to the next model up, and the same run is re-read at that tier before L7 is dropped outright
Agreement on refuted candidates Reported, not barred. A disagreement here means the cheap verifier is stricter or looser than the incumbent, which is a reading about the pool, not a lost finding
Severity agreement Recorded per candidate. Uncertainty resolving upward must survive the model change — a cheap verifier that downgrades is a cheap verifier that silently un-fails reviews

Stated as a limit: the recorded verdicts are the incumbent's judgment, not ground truth. The subset drawn from FAIL rounds whose corrective commit followed is ground truth, and is reported separately.

Arm 2 · the finder stage, both arms run

The corpus is W6's, reused as it stands: 9 cases, 21 pre-registered known-real findings, each replayed at its own base. Arm A is the skill at the merge base; arm B is the skill carrying L1, L4 and L5. Both run, in the same session, on the same cases.

The token axis has no instrument the harness writes, and this plan does not pretend otherwise. What it trades, stated before it is measured

TradeWhat could go wrongWhat answers it
The nit that was really an important L6 A finder misfiles a real blocker as a nit; nothing re-judges it; the round passes. Today the verifier's severity is the one the verdict reads (DEC-47) precisely because finders misfile. Three layers. The finder must answer the severity test — nothing observable changes and nothing drifts — in one sentence for every nit, and the orchestrator promotes any nit whose sentence does not answer it, which buys a verifier. Arm 2 measures the misfile rate directly. If it is non-zero, the fallback is a verified 1-in-N sample of nits rather than dropping L6 blind.
A cheaper judge and a resolve-to-false-positive rule push the same way L7 The rubric already tells the verifier to resolve uncertainty against the finding. A weaker model does that more often, and the failure is silent — findings simply stop appearing. Arm 1 is aimed at exactly this, on 234 labelled candidates, with total agreement required on the verified blockers and importants and severity agreement recorded per candidate.
A finding that spans two shards L4 Sharding bounds the read set by splitting the diff; a claim about two files in different shards is raised by neither. Shard only past a stated size floor, never split a file, and record the shard map on the note. Arm 2 reports which cases sharded; a known-real lost only on a sharded case drops L4 and keeps the rest.
A red Gate 0 discards the round's finder tokens L2 Today Gate 0 blocks the finders precisely so a doomed round is never bought. Accepted on the owner's priority and stated rather than hidden: the clock is the scarce thing, Gate 0 is cached and green on the common path, and the round aborts the moment it reds.
The context pack moves tokens, it does not remove them L1 The same bytes enter five finder contexts either way; claiming a token saving here would repeat W6's error in the opposite direction. L1 is claimed as a time lever only. Whether the harness charges a shared prefix at cache rates is unmeasured, and no part of this plan's arithmetic assumes it.
The nits: list changes meaning Today every entry is a verified nit; after L6 it is a proposed one. A reader of an old note and a new one must not silently conflate them. DEC-47's dispositions are untouched and 3·review-nits is not edited — an undispositioned nit still reds. The change of meaning is recorded in DEC-48 and stated in workflow.html's Evidence row; the severity mix on the note is what tells a later reader which kind it is holding.
