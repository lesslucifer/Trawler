E-SIMPWF.W1 — the gate counts its own refusals

A local tally of every check id that refused, per gate level, and of the review rounds each gated tip paid — in the shape of Gate 0's cache: under target/, per checkout, never a git note, never evidence a gate trusts.

v1 · 2026-09-12 · Trawler · T3 WU plan · E-SIMPWF.W1 · wu/simpwf/measure-the-gate off epic/simpwf · epic plan

Requirement

cargo xtask tally prints, from a local file under target/ the gate appends to on every run, every check id that refused counted per gate level, and how many review rounds each gated tip paid — so an epic's owner can name both without reading a transcript — while the file is never a git note, never leaves the checkout, and no gate check reads it.

The gate writes the measurement on its way past; nothing in the gate ever reads it, so a deleted or doctored tally cannot move a verdict.
TermDefinition this WU fixes
refused a Failure the gate reported — its check id, at the level the gate ran (commit · working-unit · epic). Waivers are not refusals and are not counted.
gate run one invocation of verify-dod wu|epic (including the merge hook), verify-dod commit, or one commit inside verify-dod range. Green, red and exempt runs are all recorded: a green tip still paid for its rounds.
review round one cr note written on a commit in the run's base..tip range. The code review writes its note on the tip it judged whether the verdict is PASS or FAIL, so a range carrying a FAIL note and a PASS note paid two rounds.
tip the gated commit. The printed table reports one row per (level, tip), so repeated runs on one tip collapse: the union of its refused check ids, and the largest round count seen.
FieldWhy it is in the record
date · level · tip · base which run this was, at which gate level, over which range — the key the aggregation groups on
status — green · exempt · red an exempt run passed no check, which is not the same as passing every check
epic · wu the identity the tip's notes already carry, so a printed row names the unit rather than a bare sha
rounds the review rounds the work behind this tip paid (the term above)
checks the check ids that refused, in the order the gate reported them; empty on a green or exempt run

Where it lives: target/.gate-tally, one key=value record per line, appended by the gate. target/ is gitignored, so the file leaves no trace in history; cargo clean wipes it with the build artifacts it sits beside — deliberately, because a measurement that survives a clean clone is a claim, not a measurement. Same shape and same reason as Gate 0's target/.gate0-green cache.

Expected result

Observable afterWhere a reader checks it
After a gate run that refused, cargo xtask tally names the refused check id under that run's level — no transcript read the command's output, from target/.gate-tally
A tip whose range carries a FAIL note and a PASS note prints 2 rounds; a tip with one PASS prints 1 the "review rounds per tip" table
Repeated gate runs on one tip collapse to one printed row, with every check that ever refused and the largest round count the same table
No git note exists for the tally, and no refs/notes/* ref changes when the gate runs git for-each-ref refs/notes before and after
A missing or hand-deleted tally changes no gate verdict; the gate re-derives everything it decides delete target/.gate-tally, re-run the same gate, compare output
Nothing printed is an estimate: rounds and refusals are recomputed from git each time the record is written xtask/src/tally.rs
