What round 2 found — a blocker, and the WU's premise was wrong

Round 2 failed the WU on a reproduced blocker. DEC-51's premise — an epic's diff is the union of seams every Working Unit review already cleared — is false. Code also lands as a standalone commit directly on an epic branch, a category CLAUDE.md and the gate have always permitted and which the walk checks at Level::Commit, where no review was ever demanded. The epic-level review had been their blunt backstop, covering every byte in base..tip however it arrived.

The verifier reproduced it end to end and both ways: at this WU's tip, a standalone code commit on an epic branch signed via mr confirm epic and greened verify-dod epic — the exact call the real pre-merge-commit hook makes — with zero cr notes anywhere in its history; at the merge base, the byte-identical scenario was refused. A silent loss of this system's central guarantee, opened by this WU.

The fix restates the rule at the altitude it should have had: code owes a review where it lands. 3·review and its three subordinate checks now run at commit level too, bound to that commit's own code paths. The epic's re-read is then sound rather than merely cheap — every level where code can land owes a review of it, and 7·walk re-reads all of them. A standalone commit that changes no code owes none, exactly as a docs-only Working Unit does: the demand follows the code, never the level.

What round 3 found — the same hole, one commit over

Round 3 failed the WU on a second blocker of the same shape. Round 2's fix made a standalone code commit owe its own review, and that covers every such commit the walk visits. DEC-2 has the walk skip one commit by name: the epic tip, because it cannot carry both an epic-level and a commit-level test note. DEC-2 justified that skip by saying "the tip's own diff is covered by the epic gate itself" — the coverage DEC-51 removed. So a code fixup landed as the epic tip was judged by nobody.

Reproduced again through the real pre-merge-commit hook, green at this tip and refused at the merge base. The verifier also closed the two escape routes: mr confirm epic deliberately never asks, and the pre-push range mirror is blind to the commit once it has landed behind a merge.

The fix: the epic asks for that one commit's review itself, bound to tip^..tip — the commit's own span, not the epic's, because that is the only binding that says anything true about it. DEC-2's row is amended where it stands.

The lesson, recorded because it cost two rounds: removing a blunt backstop means finding every case it was quietly covering. "The seams" was a guess at that set, and the guess was wrong twice — once for commits in the range, once for the commit at the tip. Both were found by this WU's own fleet, which is the argument for the fleet and against the plan's confidence.

The merge-commit case is what ended it. The other three are positions, and a position can be patched — each has a commit to hang a review on. A merge's own content has none: it exists in neither parent, so no parent-to-parent diff can contain it, and no per-commit check can reach it. The only thing that ever covered it is a binding over the endpoint base..tip diff — which is the thing being removed.

The verifier drew a distinction worth keeping, because it is stronger than "the hash covered it": at the merge base, the review skill's own input scope — git diff base..tip for an epic — contained those bytes, so they were read. After the cut, no review's input scope ever contains them. That is strictly worse, not merely differently accounted. It is also the guarantee DEC-2 states outright — "smuggled content turns the next gate red" — given up without notice.

And reachability is ordinary. merge.ff = false repo-wide, so every WU merge is --no-ff; any conflicted merge is resolved by hand-editing before the commit completes, and the resulting content is by construction neither parent's. No malice and no exotic git required.

Three patches to the same premise each looked complete when made. The fourth hole was found only by enumerating arrivals systematically instead of reading the diff — which is how the work should have started, and is what DEC-51 now demands of any future attempt. Round 4's bill: 653k tokens, 3 finders (280k) and 3 verifiers (373k), stage_seconds total 1,063.

Round 5 — the withdrawal left residue, and the fleet found it

The first round over the reverted diff raised one candidate, verified important. It is residue from the withdrawal rather than from the change that remains.

Before this Working Unit, load_notes short-circuited to None at commit level before parse_note was ever called, so a cr note there was invisible. The experiment folded that into demanded = runs_at(REVIEW, level) && any(is_code) because the review then ran at commit level too. The withdrawal reverted runs_at and every call site but kept the folded form — and demanded gates only the missing-note branch. A note that is present is parsed and validated regardless, so a malformed or stray cr note on a standalone commit had begun to fail 1·notes at a level that demands no review at all.

The verifier found the signal that makes this unambiguous: the sibling design binding two lines below kept its explicit Level::Commit guard through the same revert, so cr and design had been left inconsistent with each other. That is what an accidental leftover looks like rather than a deliberate policy — and it is the fifth time in this Working Unit that a rule moved and something nearby did not move with it.

Reachability is not contrived: SKILL.md documents reviewing recent commits ad hoc and attaching the note to that commit, and an epic's 7·walk verifies every standalone commit at Level::Commit — so the spurious refusal would surface at a real merge gate over an already-reviewed epic.

Fixed by asking the table rather than naming the level: notes == Notes::Paperwork || !runs_at(REVIEW, report.level) — byte-equivalent to the pre-WU gate, with one statement of the rule instead of two. Two cases: the malformed note greens at commit level, and still reds 1·notes at a seam where a review is owed. Round 5's bill: 249k tokens — and it is the first round the conditional actually narrowed the fleet, spawning two finders rather than three, because the diff had shrunk to one module and its tests.
