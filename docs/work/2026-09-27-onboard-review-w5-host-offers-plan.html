E-ONBREV.W5 — what each host can read and offer

A host offers only the platforms that can run beside it. A probe that cannot read says so. The network task names the address and the interface it arms, and a host with no reachable address gets a way forward.

v1 · 2026-09-27 · Trawler · T3 WU plan · E-ONBREV.W5 · branch wu/onboard-review/host-offers · epic plan · findings R8 · R9 · R10 · R11 · R19–R22 · depends on E-ONBREV.W1 (merged)

Requirement

The platform question offers the iOS Simulator on macOS only, and the Android emulator on every host. The shell's proxy probe answers unknown whenever it cannot read: on every host with no reader, and whenever a reader fails to run or prints something it cannot parse. "Check again" shows only on a host where a probe can answer. The network task always shows the address it will arm, even when there is only one. Its button and its warning name that address's interface. A host with no reachable address says how to get one and offers a re-read. The tasks below it are then dimmed without "after step 1". Switching platform remounts the tasks, so every guide opens as the new platform's rule says, whatever the user closed on the last one.

The proxy reading, before and after

flowchart LR
  R[active_system_proxy os] --> S["Set(host, port)"]
  R --> O[Off]
  R --> U[Unreadable]
  S -->|matches Trawler| ours
  S -->|another address| foreign
  O --> none
  U --> unknown
  U -.before W5.-> none
Before, the reader returned one absence for "off" and for "could not read". So Linux, and any failed networksetup or reg run, read as "the system proxy is off" (R19). After, "could not read" is a reading of its own, and it reaches the screen as unknown. The task then says "we'll confirm this on this machine's first request".
