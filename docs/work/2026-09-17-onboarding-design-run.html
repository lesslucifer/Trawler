Set up capture

Trawler sits between a device and the internet. To show a device's HTTPS traffic, that device has to trust Trawler's certificate and send its traffic to Trawler.

which device's traffic do you want to see

overflow: lead, platform, probe, done, blocked and back cannot overflow; steps grows with the platform and the column scrolls whole — no inner scroller.

Payload is mono and copies whole: a command such as sudo update-ca-certificates, the certificate URL http://192.168.1.24:7421/ca.mobileconfig (on a phone, with a code under it that encodes exactly that URL), the server 192.168.1.24 and port 7420, and a failed command's own text under details.

The Simulator reads its own store and its marked request, nothing unmarked (round 16). This machine's own request carries a mark (?trawler-check=…, visible in the list) and its tasks read nothing else (round 12). Another device's carries one too, opened there, and its tasks read unmarked traffic only from after its address was allowed and while this Mac's proxy does not point here (round 13).
