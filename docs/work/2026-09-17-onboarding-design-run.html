Design run — the onboarding screen

A run of the simplified design flow on the screen that gets a user from a fresh install to a first decrypted flow. Its purpose is two-fold: a real design of the screen, and the first end-to-end exercise of the flow as DEC-53 cut it — six items, one human gate, a three-step close.

Design run · 2026-09-17 · Trawler · T3 (docs/work/) · substrate: registry (30 entries, emitted) · rulebook (12 hard rules) · ui/src/Onboarding.tsx read for capabilities only · review round 1 rebuilt the screen around a single platform choice

Given — what the screen is handed

Not given (may not be assumed to exist): a network address a device could reach Trawler at (it binds to 127.0.0.1 only) · any attribution of observed traffic to a platform or a device · a network-reachability check · any observable per-step completion · any persistence of the selected platform, so a relaunch returns to this machine · a notification channel outside the window.

Proposals

KindWhatWhy nothing existing fitsOwner
lexicon entry arriving — a connection Trawler received and could not decrypt The screen must name a third thing that is neither flow (there is none — nothing decrypted) nor not capturing (something is plainly reaching us). The rulebook's lexicon has a term for the exchange and a term for the milestone, and nothing for the half-arrival between them, so the verdict and the headline each invent their own words for it — which is the drift a vocabulary exists to stop rulebook · docs/design-rules/ lexicon table
lexicon entry platform — the one thing a run of setup is for: this machine, another machine, a simulator or a device The substrate calls its members targets and splits them into two lists (TrustTarget, ProxyTarget) whose members are operating systems and one browser. The screen now asks the user a single question with one answer, and that answer is not an operating system — iOS Simulator and iPhone share one. A screen-level term with no home in the lexicon is how two screens end up asking the same question in two vocabularies rulebook · docs/design-rules/ lexicon table
No component, token or key binding was proposed. Twelve placements resolved to nine registry entries and zero local elements — including the disclosure this screen's predecessor had to build local, which is now Disclosure (T1) and mounted here unchanged. The single platform Select lands inside Select's @use (one choice, eight options, a target picker) and needs no option groups, which its @avoid refuses.

Blocked-on

What is missingWhose callWhat the run did meanwhile
Trawler cannot be reached from anywhere but this machine. The proxy binds to 127.0.0.1 (src/config.rs) and the control API with it, so five of the eight platforms the screen now offers — another Mac, another Windows PC, another Ubuntu machine, an iPhone, an Android device — have nothing to point at, and no route to fetch the certificate either. A bind beyond loopback is also an authorization decision, not just a flag domain · core + control API kept all eight selectable and made the unreachable ones say what is missing, in the precondition that cannot be met, instead of printing steps that cannot work. Removing them from the list would have been the same silence the Given list exists to refuse
a network address to render once that bind exists — the screen has only proxyAddr, and setup.ts's own Android line already punts with prose ("Host = your machine's LAN address") domain · control API designed the device guide around a host and port the screen would print, and left the sentence that currently substitutes for it out of the mockup rather than shipping it as the answer
instruction content for the platforms the user named: TrustTarget has no iPhone or iPad member and no another machine member, and its single android entry conflates the emulator with a device — the emulator's host note (10.0.2.2) and the device's blocker sit in the same array build WU · ui/src/setup.ts wrote the iOS-device steps in the mockup as a draft the build must confirm, and split emulator from device in the picker so the two stop sharing one answer
