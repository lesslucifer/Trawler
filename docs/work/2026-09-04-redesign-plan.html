E-REDESIGN — every shipped screen, designed

Epic plan. E-DFLOW built the design flow and deliberately shipped no UI with it. This epic runs it on all five shipped screens and executes the design → build handoff for the first time.

Epic plan · 2026-09-04 · Trawler · T3 (docs/work/) · epic/redesign · flow spec: design-flow.html · rulebook: design-rules-index.html

Intent

E-DFLOW built the design flow — a staged method, a 30-rule rulebook, a 24-component registry with @use/@avoid contracts, and a three-tier gate — and closed with an explicit non-goal: "No Trawler UI re-design — a later epic uses this flow to design/ship UI." This is that epic. Every screen in ui/src/ was built by E-UIFOUND, E-UIINSPECT and E-UISETUP before the flow existed, so not one has a design behind it. The consequence is measurable, not theoretical: Gallery.tsx — a self-described throwaway — is the only file that imports the registry, so 23 of 24 components have exactly one consumer and it is the scratch screen. Meanwhile the real screens hand-roll what those components own, and because nothing forced a reuse-or-propose verdict, the duplication was invisible. This epic puts all five shipped screens through the flow and cites each build to its design, so the registry becomes the app's actual vocabulary.

This epic is the first design → build handoff in the repo's history. No design.implements citation exists on any note, ever. E-DFLOW.W9 deferred its build to W11; W11's result recorded the build as "Out of scope — owner's call" and named "the build WU" as still owed. Both WUs touched zero files under ui/src/ (verified: empty diffs). So gate check 9·design and the {path, blob, built} citation path are untested in practice — the first build WU here should expect to discover their sharp edges.

Three real defects the redesign fixes as a side effect

Unbounded body render

BodyViewer enforces only TREE_MAX — there is no TEXT_MAX, no HEX_MAX and no CutMarker anywhere in it. A capture-capped 10 MiB text body goes straight to the DOM. Every registry renderer enforces its cap.

Two StatusPills, conflicting contracts

The registry's takes status: number | null and owns the tone map; its @avoid forbids "pre-resolving tone at the call site". The legacy one is that violation, and is the one both screens call. It is really a copy of TonedText — whose own @anatomy cites components.tsx:25 as its ancestor — while squatting StatusPill's name. The swap changes prop shape, so it is not a rename.

Statuses have no reason phrase

403 renders as a bare 403, never "403 Forbidden" in title/aria-label. A screen-reader user gets a naked number. Registry StatusPill supplies the phrase.

Pre-existing debt this epic closes

Each is already scoped by a marker in the code that names this work:

  • BodyViewer.tsx:112 — "keeps its inline renderers until a later WU rewires it to the collection (E-DFLOW.W5 Q2)". This epic is that WU. It is also why xml currently renders as plain text and XmlRenderer is unreachable.
  • setup.ts:187 TODO [UI_DEFER] — the resolvers return full sentences, so StatusLine's short-message contract cannot be met; StepStatusView needs a short field. The marker self-assigns: "it lands with the screen that consumes StatusLine."
  • Gallery.tsx and its main.tsx guard — throwaway by its own header comment, deleted once the real screens consume the registry.

Three registry gaps that block screens

The registry has no text input, no status dot and no disclosure primitive — yet its own docstrings redirect to two of them as though they exist: KeyValueRow.tsx:8 says "editable forms (that is Field)", and StatusPill.tsx:10 says "proxy connection health — StatusDot". These block App's filter bar, App's header, and Onboarding's ManualPanel. W1/W2 close them before any screen run reads the registry.

Use-case requirements

No UC contract changes shape. This epic re-designs and re-builds the surfaces behind three existing contracts; a user's observable capability is preserved, not extended:

  • UC-4 Watch live traffic in the native app — the flow list and app shell (W3/W4).
  • UC-5 Inspect a captured flow — the detail panel and body viewers (W5–W8). Two contract-level gains land here: bodies gain the truncation statement they lack today, and xml becomes a real dispatch instead of falling through to text.
  • UC-ONBOARD Guided onboarding — the setup screen and quit dialog (W9/W10).

UC-3 is explicitly out of scope: the browser shell is served from the Rust binary, not ui/src/, and web-ui.html already rules that "the shell's minimal chrome is deliberate; the native app (UC-4) is the designed surface."

At distillation, docs/use-cases/web-ui.html absorbs the two UC-5 gains and any wording a run changes; if no observable contract moves, that is stated rather than assumed.

Expected result

After the epic, a reader who wasn't here can observe all of:

  • Five closed, archived design runs under docs/work/, one per screen, each verify-doc green with all eleven items, a rulebook pin matching the tip, and all 17 soft slugs receipted.
  • A design.implements citation on every build WU's cr/v3 note — {path, blob, built} — so cargo xtask design-scope origin/epic/redesign HEAD reports zero unaccounted surfaces. This is the first time the repo has one.
  • Every .tsx under ui/src/ accounted for: cited to a design, or declared undesigned with a reason (main.tsx is bootstrap, not a rendered surface).
  • The registry is the app's vocabulary. Every screen imports from ui/src/components/; ui/src/components.tsx is deleted; Gallery.tsx and its main.tsx guard are deleted. No component is hand-rolled where a registry entry owns it.
  • Three new registry entries — Field, StatusDot, Disclosure — each with the full tag set, and the two docstrings that pointed at phantoms now resolve.
  • The three defects are gone: bodies state their truncation, 403 carries "Forbidden", and exactly one StatusPill exists.
  • FlowList.test.tsx exists — today it is the only screen in ui/src/ with no adjacent test file.
  • The e2e suite still proves UC-4, UC-5 and UC-ONBOARD on the rebuilt screens, with onboarding.spec.ts rewritten to the new selectors keeping its spine.

Non-goals

  • No new user-facing feature. Every UC keeps its shape; this epic changes how screens are built and justified, not what the app can do.
  • No redesign of UC-3's browser shell — it is served from Rust and its minimal chrome is a standing decision.
  • No change to the flow spec, rulebook or gate. The substrate is an input, frozen per run. If a run's propose forces a rulebook entry that is distilled, but rewriting the method is out of scope.
  • No reading of the archived runs. Runs #4/#6/#8 designed this same setup screen; W9 runs blind to all three, as #8 ran blind to #4 and #6.
  • No hi-fi visual design — the draft mockup that mounts real components is the finish line.
  • No dialog shell or checkbox component. ProxyCloseDialog's modal and its "don't show again" box stay screen-local, warranted at W9's Elements stage (see open questions).
  • No verification that the build honoured its design. The gate answers is there a design, and is it this one — never whether the code obeyed it (a standing limitation of the flow, not of this epic).

Open questions

QuestionProposed default
Disclosure's tier. Section's @avoid says "a Section that needs to collapse (put the disclosure inside the slot instead)", implying a sibling primitive rather than a variant. T1, slot-based, no business logic — the host owns what is inside and whether it starts open.
The dialog shell and checkbox. ProxyCloseDialog hand-rolls a modal, a backdrop and a "don't show again" box; none has a registry owner. Leave both screen-local as T4 composition with a stated warrant at W9's Elements stage. One dialog does not establish a vocabulary; widening W1 on a sample of one is the more expensive mistake.
Per-header click-to-copy. Registry KeyValueRow makes every value a CopyText; today's raw <dl> has no such affordance. Adopting it silently adds a user-facing capability. Adopt it — it is the component's contract — and record it in W5's Interaction table so the gain is a decision, not a side effect.
W11's coverage map and the DEC-13 revert question (32 assertions classified; where proxy revert belongs). Deferred by decision — W9 runs blind. Both are recorded as epic follow-ups at close, not consumed as inputs.
Does the first design.implements citation actually pass? The path is untested; W4 is where we find out. Treat W4 as the probe. Run design-scope before writing the note, and if the gate refuses something the flow spec claims is legal, that is a finding for the gate — captured, not worked around.
