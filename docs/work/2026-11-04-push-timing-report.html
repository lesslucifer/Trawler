Push timing — where the 10+ minutes go

Every check git push runs, timed one by one on main @ 4d1c1942, loaded and quiet, with the wait traced to its cause. This is the E-GATEPAR baseline.

2026-11-04 · Trawler · T3 report · E-GATEPAR · macOS 26.5.1, 14 cores, 7 worktrees on one shared target/

Verdict

Fixed on this machine: a push after a code change dropped from ≈ 15.5 min to ≈ 2 min. The tests were never slow (13–20 s). Every freshly linked test binary waited a median of 21 s on a Gatekeeper scan, held up by syspolicyd's error loop. Enabling the Developer Tools exemption for Cursor and iTerm removed the wait. Restarting syspolicyd did not clear its error loop. The biggest remaining cost is doc-tests for crates with zero doc-tests: 52 of the 67 s test run.
