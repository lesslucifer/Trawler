E-DFLOW.W8 plan — design → dev

The finished design flow has never handed anything to development. W8 builds the seam: one rule about where a design lives relative to its build, one trigger, one pointer, and the e2e leg that drives them.

WU plan · 2026-08-13 · Trawler · T3 (docs/work/) · wu/design-flow/dev-integration → epic/design-flow · epic plan: E-DFLOW · W8 · direction: W8 discussion (D1–D6 + D1a, resolved) · prior: W7 result

Requirement

The design flow hands its output to development under one rule with two halves. Upstream: a UI Working Unit that adds a new registry component or a new screen must cite the closed design it implements — path plus blob — and the gate refuses the merge when the citation is missing, unresolvable, or names a design that is not closed. Downstream: no unbuilt design survives its epic — a component design added during an epic whose component is absent from the roster at the epic tip refuses the epic merge, unless the note records it as dropped and says why. Both halves are driven by a build leg on the flow e2e: a fake build Working Unit consuming a handed-over design, gated, including the case where the build amends the design it was handed. The rule is written before it is mechanised — the flow spec gains the hand-over step and workflow.html gains the design row — and DEC-16's "lives there and nowhere else" is superseded rather than annotated.

The worklist

① No unbuilt design survives the epic

The fork that blocks the epic merge rather than just this WU, so it goes first. Everything downstream assumes its rule: design and build share one epic.

PieceShape
components·unbuilt, epic level every path added under docs/work/components/ across the epic's range (--diff-filter=A) maps through component_designed to a name that must be in the roster at the tip. This is check_retirement (xtask/src/doc.rs:702) negated and moved to epic scope — the built case is already red there, so the two together say no component design file is ever both tracked and unaccounted for
Why check 6 is not enough check_tracked_docs forces the file out of the tree; it says nothing about the code. An agent can git rm a design and merge green today. The new check is about the roster, not the tree
The drop record design.dropped: [{path, why}] in the epic's cr note — the same (thing + non-empty reason) shape walk_waivers already uses, so a drop lands in the waiver bill the epic already reports instead of hiding beside it. An empty why is not a drop
Then the four deletions the predicate has to exist before the delete key does — W7·② set that precedent. Each drop carries its reason: body-renderer · header-table · copy-all-headers-button were never built; body-viewer's code exists as ui/src/BodyViewer.tsx and was never registered, which is a different fact and is recorded as one
E-DFLOW is the first epic its own rule refuses, and that is deliberate. A rule whose author exempts himself from its first application has not been tested. The drop record is what keeps this honest: the four contracts leave as a stated decision with four reasons, not as a quiet git rm in a distillation commit.

③ The trigger and the pointer

D2's answer, mechanised. Both halves reuse surfaces W7 built, and the reviewer and the gate read the same function — the one-function-two-callers rule design-scope already establishes, so the two cannot drift.

PieceShape
The trigger the diff adds a file under ui/src/components/ whose content carries @tier, or adds a non-test .tsx directly under ui/src/. Two --diff-filter=A globs and one content test — nothing new to read, since @tier is already the roster's own membership tag
The pointer cr/v3's existing design: section gains implements: [{path, blob}]. Not a new note and not a new schema version: a cr/v3 note that omits it is exactly the silence the section already exists to refuse, and Design is already Option-shaped for a diff that carries no design
The checks trigger fires and implements is empty → red · the path does not resolve at the tip → red · the blob differs from what the tip ships → red (reusing pin_matches/pin_of, the comparison check_design_pin already makes against the rulebook) · the named doc is not a design artifact → red · it is a design run that is not archived → red

Why the blob and not just the path. A path proves a file was named; a blob proves which bytes were read. It costs one field and buys D1a case 2 for free: a build WU whose cited blob differs from the blob its design WU closed is a build that amended its design, and that is a one-command count over notes already written. No monitoring machinery is built for it — the field is the monitor.

What is deliberately not here: no judgment that the code matches the design (D4·C), no per-proposal slice, no sixth finder. The gate answers "is there a design, and is it this one" — nothing about whether the build honoured it.

④ The e2e build leg

W7's e2e already drives a fake human and a fake designing agent through all three tiers over real git and the real merge hook, and it found two live gate holes no unit fixture could. The build leg is a second Working Unit on the same harness — Flow, bless, cr_note, merge_into_epic all exist.

CaseAsserts
The happy leg a design WU merges with its Tier-3 PASS; a build WU adds a @tier component, cites the design by path + blob, and the WU gate greens
The silent build the same build WU with no implements reds on 9·design — the trigger fired and nobody named a design
The stale citation a citation whose blob no longer matches the tip's bytes reds. This is the case a path-only pointer would pass
The amendment D1a case 2 the build WU edits the design it was handed. Its diff now carries a design artifact, so Tier-3 fires on this merge via the existing check_design, and the cited blob is the amended one — proving the re-judgment is automatic, not a rule anyone has to remember
The unbuilt epic a component design merged with no component reds the epic merge, and greens once the drop record names it with a reason
Stays out of the default suite feature-gated, as the existing flow e2e and tests/e2e_manual_review.rs are

The standing risk, named at planning (Q2). W8's handoff is enforced by two predicates and driven by a fake build. A handoff nobody real has driven reads exactly like one that works — the failure mode M1 caught this epic committing once already, when three design runs produced zero lines of product code. This WU accepts that risk knowingly; W9 is where it is paid, by making the first real Tier-3 judgment and the first real build the same run.
