Deviations from the plan

WhatWhy
The grammar got stricter than the plan's parser sketch. The plan implied the exact form was “parses as u16 in 100..=599”; the landed form is exactly three characters, all digits. The unit test found it: u16::from_str accepts a sign, so +404 parsed as 404, and 0404 would have too. Neither is how a status is written, and both would have been silent acceptances of a typo. The plan's own rule — the value denotes a real status or it is refused — is what the three-character shape enforces; the sketch was the looser statement of it. Both are now named refusals in the test.
Three existing unit-test call sites in store.rs changed. A mechanical type update — Some(200) → Some(StatusMatch::Exact(200)). No assertion was relaxed, retimed or deleted, and the expected counts are unchanged. The plan promised tests/api.rs's existing assertions unedited, and those are untouched.
No deviation on scope. No file under ui/src/ is in the diff, so the WU carries no design accounting, and the e2e assertion stays W6's as the epic plan assigns it.
The recorded narrowing: ?status=999 used to be 200 [] and is now 400. Nothing depended on it — the only client is the app, whose field a human types a code into, and the change makes the typo legible rather than indistinguishable from “no such traffic”. Carried forward from the plan so it is a decision on the record, not a surprise at the epic gate.
