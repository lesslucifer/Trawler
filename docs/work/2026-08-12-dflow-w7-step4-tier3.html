What makes a diff design-bearing

Tier-3 judges a finished design, which decides the whole rule — and inverts Tier-1's.

One function, two callers. design-scope is not a convenience — it is the refusal to let the reviewer and the gate each decide what counts. The reviewer runs it, the merge calls it, and the note lists exactly what it printed.

The design: section, and what each field refuses

FieldRefuses
artifacts a PASS covering a design nobody opened. Every path design-scope prints must appear; judging one of two artifacts and passing both is the exact shape of the silence the bump exists for
rulebook a verdict about a rulebook nobody read — step ③'s finding, one tier up. Compared against the blob at the tip, so a later Working Unit revising the rulebook cannot retroactively falsify a review that was true when it ran
verdict a note whose overall PASS hides a failing design dimension
the section's presence the whole point: on a design-bearing tip, a note that says nothing about the design is refused rather than read as clean

The grandfather rule — why this step cost zero waivers

Step ③ added one rule and paid three walk waivers, and filed the arithmetic as a follow-up: a dozen by the epic merge means the walk's verdict has become mostly waiver. cr/v3 is exactly the kind of rule that would have cost more — every landed seam carries a cr/v2 note, and no edit can give one a design section without claiming a judgment nobody made.

The schema string is the record. A note declaring cr/v2 says, in its own bytes, that it was written before the design dimension existed — so the epic walk drops that one check (9·design-schema) at seams, exactly as it already drops manual review there. What it does not drop is a cr/v3 note missing or short-changing its design section: that note's own schema says the dimension was available. No date cutoff, no remembered list, no waiver — the distinction a date could never draw is drawn by the artifact itself.

The rubric — and what it refuses to look at

JudgesThe defect shape
every soft verdict in the receipt a fluent satisfied the design does not earn — the author wrote both the design and the claim
the soft rules against the design itself a rule broken by the part of the artifact its receipt row does not describe
the new-component warrant a component invented while an existing entry's @use covered it
the reuse warrant — the same question inverted run #3's finding 21: the citation resolved and was wrong. Tier-1 checks a citation exists; only a reader checks it is true
n/a · blocked · inherited the three ways a design exits a rule without satisfying it

The exclusions carry as much weight as the rows. No hard rules (thirteen predicates own them, and a second opinion is noise) · no per-rule verdict table (that is Tier-2's receipt, and re-emitting it doubles the artifact and buries the findings) · no slugless taste · and no rulebook edits — a rule that cannot be judged as written is a finding, never a same-run loosening, which is the failure DEC-15 names.

What actually exercises the tier instead. This Working Unit's own diff is design-bearing — it edits archived run #3 — so design-scope already reports one artifact to judge, and step ⑥'s review must run the design finder over it and write the first cr/v3 in the repo. The tier is proved by use, on a live merge that can be refused, rather than by a rehearsal against history. The three documented defects stay in the rubric (§4) as the bar a finder is held to — the calibration table is the specification even where the run of it was waived.

Named risk, unchanged: Tier-3 is an LLM judging prose rules and no unit test asserts a judgment is correct. What the tests below assert is everything around the judgment — that it ran, over everything, against the right rulebook, and that its absence is loud.
