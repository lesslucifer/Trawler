E-ONBREV.W4 — actions follow their task's reading

Every action, every manual step and every sentence on the setup screen is rendered from the reading of the task it belongs to and from the outcome of the action, never from the host alone. This closes the owner's report (R12) and the six sweep findings with the same root.

v1 · 2026-09-26 · Trawler · T3 WU plan · E-ONBREV.W4 · branch wu/onboard-review/actions-follow-reading · epic plan · findings R12–R18 · depends on E-ONBREV.W1 (merged, the before is recorded)

Requirement

On the setup screen, the combined "Set up this machine" action is offered only while both halves read not done; otherwise each task carries its own action and steps. A task that reads done offers no action and no install steps, only its way back. The reversal renders inside the task it reverses and names only what is installed. A failed action opens its manual route. The success line names this machine only when both probes read done, and the not-decrypting remedy never contradicts a trust probe that reads done. The design of record states each of these readings, and a permanent state-matrix test asserts the place, time and truth rules over every host × platform × trust × proxy × traffic × outcome.

Done is the probe's reading: trust reads trusted, or the proxy reads ours. Anything else, including a reading that could not conclude, is not done. The layout follows the reading and not the status line, so a re-check in flight does not flip it. The iOS Simulator already renders the per-task layout, and now follows the same rule for its proxy task (R15). A host with no automatic setup has no buttons, and its done tasks also fold to their way back.
