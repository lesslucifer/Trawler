E-DFLOW.W9 — the fresh screen, really built

Seven steps, and the epic's last unpaid debt is every one of them. The design flow runs greenfield on the setup screen, Tier-3 is made to go red before it is allowed to go green, and a real build adopts the closed design — the first time in this epic's nine Working Units that a design reaches product code.

WU plan · 2026-08-14 · Trawler · T3 (docs/work/) · wu/design-flow/fresh-screen off epic/design-flow @ 620c7c4 · discussion (3 rounds, all forks ruled) · epic plan · W8 result

Requirement

The finished design flow is run on a screen it has never designed under the current substrate, and its output is really built. Run #4 designs onboarding greenfield — six stages, against the current registry and rulebook, without runs #1–#3 as input — and closes green. Tier-3 goes red before it may go green: a deliberately doctored copy of the closed design, carrying one dishonestly paraphrased @avoid, is submitted first and must return FAIL; only then is the real design submitted, and it must return PASS. A real build then adopts the closed design through the DEC-25 handoff, citing path plus blob plus the files it produced, and firing both the new_surface and the edit legs — or, where the design honestly proposed no new surface, reporting that as a named gap rather than manufacturing one. The mockup mounts the components it claims to reuse instead of hand-drawing pictures of them, and the rule that says so is enforced rather than skipped (step ④.5). UC-ONBOARD and DEC-13 are amended where the design demands it, the screen's shipped test suite is retired with the design it guarded and replaced by the tests the new design needs, and a coverage map records what each retired test asserted and where that assertion went.

The worklist

⓪ Re-take every number this plan will rest on

This epic has corrected a restated-rather-than-re-taken figure in four consecutive review rounds. So before any step consumes one:

  • Which of the 13 hard predicates have never gone red on a real artifact — recomputed over the three archived runs, not read out of DEC-17.
  • The registry as the flow will actually load it (node scripts/design-registry.mjs) and the rulebook blob (git hash-object docs/design-rules/design-rules-index.html).
  • The exact inventory of what run #4's build will retire: every test file, every assertion, every data-testid the current screen exposes. This is the coverage map's left-hand column, and it must be taken before anything is deleted.
Pass the base explicitly and make sure it is current. design-scope and verify-dod both measure from a branch ref; a local epic ref behind its remote silently measures the wrong diff. That produced a false "1 design artifact to judge" in W7 ④ that a whole acceptance argument then rested on.

① Run #4 — the design, greenfield

The six stages (Frame → Layout → Elements → Interaction → Draft mockup → Tune) on the setup screen, per the flow spec, with verify-doc after every write and green at the close before data-status="archived".

ConstraintWhy it is a constraint and not advice
Runs #1–#3 are not read during the run D1. An independent run is what makes the later #4-vs-#3 comparison a measurement rather than a tautology

The build Working Unit cites what it built from: git rev-parse <tip>:<the design> → design.implements: [{path, blob, built}] in the cr/v3 note. This is W8's machinery used in anger for the first time — no stub component, no one-line screen, and an agent that has actually read the contract it cites.

④.5 The mockup composes the components, not pictures of them

W5 made a design file's specimen the component itself — scripts/build-specimens.mjs compiles ui/src/components/ plus React into doc-assets/components/specimens.bundle.js, which a doc loads over file:// as a classic script and reads as window.Trawler. The design run's mockup stage never migrated, and nothing noticed, because the only check that could have noticed skips exactly the files it should refuse.

The consequence that gets measured, never assumed. check_vocabulary scans authored classes, so every class a mounted component draws leaves Tier-1's sight. Taken over run #4's current mockup: 75 distinct class tokens — 55 are also drawn by a collection component and would leave the scan, 20 are the screen's own and stay. ④.5 reports which of the 13 hard predicates keep a trigger population on the migrated run and which lose one, and whether the departing classes are gated anywhere else. If they are not, the migration trades one blindness for another, and that answer goes in the record rather than being argued away.

Red before green, the same shape as ③. The new predicate must refuse run #4's current hand-drawn mockup before it is allowed to pass the migrated one. Both verdicts are recorded; a predicate that only ever went green proves nothing.

The cost, stated rather than discovered. Run #4's bytes change, so the ④ citation re-pins and, under DEC-25, the amendment re-enters Tier-3 on the merge that lands it. That is the blob pin working, not a cost to avoid.

Not here: wiring check-render.mjs into verify-dod. It drives a real Chrome and the DoD gate is hermetic — headless cargo build and cargo test stay GUI-free. ④.5 fixes the skip that made it silent and leaves a browser-in-the-gate to a record that can weigh it.

⑤ The build, and the suite that retires with the design it guarded

Onboarding is rebuilt from the closed design. Per R3, the shipped suite goes with the design it was written against — it asserts onb-next, trust-target, data-status="active" and this screen's exact microcopy, all of which are design decisions the redesign is entitled to change.

The cost R3 accepts, carried here so the result report does not rediscover it. W9 keeps no independent regression evidence. The run that changes the UI also writes the tests that judge it, so a green suite proves the new build matches the new design and nothing more. The coverage map is the whole mitigation: every retired assertion, and either where it landed in the new suite or why it was deliberately dropped with the matching UC-ONBOARD / DEC-13 amendment. Its left column is taken at step ⓪, before anything is deleted — afterwards it cannot be reconstructed.

⑥ The contract, and the non-goals struck in writing

  • UC-ONBOARD in docs/use-cases/web-ui.html and DEC-13 amended to what actually ships — or an explicit statement that neither moved.
  • The epic plan's two non-goals struck, citing DEC-25, with the reason: accepted as the verification vehicle, not as a product mandate.
  • W8 follow-up 9 answered by observation: does the first screen design retire the way DEC-16 retires a component design, and if not, what actually happened at the tip.

⑦ Distillation, review, merge

The distillation checklist runs in the same session as the change. The code-review skill on the tip, cr/v3 PASS bound to that exact diff, then the merge. Not here: promoting the flow spec to T1, the epic's drop record for the 4 of 20 unbuilt component designs, and archiving the T3 run docs — all owed at the epic distillation and merge, not this WU's.

What could go wrong, and what happens then

RiskRuled response
Tier-3 passes the doctored design. The tier cannot catch the one class it solely owns W9 halts at ③. That is a finding about the harness, not a reason to proceed — everything downstream would be evidence about a finder already known to be blind. It becomes the epic's largest result, reported as such
The redesign proposes nothing new, so new_surface never fires Ruled at Q1: report the gap. No component is manufactured to trip a predicate
All 13 predicates stay green on run #4, so the never-red set does not shrink Reported as the measurement it is. A live screen that violates nothing is weak evidence for the predicates and strong evidence for the flow — both get said, and neither is dressed as the other
The rebuild is larger than one Working Unit can carry The standing default is one WU, because splitting re-opens the exact gap DEC-25 exists to close. If it must split, the design and the build stay in the same WU and something else moves — never the handoff
A capability quietly disappears in the suite swap The coverage map is the only thing that catches it, which is why its left column is taken at ⓪ rather than reconstructed at ⑤
Mounting hollows out Tier-1. 55 of the mockup's 75 class tokens leave check_vocabulary's scan, and nothing else gates them Then ④.5 has traded a blindness for a blindness, and says so rather than shipping the trade quietly. The migration still stands — a mockup that imitates a component is wrong about what it draws, which is worse than a scan with less to read — but the uncovered set is named, counted, and left as the next question. It is not answered by widening a predicate in this WU
The bundle folds in specimen.js and the theme, which assets·specimen separately requires — so a migrated run loads both Measured before the predicate is written, not assumed: whether the doubled load double-binds anything. Whichever way it lands, the predicate is changed to match the shape that actually works, and the alternative it rejected is recorded
