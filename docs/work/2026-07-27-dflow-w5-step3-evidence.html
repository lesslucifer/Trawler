Round 2 — the check was wrong, and it hid 385 real defects

The first pass of this evidence was a false green. Review found four specimens visibly broken — CopyText's confirm, Select entirely, StatusLine's checkbox, StepList's numbering. All four were real, and the verification above had passed them. Two independent causes, both structural rather than incidental:
#Root causeWhy the first check missed itScale
1 Utilities were appended, not swapped. The old sheet expressed a state as .ct.s-confirm — a second rule that won by cascade order. The migration wrote both the resting and the state utility onto one element (text-ink-body text-ok), and two utilities setting the same property are decided by Tailwind's emit order, not by authoring order. The state silently lost. The probe skipped every element whose classes disagreed, calling it "ambiguous cascade" — so precisely the broken cases were excluded from the count. 385 utilities across 15 files, in 16 property groups
2 Scripts still emitted the deleted sheet's class names. Nine specimens build DOM at runtime; the migration rewrote static markup only. querySelectorAll('.seg'), .ht-key, .chip, .sel-opt matched nothing, and classList.add('s-confirm') added a class no stylesheet defined. The check read the file as parsed HTML. Runtime-generated markup never existed for it to read. 9 files, 6 dead selectors, 12 emitting sites
3 Two file-local rules were orphaned — .sel-pop.inflow and .seg-group.disabled. Both are compound selectors whose first class the migration replaced, so neither matched afterwards: all 17 static popups in select.html rendered absolute and overlapped. Neither class is in the shared vocabulary, so the residue scan — which checked the deleted sheet's names — had no reason to look at them. 17 popups + 2 disabled groups
What the second round changed in the method. The rewritten check asserts every utility on every element and skips nothing, so a conflict is a failure rather than an exclusion. Three of its own bugs had to be fixed before its output could be trusted — substring matching (text-control inside px-control-x), border-t-* legitimately overriding border-hairline, and inline shorthands (padding vs padding-left). Each produced a false failure, which is the safe direction. A separate static check now enforces zero same-property utility pairs across 16 groups — the invariant that makes swap-not-append checkable without a browser.
One correction worth recording. The dedupe first treated items-* and justify-* as one group; they are align-items and justify-content, and collapsing them stripped alignment from 139 elements. Caught by the browser check, restored from the mapping table, and re-verified: 0 alignment mismatches. The lesson is the same one as above — a property group is defined by the CSS property, not by the class prefix.

What was deliberately not touched

Left aloneWhy
Doc scaffolding CSS — .panel, .swatch, .part, .anno, .tsdoc, fork cardsNo code counterpart, so no drift risk. Only component contract moved. This is what keeps the change small.
14 ambiguous class names — warn, notice, key, val, active, sel, chip, cut, glyph, tag, attr, shape, arr, offEach is both a component class and htmldoc's own vocabulary (callout warn, badge warn). The migration is scoped to .app subtrees by a DOM parser, so plan and discussion docs were never rewritten. A regex-based pass would have corrupted every doc's callouts.
The four → W6 markers — 8px floor, hover washes, syntax tokensW6's to rule on. W5 made them expressible (they are now named config tokens) without deciding whether they are permissible.
specimen.jsBehaviour, not style. It absorbed the sheet's doc-interaction rules and now injects them itself.
Component code (ui/src/components/)That is step 4. Step 3's job was to make the contracts safe to build from.

Two findings the process itself produced. The migration surfaced defects nobody had filed: (1) fourteen design files each hand-declared their own copy of the .app token block — the exact duplication the shared sheet was created to remove, and which it never actually removed; (2) the assets·specimen gate demanded a file that step 3 deletes, so the gate would have blocked its own outcome. Both are fixed here.
