E-SIMPWF — the workflow costs less to obey

Cut the two costs that dominate a unit of work — hand-authoring facts the tooling already knows, and re-running the whole review when nothing it judged changed — without lowering a bar the gate holds today.

Draft v1 · 2026-09-12 · Trawler · T3 · epic/simpwf → main · E-SIMPWF

Intent

Make the workflow cheaper to obey at its two dominant costs — an agent hand-writing facts the tooling already knows, and a passing review becoming worthless because something later changed the tree — so that the same bar is held with fewer agent passes, and so that the next round of cuts is chosen from counts instead of judgment.

Where the cost actually is

Every check in the project is either a program an agent runs or a generation an agent performs. The program half is cheap and measured: verify-dod is under 0.5% of an epic's wall-clock (DEC-11). The generation half is where the time goes, and it is spent in two shapes.

ShapeWhat it looks likeWhy it repeats
Authoring YAML notes carrying hashes, bases, branch names, tiers, changed-doc paths and per-layer counts — all of them already known to a tool that just ran. A hand-typed derived field is a red check, and a red check is a repair.
Re-running The review fleet — five finders plus a design finder, and one adversarial verifier per candidate finding. Its PASS is stamped with a fingerprint of the whole diff, so any later change — a nit, a failing test, a fix found after the review — voids it and buys the fleet again.

The expensive path is not the review. It is the review bought a second time because something else moved late.

The evidence is a real epic, not a model: E-RFINISH ran eight Working Units through 144 candidate findings and 47 verified, needed a second round on one WU, and its close took three review rounds. DEC-11 separately measured that landing a gate-heavy epic cost 45–106 minutes of active agent time, with the review fleet at a stable ~25% and main-loop generation at 32–56%.

Use-case requirements

This is a process epic: it changes how work is planned, evidenced and merged. It touches no product use-case, and no UC-* contract changes. The behavior it governs is the workflow itself, whose standard is workflow.html.

The paperwork finishes before the exam A preflight command the review runs first refuses while anything tree-changing is still red — the doc predicates over every doc, every design run closed, the note schemas parsing, the citation and render gates — so no finder spawns against a tree that is still going to move. The re-run cost: a PASS that a later paperwork fix orphans. A red doc, an open design run or malformed notes stops the review before any finder spawns, in one block that names the blocker. none
The tool writes the notes, the agent writes the judgment A note-writing command in the shape of xtask mr confirm takes the judgment text and writes test/v2 and doc/v1, deriving the base, head, hashes, identity, tiers, changed-doc paths and per-layer counts. The authoring cost: facts the tooling already knows, retyped by an agent. Both notes are written in one command and pass the gate first time; a derived-field mismatch is impossible rather than repaired. W2 — the preflight is where the shape is refused before the review runs.
A nit does not restart the exam Only blockers and importants fail a review; a verified nit is recorded and must be dispositioned — fixed, or waived with a reason — in the note the gate reads. The re-run cost: a whole fleet round spent on one small finding. A tip passes with recorded, dispositioned nits; an undispositioned nit is refused; the epic's A/B against known-real findings shows recall held. W1 — the effect on recall is measured, not asserted.
The review is code-only The code review's scope and fingerprint cover code paths: a doc change is answered by the doc predicate at authoring time and by the human sign-off, never by the fleet. A whole-diff binding that puts documentation inside a code review's blast radius. A doc-only commit after a PASS leaves the PASS valid and needs no review — what docs already get at the gate, now extended to the binding — while a code commit still voids it. W1 — the decision record cites measured rounds, not an assumption.
Re-check only what changed (experiment — droppable) After a corrective fix the review re-runs only the dimensions the delta can reach, reusing the verdicts of dimensions it cannot, under a safe-delta definition stated in the skill. The re-run cost: the full fleet re-bought by every fix. A fix confined to one file re-runs at most the dimensions whose findings touched it, with the A/B showing no known-real finding escapes — and if one does, this WU is dropped and the epic closes without it. W1, W6 — the measurement decides it and the code-only scope is its precondition.

W4 is a gap on purpose. The single-unit light path was dropped at plan review — the owner ruled it not needed now — and the ids are not renumbered, so the gap records the drop rather than hiding it.

Open questions

UndecidedProposed default
Does the code-only rule of W6 also silence the design dimension, which judges design artifacts — docs by definition? No. The design finder stays the named exception until the design epic rules on it, so the rule this epic lands reads "the code review judges code", with design artifacts owned separately.
Does the measurement of W1 live in a note or only locally? Locally, in the shape of Gate 0's cache — a number to choose with, never evidence a gate trusts.
Do the authoring-time doc checks need a harness-independent backstop? No new commit-time check. The review preflight of W2 reads every doc on any harness, which is where a malformed doc can still be caught before the fleet runs.
Does the design epic open before or after this one closes? After — this epic's distillation writes its roadmap row, and the two never judge each other's seams.

W1 first because it decides the rest. W2 and W3 only remove wasted passes. W5–W7 each trade something away and are adopted only on measurement.

Stopping rule. A WU that lowers a bar — W5, W6, W7 — is dropped rather than argued for if its measurement does not hold. The epic still closes: W1–W3 stand on their own, and each of W5–W7 is named in the epic result either as landed or as measured-and-rejected, with the number that decided it.
