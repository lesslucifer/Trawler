E-RFINISH.W9 — the body view switch says what it does

One word is doing two jobs: the body pane's left segment is labelled decoded, but both of its positions are decoded — the switch is about re-indenting, not about decoding. E-DFLOW.W6 ruled the terms raw | pretty correct and the build wrong. This WU changes the build, in every surface that names the position, in one reviewed diff.

WU plan · 2026-09-08 · Trawler · T3 (docs/work/) · wu/redesign-finish/raw-pretty → epic/redesign-finish · lexicon: rulebook · contract: UC-5

Requirement

The body pane's view switch names its two positions with the lexicon's terms — raw and pretty — everywhere the position is named: on screen, in the code that holds it, in the unit, integration and e2e tests that drive it, and in the T2 documents that state the contract. Behaviour does not change: the same two fetches, the same two dispatches, the same default.

Why decoded is the wrong word

The switch has two positions and the core has three decode resolutions. Both positions the switch can reach are decoded; they differ only in whether the bytes are re-indented. So the label names the thing the two positions share instead of the thing that separates them.

What stays: the order, the default, the control

Order stays readable-first

design run #9 drew it

The archived body-viewer run drew [decoded│raw] and cited progressive-disclosure: the readable view is the default, raw is the depth. The ruling's phrase raw | pretty names the term pair the way the lexicon lists it, not a left-to-right order. So the screen reads [pretty│raw] and prose naming the pair reads raw | pretty.

Default stays pretty

unchanged

useState(true) — the pane opens on the readable view and the first fetch is ?decode=1, exactly as today. A relabelled default is still the default.

The control is not re-designed

SegmentedControl, per its @avoid

Two option labels change in the tenant's own MODES array. No prop, no state, no zone, no key binding, no dispatch. SegmentedControl's docstring says what the options mean is the tenant's business — this is that business, corrected.

Test plan

All three levels, no waiver. A pure rename has one failure mode worth testing — a surface left behind — so each level asserts the new name and the absence of the old one, and the behaviour assertions that already exist are the guard that nothing else moved.

Design citation

No design artifact. BodyViewer.tsx is declared design.undesigned on the cr/v3 note: the run that designed the body viewer resolved this control to SegmentedControl, drew the switch readable-first under progressive-disclosure, and the change is to the two option labels — the control, its order, its default and its dispatch all stand. The words were ruled wrong by E-DFLOW.W6, not the shape. The same declaration covers the two decision records and the rulebook example, all of which cite the retired label rather than a shape.
