Deviations

Difference from the planWhy
Cookie headers are joined, a rule beyond epic decision 5 (the plan flagged it in advance) the proxy's own normalization (hudsucker normalize_request) does it. An h2 seed may split cookies, and an HTTP/1.1 upstream takes one
the response body gets its own 30 s deadline after the head. A stall lands the flow with a read_error body decision 4 bounds only the wait for the head. Without a second bound, a reply that stalls mid-body would hold the send open indefinitely. A head arrived, so the exchange happened and the flow is owed
tests/api.rs's summary-row key lock gains seed the lock exists so that no field joins the row by accident. This one joins by design (epic expected result 3), so the lock is updated rather than bypassed
the recorder's version_str / headers_to_vec moved to flow.rs as version_token / header_list, with their tests the sender needs the same spellings. A second copy could drift, and the sender importing from the recorder would couple the two producers
a URL carrying user:pass@ is refused (400, or 422 on a seed), and the core's Host is the URL's host and port. Found by the review the first review round reproduced Host: user:pass@… on the wire. Credentials in a URL are neither a Host nor an Authorization header, so the doors refuse them rather than drop them or invent a header from them
the sent request body is recorded through capture::capture, not a local classifier. Found by the review the plan named the capture cap as the rule. A second implementation of it could drift, so the proxy's own function now holds both producers' bodies
the 504 integration test waits 1 s, not the shipped 30 s it drives test_support::api_router_with_sender with Sender::with_deadline, a test-only seam (cfg(test-utils)). The shipped deadline stays a constant, as decision 4 ruled

W2 · W3: the composer's draft The composer always sends a whole header list, so the API treats every row, the seed's Host included, as typed. If the user changes the URL's host and leaves a seeded Host row, the stale Host goes out. The draft module has to drop or re-derive an unedited seed Host row when the URL's authority changes, or the run has to show that row as following the URL
