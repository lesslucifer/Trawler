Why a tokeniser, and why now

Six code-review rounds each found a hole in these four functions, and each fix revealed the next. That is the signature of one missing abstraction, not six bugs — and every later step in this WU adds a predicate that would read through them.

Quoting, tag ends, comments, CDATA and single-quoted values move into the tokeniser. What stayed hand-written is the part it does not own: HTML's raw-text rule for <script> and <style>, and recovery at a tag that never closes.

The six holes, as tests rather than comments

Each was a review round in W6 ⑥. Each already had a test; the swap is what turns the long comment that explained the hole into a case the tokeniser cannot re-open.

#The holeThe test that pins it
1an attribute quoted inside another attribute's value read as a declaration an_attribute_quoted_inside_another_value_declares_nothing
2a tag end taken from a bracket inside a quoted value a_bracket_inside_a_value_does_not_end_the_tag
3re-syncing past a malformed tag and lending one element another's classes an_unclosed_quote_does_not_lend_one_element_anothers_classes
4quotes re-pairing across a fault, dropping the attributes before it a_legal_bracket_survives_a_later_fault_in_the_same_tag
5a legal title holding an escaped angle bracket a_raw_angle_bracket_in_an_attribute_value_is_red · a_raw_bracket_in_prose_is_named_not_tolerated
6a snippet cut at a byte boundary mid-character naming_a_raw_bracket_survives_a_multibyte_value

Plus unclosed_artifact_tag_fails_toward_checking_not_draft_silence, which is why Attr carries closed: a truncated tag's data-artifact is read, so the doc is governed, while its data-status is not, so it cannot fall silent.

What the swap added, and what tests it

New logicWhy it existsTest
Raw-text elements skipped a < inside a script is data. Every component design file builds its specimen from template literals, so tokenising the body reads class="${NT}" as a declaration and a < b as a tag — two corpus files stopped the parse outright before this rule a_class_a_script_writes_is_not_a_declaration
Recovery at a fault the unclosed tag yields what it declared, then reading resumes at the next <. Running to EOF instead would let one malformed tag silence nine sections and read as green a_fault_does_not_silence_the_declarations_after_it
Text is the gaps filled is now "the tokeniser did not claim this", so a comment is markup and a section holding only one is empty — the old scanner counted the tail of a value after a quoted > as text a_section_holding_only_a_comment_is_empty

The three differences the comparison did find

All three are the swap doing what it was asked to. None moves a verdict on any doc as it sits.

The dependency, against the house rule. "Never add one for what a few lines can do" — six review rounds are the evidence that these were not a few lines. The cost turned out to be zero anyway: quick-xml 0.37 is already in Cargo.lock for the proxy crate, so this adds a line to xtask/Cargo.toml and nothing to the supply chain. xtask now carries quick-xml · serde · serde_yaml · tempfile.

What was deliberately not swapped

Still hand-writtenWhy it stays
elements_of · data_rows · gists · words · inner_text the plan names four functions, and these four are where the six holes were. These read fragments for counting, and none of them decides whether a declaration exists — the failure mode that produced the rounds. Candidates for a later pass, not for this one
mockup_declarations · colour_literal · strip_css_comments they read CSS, not HTML. A tokeniser for the markup answers nothing about .a-measure{max-width:460px}
read_pragmas' comment scan the pragma is line-anchored by design (a moved line stops matching), so it reads lines, not nodes
