W2 · target-isolation — each worktree builds into its own target

A build, test or gate in one worktree never reads or overwrites another's workspace-crate artifacts; only third-party artifacts are shared, by copy-on-write clone.

Draft v1 · 2026-11-05 · Trawler · T3 WU plan · E-GATEPAR.W2 · epic: E-GATEPAR plan

Requirement

cargo xtask target seed gives a checkout a target/ directory holding only the main checkout's third-party artifacts (APFS clone, mtimes kept; empty elsewhere); target isolate replaces a symlinked target with a seeded one; target prune drops workspace-crate artifacts and incremental/ from a checkout's target/ and prints what it freed; a new worktree is seeded by post-checkout instead of symlinked; and each gate entrypoint refuses with exit 1 and cargo xtask target isolate in a checkout whose target is a symlink.

Expected result

  • A seeded worktree's first cargo build compiles only workspace crates; its target/ is a directory with no workspace-crate artifact, no incremental/, no gate marker.
  • Two checkouts that build the same workspace crate from different sources each run their own code, whatever the source files' mtimes.
  • cargo xtask lint / gate0 / verify-dod … / preflight … in a symlinked checkout print the refusal and cargo xtask target isolate, exit 1, run nothing else; after isolate they run.
  • prune prints bytes removed and volume free space before/after; the main checkout's tally history survives in the common dir.
  • This machine (rollout, owner-paused): six symlinked worktrees isolated, the main checkout pruned, numbers in the WU result.
