E-UIFOUND.W1 — Project scaffold & build integration

WU plan — establish the ui/ front-end project and wire it into cargo xtask ui, with the core workspace kept GUI-free.

v1 · 2026-07-12 · Trawler · T3 WU plan · epic: E-UIFOUND

Requirement

A ui/ front-end project (Tauri 2 + Vite + TypeScript + React + Tailwind, mirroring Strata's layout) builds to ui/dist/ and launches a native window via cargo xtask ui, with ui/src-tauri a standalone crate outside the core Cargo workspace so a headless cargo build/cargo test of the proxy stays GUI-free; the front-end test runner (Vitest) is established and the app boots to a placeholder view (real content is W2).

Maps to

Epic E-UIFOUND requirement "codebase in the build" + the project layout and thin-shell decisions. No UC (infrastructure) — the demoable tenant (UC-4) lands in W2.

Expected

  • cargo xtask ui build runs the real pnpm pipeline and emits a bundle in ui/dist/ (ui/dist/index.html present).
  • cargo xtask ui dev launches the Tauri window (the shell crate compiles; generate_context! validates config/icons/capabilities).
  • cargo metadata for the core workspace does not list the trawler-ui crate; cargo build/cargo test -p trawler pull no GUI toolchain.
  • Vitest runs; a smoke test asserts the React root mounts. App shows a placeholder view.
