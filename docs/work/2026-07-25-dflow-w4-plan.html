Test plan

LevelWhat asserts what
integrationxtask/tests/verify_doc.rs · a design run is receipted against the rulebook on disk — writes a rulebook and a run doc into a TempDir and drives the real binary: green prints the coverage tally and the machine-checked hard-rule count; a receipt missing a soft rule, carrying a verdict outside the enum, or claiming a hard rule exits 1 naming each. That is the WU's contract — a design run cannot pass by asserting things about itself.
unitxtask/src/doc.rs · 13 tests over the checker: slug extraction from the rulebook's own tables (header rows and non-slug code spans excluded) · a conforming run green with the computed tally · missing slug · hard slug · misspelling paired with its nearest miss · bad verdict · absent citation · malformed YAML surfacing serde_yaml's position · unreadable rulebook red rather than silently green · unkeyed catalog · static mockup · unlinked specimens (a prose mention does not count) · colour literal red while an id selector and color-mix over tokens stay green.
e2ewaived: the scripted flow e2e (fake user + fake agent) is W7 per the epic plan.

The design work itself remains review territory — no test asserts that a design is good. What the tests assert is that a run cannot claim to have followed the flow without having done so: the checker is wired into the doc hooks, so a red design run blocks the write and the turn.
