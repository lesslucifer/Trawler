E-ONBOARD.W1 — reach: Trawler answers off this machine

The bind stops being a constant and becomes an authorization decision: off by default, armed by one explicit confirm, reported as an address a second device can actually use.

v1 · 2026-09-19 · Trawler · T3 (docs/work/) · branch wu/onboarding-redesign/reach · epic E-ONBOARD

Requirement

Trawler binds loopback only until a user explicitly turns reachability on; once on, it also binds one interface address the user named, the control API reports that address and the certificate URL that works over it, and the proxy and /ca.crt answer there — with the CORS grant unchanged and the opt-in dying with the process.

The loopback bind is untouched by arming — reach adds a second pair of listeners rather than moving the first. Disarming drops them; so does process exit, which is why the opt-in cannot outlive a launch.

What DEC-55 settles

The epic plan left three questions open at this WU. The record answers all three, and states the exposure plainly rather than implying it.

QuestionRuling
Bind 0.0.0.0, or one interface the user names? One named address. The unspecified address is refused outright — the screen must print an address anyway, and a mistaken confirm should cost one network, not every one the host is on
Does the control API need a token, TLS or a narrowed CORS policy once reachable? No, and the boundary is written down. The confirmed opt-in is this epic's whole authorization boundary. Arming exposes the proxy and the control API — captured traffic included — to the chosen network; the record says so, so the residue is stated debt rather than an unstated assumption. The CORS grant does not widen
Does the opt-in survive a relaunch? No — re-armed per launch. Nothing is persisted; the listeners live in the process. It is the revert-on-quit symmetry DEC-13 already requires of the system proxy, got for free by never writing the state down

And one thing the record must not overclaim: the confirm establishes user intent. It is not an access control against something that already holds loopback — anything that can reach the control API can arm reach, exactly as anything that can reach it can already clear the capture. Reach is off by default and turns on only by an explicit act; that is the property, and the record states its limit.

Test plan

Every test is hermetic: ephemeral ports, a temp CA dir, a local origin. The second listener is bound on loopback — which is what makes "a second device" assertable without the network this suite may not touch. No test reaches a real interface.
