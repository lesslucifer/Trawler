The sheet is the single rendering source for every component specimen and every screen mockup that composes them.
QuestionAnswer
What is it?A 254-line stylesheet (plus a 47-line specimen.js for the doc behaviours) at docs/work/components/specimen.css. It holds the app token scope and one class block per component, so a design file's specimen and a screen mockup both link it instead of re-declaring colour, padding, radius, family or hit area.
Why does it exist?W4's review round rejected the first run-2 mockup for re-typing component values instead of composing them — it had silently drifted from five confirmed contracts. Wording could not fix that; one file to link, which the gate can then require, could.
How is W5 affected?W4 extracted it verbatim and refused to reconcile anything: where a file's specimen disagrees with its own token table, or two files draw the same thing differently, the line carries a CONFLICT: marker and the header says outright "belongs to W5; picking a side here would hide it." There are 10 markers waiting.
Why it is not cosmeticFive of the ten are registry defects, invisible while each file rendered alone. Resolving them is also what makes the build honest: the components W5 now implements must be built from one agreed value per part, not from a file that draws 10 px and specs py-3.
