E-UIINSPECT.W2 — Flow detail panel

Row click → the reserved detail region: headers · timing · HTTP versions · copy-as-curl.

v1 · 2026-07-13 · Trawler · wu-result · E-UIINSPECT.W2 · branch wu/uiinsp/detail-panel

Outcome

E-UIFOUND shipped the live flow list but left Layout.detail empty. W2 fills it: clicking a row selects the flow and opens the detail panel over the existing GET /flows/{id} — no new endpoint, no core change. The panel renders:

RegionShows
Header barmethod, status pill (functional color via statusTone), total duration, a close (×) button
Requestthe full request URI + HTTP/1.1 → HTTP/2.0 version line
Copy as curla runnable curl in a <pre> + a copy button that writes it to the clipboard
Headersrequest + response header tables (name/value), "none" when empty
Bodya one-line state summary per leg — the placeholder W3 replaces with real viewers

The typed client gains getFlow(id) → FlowView (+ HeaderView / BodyView types mirroring the server's view.rs). A useFlowDetail hook fetches on selection change with stale-response cancellation; toCurl / bodyText are pure functions in flow.ts alongside toRow. UI-only — no Rust touched, the core stays GUI-free. The requirement sentence ("row selection → the detail region; client gains getFlow; panel renders request line, status, timing, versions, header tables, and copy-as-curl; body area a placeholder W3 replaces") is met in full.

Deviations

None from the requirement or contract; no new dependencies — W2 reuses the E-UIFOUND kit (Layout, StatusPill, statusTone) and the existing typed client. One review-round fix:

The code review found one verified real defect: the copy button's copied=true state persisted when the selection moved to another flow — the same FlowDetail instance was reused, so the "copied" label showed for a flow the user never copied. Fixed by keying the panel with key={selectedId} so it remounts (and resets local state) on reselect; a regression test guards it. The other 11 candidates were adjudicated false-positive (notably atob-on-malformed-base64 is unreachable — the server's BodyView::Captured always emits STANDARD.encode base64 that atob accepts) or excluded micro-optimizations; two comment nits were trimmed to the self-documenting rule. No debt left behind.
