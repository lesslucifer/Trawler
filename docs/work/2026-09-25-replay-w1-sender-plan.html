E-REPLAY.W1 — the sender: Trawler sends a request and records what came back

Two POST doors, one sender built from the proxy's own parts, and a third provenance value. What comes back lands as a flow, and a transport failure lands nothing.

v1 · 2026-09-25 · Trawler · T3 WU plan · E-REPLAY.W1 · branch wu/replay/sender · epic plan

Requirement

POST /flows/{id}/replay sends the seed flow's request again, with any of its method, URL, headers or body overridden (an absent override is the seed's own value), and POST /flows sends a request written from scratch. Both go through one sender that verifies TLS exactly as the proxy does. The exchange lands in the ring as an ordinary flow marked source: "sent" that names its seed, and the call answers 201 with that flow once the reply exists. A transport failure answers with its reason in words and lands nothing. A seed whose body was never captured is refused by name unless the caller supplies a body.

WhereWhat lands
src/sender.rs (new, core) Sender: a hyper-util Client over upstream_connector(&config.upstream_extra_root_pems) (the proxy's own function, so verification cannot differ), the capture body_cap, and a response deadline of 30 s. send(Outgoing, seed) → Result<Flow, SendError>. The header rules are a pure function beside it. It returns the flow, and the store is the caller's concern, so the sender is testable with no ring
src/api/send.rs (new) the two JSON bodies (deny_unknown_fields), the override merge (seed + overrides → Outgoing), the compose check, and the refusal → status mapping. Pure, so every refusal is a unit test
src/api/routes.rs · src/api/mod.rs replay_flow and send_flow. /flows gains .post, and /flows/{id}/replay is a new route. AppState gains sender. router(…) takes it, and its callers follow: lib::serve, test_support::api_router and the routes-test state. The ?source= refusal names three values
src/flow.rs FlowSource::Sent, Flow.seed: Option<FlowId>, Flow::sent(seed) (the only thing that sets either). The recorder's version_str / headers_to_vec move here so the proxy and the sender spell a version and a header list one way
src/api/view.rs the sent token both ways, and seed (id or null) on FlowView and FlowSummary. It is always present, so a row has one shape whatever its source
src/store.rs nothing new. Store::import already lands a finished flow in one lock and announces both events. Its doc widens from "a file" to "outside the proxy"

The wire contract

RequestAnswer
POST /flows/{id}/replay + { "method"?, "url"?, "headers"?, "body"? | "body_base64"? }, or an empty body (= {}) 201 · Location: /flows/<new> · the new FlowView. A given headers list replaces the seed's list whole (decision 1). body is text sent as UTF-8, body_base64 is bytes, "" is an empty body, and null is absent
POST /flows + { "method", "url", "headers"?, "body"? | "body_base64"? } the same 201, seed: null
not JSON · an unknown field · body and body_base64 both · bad base64 · a missing method/url (compose) · a method that is not a token · a URL that is not absolute http(s) · a header name or value the wire cannot carry 400, naming the field: method is required, url must be absolute http(s), unknown field "header". An unknown field is refused, because a typo'd "header" would otherwise silently send the seed's headers
an id that is not a flow id · a seed no longer in the ring 400 invalid flow id · 404 no flow <id> in the ring
a seed that cannot be sent as it stands: its body streaming / too_large / read_error and no body given, or its URL not absolute http(s) and no URL given 422, naming the absence: the seed's request body was not captured (too_large); give a body to replace it. The split is 400 = the caller's request is malformed · 422 = it is well-formed but the seed lacks what must be supplied
refused, unresolvable, TLS rejected, reset 502 with the cause chain in words (send failed: … connection refused, … invalid peer certificate: UnknownIssuer). Nothing inserted
no response head within 30 s 504 no response within 30 s. Nothing inserted

Content type is not checked. The body is read as bytes and parsed, the rule the import door already keeps, so curl -d '{…}' (form content type) works as the epic's expected result 1 writes it. axum's 2 MB request limit stands on both doors: a replay with no body override sends a seed body of any captured size, and only a pasted override meets the limit.
