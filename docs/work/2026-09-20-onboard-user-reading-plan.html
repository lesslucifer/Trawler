The two components W4 proposed

Both are registry entries, built here because an epic that designs a component and does not build it owes a drop reason at its own merge. Each ships with its TSDoc contract (DEC-16), its own test file, and a specimen in the collection's mount test.

ChoiceTiles

One choice over four to eight options, every option visible. A wrapping row of tiles, exactly one selected, label in and id out. No groups, no search, no popup.

Why nothing existing fits: Select hides the choice behind a trigger — which is exactly what the reading failed on. SegmentedControl's @avoid refuses more than four, and Another Ubuntu machine is outside its width in both directions.

Keyboard: one tab stop (roving tabindex) · ← → ↑ ↓ move focus without selecting, no wrap · Enter or Space takes the focused tile.

TaskStep

One numbered task: its number, its title, one line of purpose, the state something observed for it, and a slot for what the user does. A dimmed variant for a task whose precondition is not met.

Why nothing existing fits: StepList's @avoid refuses per-step state — a ban on unobserved claims that round 1 read as a ban on numbering. StepList keeps its job: the manual steps inside a task, which carry no state.

The contract that keeps it honest: no cursor, no progress count, and no state a caller can pass without a source. The number is a reading aid; the state is a reading.

What could go wrong, and the answer

RiskThe answer
The copy drifts from the copy table while the screen is being assembled — the exact failure that made two designs of one screenthe table's rows are asserted literally in the unit tests, written from the archived run rather than from the code. A sentence that drifts fails a test that quotes the design
TaskStep becomes the stepper the run banned — a caller passes it a state nobody observedthe contract has no done prop: a state is a StepStatusView resolved by verdicts.ts or it is absent. The @avoid says so and the screen's tests assert each state's source
The one elevated act half-succeeds — the certificate installs and the proxy write failsthe two commands are joined with && inside one script, so the failure is the script's and the probes re-read both facts afterwards. The screen's state comes from the probes, never from the action's exit code
The foreign-proxy confirm becomes a second dialog on top of the password prompt for users who have no foreign proxyit is asked only where the probe says foreign — the one case where something the user owns is about to be replaced
The screen grows while being rebuilt, and the review reads a 900-line filethe two components take the tiles and the task chrome out of it, and the guides were already extracted. A line count is evidence, never a target — but the direction is down
An @avoid or @use moved under the archived mockup since round 4 closedthe substrate is re-read before the components are written; a moved contract is a finding for the build, not a silent divergence
