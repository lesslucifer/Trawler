E-ONBREV.W1 — the walkthrough recording

One command walks the real window through every platform on every host, with the machine-touching answers scripted and the traffic real. It films each step and captions it with what the screen should show. This WU records the before.

v1 · 2026-09-26 · Trawler · T3 WU plan · E-ONBREV.W1 · branch wu/onboard-review/walkthrough · epic plan · findings R1–R22 · depends on none

Requirement

cargo xtask ui walkthrough builds the app with the shell's scenario feature, drives the real window through a scripted run per host × platform, and writes target/walkthrough/: one captioned video per host × platform and an index.html with a chapter per step and a tick-box per expectation. Every finding R1–R22 is named by at least one chapter. The command is red when any chapter's anchor element is missing, when a run finished fewer chapters than it scripted, or when a finding is named by no chapter.

Mapping

E-ONBREV · the epic plan's W1 block: the owner's verification of the whole epic, every UC-ONBOARD row, R1–R22 as captions · expected-result row "Run cargo xtask ui walkthrough at the epic tip" · open questions Q9 (the real window, screenshots stitched per step) and Q10 (target/walkthrough/, out of git) · the E2E test plan's walkthrough row, which W6 re-runs for the after.

One wdio run per launch. The app reads its host OS and core address before its first script, and a navigation aborts it, so every launch is a fresh process.

A chapter is do (scripted acts) → anchor (any-of selectors that prove the screen this chapter is about has painted) → frame → expect (what UC-ONBOARD says it should show, named by finding). An anchor is neutral between before and after, so both runs film the same moment. The expectation is the owner's tick. The spec does not assert it.
