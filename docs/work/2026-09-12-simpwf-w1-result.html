E-SIMPWF.W1 — the gate counts its own refusals

Delivered: cargo xtask tally reads a local record the gate appends on every run — the refused check ids per level, and the review rounds each tip paid.

v1 · 2026-09-12 · Trawler · T3 WU result · E-SIMPWF.W1 · wu/simpwf/measure-the-gate · WU plan · epic plan

Outcome

Delivered against the WU plan's requirement, with no scope moved. Every gate run appends one record to target/.gate-tally; cargo xtask tally aggregates it.

PromisedShipped
Every check id that refused, per gate level one record per gate run at commit, working-unit and epic, carrying the ids the gate reported; the summary counts them per level, most frequent first
How many review rounds each tip needed the cr notes on the tip's own first-parent line from the gate's base, counted at record time and printed per tip
One command prints it cargo xtask tally — totals, refusals by level, then one line per tip
Never a git note, and never gate evidence a file under the gitignored target/, in the shape of Gate 0's cache; no gate check reads it, so deleting it changes no verdict — asserted by test

The file is append-only and line-oriented; the aggregation unions the check ids a tip ever refused and keeps the largest round count it showed.
ReadingMeans
status=greenthe run passed every check it ran
status=exemptdocs/infra-only (or design-exempt): the run passed nothing, which is not the same as passing everything
status=red + a checks listthe gate refused, and these are the ids it printed
rounds=nthe work behind the tip paid n review rounds — one cr note per round, PASS or FAIL, on the commit that round judged

Deviations

None from the plan. Two points the plan left to implementation, recorded so a reader does not have to infer them from the code:

PointSettled as
Which gate entry points record verify-dod wu|epic (and so the merge hook) and verify-dod commit. The epic walk's internal re-verification of a seam is not a separate record — its refusals already appear on the epic run as 7·walk·<check> — and neither is the pre-push range sweep, which re-checks commits that already paid their own gate.
Equal-check ordering in the printed refusal list most refusals first, check id ascending on a tie — so the list is stable between runs

The first review round changed five things, all of them found by finders rather than by the author, and all now covered by tests:

FoundChanged to
Rounds summed a range that a back-merge can fill with another branch's reviewed work, so an epic tip was billed for its WUs' rounds and the total counted them twice rounds are counted on the tip's own first-parent line, and a merged-in branch's rounds stay with the branch that paid them
The pre-push range sweep recorded one line per pushed commit, re-scanning the notes ref once per commit the sweep records nothing; a gate run is an invocation that computes a report
One non-UTF-8 byte (or any read error) made the whole file read as empty, printing "no gate runs recorded yet" over a file that held records the file is read lossily and per line; a torn or unparsable line is dropped, never the reading
A record was appended with several unbuffered writes, and a torn or status-less line still parsed — an unknown status even outranked red in the aggregation one write per record; a line is accepted only with its status, level and trailing checks field intact
The record was written before the receipt it describes, so a run whose receipt write failed still showed green a green record is written only after the receipt is on the tip

Three further points the review raised are recorded as waivers on the cr/v3 note rather than fixed here — the file has no schema-stable contract to hold, the test harness repeats a shape the suite already repeats five times, and a hand-written line format is what a local reading wants. Each carries its reason there.

Distillation

DEC-42 carries what the code cannot: why the measurement is local rather than a note, why a review round is a cr note in the gate's range (with the three rejected definitions), and what it does and does not authorise. Registered in the decisions index (v20).

No T1 change: the workflow standard's rules are what W2, W5 and W6 enforce, and the epic's distillation plan routes them there. Nothing in this WU changes a note schema, a gate check or a merge rule.
