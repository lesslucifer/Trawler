E-ONBRVP.W1 — list ⇄ setup: what shows, what reloads

Every way between the flow list and setup, walked against every piece of state the app holds. Each move keeps, re-reads or resets exactly what the table below says. Nine findings are waiting for the owner's ruling.

v1 · 2026-09-28 · Trawler · T3 WU plan · E-ONBRVP.W1 · branch wu/onboard-revamp/switching · off epic/onboard-revamp at 83df11b · epic plan · depends on none
Waiting for the owner. The sweep is done and nine findings are below, each with a proposed ruling. The build starts once each finding is ruled take, defer or refute. The requirement and test plan are written for the proposed rulings, and a ruling that differs edits them first.

Requirement

Every move between the flow list and setup keeps, re-reads or resets each piece of the app's state exactly as UC-ONBOARD's transition table says, and each row of that table is held by a named test. The moves are launch, the dot, "set up another device", a first success, back, the core dropping and returning, and a quit being asked.

Mapping

E-ONBRVP · the epic plan's W1 block · UC-ONBOARD: a new "moving between the list and setup" section · DEC-60 (a setup session starts when setup opens), applied rather than reopened · DEC-55 (reach is a fact about the process, re-read from what the core answers) · DEC-13 (work that changed this host stays reversible from the moment it ran). W2 builds on this: the dot (F23) and the route back (F26) are transitions this table rules. W11 builds on it too: quitting is a row here.

Also checked, and found to hold: the filter, the selection with its detail pane, and the draft survive a round trip. The selected row is scrolled back into view. The banner goes when setup opens and does not come back. A re-entered session does not reveal the list on success. A stream drop in either phase keeps what is on screen under the band.
