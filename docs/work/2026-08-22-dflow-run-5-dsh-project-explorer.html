Design run #5 — the DSH project explorer panel

The flow run against a panel that already shipped, blind, into a foreign host app — and the redesign it forces.

Draft · 2026-08-22 · Trawler · T3 (docs/work/) · rulebook b769f7e4 · run in review

Why this run exists

A file-browser panel was built into the DSH web GUI as a live Cordis plugin and shipped working. The reviewer's verdict: "the plugin works but the UI / UX is not sufficient to me." It was designed blind — no stage, no rulebook, no registry — so this run does the work in the order the flow prescribes, and the shipped panel becomes the run's before.

This run has a foreign target, and that is a first. Every previous run designed a Trawler screen: Trawler's tailwind config held the tokens, and ui/src/components/ held the components to mount. This panel renders inside DSH — a different application, with its own closed token set (--dsw-alias-*) and no access to Trawler's collection. The consequence is split, and the split is the interesting part:
  • The soft rules transfer whole. They are design judgment, not Trawler facts — and they are exactly what the reviewer's complaint is made of.
  • The hard token rules transfer as shape, not as membership. "Colour only via named tokens" holds; the token set it names is DSH's.
  • The registry transfers as contract, never as mounts. No CopyText can be mounted here. Its @avoid lines still judge the design — and they caught two defects.
Filed as findings 1 and 8; the verdict-vocabulary gap it opens is proposal verdict-mirrored.

▸ why — per call, and whether it loops back to Layout
  • the footer — two lines of instruction, resident forever, teaching what one click teaches once. Loops back to Layout: yes — zone C is deleted.
  • title bar → tree root — "Project files" labels a panel that is visibly project files, and the path line under the picker repeats what the name already says. Making the project the root node collapses three chrome rows into one content row, and it is what every file tree in the genre does. Loops back to Layout: yes — zones A and B merge into one root-plus-tree structure.
  • name type — a hard-rule breach found by the Elements pass, not by taste. A path is payload; payload is mono. Loops back: no.
  • long names — ellipsis on a payload is forbidden, and it is also a functional defect: the user cannot read the name they are about to hand over. Wrapping costs a second line on rare rows. Loops back: no.
  • the dotfile control — the strongest call in the run. Spending permanent header chrome on a rare preference inverts the hierarchy; dissolving it into the level that has hidden entries pays three rules at once and removes a control entirely. Loops back: no.
  • hit target — 22px glyphs against a 44px-ish comfortable floor, and the copy target was the text width rather than the row. Loops back: no.
  • row icons — two glyphs per row competing with the payload the row exists to carry. A trailing slash says "directory" at zero ink. Loops back: no.
  • empty state — "Empty" names no absence: empty folder, filtered to nothing, and unreadable folder are three different facts. Loops back: no.
  • refresh semantics — a behavioural defect the mockup surfaced: the shipped handler drops every expansion, so checking whether the tree is current costs the user their place. Loops back: no.

Findings

#StageFinding
1FrameThe flow has never had a foreign target, and the substrate splits three ways under one. Soft rules transfer whole, hard token rules transfer as shape but not membership, and the registry transfers as contract but not as mounts. Nothing in the base spec says which of those three a run should do, because every previous run was a Trawler screen.
2ElementsThe registry earned its keep on a panel it cannot supply a single component to. CopyText's contract caught the mono-for-wire-data breach; Notice's @use list caught the bare "Empty"; IconButton's and Select's @avoid lines settled two placement questions. Read as pure contract, with zero reuse available, it still did the work.
3ElementsThe verdict vocabulary has no arm for a foreign target. reuse · extend · propose all presume one collection. Every row here is "the contract fits, and I still must build it myself" — which is not propose (nothing new is being added to Trawler's collection) and is certainly not reuse. Written as "build local" with the trace carrying the truth; proposal verdict-mirrored.
4MockupEvery hard token rule went unchecked, in both directions. The predicates read Trawler's tailwind config, and this panel's tokens are DSH's, so spacing-scale, radius-tokens and colour-tokens-only have nothing to test — while the shipped panel breached all three (3/5/7/22px spacing, four improvised radii, an rgba() shadow). A foreign-target run is exactly where the gate is blind and the rules matter most.
5InteractionThe shipped panel had no keyboard path at all — pointer-only, every row. keyboard-parity is a hard rule with a per-row predicate, and it never ran because the panel never came through the flow. Nine use-cases now carry one; three needed bindings the conventions vocabulary does not hold.
6ElementsA cardinality rule cannot be satisfied at design time. Select's @avoid says 2–4 options belong to SegmentedControl, but the option count here is the user's project count — unknown, and variable per user. The design picks Select and accepts the miss for small counts; a contract that keys on a runtime quantity may need a third arm.
7TuneThe mockup surfaced a behavioural defect, not a visual one. Drawing refresh made it obvious that the shipped handler drops every expansion — the user pays for asking whether the tree is true. No visual stage would have found it; this is the mockup-as-decision-stage claim holding on a real case.
8FrameBlind-shipping is the actual root cause, and it is a process defect rather than a taste one. The panel was built and run without loading the rulebook that CLAUDE.md marks as load-before-UI-work. Five hard and eight soft rules were breached by a UI that worked on first activation.
