E-GATEFAST.W2 — incremental Gate 0

Skip the fmt+clippy+nextest re-run when the working tree is byte-identical to the last green run, so the ~10% cargo bucket paid 2–3× per review collapses toward one verify — without ever letting a stale "green" skip a tree it did not verify.

Plan v1 · 2026-07-07 · Trawler · T3 WU plan · epic plan · C1

Requirement

cargo xtask gate0 runs Gate 0 (fmt --check + clippy -D warnings + nextest run --all, fallback cargo test --all) and skips the run when the working tree is byte-identical to the last state it proved green, keyed off a full working-tree hash cached in a local target/.gate0-green file — so any tree change re-runs in full and a stale or hand-edited cache can never yield a skip on a tree that differs.

Maps to

E-GATEFAST · C1 → sink S1 (code-review re-runs Gate 0 from scratch every time; the main loop already ran the same trio, and a red-gate retry runs it a third). Recovers the ~10% cargo build/test bucket that today is paid 2–3× on the same unchanged tree. Load-bearing constraint: DEC-2 recompute-don't-trust — the cache is a shortcut under that invariant, never a relaxation of it.

Expected result

  1. Skip on an unchanged tree. A second gate0 on the same working tree returns instantly with a skip message and exit 0 — no fmt/clippy/nextest.
  2. Invalidate on any tree change. A tracked edit, a whitespace-only edit, or a new untracked non-ignored source file changes the key, so Gate 0 re-runs in full. Over-invalidation (a stray untracked file forcing a needless rebuild) is the accepted safe direction; a false skip is not.
  3. Never vouch for an unverified tree. The cache stores the key it proved green, never a bare verdict. A hand-edited or absent file simply misses and re-runs. On a red run the cache is not written, so the next run re-verifies.
  4. Correct storage. The cache lives at target/.gate0-green (gitignored), so cargo clean wipes it alongside the incremental build state it shortcuts, and it never syncs to origin.

Deviation from the epic plan

Storage: local target/ file, not a git note — the epic plan recorded "git note (decided)". W2 reverses that. A git note is durable, origin-synced and tamper-evident — the entire DEC-2 evidence model. A Gate-0 skip is the opposite: an ephemeral, machine-local fact about this checkout's incremental build state, worthless on any other machine (which never ran the build). A pushed green note would let a machine skip a build it never did. The target/ file co-invalidates with the cargo clean state it caches, never leaves the machine, and dissolves the epic plan's open "syncs to origin?" sub-question outright. The epic plan's C1 bullet, W2 card and open-questions list are updated to match; the rationale distils to the DEC.

The key (the load-bearing part)

Gate 0 verifies the working tree, not HEAD, so the cache key must capture everything a build sees. git stash create looked like the primitive but silently drops untracked files (verified: adding an untracked .rs did not change its tree hash), which would be a false-skip hole. The key is therefore built explicitly:

key = sha256( git rev-parse HEAD
              + git diff HEAD --no-color --no-ext-diff      (tracked, staged or not)
              + for each untracked non-ignored file: path\0 + bytes )

The --no-color --no-ext-diff flags match diff_sha256 in git.rs, so the key is config-independent. Cost is a few milliseconds (a git diff plus a text hash — no compile, no full-tree walk of unchanged files). Gitignored files (including the cache file itself and all of target/) are excluded, so the cache does not invalidate itself.

Test plan

Integration (WU contract) — xtask/tests/gate0_cache.rs, hermetic temp repos, pinning the invalidation invariant on worktree_key (the load-bearing correctness, without running cargo):

  • identical tree ⇒ identical key (the skip condition);
  • a tracked edit ⇒ key changes;
  • a whitespace-only edit ⇒ key changes (the plan's explicit case);
  • a new untracked source file ⇒ key changes (the git stash create hole, closed);
  • a gitignored file / the cache's own file / a build artifact ⇒ key unchanged.

Unit (commit) — in xtask/src/gate0.rs: the target/.gate0-green round-trip — absent cache reads none, a stored key round-trips and lives under target/, a different key is a miss.

Not tested by suite: that cargo actually runs — that is command sequencing (like the existing hooks) and is proven by the live before/after smoke run recorded in the WU result. Wall-clock is non-deterministic, so no timing assertion enters the hermetic suite (epic non-goal); the measured time-saved figure lives in the WU result report per the close protocol.

Scope note

W2 wires the cache into the code-review skill's Gate 0 (§2 now calls cargo xtask gate0) — the sink the plan targets. The pre-commit/pre-push hooks are left calling raw cargo for now; adopting gate0 there is a later, additive change with no code coupling (out of W2 scope to keep the diff small and the correctness surface one command).
