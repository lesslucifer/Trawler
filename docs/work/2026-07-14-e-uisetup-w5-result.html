E-UISETUP.W5 — result

Proxy teardown is live and symmetric: a native unset_proxy command mirrors W3's set, gated on a we-set-it marker file so a revert only ever touches a proxy Trawler set. It is exposed as a manual "stop routing" control, as auto-revert on clean quit, and as crash reconciliation at the next launch. No core / API change — the off-commands run locally in the Tauri app, same boundary as W2/W3.

Outcome

Delivered as planned. Against the W5 requirement and its "done when":

  • Native off, Rust owns the command. ui/src-tauri/src/setup.rs — unset_proxy_commands(os, services) is the mirror of set_proxy_commands: macOS → one osascript "with administrator privileges" compound script running networksetup -setwebproxystate off / -setsecurewebproxystate off for every enabled service (same parse_services + shell_quote, keeps the saved address); Windows → reg add ProxyEnable=0 + the same internet_set_option_refresh(), unelevated; else None. Registered as the third invoke_handler command.
  • Marker-gated, one predicate. A zero-content file at temp_dir()/trawler-proxy-set is written when set_proxy's commands all exit 0 and removed when unset_proxy's do. revert_if_marked() is the single gate every lifecycle path routes through — present ⇒ run the off-commands + clear the marker, absent ⇒ no-op — which is why a revert can never touch a proxy Trawler didn't set.
  • Manual "stop routing" control. Onboarding.tsx shows a "Stop routing through Trawler" control in the set-proxy body once this session's native set succeeded; App.tsx wires it to invoke("unset_proxy"). Setting the proxy again resumes routing (symmetry).
  • Quit-time check keys off the real system proxy status, not a session flag. On close, closeConfirm.ts asks Rust proxy_status(host, port), which reads the live OS proxy (macOS networksetup -getsecurewebproxy; Windows the WinINET registry) and classifies it against Trawler's configured address — read-only, no elevation. This catches a proxy the user pointed at Trawler by hand, not just one we auto-set. Three branches:
    • "ours" — a proxy on this machine routes through Trawler. Prevent the close and show ProxyCloseDialog (spelling out that keeping it may cut the internet): Remove → unset_proxy (elevation); Keep → clear_proxy_marker; Esc / backdrop / ✕ cancels.
    • "foreign" / "none" — not ours (or no local proxy), so nothing to remove here; but a device elsewhere (phone / emulator on the LAN) may still point at Trawler. Show an info-only notice — how to check / turn it off (reusing proxyOffSteps) — with a durable "don't show again" (dismiss_remote_notice, stored in the app config dir).
    New commands: proxy_status, remote_notice_dismissed, dismiss_remote_notice, clear_proxy_marker. Cmd-Q / menu Quit go through [NSApp terminate:], which never fires onCloseRequested and can't be cancelled to show a dialog — so a RunEvent::ExitRequested/Exit net in lib.rs reverts a still-set proxy synchronously on that path (safe default: restore the internet). Launch reconciliation runs silently off the main thread — the hard-crash tail.
  • Gates green, headless. 89 vitest (8 files) · 23 cargo test units in the standalone src-tauri crate · clippy pedantic clean · cargo xtask ui build clean · onboarding e2e 4/4 green (boots through the setup hook + the close guard).

Deviations

The clean-quit path grew from the plan's "auto-revert on a window-close hook" into a user-consented confirm, on review feedback that a silent elevation prompt at quit is confusing:

  • Quit revert is now user-driven and status-based, not a silent session-flag hook (design change). The plan put auto-revert on a native WindowEvent::CloseRequested hook. In practice that fires a bare OS password prompt the user can't interpret, and declining it strands them on a dead proxy. Two rounds of feedback reshaped it: (a) the revert-on-quit moved into the webview as a consented dialog; (b) the gate switched from "did we set it this session" to the actual system proxy status (proxy_status), so a hand-configured proxy is caught too, and a stale in-session flag can't mislead. Buttons are plain Keep / Remove.
  • Remote-device case: informational fallback, not a false "remove". A proxy set on another device (pointed at this machine's LAN IP) isn't readable from this system, so it can't be auto-detected or removed. When the local status is not ours (foreign or none), the dialog is info-only — check/turn-off steps + a durable "don't show again" — never a Remove button.
  • Two quit paths, because macOS Cmd-Q bypasses the window close. Code review caught that onCloseRequested fires only from the window's red button, not from Cmd-Q / menu Quit ([NSApp terminate:]) — and tao exposes no cancellable applicationShouldTerminate: to hold a dialog. So the webview confirm covers the red-button close, and a RunEvent::ExitRequested/Exit net in lib.rs guarantees the machine is never left on a dead proxy on the Cmd-Q path (synchronous revert, no dialog possible there). The net is a no-op after a consented Keep/Remove. Launch reconciliation stays a silent off-main-thread revert (the hard-crash tail).
  • Shared runner extracted. set_proxy and unset_proxy both resolve macOS services and run a Vec<Vec<String>> surfacing the OS tool's stderr — factored into macos_services() + run_all(commands, verb) rather than duplicated. The set_proxy error strings are byte-identical to W3 (verb "set").
  • Launch reconciliation runs off the main thread (review fix). A stale-marker revert can spawn an elevation prompt; on the launch path that would show a password dialog before the window paints, so it is spawned on a background thread (the app keeps running, so it completes). A hard kill with no relaunch is the unfixable tail, unchanged.

Follow-ups

  • The gone-for-good tail — app killed and never relaunched leaves a self-set proxy no live process can revert. Needs an OS-level watchdog; explicitly out of scope for this epic.
  • Temp cleared between crash and relaunch — the marker is lost, so reconciliation can't fire; collapses into the same unfixable tail. An app-data-dir marker (threading a Tauri AppHandle path) would close this narrow window if it ever matters in practice.
