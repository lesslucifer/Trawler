E-RFINISH — epic plan

Finish what E-REDESIGN deferred: pay the debt it named, answer the three design questions it sent to a later run, and re-design the one pair of screens it shipped gated but not endorsed.

v1 · 2026-09-06 · Trawler · T3 (docs/work/) · branch epic/redesign-finish

Intent

E-REDESIGN put all five shipped screens through the design flow and proved the design → build citation path for the first time. It closed delivered — and with ten open follow-ups, because the epic gate is the wrong moment to change unmeasured performance, to widen a pane the shell design owns, or to fix a docstring that has no cr/v3 note to live on. Those items were not oversights; each was deferred with a named home, and this epic is that home. It carries three kinds of work. Debt — four registry docstrings that cite code E-REDESIGN deleted, three measured-nowhere performance costs the rebuild introduced, and a flow list that cannot say the API is unreachable because useFlows catches and discards every fetch failure. Design questions — the detail pane is 380px and that width is half the header-wrap cost DEC-32 exists to bound; the status filter is a free-text u16 when the useful query is a class; and the payload cell is waiting on its second truncation sighting to earn a registry entry. A re-design — W10's own result shipped the setup screen and quit dialog "gated, not endorsed as final", after eleven review rounds that found the status model wrong at the root; Onboarding.tsx grew 464 → 563 and ProxyCloseDialog.tsx 133 → 288, and the three shape nits the epic recorded all live in exactly those two files. Why now: every one of these items is addressed, in writing, to "whichever epic next opens this file", and four different follow-ups name the same three files. Opening them once, together, is the only way to pay them without paying the review cost three times.

Use-case requirements

Three native contracts are touched. None is narrowed — DEC-13's standing rule is that a design run may not narrow a shipped capability, and W7 in particular re-designs a screen whose every current promise must survive.

  • UC-4 Watch live traffic in the native app. Two contract-level gains: the list states when the API is unreachable instead of showing a stale list indistinguishable from a quiet proxy (W6), and the status filter accepts a class — 4xx — end to end (W5 + W6). The detail pane's width becomes a designed value rather than a token nobody chose (W4 + W6).
  • UC-5 Inspect a captured flow. No capability moves. The body view switch is re-labelled to the terms its contract actually settles on — raw | pretty — closing the one-term-per-concept violation E-DFLOW.W6 recorded (W9). The wider pane changes how much of a long header value is readable without expanding it, which is the observable half of DEC-32.
  • UC-ONBOARD Guided onboarding. The whole contract is re-designed and rebuilt (W7 + W8). Everything it promises today must still hold: the two layers and the clock (DEC-33), the CA save step, the copy confirms, the quit remedy, and DEC-13's inherited assertion that stop routing appears only after the proxy was set. A gain is permitted; a loss is a review finding.

  5. GET /flows?status=4xx returns only 4xx flows, exact codes still work, and a nonsense class is a stated error rather than a silent empty list.
  6. Two closed, archived design runs — the shell/list second pass and the onboarding/quit re-design — each Tier-1 green and Tier-3 judged, each cited by its build WU's cr/v3 note through design.implements.
  7. Every .tsx this epic touches is accounted for at every seam: cited to a design, or declared undesigned with a reason that states what the edit did. Gate check 9 proves it.
  8. The three shape nits are gone: the one-second tick re-renders only what depends on it, attemptRemove is a useAction caller, and setup.ts's two concerns are two modules. The closeConfirm.remove seam has a test that wires the two modules together rather than modelling each side.

Non-goals

  • The two harness/workflow follow-ups. Tier-1's tokenizer treats <script type="text/babel"> as opaque, so every design run's rendered markup is invisible to the hard-rule predicates; and gate check 8 verifies that some report was attested, not that it is a result report. Both are real, both are xtask/process work, and mixing them into a UI epic would mean changing the gate while the gate is judging this epic's own seams — the exact thing E-REDESIGN's non-goals forbade. They move to the roadmap's Deferred backlog at W10.
  • Re-designing the flow detail panel's zoning. DEC-32 stands: headers capped and scrolling inside, the body taking the rest, the panel never scrolling as a whole. W4 designs the pane's width, not its zones.
  • Re-designing the flow list's rows. DEC-34's three conditions bound the truncating cell and the run that wrote them closed green. W4 opens the payload cell only to answer whether the second sighting has arrived.
  • Any capture-core feature. The one core change in scope is FlowQuery.status accepting a class. HAR, replay, WebSocket, persistence and rules stay on the roadmap where they are sequenced.
  • Making the screens smaller as a goal. E-REDESIGN refused to claim less code and four of five screens grew. W8 may well shrink Onboarding.tsx, and if it does the number is evidence — but a line count is not an acceptance criterion here either.
  • Revising the design flow itself. W1 corrects one skeleton that contradicts DEC-26; the stages, the rulebook's structure and the three-tier gate are inputs, not scope.
