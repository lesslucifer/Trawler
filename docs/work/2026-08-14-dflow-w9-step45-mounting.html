What the predicate reads, and why not the marking

The plan proposed seeing the mount through data-key on the host — the marking the Elements stage already demands. Executing it showed that marking cannot carry the proof: run #4's hand-drawn imitation already carried every key. The predicate reads the component's element name instead.

  every marking"| B["passes a key check"]
  C["<Section title=… >"] -->|"an element name
  cannot be drawn"| D["mockup·hand-drawn
  has nothing to say"]
Hình 1 — one character apart in the source, and only one of them is reachable by hand-drawing. The data-key requirement was dropped for buying nothing the name does not already prove.

Read off the raw mockup slice: HTML's raw-text rule makes a <script> body data to the tokeniser, so the mount script — where the composition actually lives — is invisible to attrs() and visible to contains. That same rule is what the cost below is made of.
