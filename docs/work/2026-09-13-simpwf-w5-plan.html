E-SIMPWF.W5 — a nit does not restart the exam

Severity stops being collected and discarded. Only a blocker or an important fails a review; a verified nit is recorded with a disposition in the note the gate reads, and a nit recorded without one is refused.

v1 · 2026-09-13 · Trawler · T3 WU plan · E-SIMPWF.W5 · wu/simpwf/nits off epic/simpwf · epic plan

Requirement

A review's verdict is decided by severity: a verified blocker or important fails it, a verified nit does not. Every verified nit is carried in the cr/v4 note as a claim plus a disposition — fixed, meaning the fix is inside the range this note binds, or waived with a non-empty reason — and a nit carried without one is refused by the merge gate under 3·review-nits, exactly as an empty test-layer waiver is refused. Severity stops being a free label: rubric.md states the boundary a finder and a verifier both apply, and the verifier's returned severity is the one the verdict reads. No finder is removed, no dimension changes what it looks for, and the binding rules are untouched.

The severity boundary, stated where both agents read it

Severity becomes load-bearing, so it stops being a free word. The boundary goes in rubric.md, which every finder is already instructed to read first, and the verifier prompt cites the same rows.

SeverityThe testEffect on the verdict
blocker The code is wrong, unsafe, or breaks a stated contract — a user or a caller gets a wrong answer, a crash, or a silent loss. Fails.
important The code is correct but carries a cost the project has ruled against: a duplicated rule that will drift, a reimplementation of something the tree already owns, an altitude break, a cost that grows with the data. Fails.
nit Neither: nothing observable changes and nothing drifts if it is never fixed. Naming, ordering, a clearer local shape. Does not fail. Must be recorded and dispositioned.

The recall risk lives exactly here. The rule is safe only if nothing that fails today gets relabelled a nit tomorrow. The boundary above is written so the two failing rows are the default and nit is the narrow exit — a finding is a nit only when it survives "nothing observable changes and nothing drifts". Uncertainty resolves upward, to important, mirroring the verifier's existing rule that uncertainty resolves to false-positive: in both cases the cheap error is preferred to the silent one.

The note shape

Additive on cr/v4, not a new schema: an absent nits: section is what every note written so far means — no nits recorded — so no in-flight tip is re-reviewed to satisfy a bump. It reuses the shape the tree already uses for "a thing, and why it is not where the rule would put it" (Excused, WalkWaiver, Layer::Waived).

nits:
  - finding: "capture.rs:88 — the loop variable is named `x`"
    fixed: "renamed to `frame` in this range"
  - finding: "store.rs:140 — two branches could share one helper"
    waived: "the shared helper would take three flags; split reads better"
DispositionMeansRefused when
fixed: "<what changed>" The fix is inside the range this note binds — the reviewed tip already contains it. The entry exists so the round's yield stays countable, not to license a later commit. The sentence is empty.
waived: "<reason>" Accepted as it stands, for the stated reason. No commit, no re-run. The reason is empty.
neither A recorded nit nobody decided about. Always — 3·review-nits.

W5 creates no way to change code after the verdict. fixed names a fix already inside the bound range; a fix landing after the note still moves CODE_SHA and still reds 5·diff-binding, exactly as today. Making a post-verdict fix cheap is W7's subject, and this WU deliberately does not smuggle it in.
