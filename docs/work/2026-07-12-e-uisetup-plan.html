E-UISETUP — Guided onboarding to first capture

Epic plan (T3). Walk a fresh user from an untrusted CA and an unconfigured client to their first decrypted HTTPS flow — designed flow-first, built on E-UIFOUND's native base layout. Roadmap Wave 2, GUI pillar.

Draft v1 · 2026-07-12 · Trawler · E-UISETUP · builds on E-UIFOUND (UC-4)

Intent

New users launch Trawler, see an empty list, and don't know why: their machine doesn't trust the CA and isn't routing through the proxy — the classic proxy onboarding cliff. This epic adds an onboarding surface in the native app that walks a clean machine to its first captured HTTPS flow and, because it's a native app, does the setup for the user where it can: install the CA and set the proxy in one click (with a confirm + OS elevation), guide by hand only where it can't, then a live check that turns green when the first decrypted flow arrives. Now, because E-UIFOUND already shipped the layout and SSE stream it plugs into.

W2 — Trust the CA

BuildsInstall the CA (bytes from /ca.crt) into the OS trust store natively: one-click + elevation on macOS and Windows (security add-trusted-cert / certutil -addstore); guided steps on Linux, Firefox's own store, and simulators/devices. No trust-store inspection — trust is proven by W4's capture, not by reading the store. Runs in ui/src-tauri.
Maps toUC-5 CA-trust · CA bytes from /ca.crt · new local-OS capability in the Tauri app
Done whenOn macOS/Windows one confirm installs the CA; elsewhere correct guided steps show for the detected OS. Native-install command + OS→steps mapping + text-safe render unit-tested.
NeedsW1

W3 — Set the proxy

BuildsAuto-set the system proxy to the proxy address where the OS allows (macOS networksetup, Windows WinINET), one click + elevation. For clients we can't auto-set, a copy-paste snippet. Address from config (DEC-12), never hardcoded. Concrete examples: 
curl -x http://127.0.0.1:7420 https://example.com
export HTTPS_PROXY=http://127.0.0.1:7420
# macOS (run for you):
networksetup -setsecurewebproxy Wi-Fi 127.0.0.1 7420
Maps toUC-5 proxy-config · DEC-12 configurable base · local-OS capability
Done whenmacOS/Windows: one click sets the system proxy. Elsewhere: the shown snippet carries the real proxy address per detected client. Auto-set command + snippet generation + copy unit-tested.
NeedsW1

W4 — Live check + wiring

BuildsThe "it works" check: watch /stream for the first decrypted flow after the Verify step; red → green → complete → reveal list (not re-forced). Wires state entry (onboarding when unproven, list otherwise), tying W2+W3 into the full journey. Where the proxy was auto-set (W3), the app fires its own test HTTPS request and self-verifies — zero user action.
Maps toUC-5 live-check + completion · /flows (initial) + /stream (live)
Done whenA decrypted HTTPS flow (proxied, or the app's self-test) flips the check to success and reveals the flow; fresh shows onboarding, proven doesn't. Transitions unit-tested on mock stream; this is the e2e spine.
NeedsW1 · integrates W2 + W3 (but testable on a proxied request alone)

W5 — Proxy auto-revert

BuildsTear the system proxy back down cleanly so Trawler never leaves the machine pointing at a dead proxy. A symmetric unset_proxy Tauri command runs W3's per-client turn-off commands, exposed both as a manual "stop routing through Trawler" control (turn the proxy off without quitting) and as auto-revert on clean app quit (Tauri exit / window-close hook), gated on a "we set it" marker so it only reverts what Trawler set; plus crash reconciliation at launch — the marker lets the next launch detect a stale self-set proxy and clear it (coordinated with W4's launch self-test). The unfixable tail — app gone for good with no relaunch — is called out, not solved from inside a dead process (would need an OS-level watchdog).
Maps toUC-5 consent, never silent — turning setup off is as first-class as turning it on · local-OS capability (W2/W3) · reuses W3's off-commands
Done whenA manual control turns the proxy off (and back on) without quitting; quitting the app reverts a proxy it set; relaunch after a crash detects and clears a stale self-set proxy; revert only ever touches a proxy Trawler set. unset_proxy builder + lifecycle wiring unit-tested; the quit-reverts path covered in e2e.
NeedsW3 (off-commands + set marker) · W4 (launch path)

Open questions

QuestionProposed default
How far to automate per OS?Auto CA + proxy on macOS + Windows; guided on Linux, Firefox, devices. Add Linux auto later if demand appears
Elevation / privileges?Prompt for elevation at the moment of the action; decline ⇒ guided fallback. Capability lives in ui/src-tauri, never the core
Detect which client / device connected?Not needed — Verify catches a flow from any source (incl. simulators/devices). Surfacing the source client is a possible later enhancement
Which flow counts for the check?First decrypted HTTPS flow after reaching Verify (ignore stale ones)
Persist onboarding across restarts?Derive from live capture; no new store this epic; re-invoke via help
How universal is the proxy address — same host, LAN device, internet?Same host works today (loopback default). Internet is a non-goal (open decrypting relay). The configurable defaultProxyAddr() is the universal hook regardless of bind. See W3 reachability
