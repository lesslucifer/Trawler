Deviations

Four, all recorded here rather than discovered later. The first changed the plan's method; the second and third are findings the plan could not have predicted because they only exist once the code runs; the fourth is what the merge gate then found in the result of all three.

#PlannedWhat happenedWhy it is right
1 Resolve the sheet's six W5-owned CONFLICT: markers; design files <link> it instead of copying it. Four W6-owned markers stay marked. specimen.css is deleted. Every design doc now loads the Tailwind Play CDN and ui/tailwind.config.js itself. Four of the six conflicts turned out to be translation artifacts, not disagreements — the sheet invented .ct, .sl-glyph, .sel-trigger while the app said text-ink-body, font-ui, px-control-x. Naming them in one vocabulary dissolved them; the other two were then decided on merit. The fourteen private token copies went with it. The plan's goal was "a specimen and its component cannot disagree". Linking a second file still leaves two files to drift, plus a gate to police the drift. Reading the same config is the stronger form of the same guarantee: there is no second copy. No generated file, no regeneration step, no drift gate.
2 Build T2, unit-test each member. A throwaway gallery rendering every state found a defect no unit test held: every over-cap marker read "⚠ showing 128 KiB of 128 KiB" — humanBytes rounded both sides to the same string, so a genuine truncation announced itself as no truncation. Fixed, with a test. Exactly the false statement the family's never-truncate-silently rule (DEC-12) exists to prevent, and invisible until a fixture crossed a cap by a few bytes. The gallery is scaffolding that earned its keep; it is ponytail:-marked smoke-tested, not contract-tested.
3 Two design files are "designed-only". Four design files were migrated to mount the real components rather than hand-draw them. header-table.html carried a 36-line vanilla re-implementation whose own comment admitted it ("CopyButton stand-in"); copy-all-headers-button.html — a dissolved component — hand-drew the very CopyButton and rows it claimed had moved elsewhere. A design file that imitates the component it documents is the defect class this whole epic exists to kill. Cheap to fix while the components were fresh; the alternative was shipping known-lying docs.
4 Step 7 is the report, the distillation, one code review and the merge. The step-7 review took four rounds and produced four production fixes — three real defects in the shipped collection, then one more in each of the next two fix passes and a fourth in the one after that. Eight tests were added, and FormRenderer, Select, body.ts and main.tsx all changed after the report was first written. The chain is tabled above. Code changing during step 7 is not the plan going wrong — it is the gate doing the one thing it exists for. What the plan did not anticipate is the shape: three of the four defects were introduced by the fix for the previous one, each in the interaction between two individually-correct behaviours. That is a finding about this WU's method, not just its code, so it is recorded rather than smoothed over.
The plan's own recorded deviation still stands. The epic plan and the W2 seed both place the build in "a later WU", and the epic's non-goals say "no Trawler UI re-design". D3 supersedes both for T1/T2 only, on the reviewer's instruction — "need code, implement the components in collection. For T3 / T4 & screen design we temporarily skip." No screen was re-designed, so the non-goal holds in substance; what moved is when the collection becomes code.

The step-7 review — four rounds, and what the shape of them means

The WU-level review that gates the merge: five isolated finders over the whole diff, one adversarial verifier per candidate. It found three real defects in the shipped collection. Then each of the next three rounds found a defect introduced by the fix for the one before it.

RoundOnFoundThe defect
3 a28dd06 9 candidates → 5 verified, 4 refuted FormRenderer decoded a half-escape into the value it copies. The raw text was sliced at TEXT_MAX before URLSearchParams saw it, so a cut inside a %XX left a stray literal or a U+FFFD — and URLSearchParams never throws on malformed escapes the way decodeURIComponent does, so it was silent. Breaks the family's own rule: the cut is a render cap, never a payload cap.
Select could select a row the user never looked at — active survived an options change under an open popup.
Gallery shipped into the production bundle — a static import pulled the dev-only screen and all 24 components into the release build, while the wdio plugin seven lines above already used a guarded dynamic import for exactly that reason.
4 e48549d 2, both in the fix formPairCut defeated the cap it exists to enforce (a key longer than the cap returned a cut past it) · and Select's reset broke the common case to fix the rare one: keyed on the options array, a parent rebuilding its list every render — the ordinary React pattern — reset the highlight on every unrelated re-render.
5 f191d28 1 the author missed formPairCut could return text.length while the caller's cut flag was true, so the marker read "showing 11 B of 11 B" — a truncation that never happened, slipping past humanBytePair's collision guard because the two numbers were genuinely equal rather than rounded together.
6 2ff565e 1, in that fix The id-reconcile was fighting type-to-filter: keyed on the visible list, it also ran when the filter narrowed that list — where resetting to the first match is the intended behaviour — so it put the highlight back on the previously-active option. Highlight Chrome, type "e", press Enter, and the app selected chrome instead of the first match android.
7 bd3596e 0 — PASS Every write to active traced pairwise; formPairCut checked at exact TEXT_MAX, TEXT_MAX+1, leading-&, &&&&-only, no-=-anywhere and key-longer-than-cap; non-vacuousness proven by reverting the reconcile in a scratch copy; bundle exclusion re-measured independently.
Every one of the four was in the interaction between two individually-correct behaviours. Not one was a typo or a missing null check — each was a rule that was right on its own and wrong beside its neighbour: cap-on-a-boundary vs. never-exceed-the-cap; reconcile-on-change vs. hold-on-re-render; reconcile-by-id vs. filter-resets-to-first. That is why Select now carries four tests, one per behaviour: each was broken at some point by a fix for another, so each needs its own guard. A fix pass reviewed as carefully as the original is not optional — three of these four would have shipped otherwise.

Two verified findings were recorded rather than fixed, in the cr/v2 note: TextRenderer's per-render byteLength (no shipping path feeds it a multi-MB string, the total is load-bearing for DEC-12, and the fix needs a byte length the {text: string} contract does not carry) and check-render.mjs's missing catch (the gate still exits non-zero, so it never fails open).
