A probe-green or bare connection never reveals the list — capture still does. A copy pass over the whole flow shipped alongside (see the plan's Copy — as shipped).

Deviations

  • CA probe matches on Common Name, not SHA-256 fingerprint (owner-approved before execution). Avoids a crypto dep in the thin Tauri shell. Ceiling: a stale cert reusing the CN "Trawler Proxy CA" reads as trusted; the upgrade path (hash the live /ca.crt DER, match the store's fingerprint line, add sha2) is a ponytail: note in setup.rs.
  • No new proxy probe. The plan's "proxy → us?" probe is W5's shipped proxy_status verbatim ("ours" ⇒ green) — reuse, not a new command.
  • Shipped as one WU, three layers (core + Tauri + UI), not split — the plan flagged a possible split; it stayed one coherent contract.
  • e2e asserts the W4 spine only. The connection-goes-green-before-decrypt path is proven hermetically at integration (untrusted_https_records_a_connection_not_a_flow); the WebDriver harness only drives a trusted proxied request, so the untrusted case is not re-asserted there.

Distillation

The onboarding flow is intricate enough that it must not wait for epic close, so it is distilled to T2 now: a new UC-5 in docs/use-cases/web-ui.html (indexed) captures the durable model as an observable contract — the two-truths per-step status (a fast local probe OR observed traffic; never the stepper cursor; un-probeable ⇒ "capture will confirm", never a false "not set up"), the connection-seen signal (an untrusted-CA CONNECT leaves no flow, so the core counts the tunnel: GET /stats + the connection SSE event turn the proxy step green on any traffic, decrypt or not), and the invariant that only a decrypted flow reveals the list. UC-5's provenance callout also records the new /stats · connection API surface and the reversal of W2/W4's "prove by capture only" stances (probe for the 90%, capture for the rest + the CN-match ceiling) — enough that a future agent won't have to rederive the flow.

Still deferred to epic close: a formal DEC recording the trust-store-inspection reversal + the local-OS-setup capability rationale (the epic plan already tracks this alongside DEC-12), and any T1 change — there is none (no new architecture region/route). This plan + result archive under docs/work/ (DEC-3).
