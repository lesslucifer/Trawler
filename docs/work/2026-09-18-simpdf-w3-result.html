E-SIMPDF.W3 — result

The cache key stopped hashing history, the commit hook started asking the cache, and the same question went from 12.45 s to a skip. Two deviations, both named. The one thing the plan predicted and got wrong: a build does not reinstall the hook here, because three worktrees share one hooks directory.

Outcome

The requirement holds. worktree_key hashes what a build reads and nothing about history; cargo xtask lint is the commit hook's one call, skipping when .lint-green or a stronger .gate0-green already vouches for this content; and DEC-54 records the key, amending DEC-11 whose stated definition this makes false. Measured on the tree that closed this WU, the two gates answer the same question at opposite prices:

The middle row is the defect, not the headline: clippy is near-free warm, and cargo clippy and cargo test invalidate each other, so every hook run following a test suite paid full price. The key got cheaper too — the old one forked git twice to ask a question the filesystem answers.

The second half of the fix is the one the plan had to find first: hashing HEAD meant a commit invalidated a proof its content never touched, so wiring the hook to the cache without changing the key would have bought a Working Unit exactly one free commit. Deviations

#Plan saidWhat happenedWhy it stands
1 "The hook is installed by cargo-husky at build time … the result report states the reinstall." The hook was deliberately not installed. The hooks directory is the shared --git-common-dir of three worktrees — Trawler at main, MBL6-Codex at epic/codex, and this one — and neither of the other two carries the lint subcommand. Installing it would have made every commit in those two worktrees fail on an unknown subcommand. The plan knew the hook needs a build; it did not know the directory is shared. The reinstall happens after this merges to main and a build runs, which is when both other worktrees have the subcommand too. Recorded here rather than worked around, because the workaround — a self-degrading hook that falls back to the blind pair — would be permanent complexity bought for a one-time transition.
2 A unit test in xtask/src/git.rs for "sorted order is stable regardless of the order git lists paths in" and "the mode bit reaches the hash". Both are asserted in the integration suite instead — clean_tree_is_stable_across_calls and flipping_the_executable_bit_changes_the_key, over a real git repo. The unit tests in git.rs cover the framing the plan did not enumerate: contents that could imitate the next entry, an empty file against a missing one, a link target against the same bytes as content. Sorting exists so a listing order cannot change the key; that is a property of the key over a repo, and a unit test with no repo could only re-assert that sort_unstable sorts. The framing tests earn their unit level — they pin a collision the delimiter scheme alone would allow, which no repo-level test would ever stumble on.

Scope held otherwise. The e2e waiver was declared in the plan, not discovered: a Working Unit's contract is bounded, the integration suites drive the real key and the real hook over real git repos, and no user-facing flow moves.

The review round

Three finders — correctness, efficiency, altitude — over a three-module diff, then three relevance-batched verifiers. Six candidates, three refuted, one important, two nits. The round is worth reading because the important finding was a claim this very report made about itself.

FindingVerdictDisposition
important · the --workspace guarantee is pinned on the CLIPPY constant, not on the command run_lints actually spawns real — the verifier dropped --workspace from run_lints, left CLIPPY untouched, and every test in the workspace stayed green Fixed — xtask/tests/lint_spawn.rs. Reproduced the escape before writing it and confirmed the new suite fails by name after it. DEC-54's own text asserted the guarantee had moved intact; that sentence was wrong and is corrected in the record.
nit · build_inputs spawns two git ls-files processes where one would do real — verified byte-identical output for the combined call, ~7 ms per commit Fixed — one ls-files -z --cached --others --exclude-standard.
nit · lint_cache_path is pub with no cross-crate caller real Fixed — made private. cache_path's pub is earned by xtask/tests/preflight.rs; this one's was not.
nit · push_entry hashes a symlink's link text, never the target's bytes real — demonstrated on a symlink pointing outside the tracked set Waived — all four tracked symlinks here resolve to independently-tracked paths, so the aggregate key still moves when their content does. It would bite only if a symlink pointed at a build input outside the tracked set, which is not this repo's convention.
important · the whole-tree hash buffer is not streamed into the hasher refuted Measured: 45–53 ms for a whole cache-hit run against ~12 s for a cold lint. Re-litigates the O(tree) cost DEC-54 adopts deliberately.
important · an unreadable path collapses to one byte, so the cache could green a tree it never verified refuted A path fs::read cannot read, cargo cannot read either — same user, same process model — so the build fails and nothing is cached. The submodule case that could diverge needs a submodule; this repo has none.

The fixed tip is re-reviewed from scratch; this report does not speak for that round's verdict, which lives on the cr/v5 note bound to the code it judged.
