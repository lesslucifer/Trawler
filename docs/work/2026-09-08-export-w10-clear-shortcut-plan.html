E-EXPORT.W10 — the clear shortcut, and the ask that can be turned off

Clear leaves the menu for the header, and its confirm gains a switch that silences it for good.

Draft v1 · 2026-09-08 · Trawler · T3 working-unit plan

The requirement sentence

Clearing the capture is a one-click act in the header, not a menu item — and its confirm carries don't show this again, after which the click clears with no ask at all.

Two facts drive it. Clear is the act of this trio a user reaches for most, and it is the only one the ⋮ menu was making them reach twice for. And the app already owns this exact suppression shape — ProxyCloseDialog's remote mode (CLOSE_COPY.remote.dontShowAgain), persisted as a marker file in the app config dir.

What this reverses, and why that is allowed

Design run 11 put clear inside the menu, last, behind a hairline its own code calls "the additive/irreversible boundary". This WU takes it out. The reversal is deliberate and it is argued, not assumed:

Run 11's reasoningWhat changed
An irreversible act should cost more than one click, so it sits behind a trigger and below a separator. Still true of the act — but the cost was being paid on every use, and the frequency was not measured when the boundary was drawn. familiar-idioms is a rulebook entry: the genre's clear control is one toolbar click, and departing from a genre needs a driver in the Frame. Rarity was the assumed driver and it does not hold.
The ask carries the consequence sentence — the capture is not saved anywhere. Unchanged by default. The ask still opens, still carries that sentence, and the switch that silences it is opt-in and per-user.

The hole this opens, stated plainly. Clear is scoped by the live filter. Once the ask is off, one click deletes whatever the filter currently selects, with no undo and no sentence naming the scope — a forgotten filter can remove 8 flows out of 120,000, or the whole ring. The decision on record is suppress always: one rule, no exceptions to learn. The scope is carried by the control's accessible name and tooltip (clear 8 flows, recomputed from the live filter) and nowhere else.

The preference store — generalised, once

ui/src-tauri/src/setup.rs owns one hardcoded pair today: remote_notice_dismissed / dismiss_remote_notice, backed by a remote-notice-dismissed marker file. A second suppressible dialog makes the shape a vocabulary, and the deferred settings screen needs to enumerate it.

ConcernThis WU
APIkeyed: notice_dismissed(key) / dismiss_notice(key). The pure, dir-injected file logic stays pure and stays unit-tested.
keysa closed set in one place — remote-notice, clear-ask. An unknown key is refused, not written: the settings screen must be able to list them.
migrationthe existing remote-notice-dismissed filename is kept as the remote-notice key's file, so a user who already dismissed it stays dismissed.
outside Tauriinvoke is absent in a plain browser. The read must answer not dismissed rather than throw — closeConfirm.ts's unguarded getCurrentWindow() is the bug not to repeat.

Deferred, on purpose

There is no way back. Once a user turns either ask off, nothing in the app turns it on again — the marker file must be deleted by hand. Two dialogs now carry a switch with no inverse, and that is accepted for this WU and recorded here so it is not rediscovered as a bug.

Owed by a later WU: a settings screen that lists every suppressible ask and restores it. That screen is why the store is keyed and why the key set is closed and enumerable — this WU pays that cost up front so the later one is a screen and not a migration.

Sequencing — the one thing this plan cannot decide

W10 modifies CaptureControls.tsx and CaptureMenu.tsx as W6 leaves them. W6 is not merged — wu/export/controls-build is eight commits ahead of epic/export, sitting at its manual-review gate, and carries further uncommitted work. A W10 branched off epic/export would not contain the controls it edits.

So W10 stacks on W6's tip and inherits its merge order. It cannot start until W6's working tree is committed, and the docs half of that commit needs cargo xtask mr commit — which the agent never runs.
