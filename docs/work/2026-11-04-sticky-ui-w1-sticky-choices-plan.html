E-STICKY.W1 — sticky choices

The detail's leg and body mode, setup's last platform and the Settings window outlive a flow and a relaunch, through one preference store with one writer.

v1 · 2026-11-04 · Trawler · T3 WU plan · E-STICKY.W1 · branch wu/sticky-ui/sticky-choices · epic plan · base ea973847

Requirement

Shell holds the detail's leg, the body mode and setup's last platform in one record, read once at launch from view-prefs.json in the app config dir (a choice made before the read lands wins) and written whole, debounced, keeping the file's fields it does not know; every flow opens on that leg and body mode, setup the user opens lands on that platform while the launch check's own opening stays on This machine, a missing, corrupt or wrong-typed field reads as its default, and the Settings window reopens where it was left without a visible jump.

Mapping

E-STICKY · its W1 summary block · UC-5 (leg and body mode sticky + relaunch), UC-ONBOARD (setup the user opens lands on the last platform), UC-SVC (Settings window reopens where it was) · rulings Q1 (one shared body mode), Q2 (Reset Layout leaves prefs), Q3 (lastPlatform only, chosen starts at "this"), Q4 (the store is the one E-QUERY writes through), Q5 (a pending flow keeps the sticky Response leg).
