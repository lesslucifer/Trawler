Why two build Working Units and not one. The plan's happy leg and its amendment are the same event seen twice, so folding them into one branch would have made the green merge an amended build and left the plain hand-over undriven. Splitting them costs one extra branch and buys the ordering the rule actually claims: a build cites what it was handed, and a build that moves those bytes owes the judgment as well as the pin.

The defect this step found was not in the rule

Gate 0 was red before this step started. cargo clippy --workspace --all-targets --all-features -D warnings — the exact command xtask/src/gate0.rs runs — refuses step ③'s a_build_that_adds_a_surface_cites_a_design_the_tip_ships_or_reds at 117/100 lines. It is the lib test target, which is why the step's own cargo test never saw it, and it is the same class of miss W7 ⑥ closed for the xtask crate itself: a target no gate had linted.

Fixed by shrinking, not by allowing. The seven citation refusals became one table of (note body → expected red); the assertion count is unchanged and the function is 91 lines. No #[allow] — the first one in this repo should not be bought by a test that could simply be shorter.
