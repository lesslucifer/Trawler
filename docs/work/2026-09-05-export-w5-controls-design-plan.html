A closed, archived design run over the flow-list surface resolves where the export, import and clear controls live, what the destructive one asks before it acts, how an imported flow is marked in a row without adding a column, how a pasted curl command is accepted and how its refusal reads, and what each control says while it is working — every element resolved to reuse, extend or propose against the registry, every soft rule receipted against rulebook blob aeff5b0f, and the lexicon conflict this epic creates settled in writing. No build.

Mapping

E-EXPORT · the epic plan's W5 row · UC-4's surface (the flow list is where the controls live) · the roadmap's rule that a post-viewer epic ships its own UI controls · follows the design flow, judged by DEC-24, handed over per DEC-25.

Why this WU is designable now, and what it must not assume

The run designs controls for contracts that already exist. W2, W3 and W4 are merged, so GET /flows/export, POST /flows/import, DELETE /flows and DELETE /flows/{id} are real endpoints with real response shapes, and source: captured | imported is a real field on the flow. The run reads those from src/api/routes.rs and src/flow.rs, never from the epic plan's prose.

The one thing it designs ahead of its contract is the curl paste. W7 is not built: ?format=curl does not exist, and the refusal wording that names the rejected flag has no implementation to read. The run designs the paste affordance and states the shape of the refusal it needs; W7 either honours that shape or the deviation is recorded. That is a designed-ahead dependency, and it goes on the run's blocked-on list rather than being quietly invented.

What the run has to answer

#QuestionWhy it is not obviousStage that owns it
Q1 Where do three new controls live on a header already carrying four filter fields and a count? Adding them inline pushes the filter fields below the useful width; a second row costs vertical space on the screen whose whole job is rows. choose-before-act also binds the ordering. Layout
Q2 What does clear ask before it acts, and where does the asking appear? It is the app's first destructive action. useConfirm is a ~2 s after-the-fact flash, not a prompt — the plan's assumption that it can carry the confirmation is wrong and the run must say so. confirm-at-point forbids a toast; nothing in the registry is a dialog. Elements · Interaction
Q3 How is an imported flow marked in a row, with no new column? The row is a fixed-height 6-column grid at 30px. data-ink-first refuses a badge that informs nothing on the 99% captured case; colour-plus-text refuses a tint alone. Elements
Q4 How is a curl command pasted, and where does a refusal naming a flag land? A paste target is not a control the registry has. The refusal is a sentence with a cause — absence-names-itself and empty-states-orient both bind, and the message comes from the server, not the screen. Elements · Interaction
Q5 What does each control say while it is working? Export of a large capture and import of a large file are both slow. Button's @states is explicit: no loading state of its own — a slow action needs the disabled button and a progress line beside it, both halves or neither (fork D4). Interaction
Q6 Which word does the UI use for the operation, given the lexicon reserves export? The Lexicon row says copy means clipboard and must never be called export — which reserves the word against copy, but does not license it here. one-term-per-concept forces a stated answer, and the epic's distillation plan expects a rulebook write-back. Frame · Tune · receipt
