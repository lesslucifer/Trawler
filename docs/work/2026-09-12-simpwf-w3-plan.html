E-SIMPWF.W3 — the tool writes the notes, the agent writes the judgment

One command derives every fact git already knows — the range, the identity, the doc paths and their tiers, the per-layer counts — and writes both the test/v2 and doc/v1 notes from one judgment text, so a derived field is never retyped, and never wrong.

v1 · 2026-09-12 · Trawler · T3 WU plan · E-SIMPWF.W3 · wu/simpwf/note-tool off epic/simpwf · epic plan

Requirement

cargo xtask notes write <wu|epic|commit> <tip> [--target <ref>] [--judgment <path>|--template] reads one YAML judgment document (stdin by default) and writes the tip's test/v2 and doc/v1 notes in one command, deriving every field git can answer: the range (base = merge-base with the target, head = the tip, and the diff's sha256), the identity block, the branch label, the tier of every doc the range touches, and the per-layer counts read off the test files the judgment names. The judgment carries only what the tooling cannot know — the covers text, a layer's waiver, each changed doc's action and its distillation. A judgment that contradicts the range is refused before anything is written, in the gate's own blocks, and the command prints the range it pinned so the review writes the same base, head and diff_sha256 into its cr/v3 note.

What the tool derives, what the agent judges

In the notesWho answers itFrom where
base, head, diff_sha256 derived the same functions the gate's own open uses: merge-base <target> <tip>, rev-parse <tip>, and the sha256 of git diff --no-color --no-ext-diff base..head — printed, so the review pins the identical range
schema, level, epic, wu, branch derived the level is the scope the caller named; the epic half of the identity is computed from the declared WU id (E-SIMPWF.W3 ⇒ E-SIMPWF); the branch label is the tip ref when it is a branch. One block, written into both notes, so 1·notes cannot disagree with itself
every changed doc path, and its tier derived git diff --name-only base..head filtered to docs/, each path through the gate's own tier_of — plus, at a WU seam, a design the range retired at bytes the base never held (DEC-29), which the endpoint diff cannot show
each layer's count derived the test files the judgment names, read at the tip, counted by the declaration the file's language uses: #[test] and #[tokio::test] in Rust, it( and test( in TypeScript. A file the counter does not know, or one absent at the tip, is refused rather than counted as zero
the covers sentence judged the agent: what those tests establish, in the words a reviewer reads. The gate never counted it, and no command can
a layer's waived reason, and t2_waived judged the agent: why a layer owes no test here, and why a code change distilled into no T2 doc. Both are review subjects, never free passes
each doc entry's action, distills, distilled_to judged the agent: whether the doc was added, updated or archived, and what it carries. The path and the tier are not the agent's to type
the verdict not here the cr/v3 note is the review's output and stays the review's; this command writes the two notes the review reads, and never the one it writes

The judgment document is the two notes with every derived field removed — tests without count, changes without tier, and no schema, level, epic, wu or branch. The command puts them back from git, so the judgment and the notes cannot drift: there is one copy of each derived fact, and the command is the only one that writes it.

What it refuses, and what it leaves to the gate

CheckRefused whenWhy here rather than at the merge
0·judgment this command's own the judgment is not YAML, carries no identity for the level it is written at (or carries one at commit level), a named test file is absent at the tip or of a kind the counter does not know, or a layer name is not one of the three the schema has these are facts about the input document, and every one of them would otherwise be written into a note as a different fact — an unknown extension counted as zero tests, a typo'd layer silently dropped
2·manifest the gate's own the derived manifest would be red: the level's required layer (commit ⇒ unit, working unit ⇒ integration, epic ⇒ e2e) has no count ≥ 1 and no waiver the same block, the same wording and the same code path as the merge gate's — a refusal the author reads once instead of the reviewer reading it later
6·doc-note the gate's own a doc the range touches has no judgment entry; a judgment entry names a path the range does not touch; an archived entry carries no distillation lineage; or a code change has no T2 entry and no t2_waived reason the tier and the path list are derived, so the only thing left to get wrong is a disagreement between the judgment and the range — and that disagreement is the whole refusal
everything else not asked here: the review's own cr/v3, the design verdict, the human signature, and the checks that judge the merge rather than the notes the writer produces two notes; it is not a second gate. 3·review onwards belongs to the review and the merge, exactly as DEC-43 drew that line for the preflight

It reads committed bytes only. The counts come from the test files at the tip, and the paths from the range — never from the working tree. Proving that the checkout is that tip, with nothing uncommitted and the suite green, stays the preflight's job (DEC-43), so a note written from a dirty checkout is a note about the tip, not about the dirt.

Expected result

Observable afterWhere a reader checks it
Both notes are written in one command and pass the gate first time; a derived-field mismatch is impossible rather than repaired write the notes on a real WU range, then cargo xtask verify-dod wu <tip>: no 1·notes, 2·manifest or 6·doc-note block appears, and the counts, tiers and identity in the notes are the ones the range and the files imply
A judgment that contradicts the range is refused before a note exists, naming the blocker in the gate's own words the command's exit 1 and its FAIL blocks, over the omitted-path, phantom-path and zero-layer cases in xtask/tests/notes_write.rs; git notes shows no new note
The counts are read from the files, not typed: a test the judgment's files declare is counted, and a file the counter cannot read is refused rather than counted as zero the unit tests over the counter, and the integration case whose derived count is the number of #[test] declarations in the named file at the tip
The range is pinned once: the command's printed base, head and diff_sha256 are the ones the gate recomputes for the same tip the printed scope line next to cargo xtask verify-dod's own 5·diff-binding recomputation, asserted equal in the integration suite
--template answers the "which docs did I touch, and what tier are they" question without a second reading of the diff, and writes nothing its output against git diff --name-only base..head, and git for-each-ref refs/notes unchanged across the run
Running it writes nothing but the two notes: no receipt, no tally entry, no other note ref git for-each-ref refs/notes and target/.gate-tally before and after
