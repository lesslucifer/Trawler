Requirement

One test walks the whole epic the way a Codex session consumes it — T0 through AGENTS.md, the code-review skill through .agents/skills/, then the committed hook command strings read out of .codex/hooks.json and run over both harnesses' payload shapes — and proves Codex gets the identical verdict Claude gets on a red doc, a green doc and a non-doc edit, with the turn-end backstop still refusing; and the three T1 process docs that today assert one harness and one payload shape state the arrangement DEC-52 fixed.

What W1 already landed, and why this WU is not it. W1 built the four doors and the drift alarms: harness_parity.rs asserts each door in isolation against constants it declares itself, and doc_hooks.rs asserts the script's payload tolerance by invoking the script directly. Neither reads the committed config, and neither composes the doors into the session a Codex agent actually has. W1 also pulled DEC-52 and its index row forward (deviation 1 on its result) — so this WU's distillation is the three T1 edits, not the decision record.

Maps to

E-CODEX — the epic's own e2e obligation and gate G6, the last of the six expected results. No UC-*: this is a process epic and nothing user-visible in the proxy or the UI moves. The truth it absorbs is DEC-52, already written; what lands here is the T1 wording that record amends.

Test plan

LevelWhat it covers
e2e The deliverable. xtask/tests/e2e_codex_harness.rs, one flow in five steps:
  1. T0 door — AGENTS.md is mode 120000 in git ls-files -s and its blob hash is CLAUDE.md's; reading the path yields those bytes.
  2. Skills door — every .claude/skills/*/SKILL.md reads byte-identically through .agents/skills/ and carries name + description; code-review is present by name.
  3. Red doc, both shapes — the PostToolUse command string, deserialized from .codex/hooks.json, runs in a temp repo whose .claude/ is the repository's, once per payload shape over the same red ready doc: exit 2, stderr names the missing checklist items, and the two stderrs are equal.
  4. Green doc and a non-doc patch — same command, both shapes: exit 0, stderr empty. No false red, no noise.
  5. Turn end — the Stop command string over that repo holding a tracked red doc: exit 2 with the refusal naming the doc.
Hermetic: steps 3–5 are tempfile repos and the real xtask binary via CARGO_BIN_EXE_xtask; no network, no repository writes.
integration Waived — waived: "the WU's contract is the composed flow, and each door's bounded contract is already pinned by W1's harness_parity.rs and doc_hooks.rs; a per-door integration test here would restate them". What this WU adds that no existing test has is exactly the composition and the config-derived command, which is the e2e's subject and cannot be asserted below it.
unit Waived — waived: "the diff adds no production code path: one test file, one Cargo.toml feature + [[test]] entry, and doc edits". If review finds any logic worth extracting into xtask/src/ — as round 3 of W1 did — the waiver is replaced by real unit tests in the same commit.

Run with cargo test --all --all-features; the feature gate follows e2e_design_flow's precedent, so the epic e2e is opt-in exactly as the other epic-level suites are.

Deliberately not asserted

ThingWhy a test cannot have it
Codex's /hooks trust store Per-machine, keyed to the hook definition, reviewed by a human once. DEC-52 rules it an operator step, like .mr-allowed. It becomes step 6 of the expected results and a recorded smoke in the WU result.
Codex's own discovery pass over AGENTS.md and .agents/skills/ That is the harness reading the files; the epic's contract is that the files are there with the right bytes, which steps 1–2 assert. Asserting the harness would mean shipping Codex into the suite.
