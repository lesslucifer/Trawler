Step 1 — distil, then archive (the 72)

The rule is synthesize UP, never duplicate DOWN: a work doc leaves the tree only after the truth it earned is in a tier that outlives it. Sixty-eight of the 72 are E-DFLOW's own; the other four are the epic's base docs.

T3 sourceCarriesDistils to
W1–W11 plans · results · discussions (~60) the flow's construction history nothing new — superseded by the T1 flow doc and the rulebook they produced. Archive.
design-flow-base.html · component-design-base.html the flow spec and the component-design contract the runs actually load Verify first. These are live substrate, not scratch — if a run reads them, they belong in a durable tier, not docs/work/. Resolve before archiving.
runs #1–#8 (8 docs) the worked proof the flow produces receipted designs the acceptance evidence is the epic result; runs archive behind it.
W11 coverage map 32 assertions: 30 inherited · 1 retired · 1 held the build WU consumes it — archive only once that WU exists to carry it, else the retirement contract evaporates.
The one real risk in this step. design-flow-base.html is loaded by every design run. Archiving it to a gitignored folder would delete the flow's own substrate from the repo. Step 1 begins by resolving where it belongs — a durable tier — and only then archives the genuine scratch. A doc that something still reads is not scratch.

Step 4 — the DEC-13 question, homed

W11 raised a real question and deliberately left it unanswered: run #8 first marked the unset the proxy capability unused, and the design review found that false against ui/src/Onboarding.tsx, which renders Stop routing inside the set-proxy step. The run now carries it as blocked.

Today that question lives only in a T3 result doc — which this WU archives. docs/decisions/dec-13-onboarding-capabilities.html says nothing about it. Archiving the result without homing the question first would erase it.

This WU records the question on DEC-13; it does not answer it. The answer is the build WU's, with the owner's call: either the build keeps an unset affordance (assertion #14 inherited, not retired), or the removal is argued on its own merits and DEC-13 is amended to say where revert now lives. A design run may not narrow a shipped capability by listing it unused.
