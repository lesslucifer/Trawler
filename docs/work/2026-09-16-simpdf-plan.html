E-SIMPDF — the design flow, cut to the mockup

Six staged artifacts, two loop-backs, a five-step close, a 17-row receipt and an adversarial finder were built so an agent would think before it drew. The human reviewing the mockup is the gate anyway, and every round of that review re-edits the upstream artifacts to keep them consistent with it. Keep the mockup and the lists that record what the screen was handed, what keys drive it and what the human said; cut the rest; land it in the spec, the rulebook, the checker and the skill together.

Draft v2.2 · 2026-09-17 · Trawler · T3 epic plan · E-SIMPDF · supersedes v1 (2026-09-16, a measure-then-cut plan in five WUs) · v2.2 folds in the owner's seven review comments

Intent

The design flow was built by E-DFLOW so an AI agent would think before it drew, and it has never been re-scoped. Fifteen closed runs later the owner's reading is that the design still needs the human's feedback on the mockup, every time, so the artifacts that exist to make the agent think are not the gate. They are cost: each is edited again after every review round to stay consistent with the mockup it was supposed to precede. v1 of this plan proposed to count the corpus and bill a paired re-run before cutting anything, borrowing E-SIMPWF's discipline (DEC-48 · DEC-49 · DEC-50). The owner scoped that out: this is a scope call, not a cost optimisation. What survives of the discipline is DEC-50's habit — the corpus number stands beside each cut so a later reading cannot re-buy a station without new evidence — and the numbers are already in this plan. Now, because E-ONBOARD and E-REPLAY's composer run this flow next, at full price.

Use-case requirements

A process epic — it delivers no UC-* behaviour and changes none. No proxy behaviour, no API surface and no shipped screen moves; this epic designs nothing and builds nothing a user can see. What changes is the contract an AI agent follows when it does design a screen, so the truth lands in one T2 decision (the next free number after DEC-52), in the T2 rulebook where the receipt obligation and the soft-rules table are (design-rules-index, governed by DEC-14, which the record amends), in the T1 design flow spec, which is rule-bearing and is edited under a Reviewed-By trailer, and in the design-review skill, which is infrastructure.

A fake designing agent emits one item at a time, a fake human answers each, and the checker and the merge gate judge the result over a real git tree.
