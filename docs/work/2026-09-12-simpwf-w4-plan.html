E-SIMPWF.W4 — the review is code-only

The code review's subject, its binding and its inputs become the code paths. A document cannot change what it judged or ask it for anything, a diff that changes no code asks for no cr note at all, and the design dimension leaves the fleet for a step whose verdict 9·design reads on its own.

v1 · 2026-09-12 · Trawler · T3 WU plan · E-SIMPWF.W4 · wu/simpwf/code-only off epic/simpwf · epic plan

Requirement

The code review judges code, and only code: its subject, its recomputed fingerprint and the files it reads are the code paths — src/, xtask/, tests/, ui/src/, ui/e2e/. It writes cr/v4, whose diff_sha256 is computed over that subset, so a doc-only commit neither voids a PASS nor has one demanded of it, and a diff that changes no code is asked for no cr note at all. The design dimension stops being the review's sixth finder: its judgment moves to a step that writes its own design/v1 note on refs/notes/design, which 9·design reads, and the review neither spawns that step nor carries its verdict. The five code dimensions are unchanged in what they look for, and no severity moves.

Where the design verdict lives, and why not on the cr note

A design artifact is a document — a component design or a closed design run under docs/ — so a diff can carry one and change no code at all. The plan puts those two rules in the same breath: the review binds code paths only, and a diff that changes no code demands no cr note. A design verdict living on the cr note would break one of the two, and it would be a claim about paths that the note's own binding no longer covers. So the verdict moves to a carrier of its own.

Decision
Carrier design/v1, one YAML note on refs/notes/design, holding the section the cr/v3 note holds today: the artifacts judged, the rulebook blob, its own verdict, and the hand-off citations and drops
When it is owed iff the diff carries a design artifact, or renders a file that owes the accounting — the same predicate design-scope prints today, so nothing new is asked for and nothing already asked for is dropped
Who writes it the design step: cargo xtask design-scope <base> <head> still prints what must be judged, and the judgment instructions move out of the code-review skill into .claude/skills/design-review/SKILL.md, verbatim where they are rules, with the existing design-rubric.md as the rubric it reads
What the code review keeps nothing about design: no finder, no verdict, no citation, no design: section, and no finding about a document
What the design epic inherits the step, its carrier and its cost. Whether the design flow keeps the 17-row receipt, and what the step becomes, stays that epic's call — this WU gives it a verdict 9·design can read and nothing more

The fingerprint, exactly

One hash, three places that must agree byte for byte, and a schema that keeps old tips readable.
The set the paths notes::is_code returns for: src/, xtask/, tests/, ui/src/, ui/e2e/. One definition, so the skill, the writer and the gate cannot drift
The bytes git diff --no-color --no-ext-diff BASE..HEAD -- those paths, hashed as today. A path outside the set contributes nothing; a path inside it changes the hash even if its only edit is whitespace
The empty case no code path in the diff ⇒ no cr note, so there is nothing to compare and no fingerprint to write
Versioning cr/v4 declares the code-subset fingerprint; the gate reads a cr/v2 or cr/v3 note as the whole-diff fingerprint its schema was written against. The comparison branches on the schema the tip declared, never on what the note happens to contain
The notes beside it test/v2, doc/v1 and design/v1 are untouched by the fingerprint: none of them is a claim about the code diff
