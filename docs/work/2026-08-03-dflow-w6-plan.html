⓪ The sweep — which scales are actually open

The discussion flagged that closing four scales leaves the vocabulary half shut. Resolved against the real config: ~800 utilities resolve across 22 scales, and the project defines tokens in only six.

ScaleResolvesProject tokensAction
spacing5021close replace, keep only project keys

width · height · minWidth · minHeight · maxWidth · maxHeight · inset · translate54–85 each0close these inherit wholesale — w-96, max-h-64 all legal today. They derive from spacing plus keywords, so closing spacing fixes the numeric half; the keyword half needs the ruling below
gap · padding · margin · space50–510inherits spacing — closed for free once spacing is
lineHeight · letterSpacing · borderWidth · zIndex5–140rule needed — in use today (leading-none, tracking-wide, border-t, z-20) and the ruling never named them
The sweep surfaced a distinction the ruling did not make: values vs keywords. Some off-list classes are scale values (p-5 = 1.25rem — a number someone picked). Others are keywords with no numeric choice in them: rounded-full, max-w-full, min-w-full, border-none, border-t, leading-none, w-px. All are in use in the shipped collection.

Proposed rule, following the zero-value precedent: a keyword that expresses a relationship or a reset rather than a magnitude is always legal — full, none, px, auto, and the side-only border utilities. It is the same argument that settled min-w-0: "100% of the parent" is not a value picked off a scale. Everything with a number in it stays closed. This is the one ruling the plan makes on its own; it is called out here for review rather than buried in step 1, and if it is wrong the fix is 7 class usages, not a re-plan.

leading-relaxed (1.625) and tracking-wide (0.025em) are not keywords by this test — they are named magnitudes. Both become project tokens in step 1.

The pragma. // design-allow: <class> — <reason>, applying to the next line only. Enforced by the predicate itself: the named class must appear on that line (so an edited line stops matching and reds) · the reason must be non-empty, mirroring the gate's waived: rule · a pragma over a bare size value is rejected, never suppressed · the live total is printed on every run, so suppressions are visible debt rather than a silent hole.

The risk this WU carries, named at planning. Twelve predicates written against the only two design runs that exist will tend to over-fit to them. The regression pass is necessary and not sufficient — a predicate can pass both runs and still be wrong about the third screen. The mitigation is discipline, not tooling: each predicate checks the rule, not the run, and where that cannot be written honestly, the rule stays unchecked and the gap keeps printing — exactly what W4 did with these twelve rather than shipping a predicate it did not believe.
