The screen as it ships — five zones, and what each one costs today

The design's subject is 123 lines of ui/src/FlowDetail.tsx. It is not greenfield: every zone below ships, which makes each one a precedent the run must cite by file:line and then keep, change, or argue away.

Identity bar header

FlowDetail.tsx:67–86

Raw verb in a bare <span>, a real StatusPill, a hand-formatted ${duration} ms, and a bare <button>×.

Costs: the verb loses MethodLabel's verb→tone mapping; the duration is the second inline copy of formatting DurationText owns.

Request leg uri + versions

FlowDetail.tsx:89–95

The URI as a mono <p>; the two HTTP versions joined by an arrow into one muted line.

Costs: the URI is a full value the user grabs whole and cannot click to copy — CopyText's stated @use.

Copy as curl payload + action

FlowDetail.tsx:97–115

A <pre> of the rendered command beside a hand-rolled copy button.

Costs: setCopied(true) is never reversed — the sticky "copied" defect, which CopyButton's timed confirm deletes.

Header legs ×2 wire collections

FlowDetail.tsx:16–33

A local HeaderTable: a raw <dl> grid, with "none" as a bare <p> when empty.

Costs: no per-value click-to-copy, and "none" is a word where Notice's empty-states-orient sentence belongs.

Body SEAM — W7

FlowDetail.tsx:117–119

A local Section wrapping <BodyViewer>.

This run stops at the zone boundary. It designs the slot the body pane sits in — label, order, scroll ownership — and declares the seam. It does not design the pane.

Where this run stops — the W7 seam, stated once

The run designs the container, W7 designs the contents. Concretely, W5 owns: which zone the body occupies, its label, its position in the scan order, and which zone owns the scroll. W5 does not own: the raw/decoded toggle, the renderer dispatch, the copy and save affordances, the five absence notices, or the cut marker — every one of those is a BodyViewer decision and lands in W7's run.

In the mockup the body zone is therefore stubbed, which the flow spec explicitly sanctions: "stubbed — a component's internals: code surfaces, live clipboard, renderer dispatch, transitions". A stub here is the correct artifact, not a gap.

What could go wrong

RiskHandling
The forced reuse. The epic plan states the expected outcome ("Section and HeaderTable resolve to reuse"), and a run that reads that as an instruction will write the verdict it was told to reach — exactly the "complete, fluent and false" receipt Tier-3 hunts. Read @avoid first, per the flow's own principle, and let it decide. An @avoid hit is the stage's most valuable output. If a fit genuinely fails, the run writes propose + a blocked-on row and the epic plan's row is what turns out wrong.
Designing through the seam. The body is the panel's largest zone and its most interesting one; a run that drifts into the raw/decoded toggle or the renderer dispatch has stolen W7's screen and will collide with it. The seam is declared in the run's Frame as a non-goal and the body zone is stubbed in the mockup. Any body-pane decision the container seems to force goes on blocked-on addressed to W7, never decided here.
First-ever execution. No prior screen run exists — only the spec and W1's component-design format. Some Tier-1 predicate may prove unsatisfiable as written, or the spec ambiguous. verify-doc's failure output is the oracle — never the checker source. Edits are batched: one pass, verify once, batch residuals, verify again — the norm is edit twice, verify twice. Genuine spec friction is recorded on blocked-on for the epic to rule on; this WU does not amend T1 process docs.
Restating what a component owns. The registry entries here are unusually rich (CopyButton's confirm timing, Notice's seven renders, Section's two-level cap). Re-listing any of it in the run breaks "never re-decide what a component owns". The States column is filled by reference — cite the entry, never re-type its values. The run's own content is the assembly: zoning, order, which absence gets which sentence, what the identity bar ranks first.
The mockup drifting into a drawing. A hand-drawn component in correct utilities is "still a fork no class check can see" — and specimens.bundle.js is generated and git-ignored, so it may simply be absent. Build it (cargo xtask ui specimens) before the mockup stage and mount every reuse/extend from window.Trawler. mockup·hand-drawn is a Tier-1 predicate, so a drawing reds the gate rather than reaching review.
