1 · Frame

Purpose: a developer mid-debug reads what one captured exchange was, and takes a piece of it out to a terminal.

Given: method · status · duration · both HTTP versions · the full URI · request headers in wire order · response headers in wire order · a derived curl command · the body pane as a mounted child · a close handler · a null flow meaning "still loading".

Not given: no timing breakdown · no per-leg timestamps · no body size before fetching · no eviction notice while open · no replay · no next/previous flow.

  share a single vertical scroll region (flex:1, min-height:0, overflow-y:auto)
  — the panel scrolls as one document, so a 40-header request pushes the
  response leg down rather than scrolling inside itself.
  Unbounded zones and their caps:
    C     the selected leg's header collection — NO cap; every header renders
          (constraint "read the wire truth"). Capped only by the shared scroll
          region, which the SCREEN owns. Switching leg replaces its contents,
          never appends.
    D     body — capped by BodyViewer's own family policy (TEXT_MAX / HEX_MAX
          / TREE_MAX, each with a CutMarker). Cap owner: the COMPONENT, W7.
    B     the URI — unbounded in length, bounded in height by wrapping; no
          scroll of its own, and it SCROLLS AWAY rather than being pinned,
          so a 3-line URI never eats the panel's fixed chrome. Cap owner:
          the screen, via wrap-not-truncate. The curl action adds nothing
          unbounded: the command it copies is never rendered (Tune 7).
    A     the identity row is fixed-height and must stay one line: verb,
          status and duration are all bounded, and the selector is two
          fixed segments. Nothing unbounded may enter it - which is why
          the URI sits in B and not here.

SegmentedControl
T1		 A · reuse

why
  • @avoid "actions (that is a button)" — selecting a leg changes what is displayed; it performs nothing.
  • @avoid "multi-select" — exactly one leg is shown.

 Esc — the rulebook's "dismiss the surface" convention, already sighted on flow detail panel · Enter/Space on the focused ✕

Which leg opens selected — the panel's decision, not the control's. SegmentedControl's @avoid puts defaults on the tenant, so this run states it: the panel opens on request, always. The shipped body picks per-flow (flow.response_body ? "response" : "request", BodyViewer.tsx:148 at ca18daa) — a rule that made the selected leg depend on what the flow happened to contain. With one panel-level selector that would move the whole screen under the user between flows, so it goes: a request always exists, and it is what the user clicked a row to identify.

One keyboard path is not yet true in code. The rulebook sights Esc on the flow detail panel, but FlowDetail.tsx binds no key handler — only the ✕ closes it. This run designs it as the rulebook states it; W6 is where it becomes true, and it is listed in blocked-on so the build does not read it as already shipped.
