Intent

E-ONBREV made setup appear, open its guide and say "set up" at the moments UC-ONBOARD names, and it left content, copy and layout alone. Users still meet four problems. What shows and what reloads when they move between the list and setup depends on state nobody has walked through. Each platform's tasks report a status that is honest but not always the most accurate or useful reading available. The instructions are dense, neutral text, so a user cannot tell what to act on or what to skip. They are also text only: the user must copy values by hand and find each settings screen alone. And eight known problems sit parked on the roadmap, including a close dialog that was never redesigned. The user-visible change: moving between screens keeps or reloads exactly what the state calls for. Each platform shows the most accurate status it can verify. Each guide makes the one thing to do next stand out. Each step offers the easiest route there is: an interactive one where it can (a QR code, a link that opens the right screen), otherwise an image or video of the step. The close dialog behaves and reads to the same standard. It comes now because E-ONBREV's timing rules are settled, so these reviews no longer mix with timing defects.

Carried into W3–W10 (the owner, 2026-09-28): a captured flow is not permanent proof that a setup step works. A step turned green by traffic expires after a while, and each status WU decides, for its platform, how the step reads once its proof is old. Example: an iPhone's certificate step is green from a request an hour ago, and the profile has since been deleted.

Non-goals

  • Re-opening E-ONBREV's timing rules: captured-only proof, the launch gate, the setup session (DEC-60). One changes only if a finding shows it is wrong, and then as a new DEC. The owner's 2026-09-28 proposals change two of them in W1, as DEC-61: the dot opens the list before anything is captured, and capture proof expires.
  • Core changes: the failed-handshake reason (R31) and device attribution each stay their own roadmap epic. A status WU may name the gap they would close, but does not close it.
  • New probes, such as a Linux trust probe, unless a status WU's owner ruling asks for one (Q8).
  • New platforms.

Q1Are copy and layout in scope?
Copy = every word the screen shows: task titles ("On your iPhone, install the certificate"), step sentences, status lines, button labels, notes ("The password prompt was cancelled. Try again, or follow the manual steps."), and the labels of the collapsible sections ("details", "other ways", "to undo it later").
Layout = how that is arranged: the order of tasks and steps, what is open and what is collapsed, what is a button and what is text, what stands out and what recedes, and how much sits on screen at once.		 Ruled 2026-09-27: yes, as W12–W19. Steps also gain interactive routes or media (Q11).
