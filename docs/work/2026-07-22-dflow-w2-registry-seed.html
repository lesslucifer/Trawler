① The component-design template

Six fields. Filling them is designing the component; carrying them as TSDoc is registering it. A field that can't be filled honestly means the component isn't understood yet.

FieldTSDocWhat it answers
name + one-linerfirst lineWhat is it? PascalCase name — a dash — one sentence.
tier@tierThe reuse judgment: T0–T4 plus the why (T1↔T2 = business logic; a one-off is T3, not T1).
anatomy@anatomyThe visible parts, in order. What a builder assembles; what a reviewer checks.
use / avoid@use / @avoidThe fit-first contract: when to reuse it — and when reaching for it is the wrong call.
states@statesEvery state it owns: hover/focus/active/disabled plus domain states (confirming, empty, in-flight). These live here, not in screen designs — W1 showed per-element defaults never belong to a screen's Interaction stage.
made-of@madeofThe lower-tier registry components it composes (— for primitives). This is how the registry expresses composition, the W1 finding that validated the tier ladder.

The same template as it will appear in code — the required TSDoc shape the generator reads and the freshness gate enforces:

/**
 * CopyButton — copies a caller-supplied string; label swaps to "copied" for ~2 s.
 * @tier T1 — clipboard + confirm swap is generic UI, no business logic
 * @anatomy compact bordered button · label (word or glyph) → transient "copied" → reverts
 * @use any one-click copy affordance; copy-as-curl = CopyButton + a curl serialiser fn
 * @avoid implicit copy on a value (that is CopyText) · anything that is not a copy
 * @states idle · hover · focus · active · confirming (~2 s; resets if the target changes) · disabled
 * @madeof —
 */
export function CopyButton(/* … */) { /* … */ }
Tier ladder (from the epic): T1 Primitive no business logic · T2 Widget has business logic · T3 Local screen-specific one-off · T4 Composition built local, broken into lower-tier parts. T0 Foundation is external (Tailwind tokens). Collection = T1 + T2 — the tier verdict is the membership decision.

② The mechanism — TSDoc → generated index → freshness gate

flowchart LR
  SRC["ui/src/components/*.tsx
TSDoc = truth"] --> GEN["gen-index
(deterministic)"]
  GEN --> IDX["index (committed,
generated file)"]
  IDX --> GATE{"gate: re-run gen-index,
git diff vs committed?"}
  GATE -->|"differs"| RED["❌ stale — run gen-index"]
  GATE -->|"identical"| GREEN["✅ fresh"]
Store nothing forgeable. The gate regenerates the index from the real .tsx and diffs against the committed copy — the committer never supplies the comparison value, so a hand-edited index or a pasted hash can't pass. Same pattern as Cargo.lock freshness.

The reuse-or-propose contract (for every future screen)

flowchart TD
  EL["Elements stage of any design run"] --> LOAD["load the index
(one file = whole vocabulary)"]
  LOAD --> Q{"per element:
does a collected
component fit?"}
  Q -->|"fits"| REUSE["reuse as-is —
cite it by name"]
  Q -->|"nearly"| EXTEND["extend the component
(never fork a copy)"]
  Q -->|"no fit"| PROPOSE["propose-new:
fill the template, tier it"]
  PROPOSE --> T12["T1/T2 → collection candidate"]
  PROPOSE --> T34["T3 stays local · T4 breaks down"]
Reuse-first, fit-first: fit is judged against the entry's @use/@avoid — forcing a component past its @avoid line is a propose, not a reuse. W4 realises the propose path inside the revised flow.

Deliberately absent

No ui/ code, no TSDoc in real components, no generator, no gate, no T1/T2 doc changes. These designs stay T3 until W4 validates the flow that consumes them — distillation upward happens then. The build WU turns each card into a component whose TSDoc is the card's fields.
