E-EXPORT.W1 result — the listing pages, and nothing that reads it noticed

Opt-in limit + cursor on GET /flows, delivered as planned: the unparameterised contract is untouched, and the no-duplicate/no-skip invariant is proven as a property.

v1 · 2026-09-04 · Trawler · T3 WU result · E-EXPORT.W1 · WU plan · epic plan

Outcome

Delivered, against the requirement as written. GET /flows now accepts an optional limit and cursor; with neither it returns the same bare, unbounded, newest-first array it returned before, and with limit=n it returns an envelope of at most n summaries plus the cursor that continues the walk. Every one of the WU plan's five observables holds:

Two contract calls the plan left to the build

CallMadeWhy
how a full final page reports the end the walk peeks one row past the page, so a page that exactly empties the ring carries next_cursor: null the plan pinned "next_cursor is null on the last page". Without the peek a full last page hands out a cursor whose follow-up is an empty page — technically walkable, but it makes the caller's stop condition "an empty page" instead of "no cursor", and hands out a cursor that resolves to nothing.

Deviations

None from the WU plan. Both calls in the table above are the plan's own contract implemented, not departures from it — the plan pinned the null-cursor-on-last-page behaviour and the named refusals, and each row records the mechanism chosen to satisfy it. One test was renamed during the work (…is_byte_identical_to… → …keeps_its_pre_paging_shape) because it asserts the summary row's field set, not bytes, and a test name must claim only what it proves.

One change the review added. The reuse dimension found that list and page each spelled out the same newest-first-then-filter chain, so the listing rule had two independent definitions one module apart. Fixed in f707ee8 by extracting Ring::newest_first (the ordering) and Ring::matching (id resolution plus the filter), which both reads now compose. Behaviour-preserving — page keeps its own cursor probe, which must consume the unfiltered order before filtering, and that invariant is now stated where it is load-bearing rather than only in the plan. Suite green unchanged.

Deviation from the epic plan: none. W1's summary block, its dependency ("none — first WU") and its expected result are all as planned; question 1's settled answer (the cursor is the last row's id, resolved against the ring's order) is what shipped.

The review round

Five isolated finders over the WU diff, plus adversarial verification of every candidate. 11 candidates, 10 refuted, 1 real — and the one real finding was a nit, fixed rather than waived.

DimensionRaisedOutcome
reuse 3 1 real (nit) — the duplicated listing walk, fixed in f707ee8. The verifier compiled both candidate remedies and this is the one that shares the rule without routing every unbounded read through a usize::MAX sentinel. Two nits refuted: the proptest does not subsume the deterministic page tests (it asserts only walked == listed, so it is blind to page composition and to the dead-cursor quirk), and flow_summary_is_lean is not a field-set lock at all.
correctness 2 both refuted on substance. An unbounded limit is correct "at most n" paging: the unparameterised endpoint is unbounded by documented design, so a large limit grants no extra read amplification, and the overflow case is already a 400 rather than a wrap. Refusal precedence between two simultaneously invalid parameters is taste — both outcomes name a genuinely invalid parameter. The load-bearing invariant was independently stress-tested and held: 1920 deterministic cases, 257 genuinely truncated walks, zero skips — so the no-skip branch of the proptest is non-vacuously exercised.
simplification 3 all refuted. Deleting the handler unit tests because the router tests overlap is the substitution the testing standard forbids ("a WU test never excuses unit tests on its commits — coverage is additive"), and the two suites sit at different seams: the handler function versus the assembled router.
altitude 3 all refuted. Notably the T2 doc was accused of leaking Store::page's mechanism; verification found the opposite — every accused phrase states a client-observable consequence, while the genuinely internal facts (the single lock, the reversed iterator, the peek) never left the code.
efficiency 0 nothing, by measurement rather than inspection: the paged walk of 200k rows at limit=50 ran 186ms against 95ms for one unpaged list — under 2×, not quadratic. page also cuts the worst-case lock hold from ~95ms to ~105µs versus the list it replaces, since the clone is bounded by limit.

The design dimension did not run: cargo xtask design-scope reports no design artifact and no rendered file in the diff, so the cr/v3 note carries no design: section.
