The three defects the diff caught

Recorded at length because each was invisible to the two gates that exist today. Both tsc -b and all 447 tests were green with every one of these in place.

① A token name collided across two scales

borderWidth.hairline silently re-widthed every border in the app. hairline was already a colour token, and border-hairline is written 22 times. Adding a borderWidth key of the same name makes Tailwind emit both utilities under one selector:

.border-hairline { border-width: 1.5px; border-color: rgb(63 58 54); }

Every 1px hairline in the UI becomes 1.5px. No error, no warning, no failing test — the class still exists, still resolves, and the tests assert on class names. Only the before/after CSS diff shows it. Renamed to emphasis, and the reason is now a comment in the config so the next agent does not re-add it.

Generalised rather than patched: the same collision is possible for every prefix two scales share. Checked mechanically across border-, outline-, text- and font- — the only remaining overlap is border-'s DEFAULT, which is Tailwind's stock border = 1px and exactly what the ⓪ ruling blessed. This check belongs in the ②ᵃ rule's test suite, not just in this session's shell history.

② One scale survives closing spacing

The plan and the sweep both say the derived size scales close for free once spacing does. That is true of eight of them and false of maxWidth.

width, height, minWidth, minHeight, maxHeight, inset, translate, flexBasis derive from spacing plus relationship keywords — closing spacing shuts them. maxWidth does not: it carries its own independent magnitude ladder — xs sm md … 7xl, plus prose and six screen-* — that has nothing to do with spacing and survives untouched. 22 magnitudes still resolvable, and max-w-sm is in use today.

Redeclared as spacing + relationship keywords only (none full min max fit). Verified: max-w-prose, max-w-2xl, max-w-screen-lg and max-w-sm now emit nothing; max-w-full and w-1/2 still do.

Why it matters beyond the fix: "derived scales close for free" was an assumption carried through both the plan and the sweep, and it was 8-for-9. The general lesson is the ⓪ lesson again — diff the emitted CSS, do not reason about the config. Fractions (w-1/2), viewport units (h-screen, min-h-dvh) and min/max/fit also survive across every derived scale; all are relationships under the ⓪ test, so they stay legal by ruling rather than by oversight.

③ Closing opacity kills slash modifiers

Four colour classes died as collateral, and none of them is an opacity class. bg-canvas-soft/30, border-hairline/40, border-hairline/50, bg-black/50 stopped emitting the moment opacity was closed to its single disabled key — the /nn modifier resolves against the opacity scale, so closing it removes every step the modifier could name.

Step ⓪ ruled these split into "colour token + opacity modifier, each checked against its own scale". That ruling holds and is exactly right — but it implies the opacity scale must carry the steps, which no document stated. Three named steps added: wash .3, hairline .4, scrim .5, so step ② re-expresses bg-canvas-soft/30 → bg-canvas-soft/wash rather than losing the dimming.

The scrim is the exception: bg-black/50 cannot be re-expressed this way, because black is deliberately not a colour token. It becomes the scrim colour instead — one token, no modifier.
