E-SIMPWF.W2 — the paperwork finishes before the exam

One command the review runs first: Gate 0's fmt, clippy and suite, and the notes that review is about to read — refused in one block that names the blocker, before a single finder spawns against a tree that is still going to move.

v1 · 2026-09-12 · Trawler · T3 WU plan · E-SIMPWF.W2 · wu/simpwf/preflight off epic/simpwf · epic plan

Requirement

cargo xtask preflight wu|epic <tip> [--target <ref>] refuses, before any finder spawns, while the tree the review would bind is not green — fmt, clippy, the suite — or while the notes that review reads (test/v2 and doc/v1 on the reviewed tip) are absent, unparseable, or short of the level's required test layer. It prints one block per blocker that names it, and spawns nothing. A diff that asks for no review passes it untouched, and it runs no doc predicate.

A process epic: no UC-* is delivered or changed. This WU adds one xtask subcommand, shares the gate's own note checks with it, and edits the review skill to call it first. It adds no check the merge gate runs, no note schema, and no rule about what the review judges.

The preflight is the only place a red tree can still be fixed for free. Everything after the verdict is a repair that orphans it, and the merge gate cannot tell the two apart.

What it runs

Check idReadsWhy a red one must stop the review
0·tree the working tree, through Gate 0's three commands: fmt --all --check, clippy --workspace with -D warnings, and the suite — skipped when the tree is byte-identical to the last green run (the cache it already keeps) the repair is a commit. A suite fixed after the verdict is a diff that is no longer the diff the note pins, so the review is bought twice for a finding the fleet never saw
1·notes test/v2 and doc/v1 on the reviewed tip: present, parseable at the schema the gate reads, and carrying the same identity block a missing or unparseable note is an input the review is about to read and the caller is about to rewrite. The gate's own message for it is the fix — this is the same code path
2·manifest the test note's level against the scope being reviewed, and the layer that level requires (working unit ⇒ integration ≥ 1, or a non-empty waiver) a layer that is absent or zero is a test nobody has written yet, which is the clearest case there is: the tree moves the moment it exists

What it never runs

The boundary is what the review reads. Every check below is either the exam's own output, a fact about the merge, or a document predicate — and none of them is repaired by a commit that lands under a verdict.

Not runCheck idsWhy not
the review's own evidence 3·review, 4·review-base, 5·diff-binding they judge the cr/v3 note this preflight precedes. Refusing on them would be a deadlock: the exam may not be required to pass itself
the design verdict 9·design, components·unbuilt also the exam's output — written by the review the preflight gates
doc-note coverage 6·doc-note the note is read — its shape is checked under 1·notes — but whether it lists every changed doc is a completeness fact about the merge, repaired in the note, moving nothing the review bound
the human signature 8·manual-review the signature goes last by rule (DEC-27): the human is asked once the tree has settled, which is after the review, not before it
the doc predicate verify-doc the owner ruled the commit- and merge-level doc checks useless: a document is verified where it is authored, by the harness hooks. The consequence is recorded in docs/decisions/dec-43-…, minted by this WU

Expected result

Observable afterWhere a reader checks it
A failing test or a malformed note stops the review before any finder spawns, in one block that names the blocker cargo xtask preflight wu <tip> — exit 1, one FAIL block per blocker with its check id and its fix, and the session's own report that it spawned nothing
A tip whose tree is green and whose notes parse passes, and says so in one line the same command — exit 0
A diff that asks for no review — docs or infra only — is not refused, and no note is demanded of it the same command on such a diff: it reports that no review is asked for, and demands no test/v2 or doc/v1
Nothing the preflight prints is an estimate or a stored verdict: the notes are re-read and the tree is re-measured on every run xtask/src/preflight.rs, and xtask/src/gate.rs's shared note checks
The preflight and the merge gate can never disagree about 1·notes or 2·manifest: one function answers both a test that runs both over one tip and compares the two refusals
Running it changes nothing: no note, no receipt, no refs/notes/* ref, no entry in the local gate tally git for-each-ref refs/notes before and after, and target/.gate-tally
