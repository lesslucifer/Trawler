Incremental Gate 0 delivered: cargo xtask gate0 skips fmt+clippy+nextest when the working tree is byte-identical to the last green run, keyed off a full working-tree hash cached in a local target/ file.

Result v1 · 2026-07-08 · Trawler · T3 WU result · W2 plan · epic plan

Outcome

Delivered as planned. cargo xtask gate0 ([xtask/src/gate0.rs](../../xtask/src/gate0.rs)) runs Gate 0 and skips it when the working tree is unchanged since the last proven-green state. The key ([xtask/src/git.rs · worktree_key](../../xtask/src/git.rs)) is sha256(HEAD + git diff HEAD + untracked non-ignored contents); the cache is a single target/.gate0-green file holding that key. The code-review skill's Gate 0 (§2) now calls the subcommand.

The load-bearing invariant holds, verified live: a changed tip re-ran Gate 0 (its cache key moved), an unchanged tree skipped it, and a red run (a stray trailing newline) re-ran and refused to cache. A stale or hand-edited cache can never yield a skip on a differing tree, because the skip fires only when the recomputed key matches — DEC-2 recompute-don't-trust, applied to a cache instead of a receipt.

Measured time saved

Per-skip saving, measured on this machine with /usr/bin/time:

  • Fully-warm baseline (incremental cargo already built): cold Gate 0 ~1.97 s vs a cached skip ~0.03 s → ~1.9 s saved per otherwise-redundant run.
  • Cold-ish invocation (as seen in this WU's own review Gate 0, which had to compile after a branch switch): the full fmt+clippy+nextest pass took ~15.5 s of build+test; the same tree re-verified would be the ~0.03 s skip. This is the realistic per-review-retry saving, matching the discussion's measured 7–35 s incremental-cargo range (discussion §Q3).

Where it compounds: the discussion measured the cargo trio paid 2–3× per gate-heavy epic on the same unchanged tree (main loop, then each code-review Gate 0, then red-gate retries). C1 collapses the duplicate runs toward one verify: on an epic with N redundant Gate-0 runs the saving is roughly (N−1) × one-Gate-0, i.e. tens of seconds to a few minutes of wall-clock per epic, entirely on the review fleet's critical path. No timing assertion enters the hermetic suite (wall-clock is non-deterministic — epic non-goal); this figure is the recorded before/after the close protocol requires.

Deviations

  • Storage: local target/.gate0-green file, not a git note — reverses the epic plan's "git note (decided)". A note is durable, origin-synced and tamper-evident (the DEC-2 evidence model); a Gate-0 skip is an ephemeral, machine-local build fact worthless elsewhere, and a pushed green note would let a machine skip a build it never ran. The file co-invalidates with cargo clean and never syncs. This also dissolved the plan's open "syncs to origin?" sub-question. Rationale specced up-front in the W2 plan; the epic plan's C1 bullet, W2 card and open-questions list were updated to match (owner-reviewed, DEC-7 sign-off on that doc commit).
  • git stash create rejected as the key primitive — it silently drops untracked files (verified: adding an untracked .rs did not move its tree hash), which would be a false-skip hole. The key is built explicitly instead. Pinned by the an_untracked_source_file_changes_the_key regression test.
  • Scope held to the code-review Gate 0 — the pre-commit/pre-push hooks still call raw cargo; adopting gate0 there is a later additive change with no code coupling (noted in the W2 plan). Kept the diff small and the correctness surface to one command.
