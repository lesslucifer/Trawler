Gate parity 2 — the merge proves the tree it creates, the push reads that proof

A green merge into main must leave a tree the push accepts, and the push must not pay again for proof the merge already bought.

v1 · 2026-11-05 · Trawler · T3 epic plan · E-GATEPAR2 · cut from E-GATEPAR plan v3 (roadmap row)

Intent

main can take a green epic merge and then go red at git push: the merge gate reads notes only, and the suite first meets the merged tree at pre-push, after the merge commit already sits on a merge-only branch. Parallel epics make every landing a combination no gate has tested. Fix the order first (prove the merged tree at the merge), then the cost: the push re-runs the suite blind, a slow-launch machine turns the suite into a 15-minute wait or a false red, and the suite pays for its structure rather than its tests (push timing report). Now, because E-GATEPAR gave every worktree its own hooks and target/, so a proof written in a checkout is finally that checkout's own.

The suite's first contact with the merged tree moves from push to merge; the push reads the merge's marker in the same checkout.

Use-case requirements

A process epic — it delivers no UC-* behaviour and changes no use-case contract. Its contracts are the workflow's hook rules (workflow.html § Hooks, DoD-E "merge --no-ff into main") and decisions/workflow-gates.html.

Expected result

  • A merge into main whose merged tree fails fmt, clippy or the suite is refused at the merge, with the abort/back-merge line; no red merge commit reaches main. Merges into epic/* keep the notes-only gate.
  • A merge whose tree that checkout already proved green costs a marker lookup, not a suite run.
  • Checks Gate 0 spawns never see the hook's GIT_* environment.
  • Pushing a sha whose tree is the clean checked-out tree reads the Gate 0 marker (gate0 skipped … (<key>)); any other pushed sha is proven before it leaves.
  • On a machine with the launch-assessment wait, a suite-running gate refuses in seconds with the Developer Tools fix line (override TRAWLER_ACCEPT_SLOW_LAUNCH=1); without cargo-nextest it refuses with the install line.
  • No doc-test pass runs for a crate with no doc-tests, and a guard fails when one gains a runnable example; integration tests run as one binary per crate, passed count unchanged.
  • The push timing report's commands, re-run at close, give per-check wall time before vs after on the same machine.

Non-goals

  • No change to what a note proves or to gate checks 1–9; the review / mr / dod chain is untouched.
  • No Gate 0 on merges into epic/* — a WU seam stays notes-only.
  • No proof shared between checkouts: each checkout's marker answers for its own tree only (DEC-73).
  • No remote CI, no test selection or sharding, and no test removed — W4 changes how the suite is packaged, not what it checks.
  • No change to macOS security settings from code; the gate only detects and names the exemption.

Working units

W1 · merge-proves-tree — the merge into main runs Gate 0 on the merged tree

For a merge into main only, pre-merge-commit and the conflicted-merge path in pre-commit run cargo xtask gate0 merge once verify-dod hook epic is green; red refuses the merge with the abort/back-merge line. Gate 0 strips GIT_* from every check it spawns. New DEC-74.

E-GATEPAR2 · C1, C2, C10 · DoD-E "merge --no-ff into main" · workflow.html § Hooks.

An epic merge into main whose merged tree fails Gate 0 is refused before the merge commit exists, and main stays where it was; a tree already proven in that checkout is a marker hit; a WU merge into epic/* runs no suite.

none — E-GATEPAR (on main) put the tracked hooks and a per-checkout marker in place.

W2 · push-reads-proof — pre-push reuses Gate 0

pre-push calls the marker-aware cargo xtask gate0 instead of a blind suite when every pushed sha's tree is the clean checked-out tree; otherwise it proves the pushed tree before the push leaves (never skips an unproven sha). Keeps the range check and the notes sync.

E-GATEPAR2 · C3 · workflow.html § Hooks (pre-push).

A push right after a green merge runs no suite and prints the marker hit; a push of a dirty tree or a non-HEAD sha runs it.

E-GATEPAR2.W1 (the merge writes the marker the push reads).

W3 · launch-guard — a slow-launch machine is named, not endured

Suite-running gates probe the machine once: link a fresh tiny binary and time its first launch; above a threshold, refuse with the Developer Tools fix line, overridable by TRAWLER_ACCEPT_SLOW_LAUNCH=1; the verdict is cached per machine. cargo-nextest becomes a checked prerequisite and the serial fallback goes.

E-GATEPAR2 · C6, C7 · push timing report F1, F3, F5.

On a machine with the Gatekeeper wait the gate names the cause in seconds; without nextest it refuses with the install line; a fast machine pays the probe once.

E-GATEPAR2.W2 (both suite-running gates exist in their final form).

W4 · suite-cost — the suite costs its tests, not its structure

doctest = false for each crate with no doc-tests, plus a guard test that fails when a doc comment in such a crate gains a runnable example; integration tests consolidated to one binary per crate (feature-gated hook tests keep their own targets).

cargo test --all after a change drops toward its seconds of tests; the passed count before and after is identical.
