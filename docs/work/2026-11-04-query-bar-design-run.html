Design run: the query bar

The header with one query bar where the free-text field, the host and method dropdowns and the status field were. Every filter is a chip. Typing writes a draft and suggestions follow it. The list follows the chips, never a keystroke.

Design run · round 1 on 2026-11-04, open for the owner · Trawler · T3 (docs/work/) · E-QUERY.W2 · branch wu/query-bar/query-bar-design · epic E-QUERY · WU plan · component: QueryBar · within DEC-70

Mockup

Live. Click the bar (or hover the frame and press ⌘F) and type. st then Tab completes status:; 4 then Tab makes a status:4xx chip, and only then do the rows move. Enter takes what you typed, Space ends a chip, ↑/↓ move through the suggestions, Backspace in an empty draft removes the last chip, and each chip's × removes that one. Try -method:OPTIONS, host:localhost:8080, login token, stauts:4xx. The buttons under the frame force one state at a time.

overflow: app header pinned; it grows a line rather than clipping (Layout), and the query bar's chips wrap inside it, so the bar takes a second line once its chips fill the first. No cap: every chip is one the user added. The suggestions overlay below the draft and never push content; they scroll past listing-max (184 px, about seven rows), the cap Select's popup already uses. A chip's value wraps, never truncates. flow list: rows scroll vertically, capped by the capture ring, as today.

Payload is mono: each row's cells (api.example.com, path, time, method, status, duration) and every host a suggestion offers. The bar itself is mono too: the draft, the chips and the suggestions are typed grammar, read as typed (C5).
