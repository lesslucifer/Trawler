What the run hardened (stage definitions that moved from the plan's first cut)

  • Frame → a driver table (driver → consequence → why → checked by); functional requirements are input, the design lens is output; no coded ids.
  • Layout → an annotated ASCII region sketch (draw.io trialled, no added value).
  • Elements → a tiered component catalog (T0–T4; T1↔T2 = business logic; "used in" surfaces reuse; T4 → break down).
  • Interaction → a use-case table grounded in the Frame goals (not per-element states; those belong to the registry).
  • Draft mockup → a native HTML/CSS build (dark tokens, stateful) — a decision stage, not assembly.
  • Tune → before/after notes; genuinely loops back to Layout, so it earns a stage.
  • Cross-cutting: representation is load-bearing — optimize every artifact for human perception.

Seed lists (feed the rest of the epic)

  • → W2 registry: the catalog rows + T4 break-downs (status pill, header table, body viewer, copy button, icon button, section container, …).
  • → W3 rulebook: hard (state declarations, mono-for-wire-data, tokens-not-hex, spacing scale) and soft (wording, visual-weight, grouping, ordering).
  • → W4 flow revision: Layout/Elements boundary; no escalation path for upstream-undefined states; the two stage redefinitions (Elements → tiered catalog, Interaction → use-cases).
