E-INSPWIN.W1 — hand data to a window of its own

The decision record and the shell plumbing that every later WU stands on: an opener hands a payload by value, the shell creates or focuses one window per key, and that window claims its payload once.

v1 · 2026-11-03 · Trawler · T3 WU plan · E-INSPWIN.W1 · branch wu/inspect-window/payload-handoff · epic plan

Requirement

openDataWindow({key, title, bytes, typeHint?}) opens a native window labelled data-<hex(key)> titled title, or focuses the open one with that key without touching its payload; the new window's takeDataPayload() returns exactly the bytes and caption handed over, once, and every data window closes with the main window.

Mapping

E-INSPWIN · UC-9 window lifecycle · epic expected rows 2 (same key focuses, another key opens a second window, data windows close with the main one) and 10 (the shell relays, the core is never called) · mints DEC-71 (the data window; DEC-67 is held by epic/panels).

What it builds

sequenceDiagram
  participant O as opener (main window)
  participant S as shell (data_window.rs)
  participant D as data-<hex(key)>
  O->>S: open_data_window — raw body: frame(caption, bytes)
  alt label open or parked
    S->>D: set_focus (payload untouched)
  else new key
    S->>S: park(label, payload)
    S->>D: build window (same bundle, title)
    D->>S: take_data_payload
    S-->>D: raw frame, then nothing (claimed once)
  end
  Note over S,D: main Destroyed → every data-* destroyed · data-* Destroyed → its unclaimed payload dropped
Bytes travel as raw IPC bodies both ways; the frame is a 4-byte big-endian caption length, the caption as JSON, then the bytes.
