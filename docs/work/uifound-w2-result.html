Outcome

Delivered. The native app now shows the Warp-styled base layout with a live, filterable flow list on a typed API client — the epic's demoable tenant. Every expected result from the plan is observable, and the epic e2e drives the real window end to end:

  • Warp tokens are the Tailwind theme — warm-dark canvas #2b2622, off-white ink #f7f5f0, hairline borders, Inter / DM Mono / Instrument Serif, 4px spacing, 3–4px radii — with functional 2xx→ok / 4xx·5xx→warn status color kept as the deliberate exception a debugging proxy needs.
  • The base layout exposes named regions later UI epics slot into (header/filter bar, main content, a reserved detail region). The flow list is virtualized with @tanstack/react-virtual.
  • The typed API client reads GET /flows and subscribes to GET /stream (SSE) at a configurable base URL — server-side filtering + debounced refetch ported from the web shell, not reinvented.
  • cargo xtask ui e2e builds the app and drives the real WebKit window via @wdio/tauri-service against an ephemeral core: empty layout renders → a proxied request appears live → the filter narrows and restores → a second request appends without refresh. 4/4 pass. This discharges the E-UISHELL browser-assertion waiver in full.
  • Core stays GUI-free; the web shell (GET /) still works unchanged.

Deviations

  • Core API gains an open CORS grant (Access-Control-Allow-Origin: *). The plan listed "any change to an existing API" as a non-goal, but UC-4 is impossible without it: the native webview is a cross-origin client of 127.0.0.1:7421, so its fetch/EventSource are blocked with no CORS header. Added as a small axum middleware (grant on every response, OPTIONS preflight → 204). Owner-approved as a DEC-12 consequence: the API is a read-only loopback inspection surface — everything it exposes is already curl-reachable, so * adds no exposure the 127.0.0.1 bind does not already imply. Carries its own unit + integration test.
  • The API base URL is resolved runtime-first. A runtime window.__TRAWLER_API__ / sessionStorage value wins over the build-time VITE_TRAWLER_API env, which wins over the :7421 dev default. This is the plan's "configurable, including at release" decision; it is also how the e2e injects an ephemeral port with no rebuild.
  • e2e harness shape. macOS has no raw tauri-driver, so the e2e uses @wdio/tauri-service's embedded provider (wdio plugins gated behind a src-tauri e2e Cargo feature so release stays thin; built via tauri build --config tauri.conf.e2e.json to merge withGlobalTauri + the wdio capability). The ephemeral core + local origin run in a standalone launcher crate outside the core workspace, exposing a tiny HTTP control server (/hit, /stop) because wdio's launcher and worker are separate processes. A pnpm override pins @wdio/native-utils@2.5.0 around a broken transitive pin in @wdio/tauri-service@1.2.0.
  • jest-dom added. W1 deferred it; W2's richer DOM assertions (integration test) justify @testing-library/jest-dom — the conventional RTL matcher set, one devDependency.
