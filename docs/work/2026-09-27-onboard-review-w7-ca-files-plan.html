E-ONBREV.W7 — the certificate file each platform opens

Each platform downloads, saves and is told about one certificate file, in the format its own installer opens. An iPhone gets a configuration profile, Android gets DER, and the desktops keep PEM.

v2 · 2026-09-27 · the owner's second iPhone report (R29, R30) added · Trawler · T3 WU plan · E-ONBREV.W7 · branch wu/onboard-review/ca-files · epic plan · findings R23–R30 below · depends on E-ONBREV.W1 (merged, the before is recorded)

Requirement

The core serves its one CA as PEM at /ca.pem, as DER at /ca.cer and as an Apple configuration profile at /ca.mobileconfig. Each download suggests a file name that matches its URL, and /reach names all three URLs. iPhone and iPad are sent to the profile in Safari. Android and its emulator get the DER file. Every desktop and the iOS Simulator keep PEM. In every platform's certificate task, the download, the save control and every command name the same one file. The iPhone's trust step says installing the profile does not trust it. When traffic arrives and doesn't decrypt, each platform's certificate task names the check its users most often miss.

Audit: what each platform is told and given today

One route serves every platform: GET /ca.crt answers the PEM with Content-Disposition: attachment; filename="trawler-ca.pem". The save control writes the same PEM as trawler-ca.pem (CA_FILENAME).

One CA and three encodings. /ca.crt stays for UC-1, curl --cacert and every existing client (Q13).
FormatContentsWhy this platform
PEMthe file on disk, byte for byte Every desktop trust command and simctl read PEM. Linux's update-ca-certificates needs PEM content under a .crt name, which the given cp already does.
DERthe certificate's DER bytes, decoded from the PEM Every Android version's CA installer reads DER, and its picker lists .cer (Q12).
profilea plist: a Configuration payload holding one com.apple.security.root payload, whose data is the DER. The display name is "Trawler Proxy CA". The UUIDs are derived from the DER (uuid v5), so reinstalling the same CA replaces the old profile instead of adding a second one Safari hands a profile to Settings. It also installs from Files and AirDrop, which a bare certificate does not. It is unsigned, so iOS labels it "Not Verified" (Q11).
