E-PANELS.W1 — the decision and the layout store

The record that lets the user size the layout, and the shell file that remembers the sizes. Nothing on screen changes yet: W3 and W4 read and write this store.

v1 · 2026-11-03 · Trawler · T3 WU plan · E-PANELS.W1 · branch wu/panels/layout-store · epic plan · base 2c3178d5

Requirement

The shell keeps one saved layout (pane width, headers share, five column widths) in layout.json in its config directory: layout_write replaces it whole, and layout_read returns it only when the file parses into exactly that shape, and nothing otherwise.

Mapping

E-PANELS · UC-4 / UC-5 persistence rows · the epic's expected results 4 (sizes survive a relaunch), 5 (a broken save gives the defaults) and 8 (no layout state in the core) · rulings Q2, Q3, Q4 · mints DEC-67, superseding DEC-36's rejection of a draggable split.
