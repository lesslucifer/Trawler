E-EXPORT.W7 — paste a curl command, get a flow

The inverse of the copy-as-curl the app already ships: a parser that turns one pasted curl command into one request-only flow, reached as POST /flows/import?format=curl — accepting exactly what a browser's "Copy as cURL" and Trawler's own toCurl emit, and refusing everything else by name.

v1 · 2026-09-05 · Trawler · T3 WU plan · E-EXPORT.W7 · epic plan · W3 result · W5 plan

Requirement

POST /flows/import?format=curl reads one curl command — the shape a browser's "Copy as cURL" or Trawler's own toCurl emits, shell quoting and backslash line-continuations included — and inserts one request-only flow marked imported, carrying the command's method, URL, headers and body, with -u, -b and --compressed expanded into the headers they stand for and transfer-only flags consumed silently; any other flag, a second URL, or a value the command does not itself carry is refused with 400 and a reason naming it, leaving the capture unchanged.

Mapping

E-EXPORT · the epic plan's W7 summary block · UC-6 extended to a second, single-request import form — the inverse of UC-5's copy-as-curl · the epic plan's expected result 8 and settled question 8, which fixed the accepted flag set before a line was written. Depends on W3: reuses Flow::imported(), Store::import, the source filter and the plain-text 400 refusal shape. Lands before W6 so the build has a real endpoint behind the paste target W5 designed — W5's run recorded this WU's refusal contract as its one open blocked-on and designed the paste affordance against W3's shape; this WU honours exactly that shape.

What the parser accepts — the set settled in question 8, made concrete

TokenBecomesDetail the build must honour
the leading curlrequiredthe first word must be curl (a path ending in /curl counts); anything else is "not a curl command" — a paste target that accepts any text is not a curl paste target
the bare URL · --urlthe URIexactly one, absolute, http:// or https:// — a second is refused as such, none is refused as such, a scheme-less or unparsable one is refused naming it
-X · --requestthe methodkept as typed; absent ⇒ GET, or POST when a body flag is present — curl's own rule
-H · --headera request headerName: value with the value trimmed of its leading space; Name; is curl's spelling of an empty value; Name: alone is curl's "send no such header" and adds nothing; no colon at all is refused; a value starting with @ reads a file and is refused
-d · --data · --data-raw · --data-binary · --data-asciithe request bodyseveral are joined with &, as curl does; @file under every spelling but --data-raw is refused because the bytes are not in the command; --data-raw @x is literal, exactly curl's distinction
-b · --cookiea Cookie headera value with no = names a cookie-jar file to curl and is refused
-u · --userAuthorization: Basic + base64expanded, because dropping it changes what the request is; a value with no : would make curl prompt for a password and is refused

--end of flagseverything after it is the URL

The ignore list is closed and enumerated in code; it is the only silent case and it is safe precisely because none of these leaves a trace in the request. Everything not in the accepted table or this one is refused naming the flag — -F, -T, --form-string, --data-urlencode, -G, -I, --json, -A, -e, and anything unrecognised — because silently dropping any of them would produce a flow subtly unlike the request the user pasted. -A and -e are headers in disguise like -u, but browsers never emit them and the settled set does not include them; a refusal that says "write it as -H" is one edit away, a silent guess is not.

Written in the crate rather than pulled in: the subset is small, every refusal needs its own wording, and $'…' is outside what the common shell-words crates read. No new dependency.

The contract calls this WU makes

QuestionCall, and why
Where does the parser live? src/api/curl.rs, beside har.rs: a second format behind the same import door. It is not inside har.rs — the two share nothing but the Flow they produce — and not in routes.rs, which stays the thin HTTP layer. One public function, flow_from_curl(&str) -> Result<Flow, CurlError>, and a CurlError whose Display is the refusal text.
How is the format selected? ?format= on the existing route: absent or har ⇒ W3's parser, curl ⇒ this one, anything else ⇒ 400 format must be har or curl — the same refuse-by-name rule ?source= follows, because a silently defaulted format would parse a curl command as JSON and report "not a JSON document" for the wrong reason.
What is the request body? The pasted command, raw, as UTF-8 text — not wrapped in JSON. A wrapper would add a quoting layer to an input whose whole difficulty is quoting; the paste target sends what was pasted. Bytes that are not UTF-8 are refused as such.
What does success answer? { "imported": 1 } — the envelope the door already answers with. A pasted command is an import of one.
Which headers are synthesised? Only the ones a flag is. -u, -b and --compressed are headers spelled as flags, so they expand. curl's own runtime defaults — Host, User-Agent, Accept: */*, Content-Length, the application/x-www-form-urlencoded it assumes for -d — are not invented: the flow records the command, not one tool's runtime, and this is also what makes toCurl → parse an exact inverse rather than one that grows headers on every trip.
What instant and version does the flow carry? started_at = the moment it was read, which Flow::new already stamps: nothing happened on a wire, so the only truthful instant is when the flow came to exist — the same one a captured flow gets. version is HTTP/1.1, the wire default W3 already uses for a writer that recorded none. No response, no duration: the shape the store, the API and the UI already handle between request and reply.
How is the round trip against toCurl proven, given it is TypeScript? A test-only Rust mirror of toCurl — the ten-line serializer (-X omitted for GET, single-quoted URL, -H per header, --data-raw for a captured body, the '\'' idiom) — drives the proptest. The mirror is anchored to the TS test file's own pinned literal outputs (ui/src/flow.test.ts asserts exact strings), each repeated as a Rust example test, so the mirror cannot drift from the TS without a test naming the drift. The e2e's real paste through the app closes the loop at epic close.
