Both suites share one e2e build. The owned suite is a separate wdio run because the app's environment is fixed per launcher, and an owned launch must not carry TRAWLER_API.

The owned spec, step by step

JourneyDrivesAsserts
J1 · one launch capturesread core_status in the main window; send GET http://127.0.0.1:<origin>/one-app through the reported proxy; press onboarding's way back to the list (DEC-61 — a plain-HTTP row proves no device setup, so it never reveals the list by itself)the state is running on non-fixed ports; the injected __TRAWLER_API__ is the reported API; the row appears; GET /flows on the reported API returns it; the core's parent is the app
J2 · the service page tells the truthopen_settings, switch to the settings window; SIGKILL the core's pid from the worker; press restartrunning with the reported pid, proxy and API; the log's start mark names the pid. After the kill: "stopped" with the signal, and the main window still answers. After restart: running with a new pid, the same API address, and GET /flows answers there
J3 · quit releasesdestroy the main window (the window's quit path)the app's WebDriver stops answering; both reported ports bind again; neither the app's pid nor the core's remains
