E-UIINSPECT.W3 — Body viewers

The Body section becomes real: type dispatch → JSON tree · text · image · form · hex, raw/decoded toggle, copy/save — and the epic e2e.

v1 · 2026-07-13 · Trawler · wu-result · E-UIINSPECT.W3 · branch wu/uiinsp/body-viewers

Outcome

W2 left the detail panel's Body section as a one-line placeholder. W3 replaces it with the real viewers over GET /flows/{id}/{leg}/body?decode=1|0 — the epic's demoable tenant, completing UC-5. The dispatch is the core contract:

Content typeRenders as
application/json · *+jsoncollapsible tree (native <details>, no state code); over TREE_MAX (128 KiB) or unparseable → text
image/*<img> over an object URL (revoked on unmount)
x-www-form-urlencodeddecoded key/value table (URLSearchParams)
text/* · XML · *+xml · javascripttext (<pre>) — XML arrives pretty-printed by W1's server-side decode
anything else / unknownhex dump (offset · 16 pairs · ascii gutter), capped at HEX_MAX (4 KiB) with a remainder line

Around the viewers: request/response leg tabs (default = response), a raw/decoded toggle that switches the fetch (decode=1|0; raw mode sniffs the stored bytes — printable UTF-8 → text, else hex), copy body (copies the shown rendering: body text, or the hex dump for hex-rendered bodies; hidden for images, which have no text representation), and save body to a file — a native OS save dialog in the Tauri app (tauri-plugin-dialog + tauri-plugin-fs, filename derived from short flow id + leg + content-type extension), an anchor download in a plain browser. Every non-captured state (empty · streaming · too-large · read-error · no-response-yet · fetch-failure) renders an explicit notice — never blank.

Pure logic lives in body.ts (dispatch, sniff, hex format, form parse, notices, filename); BodyViewer.tsx is the one component; the typed client gains getBody(id, leg, decode) → bytes + content-type. The core is untouched — no Rust outside ui/ and the e2e harness. The requirement sentence ("fetch …/body?decode=1|0; dispatch on content type → JSON tree · XML/HTML text · image · form table · text · else hex; body states → explicit notices; a raw/decoded toggle switches the fetch, plus copy body and save body to a file on the shown leg") is met in full.

Deviations

None from the requirement or contract. Two new dependencies beyond the plan's expectation, both confined to the Tauri shell: tauri-plugin-dialog and tauri-plugin-fs — "save body to a file" needs a native save dialog, and WKWebView does not honor anchor downloads; the official plugins are the supported path (dialog-picked paths join the fs scope at runtime; capability grants dialog:allow-save + fs:allow-write-file only). One harness fix caught by the first e2e run: /hit?p=/json double-joined the origin URL (…//json → 404) — normalized in the harness; the failing run incidentally proved the 404/empty-body notice path end to end.

The code review verified three real findings, all fixed on the tip with named regression tests first: (1) copy ≠ shown — copy body delivered UTF-8-mangled bytes where the viewer showed a hex dump; copy now delivers the shown rendering and is hidden for images; (2) unbounded JSON tree — cap-sized bodies would render tens of thousands of DOM nodes while the hex view was already capped; TREE_MAX now falls back to text; (3) webp/avif saved as .bin — extensions added. The other 13 candidates over two rounds were adjudicated false-positive (form-copy copies the replayable wire text on purpose; missing AbortController matches the established useFlowDetail pattern on a loopback API; the rest were code golf or micro-optimizations).
