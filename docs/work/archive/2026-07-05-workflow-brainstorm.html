The gap. The code-review skill says "a DoD-check agent parses it at done-gates" — that agent doesn't exist, and nothing defines the gates themselves. DoD facts are scattered across three documents, there is no branching/merge model, and completeness is judged by convention, not by a command that exits 0 or 1.
Trust boundary — the round-1 theme. Agents do the work; git does the bookkeeping; hooks + the gate tool do the judging. Every DoD line below is either mechanical (a hook or verify-dod enforces it — an agent cannot skip it, forget it, or claim it) or explicitly marked judgment (a reviewer decides). Where quality itself can't be mechanized ("is this use-case wording right?"), the mechanical check is that the judgment happened: a note cryptographically bound to the exact diff.

One epic's life. Commits stay cheap (hooks only); evidence ceremony concentrates at the two merges — and the merge itself is the gate: a hook runs the verifier and refuses to create the merge commit while anything is red.

An epic starts as a T3 plan doc and an epic/* branch; each working unit is a wu/<epic>/* branch off it, built from hook-gated commits, and can only merge back through a green verify-dod wu — the hook makes a red merge physically fail. When the last WU lands, the epic gate replays the whole story (every WU receipt, every standalone commit, the e2e manifest, the epic review) before main will accept it. Distillation is part of that gate, not an afterthought: the epic cannot merge while its own plan doc sits unarchived (checked against the file tree, not against anyone's memory).

The three levels — workflow view

The charter owns what each level must test; the rows below add only the workflow facts — branch, plan artifact, gate, evidence.

Epic E<n>

A big, user-visible feature — the largest unit of planning (charter's definition).

Branch epic/<slug> off main · Plan one T3 work doc listing its WUs, each with requirement + test plan · Gate DoD-E, hook-enforced at the merge into main · Evidence on the epic tip: test/v2 (level epic) + cr/v2 PASS + doc/v1 + dod/v1 receipt.

Working Unit E<n>.W<m>

A bounded slice of an epic with one explicit, testable requirement sentence and a detailed test plan; independently shippable (charter's definition + D9).

Branch wu/<epic-slug>/<slug> off its epic · Plan its row in the epic plan: requirement sentence + test plan, written before code · Gate DoD-W, hook-enforced at the merge into the epic · Evidence on the WU tip: test/v2 (level working-unit) + cr/v2 PASS + doc/v1 + dod/v1 receipt.

Commit

The smallest coherent increment — one logical change, imperative subject line that names it. If the message needs "and", it's two commits.

On a WU branch — DoD-C only, enforced by hooks; no note, no ceremony. Standalone (landing directly on main or an epic, outside any WU): additionally carries a test/v2 note, level: commit, unit ≥ 1 or a recorded waiver — docs/infra-only commits are exempt (their diff touches no src/).

Collapse rule (mirrors the charter): a genuinely small epic may be a single WU, and a small WU a single commit — but every gate is still met explicitly. A one-WU epic still needs both a DoD-W pass and a DoD-E pass; they may be satisfied by the same branch and review run, with all notes written.

Identity — how notes name their work

Round-1 decision: branch names follow the convention above, but identity never rides on a branch name — names drift, get abbreviated, or predate the convention. Instead every note schema carries the same three-line identity block, so any evidence is self-describing and queryable even after branches are deleted:

## identity block — added to every schema (test/v2, cr/v2, doc/v1, dod/v1)
epic: E1                          # always present for epic/WU work
wu: E1.W2                         # only when the work is a working unit
branch: wu/capture/pagination     # informative label — the ids are the truth

Standalone commits omit epic/wu. Existing v1 notes on main (the E0 baseline) are grandfathered — new work writes v2. Given a tip, its notes hang directly on it (git notes --ref=<ref> show <tip>); given an id, the notes are the index: cargo xtask dod list --epic E1 scans refs/notes/dod and prints every receipt for E1 — which WUs exist, which passed, when.

Waivers (round-2 decision, D10). Some work genuinely needs no test at a given layer. The manifest may replace a required count with a recorded judgment: integration: { waived: "no new boundary — the WU only tightens an internal invariant" }. The gate accepts a waiver mechanically (present + non-empty reason); whether the waiver is justified is a review question — an unjustified waiver is a review finding, so laziness can't hide in one. Vocabulary: waived = an agent considered it and recorded why (judgment, visible, reviewable) · exempt = a rule says no evidence is needed at all (mechanical, e.g. docs-only commits). Word choice for "waived" — alternatives considered: exempt (reads rule-based, hides the judgment), n/a (dismissive, invites abuse), assessed/considered (vague about the outcome). Recommend waived — it matches the review skill's existing waiver vocabulary: an obligation exists and is excused with a visible reason.
Additive, like the test charter. Unit obligations at WU/epic level are proven by the child gates below them, not re-declared — but never waived wholesale: a green epic gate can't exist over a WU that never passed, because the walk re-verifies every seam. Each gate checks what only it can see.

Who judges — the review machinery behind every "judgment" tag

Every judgment row above resolves to one thing: a run of the code-review skill (.claude/skills/code-review/ — the owner of this machinery; summary here, detail there). The people involved are all AI subagents with fresh, isolated contexts — independence is the substitute for the second human this project doesn't have. The session that finished the work triggers the run but never judges its own diff: it only orchestrates.

flowchart LR
  T["triggering session
(the agent closing the WU/epic)"] --> G0["Gate 0 — mechanical preflight

red ⇒ abort, zero agents spawned"]
  G0 --> F["FIND — 5 finders in parallel

  F --> V["VERIFY — one adversarial verifier per finding
fresh context, sees only the claim + scope

  V --> VD["VERDICT
PASS = Gate 0 green and zero
verified findings left unwaived"]
  VD --> N["cr/v2 note on the tip
diff_sha256-bound, PASS or FAIL"]
A review run is read-only — no agent in it edits or commits. On FAIL, fixing belongs to the triggering session (a correctness bug gets its failing, named regression test first), which then re-runs the review on the fixed tip until a run returns PASS — every re-run with fresh agents.

The five finder dimensions and the cross-cutting principles live in the skill's rubric.md (floor, not ceiling — a finder may report beyond it). How they cover the judgment rows of the DoD:

Judgment row in the DoDWhich finder judges it
Unit coverage of the exact diff · tests match the requirement + test plan · test-layer waivers justifiedCorrectness — "what does this change do that its tests don't cover?"
Reimplementing helpers the codebase already hasReuse
Needless indirection, dead branches, one-caller generality · commit coherenceSimplification
Avoidable hot-path costs (buffering streams, per-request copies, unbounded queues)Efficiency
Logic at the right layer · self-documenting code, comment disciplineAltitude (+ principle P5, intent legibility)
Distillation adequacy — T2 wording matches behavior, archive lineage honest, waivers in doc/v1 justifiedthe epic-scope run: finders read the tip's test/v2 + doc/v1 notes alongside the diff; verifiers consult docs/decisions/ before confirming a finding that "fixes" something deliberate

Why the verdict is trustworthy without a human: finders never see the author's reasoning, the chat history, or each other — five overlapping blind sweeps give recall. Verifiers never see the finder's reasoning — they get only the falsifiable claim and the scope, read the full surrounding code, trace callers, and default to refuted when uncertain (with no human filter downstream, a false positive costs more than a missed nit). And the gate tool never cares who judged: it verifies a PASS judgment exists for exactly this diff (cr/v2 + diff_sha256). The review machinery can grow — more finders, new dimensions, rubric distillation — without touching the gate.

The evidence chain — proving completeness from main

flowchart LR
  S["standalone fix commit"] --> E

  NW["notes on WU tip:

  NS["notes on standalone commit:

Because merges are --no-ff, every gated tip stays addressable from main forever. Walking first-parent merges recovers every WU tip and its notes; non-merge commits classify as standalone and must carry their own manifest. Completeness is recomputable at any time, by anyone, offline.

The binding is tamper-evident by construction: notes attach to a commit, and cr/v2 additionally pins the diff via diff_sha256. Amend or rebase a gated branch and the new tip simply has no notes — the next gate goes red, no vigilance required. The dod/v1 receipt (below) is written only by the gate tool and only on green — but it is never blind trust: anyone can rerun verify-dod and recompute the whole verdict from the underlying notes.

The gate tool — cargo xtask verify-dod

Round-1 decision: a Rust xtask workspace member, not shell — same toolchain as everything else, unit-testable, no new dependency. An agent (or a hook, or CI) runs it; it never trusts an agent's memory.

cargo xtask verify-dod wu   wu/capture/pagination        # WU gate: merge-ready into its epic?
cargo xtask verify-dod epic epic/capture                 # epic gate: complete against main?
cargo xtask dod list --epic E1                           # query receipts by identity
# exit 0 — every check green; the dod/v1 receipt is written on the tip
# exit 1 — agent-actionable failures (below); no receipt, and the merge hook refuses

Round-2 decision (D12): failure output is written for the fixing agent, not just for a log — every line names the check, what was expected vs found, and the concrete action that turns it green:

The four notes — one tip, the whole story

Round-2 decision (D11): doc evidence is its own note on refs/notes/doc, not a block inside the receipt — each note has one job, and the receipt stays a pure gate record. A gated tip carries: test/v2 (what proves it), cr/v2 (who judged it), doc/v1 (what knowledge moved where), dod/v1 (the gate's own receipt).

The doc/v1 template — one entry per doc file changed in the gated diff, so distillation is accounted for file by file (schema owner will be documentation-system.html, which owns the tier rules):

schema: doc/v1
epic: E1
wu: E1.W2                         # identity block, as everywhere
branch: wu/capture/pagination
changes:                          # exactly one entry per docs/ path in git diff base..tip
  - path: docs/use-cases/control-api.html
    tier: T2
    action: updated               # added | updated | archived | deleted
    distills: "UC-API-7 pagination contract — requirement sentence + cursor edge cases learned in the WU"
  - path: docs/work/2026-07-05-epic-capture-plan.html
    tier: T3
    action: archived
    distilled_to: [docs/use-cases/control-api.html]   # or none: "dead end — nothing citable survived"
t2_waived: null                   # required reason when src/ changed but no T2 entry exists,
                                  # e.g. "pure refactor — no behavior contract changed"
date: 2026-07-05

The receipt — the queryable "gate passed" record (round-1 decision, D3), now free of doc payload:

schema: dod/v1

The gate's own tests (the charter applies to the tool too): unit tests inside the xtask crate for parsing and classification; tests/dod_gate.rs builds scratch repos in tempdirs (git init, synthetic commits, planted notes) and asserts every pass/fail path — deterministic and hermetic, per the testing contract.

Hooks — where the mechanics bite

HookFiresEnforces
pre-commit (exists)every commitfmt + clippy -D warnings
pre-push (exists, extended)every pushsuite green; new: auto-push refs/notes/test cr doc dod alongside (the Q7 ritual, mechanized); when pushing main/epic/*, any new non-merge commit touching src/ must carry its level: commit manifest (count or waiver)
pre-merge-commit (new)a merge into the current branch, before the merge commit is createdruns the gate against MERGE_HEAD: merging into epic/* ⇒ wu gate; into main ⇒ epic gate. Red ⇒ the merge itself fails — this is the "check dod notes before allowing the merge" hook
Bypass honesty. Git hooks can always be skipped with --no-verify, and a fast-forward creates no merge commit so pre-merge-commit never fires. Mitigations: merge.ff = false in repo config (set by the existing worktree setup), and — decisive — the next gate's walk re-verifies everything, so content smuggled past a hook turns the epic gate red before it can reach main. Receipts are recomputable, so even a bypassed hook can't mint one.
