Specimens in React — feasibility, proven; then the migration

The design files draw components by hand-pasting the same Tailwind class string fifteen times. React + Babel from CDN makes the specimen be the component instead of resembling it. Verified in a real browser before proposing anything.

Investigation + migration plan · 2026-07-27 · Trawler · T3 (docs/work/) · side task of E-DFLOW.W5 · format owner: component-design-base

Verdict first

Feasible — proven, not assumed. React 18.3.1 via esm.sh + @babel/standalone with the typescript preset renders TSX in the browser with no build step, and the Tailwind Play CDN's mutation observer picks up React-rendered class names using the app's real theme. Every computed value in this doc came out of a headless Chrome render, not from documentation.

And better than first proposed: a design file renders the app's real component. No copies, and it still opens by double-click. A first draft had the docs holding their own specimens.tsx — a second implementation of every component, policed by a parity test. Discarded. A second draft read ui/src/ at run time, which worked but needed an HTTP origin. Also discarded. What shipped compiles the collection at author time (§ how): esbuild bundles ui/src/components/ + React into one generated, git-ignored classic script the doc loads with a plain <script src>. The specimen is the component, drift is impossible, and file:// works with no server and no flags.

Scope is still narrower than the request: migrate the specimens, not the docs. Prose, tables, diagrams and fork cards stay exactly as they are. See scope.

One finding in the component, surfaced by the migration. Button's shape="square" path sets a fixed width/height and drops min-h-control, so computed min-height is auto. Also cosmetic, not a defect: frame="bare" computes border-color: rgb(229,231,235), Tailwind's default. border-none sets border-style: none, so the colour never paints.

The file:// constraint — and the workaround

A file:// page cannot read a local file by any route. fetch, synchronous XMLHttpRequest and asynchronous XHR are all refused, and <script type="module"> never executes at all, because module loading is CORS-governed and a file:// origin is opaque. All four measured, not assumed.

So the run-time loader — fetch the .tsx, transpile, blob-import — cannot work on a double-clicked doc. It needed a served origin, and requiring a local server to read a design doc was rejected.
The exception that makes it work: a classic <script src> is not CORS-restricted, and does execute from file://. Verified directly — a local .js file loaded by a plain script tag ran and set its globals.

That is the whole workaround: move the compile from load time to author time. esbuild (already present via Vite — no new dependency) bundles ui/src/components/index.ts plus React into specimens.bundle.js, exposed as window.Trawler, together with the app's Tailwind theme and the shared specimen.js behaviours. The doc loads it with one ordinary script tag and needs nothing at run time.

A build step, but still not a copy — the distinction that matters. Nobody writes or edits the generated files; they are derived from ui/src/ by one command, and they are git-ignored, so a stale bundle is a re-run rather than a divergence to reconcile in review. The invariant is unchanged — the specimen is the component — only when the compile happens moved.

What it costs: one command after editing a component (cargo xtask ui specimens, ~60 ms), and a 732 kB generated file on disk that is never committed. What it buys back is the htmldoc double-click rule, intact.

How the first two attempts got this wrong, stated plainly. Every early verification passed --allow-file-access-from-files, granting the gate a permission no reader's browser has; the docs "passed" while blank when opened normally. The second gate served over HTTP — the same mistake in a different costume. The gate now opens each doc over file:// with no flags, exactly as a reader does.

Pre-existing, and why nobody noticed: tw-config.js is also a module script, so on file:// the app's Tailwind theme has never loaded — since W5 step 3 every design file has rendered its specimens unstyled when double-clicked. The migration did not cause it; it turned a partial silent failure into a total one, which is what finally surfaced it. The bundle carries the theme now, which fixes it for the migrated files.

The problem, measured

The discrepancy is real and countable. W5 step 3 moved specimens to the app's Tailwind vocabulary, which fixed the vocabulary — but each specimen is still a hand-written HTML string, so the same button is re-typed everywhere it appears.

component-design-base already states the invariant this migration would enforce: "The specimen's class string is the component's className, verbatim, so the build copies rather than translates and the two cannot drift."

Today that is a promise a human keeps by retyping. Nothing checks it. Fifteen copies of one string in one file is precisely the condition under which the promise fails silently — and W5's own worklist records three token values that had already drifted between Button and CopyButton while both files claimed identical chrome. The registry's response was to make Button the single shell in code. This proposal is the same fix applied to the drawings.

The proof — what actually ran

A probe was rendered in headless Chrome over file:// with --allow-file-access-from-files, mounting a real <Button> with the three prop axes W5 gave it (frame · shape · tone), then reading back getComputedStyle from the live DOM.

The probe found a real defect on its first run incidental

shape="square" composes w-control h-control but drops min-h-control, so computed min-height is auto. button.html claims the 24 px WCAG 2.5.8 floor is "inherited, not restated" by all three siblings — a square Button does not inherit it.

Whether the fixed 24 px height satisfies the requirement in practice is a judgement for the Button file's owner; IconButton passes size={28} and is fine either way. The point is the mechanism: a hand-drawn specimen cannot surface this, because a hand-drawn specimen has no props to combine. A rendered one caught it in the first render. This is the argument for the migration, stated as evidence rather than as a claim.

Scope — migrate specimens, not docs

The request was "apply React to the design docs". The recommendation is to apply it to the specimens only — roughly the 1,326 class instances — and leave prose, tables, Mermaid diagrams, fork cards and spec grids as static HTML.

Why: the discrepancy being fixed is drawn components diverging from built components. A table of driver rationale has no counterpart in ui/src/ and cannot drift from it. Rewriting it as JSX adds a transpiler between the reader and the words, costs the diff layer its readable segments, and fixes nothing. Say no to that half.

Two checks, neither of which exists: (1) a design file whose component is implemented must not re-draw it — the file either goes away or composes the real component; (2) a component that exists in ui/src/components/ must carry the full TSDoc tag set, since deleting its design file makes that block the only surviving contract. Today both are conventions an agent can silently break, and the failure is invisible: a stale design file looks authoritative.
Retiring a design file whose component is implemented — the ordered flowdeferred to W7 (harness). Confirmed at review: distillation comes before removal, and the harness enforces that order rather than trusting it.
  1. Distil the forks to docs/decisions/ — each of the 16 files carries ~12 fork sections: the alternatives considered and why they lost. Code cannot express a design that was not built. @avoid records the conclusion ("not a combobox") but never the rejected alternative or its conditional fallback ("native <select>, rejected because a native popup cannot carry the search row or the tick column, but it is the fallback if the keyboard contract proves hard to hold"). 7288 lines of design file against 9-line TSDoc blocks.
  2. Verify the TSDoc block is complete — once the design file is gone that block is the only surviving contract, so the full tag set (@tier @anatomy @use @avoid @states @madeof) becomes mandatory, not conventional.
  3. Then remove the design file — the component's code is its documentation from that point on.

A removal that skips step 1 is silent data loss: the file looks redundant precisely because the part only it holds is the part nobody re-reads. The check must refuse step 3 until step 1 has landed.

Running the render gate at merge timedeferred to W7 (harness). cargo xtask ui specimens --check drives headless Chrome, so wiring it into Gate::verify would make every merge on every machine require a browser. Note verify-doc is not wired into the merge gate either — pre-existing, and the same W7 decision covers both: which doc checks are cheap enough to gate a merge, and which stay author-invoked.
Closing the stale-bundle holedeferred to W7 (harness). Editing a component without re-running the build renders the previous version, and --check does not catch it. The fix is a freshness comparison (bundle mtime vs newest ui/src/components/ mtime) and it belongs with the rest of the harness work.
