Outcome

Delivered as planned. Against the W1 requirement and its "done when":

  • Design reviewed & settled. The W1 plan went through three review rounds (proof-by-live-capture, broken-setup recovery, the 3-state status dot + Back control); all comments resolved.
  • Pure state machine. onboardingMachine.ts — initial, reduce (every event: next/back/goto/captured/not-detected/re-invoke/exit), stepStatus, dotStatus, STEPS, COPY. No React, no I/O, so transitions are unit-testable directly.
  • Navigable shell. On launch the app shows the onboarding stepper (three steps: trust the CA · set the proxy · verify), not the bare "no flows yet" list. Next/Back and clicking a step walk the active step; Verify shows the waiting copy. Step actions are inert placeholders.
  • 3-state capture-status dot. The header StatusDot renders broken/checking/connected from dotStatus(state) and, tapped, dispatches re-invoke to re-open setup. It supersedes the old 2-state LiveDot.
  • Phase-driven entry. App shows Onboarding until proven, then the full filter header + FlowList. everProven gates a Back to flows control (hidden on first run). W1 dispatches not-detected on mount as the placeholder for W4's scheduled self-test.
  • Layout and FlowList reused unchanged.

Deviations

  • File renamed onboarding.ts → onboardingMachine.ts. The plan named the pure module onboarding.ts, but that case-collides with the component Onboarding.tsx on macOS's case-insensitive filesystem — TypeScript resolved ./Onboarding to the machine file and the build failed. Renamed the machine module (and its test). The plan's files table is updated to match; W2–W4 import from onboardingMachine.
  • checking dot renders muted grey, not amber. The wireframe legend showed checking in an accent colour, but the Warp theme deliberately has no chromatic accent token (DEC-11) — only ok/warn + muted. So the dot maps connected→ok (green), broken→warn (red), checking→ink-mute (grey). checking is transient (mount immediately dispatches not-detected), so this is cosmetic; the tooltip still says "Checking capture…".
