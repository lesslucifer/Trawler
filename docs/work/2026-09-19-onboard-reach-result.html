Deviations

DeviationWhy
DEC-55's index row landed here, not at W4, where the epic plan's distillation table allocated it The decisions index is the read path an agent checks before "fixing" something odd. A record invisible there for the length of an epic is a record not doing its job. W4's distillation item for it is therefore already satisfied; nothing else moved
No candidate-list check on the arming address. The plan implied the user picks from what the API enumerates; the code refuses only the unspecified address and lets the bind adjudicate the rest The kernel already owns the question "does this machine hold that address", and duplicating it as a list would have been a second, staler answer — and would have made the hermetic loopback test impossible, because loopback is deliberately not offered as a choice. Enumeration stays what it was for: the choice the screen offers. The refusal that carries the decision — one named address, never all of them — is enforced exactly
Re-arm semantics were unplanned, and the first attempt at them was a blocker. The code as first written stopped the armed session before trying the new binds, so a re-arm that bound nothing silently revoked an exposure a user had confirmed and a device was routing through — a 400 was the only trace. The review reproduced it against a running controller. Now: arming the address already armed is a no-op returning what is listening, and arming a different one brings the new pair up before the old goes down, so a refusal costs nothing Reported and fixed inside this WU, with both rules under named tests written before the fix. Recorded here rather than only in the review note because the rule it established — nothing a user confirmed is torn down by a request that failed — is the kind of thing W3 needs to be able to rely on
The arm lock does not span a teardown. The second review round found that both arm and disarm held the controller's mutex across the outgoing session's drain That drain waits on a device's open exchange — measured at five seconds against a held request, and unbounded in principle. While it ran, every reader of the reach state queued behind it, including the disarm a user issues to revoke the exposure, which is the one thing DEC-55 promises stays available. The lock now covers the swap and the bind that must not race a second arm, and nothing else. The regression test polls across the whole drain window rather than reading once — the first version of it raced ahead of the lock and passed against the bug
The CA is carried as bytes, not re-read. CaMaterial gained the key PEM and a shared ca::issuer; the controller rebuilds its authority from memory Also from the review: the first version called ca::load_or_create — blocking file I/O, and key generation on a cold CA — on a tokio worker thread while holding the arm lock, which is the execution-context discipline the project has already ruled on. A second authority is still required because RcgenAuthority consumes the issuer it is given; only the disk read is gone
A dependency joined the core: if-addrs 0.15 There is no std interface enumeration, and the alternative was parsing ifconfig/ipconfig output from a core that DEC-13 keeps out of shelling to the OS
No ui/src/*.tsx was touched, as planned — so this WU carries no design accounting of its own W3 rebuilds the screen from the closed run and wires the confirm to this client. Wiring reach into the stepper W3 deletes would have been work thrown away
