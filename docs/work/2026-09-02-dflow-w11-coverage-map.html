Why a map and not a deletion

The shipped suite guards the screen that still ships — run #8 is a design, not a build. Retiring tests now would leave the live screen unguarded for the whole gap between this WU and the build WU. So nothing is deleted here. This map is the decision record for each assertion, and the build WU executes it.

The rule this map applies. An assertion is layout-bound when it can only be true of the centred-column stepper — it dies with that design. It is capability-bound when it states something UC-ONBOARD promises, which must hold whatever the screen looks like. The second kind is never deleted; it is re-pointed at the new markup.

onboardingMachine.test.ts — untouched

Nine assertions over initial · reduce · stepStatus · dotStatus. No rendering, no DOM, no layout. Run #8 changes no transition, adds no step and removes none — STEPS is still the whole list, and the rail dispatches the same goto the stepper did. The file survives byte-for-byte.

One caveat for the build. stepStatus derives done/active/pending from step order. Run #8's rail does not render that ordering as progress — it shows each step's probed verdict instead. The reducer keeps its meaning (which step's body is expanded), but the build must not let stepStatus leak into the rail's glyphs, or the redesign re-introduces exactly the "✓ because you clicked past it" defect UC-ONBOARD forbids.

Assertion 14 is a scope decision the build must not silently execute. Run #8 first dropped the "Stop routing" affordance, marking unset the proxy deliberately unused. That removes a capability the shipped screen offers today, and DEC-13 explicitly names symmetric revert as part of why the app is allowed to write OS state at all. Deleting this test would quietly narrow a shipped capability on a design run's say-so — so the run now records the capability as blocked instead, with the decision named as what is missing.

The run's own reason does not survive contact with the code: it says the affordance belongs to "the settings surface, not the doorway", but ui/src/Onboarding.tsx renders Stop routing through Trawler inside the set-proxy step of this screen. So the design did not move the capability elsewhere — it removed it, on a premise that is false about where it lives.

Owed: either the build keeps an unset affordance (and assertion 14 is inherited, not retired), or the removal is argued on its own and DEC-13 is amended to say where revert now lives. This is the one place W11 genuinely touches DEC-13 — and it is a question, not an edit. Until it is answered, assertion 14 stands: this map counts it neither inherited nor retired, and a build that deletes it without the decision is acting outside this contract.
