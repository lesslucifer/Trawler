E-GATEBM — epic plan

Fix the DoD seam-walk's back-merge blind spot (#2, target-reachability) and add R5, a recorded per-seam walk-error waiver valve on the cr/v2 note — so a walk misfire never again forces a blanket --no-verify.

Plan v1 · 2026-07-07 · Trawler · T3 epic plan · solution discussion · problems & requirements

Intent

The epic gate's seam walk (gate.rs, three-parent arm) mis-classifies a back-merge of already-gated history as an ungated Working-Unit seam, turning the epic gate red on legitimate integrations. This is not hypothetical: it already forced a blanket --no-verify on main — epic E-NMWF was gated green at 7523de7, back-merged main (31982b7), and landed as 8871d7b with no receipt on the back-merged tip. This epic makes the walk recognise back-merges of landed history (walk clean) while still gating genuine seams, and adds a surgical, recorded escape valve so any future walk misfire is overridden on the record rather than by skipping every gate. Now, because a real epic (epic/notes-view, E-NV.W2/W3) is blocked on it and the gate has already been defeated once. Full analysis in the solution discussion.

Use-case requirements

None — E-GATEBM is a process/tooling epic on the DoD workflow gate and touches no product use-case (no UC-*). The contract it changes is the workflow-gates decision record (workflow-gates.html, DEC-2: "smuggled/bypassed content turns the next gate red"); the epic's truth distills there as a new DEC.

Expected result

  1. Dry-run cargo xtask verify-dod epic <tip> --target main on a stale epic that has back-merged an up-to-date main walks clean — the 7·walk·1·notes [working-unit <tip>] no cr/v2 note on tip <main-tip> line is gone.
  2. A genuinely ungated forward WU seam merged into an epic still turns the walk red (unchanged from today) — the R2 guardrail holds.
  3. A walk seam failure is suppressed by adding a walk_waivers entry (seam sha + non-empty why) to the tip's cr/v2 note; the walk then passes while every other gate check still runs. Without the entry it stays red, and the red output names the exact command to waive and warns against --no-verify.

Non-goals

  • #3′ gated-lineage check for unlanded cross-epic integration — resolved decision: build #2 only; cross-epic dependencies serialize through main. A future epic only if live cross-epic integration ever proves frequent.
  • Removing the walk — considered in the discussion and rejected; it is the only unbypassable backstop against a fail-open/bypassed sub-gate.
  • Per-check waiver granularity — waivers key on the whole seam sha; refine only if it proves too coarse.
  • The tooling/binary mismatch that forces back-merges (the commit-msg USAGE failure) — self-resolves once a branch is current with main.
  • Landing E-NV.W2/W3 on main — downstream of this epic, not part of it.

Working Units

Two WUs: the discriminator lands first and unblocks the stuck merge on its own; the waiver valve layers on top. Each carries its own WU plan doc before its code.

E-GATEBM.W1

Target-reachability discriminator (#2)

Add the target-reachability skip to the walk's three-parent arm in gate.rs: skip a seam when its merged-in parent (p2) is already an ancestor of the gate target (already on main). Keep the existing p2 ⊑ mainline check; thread the target ref into walk().

E-GATEBM · R1 (recognise back-merges of landed history), R2 (preserve the genuine seam gate), R4 (record the discriminator rationale in the workflow-gates DEC).

A stale epic that back-merged main walks clean; a real ungated forward seam still turns red; the discriminator rationale and the rejected #1 symmetric-ancestry alternative are recorded in workflow-gates.html.

none.

E-GATEBM.W2

Walk-error waiver valve (R5)

Add a walk_waivers: [{seam, why}] field to the tip's cr/v2 note (CrNote in notes.rs). The walk reads the tip's cr note, matches a failed seam's sha against it, and on a non-empty why records waived instead of failing. The seam failure's fix line instructs the exact waiver command and warns off --no-verify.

E-GATEBM · R5 (surgical, recorded, reviewable walk-error suppression that isn't --no-verify), R4 (record the cr/v2-carrier rationale).

A matching walk_waivers entry suppresses exactly one seam's walk failure; a missing/empty why does not; all other gate checks still run; the red output is self-instructing. Carrier rationale (cr/v2 = a review judgment, and it is diff-bound) recorded in the DEC.

E-GATEBM.W1 — both edit the walk's three-parent arm; W2 builds on W1's landed state.

E2E test plan

One hermetic e2e test (temp repo, ephemeral ports/tempfiles, in the existing hook/gate suite — tests/dod_hooks.rs or xtask/tests/dod_gate.rs; the implementing WU picks) walking the whole epic flow:

  1. W1 / back-merge: build a stale epic branch, advance main, back-merge main into the epic; run the epic gate dry-run → green walk.
  2. R2 / guardrail: build an epic with a genuinely ungated forward WU seam; run the epic gate → red on that seam (the fix must not widen into a hole).
  3. W2 / waiver: on a red walk seam, add a walk_waivers entry to the tip's cr/v2 note → gate green; blank the why → red again with the instructing message.

This composes both WUs into one end-to-end flow per the testing standard. Each WU additionally carries its own integration test for its bounded contract, and each commit its unit test — additive, never substitutive. No waivers intended at any level.
