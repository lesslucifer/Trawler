Design rules — the KB, one file

The enumerable, slug-id'd design rules every Trawler screen design must consider. Hard rules are one-liners — their Tier-1 predicate carries them; soft rules carry the judgment guidance a Tier-3 reviewer needs.

Living T2 · the design-rules KB's single file (index = rulebook) · Trawler · rationale: DEC-14 · tokens: DEC-11 · closed vocabulary: DEC-17 · truncation escape: DEC-34

What this is

Most rules are extracted — the codebase or a design run already made the decision and this is where it was written down. A marked minority are principle imports. Rules are cited by slug (stable kebab name, never renamed once a receipt cites it — deprecate instead).

One list, two surfaces. A design can pick an illegal value and so can a built component — binds says which. The coverage list = every slug in the hard + soft tables; a design receipt must cite them all.
binds — where a rule can be violated. It decides which surface judges the rule, and whether a screen must answer for it at all.

The hard/soft litmus is the check. If a mechanical predicate exists the rule is hard. If the check is a reviewer's question, it is soft. If neither can be written, it is not a rule yet — it stays out.
Consistency is vocabulary, not vigilance. Anywhere designs must agree across screens — colours, spacing, key bindings, words — a vocabulary fixes the options in one place. A screen never re-decides what warn means — it reuses the entry or proposes a new one.

Vocabularies

The fixed sets rules force designs to pick from. This section names the sets and their governing rules; it never lists their members — the member list is ui/tailwind.config.js.

The second sanctioned escape: raw CSS configuring a third-party styling API. Every colour in it must still be a palette value, asserted mechanically over all of ui/src/.

The one thing a mockup must declare: data-wire. Three hard rules turn on which elements render a verbatim payload. The mockup says so: data-wire="<what it is>" on every payload element, data-wire="collection" on a catalog row that renders a captured collection, and data-wire="none" once when the screen renders no payload at all.

A collection row carries data-order beside it — "wire", or the sort and why.

Soft rules Tier-3

Principles a reviewer judges — each with its DO/DON'T pair and the question the adversarial reviewer asks.

visual-weight-follows-goals The visual hierarchy matches the Frame's goal ranking — the top goal owns the most visual weight. ✓ top goal "scan failures" → status column carries the most weight
✗ timestamps heavier than statuses		 Compare the Layout/mockup hierarchy against the Frame goal table, top to bottom — where do they diverge? screen extracted

progressive-disclosure The default view is the scan level; depth is one explicit, invited act away. ✓ list row → detail panel · raw body → decode toggle
✗ full bodies inline in the list		 At rest, is the scan clean? After one act, is the depth there? screen extracted
data-ink-first Every non-data pixel earns its place — backgrounds, borders, icons, badges only when they inform. ✓ tinted text is the whole StatusPill
✗ a bordered badge around every status		 Strip each piece of chrome in imagination: is any information lost? both import
generous-targets A hit target is the largest natural area — never a small glyph beside the thing it acts on. ✓ the whole value copies on click
✗ a 12px icon as the only target		 For each interaction: could the target be bigger for free? component import
motion-informs Motion and transience only communicate state change; nothing animates for decoration; transient feedback expires (~2 s). ✓ confirm chip appears, expires
✗ hover glow, panels sliding for style		 For each animation: what does it tell the user? "Nothing" fails. component import
empty-states-orient A zone's empty state says what will appear and — where the user can cause it — how. Where they cannot, it explains what happened. ✓ "waiting for traffic — point a client at :7420" · ✓ "not captured — too large"
✗ a blank panel · ✗ a retry button on a flow the ring has dropped		 Land on each empty state cold: do you know what happened, and — if you can act — what to do next? both import
familiar-idioms When a devtools convention exists for the job, prefer it; novelty needs a driver in the Frame. ✓ network-table row grammar (method · path · status · time) · ✓ "a checklist rather than a wizard"
✗ a novel traffic viz with no driver		 Does this surface have a genre? If yes: name the idiom it follows, or the driver that justifies departing from it. screen import
display-equals-payload A displayed wire value is the payload verbatim, or a named and reversible view of it. ✓ the view is named — pretty / raw — and one act switches it
✗ JSON pretty-printed with nothing saying so		 For every displayed wire value: is it the bytes, or a view? If a view — is it named on screen, and is one act enough to get back? both extracted
labels-add-context A label carries only the fact its context doesn't already state. ✓ "copy all"
✗ "copy request headers" (under that heading)		 Read each label in situ: does any word repeat its surroundings? both extracted

✗ "Copied!" · "No headers found."		 Scan all microcopy for case, length, exclamation. both extracted

✗ a corner toast		 Trace each use-case's feedback: where does the eye have to go? component extracted

A rule this codebase currently breaks is not recorded here. It goes to the deferred backlog. A rulebook that lists its own live exceptions teaches that the rules are negotiable.

Lifecycle

This doc is never finished — it is a living rulebook, the fourth T2 KB docs/design-rules/. Rules grow in place with the codebase (DEC-14).

EventWhat happens to this doc
a design runconsumes this list frozen. Findings recorded against it, nothing edited mid-run
a revision, after a runrules added, retagged or sharpened in place. A cited slug is never renamed
the harnesshard rules become the Tier-1 predicates; the two rule tables become the receipt-coverage list; a receipt pins the rulebook version (git blob hash)
epic distillationlinks into docs/work/ re-point to the components' post-epic home

The sanctioned escapes

Exactly two narrow escapes: a raw CSS block whose colours are still checked — and the pragma below for a template shape.

Rule of the escapeWhy
Form is design-allow: <class> — <reason> in a comment, applying to the next line only. The comment is the host language's: // design-allow: … in JSX, <!-- design-allow: … --> in HTML mockupSame granularity as eslint-disable-next-line
The named class must appear on the line belowAn edited line stops matching — stale pragma cannot protect silently
The reason must be non-emptyMirrors the merge gate's waived: rule
A pragma over a size value is rejectedExists for template shapes; the moment it could excuse text-[11px], the vocabulary is advisory
The live count is printed on every runSuppressions are visible debt
