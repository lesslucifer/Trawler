Documentation System

Five tiers so every AI session reads current truth — information synthesizes UP, is read DOWN, and is never duplicated down.

Draft v4 · 2026-07-05 · Trawler · T1 process doc

The five tiers

Prime directive. Source code (T4) is the source of truth; docs carry only what code cannot say — intent, rationale, behavior contracts, the map of the system's shape. Every fact lives at exactly one tier; elsewhere, link. When a doc and the code disagree, code wins — the session that finds the conflict fixes the doc in that same session.
AI-first. All code is written by AI agents and no human reads a diff before it lands. Every doc targets an AI reader: optimize for machine consumption, and never include work estimates — effort, timelines, and sizing carry no meaning here.

Tiers are ordered by stability: T0 changes only by the user's hand (an agent proposes a diff in chat and stops), T4 changes every commit. T1 is deliberately hard to grow — a page must be permanent and shape-level, else it belongs in T2. T4 is never hand-documented; docs reference it by path and symbol (src/capture.rs · CaptureSession), never by generated API pages or mirrored descriptions.

Tier style: T0 is super compact — hard cap 200 lines. T1 is concise and direct — no repeated information, no extra detail, no out-of-scope explanation; anything deeper links down a tier.

No code in docs. Docs never copy code — no snippets, signatures, or config values; path + symbol references only, so nothing can rot into a stale copy. Every T1/T2 claim must be either verifiable against src/ via those references or be pure rationale/contract that code cannot express. Sole exception: wire formats and API request/response examples that define a contract.

T2 · Indexed knowledge bases

Each KB directory holds topical files behind exactly one *-index.html. The index is a pure routing table — one row per topic file with a one-line scope, ID prefix (never reused or renumbered), and status — and contains no knowledge of its own. Sessions read index-first: open only the relevant topic file(s), synthesize back into only those files, never bulk-read a KB. Topic boundaries follow the architecture's component map; when a file outgrows one comfortable read, split it and update the index.

use-cases/ — behavior contracts (what)

Each entry UC-<AREA>-<n> states trigger, expected behavior, edge cases, and what constitutes failure — contract-level, implementation-free. Use-cases are current truth: updated in place, superseded behavior deleted (history lives in git and snapshots).

decisions/ — decision records (why)

Each entry DEC-<n> records context, options, the choice, and its consequences. Append-only: never rewritten — a reversal flips the old record to superseded by DEC-m and adds a new one. An agent about to “fix” something odd checks here first to learn whether the oddity is load-bearing.

T3 · Working docs

The scratch space where a task thinks, named docs/work/YYYY-MM-DD-<slug>.html. No quality bar, no altitude rule. Every work doc ends the same way: distilled up, then moved to docs/work/archive/ — which sessions never read; if the archive still holds something needed, that fact wasn't distilled.

Session protocol

T0 arrives automatically with every session; everything else is opened on demand, index-first.

Task typeRead before touching code
New featureT1 architecture → relevant use-case topic(s) → related decisions. T3 work doc if the task spans sessions or needs a plan.
Bug fixRelevant use-case topic (what should happen) → T4. Check decisions before “fixing” anything that looks deliberate.
RefactorT1 architecture (boundaries to preserve) → decisions touching the area.
Docs taskPer T0: open comments of every doc to be touched, first; snapshot before editing.
“How/why does X…?”Index → one topic file → T4. Never answer from memory of a previous session.
Write-back rule. A task is done not when the code lands but when the distillation checklist has run and the affected T2 files and their index (rarely T1) reflect the new truth — in the same session as the change, never “later”.
