DEC-19 — colour is a closed set, widened by amendment and never by a prop

Six components each wanted a colour. Five were refused and one was granted — the difference is not taste, it is whether the colour was minted as a named token or reached for at a call site.

DEC-19 · 2026-08-12 · Trawler · E-DFLOW.W7 · distilled from MethodLabel D1 · IconButton D1 · DurationText D2 · StatusPill D2 · Notice D4 · TonedText D3 · status: active

Context

DEC-11's zero-chromatic-accent rule reserves colour for status outcomes. Every component that designed a colour decision hit the same fork, and the file-by-file answers looked inconsistent — MethodLabel got five new hues while DurationText was refused one. Read together they are one rule, and it is not "no colour".

Choice

The chromatic set is closed and lives in ui/tailwind.config.js. Widening it is an amendment — a named token plus a record — and it is judged once, centrally. What is refused is a component deciding a colour: a tint chosen per call site, a threshold that maps a value to a tone, a prop that lets a caller paint.
WantedVerdictBecause
MethodLabel — per-verb colour granted The verb is a primary scan target, and colour makes it pre-attentive. Granted as five named tokens (GET · POST · PUT · DELETE · PATCH) joining ok/warn as declared exceptions — the set widened, it was not breached. The five-verb cap is what contains the flag-parade risk: HEAD, OPTIONS, CONNECT, TRACE and non-standard verbs stay body tone, because plumbing verbs add noise rather than scan value
Notice — an ok tone granted Reverses this component's own "a notice is never an outcome" driver, which was true of every tenant the read-only panel had. A screen appeared whose zone content is a standing outcome, and the roster had nothing else that renders one. The boundary that keeps it from spreading: ok is for a standing outcome, never an acknowledgement of something the user just did — those stay confirm-at-point
DurationText — warn for slow refused The threshold that makes a request slow is application-specific and this component cannot know it. Hardcoding 1 s is a design judgment belonging to the screen, not the primitive. Tinting an informational datum also bleeds the warning signal
IconButton — an accent ring on hover refused Hover shifts mute → ink plus a 7% ink wash. A chromatic ring introduces accent for decoration, which is the exact thing ok/warn are reserved against
StatusPill — ok for 3xx refused The spec calls 3xx "successful redirection", but from the proxy's seat the intercepted request was redirected, not served. ok would obscure infinite-redirect bugs. Muted reads "informational / non-terminal"
TonedText — a fourth tone deferred by design Left open above the primitive on purpose: a new tone is a DEC-11 amendment plus a token, arriving in StatusTone. The component would gain a value, not a design — so the first real tenant reopens the record instead of adding a prop here

Options rejected

OptionWhy not
Keep zero colour absolutely — MethodLabel in body tone, the original W2 draft Protects the calm, but the verb is the row's primary scan target and the cost of reading it as text is paid on every row. The exception set widening under a name is safer than the rule being breached ad hoc later
A per-tone default glyph on TonedText, to guarantee the second channel Puts a tone→glyph map back in the primitive — the mapping StatusPill's own fork had just removed — and would prefix a 404 with a ⚠ the flow list has never shown and has no room for
A family prop on TonedText so a sentence-shaped verdict can be Inter Makes the primitive the app's general toned-anything, competing with Notice — and lets two components render the same warn sentence in two families, which is the drift this collection was built to end
A configurable SLO threshold on DurationText Not refused forever — but it is a T2 wrapper's mapping, not a primitive's prop

Consequences

  • A design run that wants a new colour is proposing a token plus an amendment to this record, and says so. It is not a component-level choice.
  • colour-plus-text still binds: a granted colour never carries meaning alone. MethodLabel's verb is the word, StatusPill's is the code, Notice's ok carries ✓ on the same rules as warn's ⚠.
  • GET shares the ok hue and DELETE the warn hue deliberately — same semantic family (safe vs destructive); column position disambiguates method from status.
  • The enforcement surface is DEC-17's closed vocabulary: a colour not in the config emits no CSS, so an ungranted tint cannot ship silently.
