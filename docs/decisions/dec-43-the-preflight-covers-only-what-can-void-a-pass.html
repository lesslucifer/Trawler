DEC-43 — the review's preflight covers only what can void a PASS

E-SIMPWF.W2 puts one refusal in front of the review fleet: the tree Gate 0 proves, and the notes the finders are about to read. This records where that boundary is, why the doc predicates are not on the near side of it, and what that costs.

Decided 2026-09-12 · E-SIMPWF.W2 · active

The decision

The review's first step is cargo xtask preflight wu|epic <tip> [--target <ref>], and it refuses on exactly three things: the tree, through Gate 0 (fmt, clippy, the suite — 0·tree), and the two notes the review reads on the reviewed tip (1·notes, 2·manifest). It asks for nothing else: not the cr/v3 note it precedes, not that note's design section, not the human signature that follows it, not the doc-note coverage the merge checks, and no doc predicate anywhere. A diff that asks for no review is not refused and demands no note. The criterion is one line: a check belongs in the preflight only if a red one is repaired by a commit — which moves the tree the verdict binds — or makes an input the review reads unreadable.

Why it needed deciding

A review's PASS is stamped with the diff it judged, so everything after the verdict is expensive: a fix is a new commit, a new diff, another fleet round, and another human signature (DEC-27 already orders the signature last for the same reason). The preflight is where the same fact is applied one step earlier — the fleet is not asked to judge a tree that is still going to move.

Two of the plan's questions had no answer in the tree: what may the preflight refuse on, and whether the authoring-time doc checks need a harness-independent backstop at commit or merge time. The owner answered the second: no. This record states the consequence of that answer rather than leaving it implied by an absence.

The boundary

In the preflightWhy a red one cannot survive to the merge
0·tree — the working tree, through Gate 0's three commands, with its unchanged-tree skip the repair is a commit, and a commit after the verdict is a different diff: the note is orphaned and the fleet is bought a second time for a finding it never saw.
1·notes — test/v2 and doc/v1 on the reviewed tip: present, parseable, one identity block these are what the finders read: a waiver is a review subject, not a free pass. A note that is missing or unreadable is an input the review is about to read and the caller is about to rewrite.
2·manifest — the test note's level, and the layer that level requires (working unit ⇒ integration ≥ 1 or a waiver) a layer that is absent or zero is a test nobody has written yet. The tree moves the moment it exists, which is the clearest case of the criterion there is.

The consequence, stated rather than hidden

Doc predicates run only where the authoring hooks fire (workflow §Hooks, .claude/settings.json). On a harness that does not run them, nothing reads the document at all: the merge gate still holds that the docs a diff touched are listed in doc/v1, that the level's result report exists on the tip, and that the human's signature names its bytes — but no check opens the file. That is accepted here, on the owner's ruling that the commit- and merge-level doc checks are useless, and this epic adds none.

The preflight is not a second gate. It shares the merge gate's own code for 1·notes and 2·manifest, so the two can never disagree about a note they both read, and it writes nothing — no note, no receipt, and no entry in the local gate tally, which counts gate runs (DEC-42). Every verdict at the merge is still re-derived from the tree, unchanged (DEC-2).
