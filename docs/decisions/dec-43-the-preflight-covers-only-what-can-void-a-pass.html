DEC-43 — the review's preflight covers only what can void a PASS

E-SIMPWF.W2 puts one refusal in front of the review fleet: the tree Gate 0 proves, and the notes the finders are about to read. This records where that boundary is, why the doc predicates are not on the near side of it, and what that costs.

Decided 2026-09-12 · E-SIMPWF.W2 · active — inputs narrowed by DEC-45

Narrowed by DEC-45 (E-SIMPWF.W4), the criterion unchanged. The review stopped reading doc/v1, and a doc note can no longer orphan a PASS — so the preflight stops asking for it and refuses on the tree and test/v2 alone. Everything below about the boundary is what it was; the list of notes on the near side of it is one shorter.

The decision

The review's first step is cargo xtask preflight wu|epic <tip> [--target <ref>], and it refuses on exactly three things: the tree, through Gate 0 (fmt, clippy, the suite — 0·tree), and the two notes the review reads on the reviewed tip (1·notes, 2·manifest). It asks for nothing else: not the cr/v3 note it precedes, not that note's design section, not the human signature that follows it, not the doc-note facts the merge checks, and no doc-format predicate anywhere — verify-doc's checklist and link checks stay where a document is authored. A diff that asks for no review is not refused, demands no note, and is not measured at all: the preflight protects a review, and cargo xtask gate0 is how to ask about the tree on its own.

Those three are the review's inputs, and that is the whole test: a check belongs here when its subject is what the review is about to read, because a red one is either repaired by a commit — which moves the tree the PASS pins — or is an input the finders would read unreadable. This is deliberately not a completeness claim about the gate: the preflight is not a backstop, and every other check is refused where it is decided.

Why it needed deciding

A review's PASS is stamped with the diff it judged, so everything after the verdict is expensive: a fix is a new commit, a new diff, another fleet round, and another human signature (DEC-27 already orders the signature last for the same reason). The preflight is where the same fact is applied one step earlier — the fleet is not asked to judge a tree that is still going to move.

Two of the plan's questions had no answer in the tree: what may the preflight refuse on, and whether the authoring-time doc checks need a harness-independent backstop at commit or merge time. The owner answered the second: no. This record states the consequence of that answer rather than leaving it implied by an absence.

The consequence, stated rather than hidden

Doc predicates run only where the authoring hooks fire (workflow §Hooks, .claude/settings.json). On a harness that does not run them, nothing checks a document's form at all: the merge reads document facts — that the docs a diff touched are listed in doc/v1, that the level's result report exists at the tip with the bytes a human signed, that a design run is closed, that a file is a design artifact — but no check reads a document against a checklist or a link. That is accepted here, on the owner's ruling that the commit- and merge-level doc checks are useless, and this epic adds none.

The preflight is not a second gate. It runs the merge gate's own code for 1·notes and 2·manifest over the notes it reads — test/v2, and doc/v1 until DEC-45 narrowed the review's inputs — so a refusal it prints is the gate's own block, with the gate's own fix line rather than a paraphrase of it. The cr/v3 note is deliberately not loaded: it is the exam's own output, and the round that follows writes it after this runs, so the identity check covers the two notes the review reads and not the three the merge sees. Nothing else is written — no note, no receipt, and no entry in the local gate tally, which counts gate runs (DEC-42). Every verdict at the merge is still re-derived from the tree, unchanged (DEC-2).
