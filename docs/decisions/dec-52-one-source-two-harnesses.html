DEC-52 — one source, two harnesses: the agent config is Claude's, read through symlinks

The workflow's authoring-time guarantees are harness guarantees, and a Codex session was outside all of them. The canonical artifacts stay where the gate, the husky hooks and the T1 docs already name them; Codex reaches them through four links.

Decided 2026-09-11 · E-CODEX.W1 · extends DEC-4's "the harness executes them" to both harnesses

The decision

CLAUDE.md and .claude/ are the single sources; Codex reads them through four symlinks, and nothing is copied. AGENTS.md → CLAUDE.md; .agents/skills → .claude/skills; .codex/hooks.json → .claude/settings.json; .codex/hooks → .claude/hooks. The shared hooks file stays hooks-only and its commands resolve the active git root; one verify-doc-post.sh reads both harnesses' edit payloads. Codex's per-machine hook trust (/hooks) is an operator step, not a repo artifact.

Why it needed deciding

The work-planning standard states the premise of its own checks: hooks are versioned in .claude/settings.json, "the harness executes them, not the agent, and in an AI-first repo every author is a harness session, so authoring-time coverage is total". In a Codex session none of the three promises held — T0 was not read (Codex looks for AGENTS.md), the cr/v3 skill was not discovered (Codex scans .agents/skills/), and the doc-feedback hook fired but parsed a payload field Codex never sends, so it exited 0 on every edit. Nothing failed loudly: a skipped check and a passing check print the same nothing. The tree already carried the cost — the hand-made AGENTS.md copy had drifted from CLAUDE.md at line 80 before it was ever committed, which is what a second source does.

The four doors

Stop payload not read not read identical already; only the shared root resolution was added
Exit code 2 refuses the turn / feeds the reason back same contract the problem blocks stay on stderr, unchanged
The coverage boundary is unchanged by this record. PostToolUse sees edits the harness routes through its edit tool. A doc written by a shell command or an MCP tool is missed in both harnesses; the turn-end Stop backstop is what catches it, which is why that hook exists and why it is not the redundant one.

Rejected

AlternativeWhy not
Move canonical to AGENTS.md and .codex/ Would rename the T0 the gate hard-codes (is_rule_bearing), the commit-msg hook text, the husky hook comments, four T1/T2 docs and the cr/v3 rulebook path — all for a name, while the alias costs one line and no code.
A project .codex/config.toml with project_doc_fallback_filenames = ["CLAUDE.md"] Covers T0 only, invents a second config language for the same fact, is invisible in the file tree, and leaves the skill and hook doors unsolved. Kept as a fallback for T0 alone if the symlink ever stops being read.
Keep the .codex copies and add a drift test A copy drifts in the window before any test runs — this tree proved it: the existing copy had already diverged at line 80. The link removes the window instead of watching it.
One symlink per skill instead of the skill root Every new skill would need a second step, and a forgotten step is invisible. The per-skill form stays recorded as the contingency if Codex ever stops following a symlinked skill root.

What follows from it

  • The shared file stays hooks-only. .claude/settings.json is now Codex's hooks file too, and the parity test locks its bytes, so a committed Claude-only setting reds the test instead of failing Codex silently. Local Claude settings belong in the untracked .claude/settings.local.json.
  • If a committed Claude-only section is ever needed, the split is mechanical: a real .codex/hooks.json carrying the same definitions, with the parity test still asserting that both harnesses resolve to the same command set — the contract, not the link.
  • Editing the shared config re-prompts Codex's hook trust. That is the intended review point: the trust store is keyed to the hook definition, so a change to the gates asks the human once. /hooks is a per-machine step and no test can assert it, exactly like .mr-allowed.
  • Rule-bearing docs keep their names. CLAUDE.md is still T0 and still needs a Reviewed-By trailer; AGENTS.md is a second name for the same bytes, so a commit that edits the rules is caught exactly as before.
  • The drift alarm is xtask/tests/suite/harness_parity.rs. Copy, one-sided skill, divergent hook definitions and a hard-coded path each red it by construction.
