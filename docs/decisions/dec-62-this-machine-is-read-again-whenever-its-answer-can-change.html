Decision. This machine's certificate task reads the live certificate the core serves, and its proxy task reads the proxy HTTPS goes through now. Both are read again after every action whatever its outcome, when the core comes back, on focus, on check again, and every 3 s while setup is on screen, its core answering and the window visible. A read the user did not ask for is quiet. Where no probe answers, a request this app made — marked, and captured decrypted in this setup session — settles both tasks; no other device's traffic does.

The rules a build owes

#RuleWhy
1The certificate is matched on its bytes, never its name: macOS looks for the live certificate in a keychain and verifies only one it holds, which tells trusted from installed-not-trusted from absent; Windows looks for its thumbprint in the machine and the user root store; Linux looks in the host's CA bundlea browser trusts bytes; a name is what a stale copy shares. A browser is sent only the leaf, so it must find the CA first — and a trust setting outlives its certificate, so the live bytes still verify after the certificate is deleted
2The proxy is the one HTTPS goes through now: macOS's resolved dictionary, Windows's https= entry or its one address, GNOME's HTTPS proxy. localhost on Trawler's port is Trawler, as 127.0.0.1 is; no other loopback address is. Quit keeps its wider question — anything on this system still pointing herea proxy on an idle service routes nothing now, and strands the machine later. localhost resolves to the address the core binds; 127.0.0.2 and ::1 reach nothing it listens on
3A read shows checking only when the user asked for it: setup opening, an action's outcome, check again. Focus, the watch and the core's return are quiet. Only the newest read landsa line that flashes on every focus says nothing changed, loudly
4The watch runs only while setup is on screen, its core answering and the window visible its cost is paid only where its answer is read
5The request the app makes carries a mark visible in the list. Where no probe answers, a marked row decrypted in this session settles both tasks, with its time. The request's note reports the route the core saw — through, reached and not decrypted, around — and never moves a taskthe mark is what makes the row this machine's; DEC-56 rule 1 holds — the flow, not the click, is the evidence
6This machine's try task keeps its proof once traffic goes quiet: done — decrypted at 14:02, nothing sinceits two other tasks re-read themselves, so the proof cannot hide a change
