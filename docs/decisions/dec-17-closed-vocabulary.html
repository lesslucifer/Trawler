DEC-17 — the design vocabulary is closed, and legality is membership of a declared scale

Why the token list is exhaustive rather than preferred, why the Tailwind config is its single home, and the two surfaces that enforce it.

DEC-17 · 2026-08-10 · Trawler · E-DFLOW.W6 · status: active

Context

DEC-14 gave the design rules a home and DEC-15 made a design run a governed artifact. Neither said what a token is. The rulebook listed members — colours, sizes, spacings — and three rules said designs must pick from those lists. Two W4 design runs and one sweep showed what that was worth:

MeasuredWhat it means
63 of the config's size- or style-bearing scales were open — declared under theme.extend, so Tailwind's own ladder stayed live beneath every project token font-bold, duration-500, animate-bounce were all legal. Not by anyone's decision — by inheritance
142 off-vocabulary classes across 58 distinct names shipped in ui/src/ The rulebook had said colour, type and spacing came from tokens since W3. The built code disagreed, and nothing noticed
33 reds over 29 distinct sites in the two closed design runs The designs that wrote the rules broke them, including a .a- CSS block that opens by promising "zero component values re-typed" and then writes seven magnitudes
The failure mode is silence, not error. Tailwind drops an unknown utility without a word — no build error, no warning, no missing-class report. A class that governs nothing looks exactly like a class that governs something. So a vocabulary is only as closed as the thing that checks it, and a list in a document checks nothing.

Choice

RuleWhy
The token list is exhaustive, not preferred. Every scale replaces Tailwind's rather than extending it — theme, never theme.extend A preferred list is advisory and drifts by omission: the off-list value keeps working, so the only thing standing between the code and the vocabulary is whether somebody remembered. Replacing the scale means an off-list value emits no CSS at all — the vocabulary becomes a property of the build rather than of attention
Legality is membership of a scale the config declares — never of what Tailwind can emit The narrower test is the one that fails safe. An undeclared scale inherits its whole default ladder, and every member of it emits, so nothing drawn from it can ever red — the leak is invisible by construction and no amount of linting finds it. One line of definition closed 63 scales at once; the alternative was 63 config entries, added one defect at a time
ui/tailwind.config.js is the source of truth; the rulebook points at it and never lists a member Two copies of a list is one list plus a drift schedule. The Vocabularies section therefore names the sets and the rule that forces a pick from each, with the config key beside it. What is fixed in the rulebook is the part the config cannot hold: what each chromatic token means
Two enforcement surfaces, one list. The Tier-1 predicates judge the design run's artifacts; the design/vocabulary ESLint rule judges ui/src/. The rulebook's binds axis says which surface owns a rule A design can pick an illegal value and so can a built component, and they fail at different times: a design fails once, at review; a component fails on every edit forever. A single surface would either leave built code ungoverned or leave designs unjudged until they became code
One oracle, derived — never transcribed. Both checkers resolve legality through Tailwind's own getClassList() over the real config Which classes a rule owns is computed (empty the scale, diff the emitted list), and the chromatic set is measured (a colour is chromatic when its channels disagree by more than 40). Rust cannot import an ES module, so scripts/design-vocabulary.mjs emits the vocabulary as JSON from that same oracle and the predicates read it. A hand-copied class list is the exact drift this record exists to end
The chromatic set is measured, and its size was never the point. W6 was directed to reduce zero-accent to "chromatic colour is ok and warn"; it has eight members. The five verb tones proved to be a palette gap rather than a deletion, and DEC-11's three syntax tones proved to be already painted as hex literals while the config called them unreferenced. What the ruling actually asked for is the shape — one membership test, no exception list — and that is what shipped. Membership is fixed in the config, meaning is fixed in the rulebook (the one thing a config cannot hold), and "chromatic" itself is computed rather than enumerated.

Why the code-side check is a local ESLint rule

OptionWhy not
A published Tailwind lint pluginNone judges membership of this config's declared scales — they check ordering, shorthand and typos against Tailwind's defaults, which is the test being rejected here
A grep or a CI scriptIt would run after the fact, at a moment nobody is reading. The rule fires in the editor, on the line, while the class is being typed — and --fix-less by design, because the fix is a decision
A type-level trick over classNametsc is already green over all 142 violations. Class names are strings and the vocabulary lives in a JS config; there is no type to be wrong about

So: ui/eslint-rules/vocabulary.js plus classes.js as the shared oracle, wired into the flat config. This WU introduces the lint toolchain — ESLint 9 was not previously in the tree — and the rule's own RuleTester suite pins every judgement it makes.

Five requirements on the checker, each earned by a defect

#RequirementWhat goes wrong without it
1Classify on the resolved (prefix, value) pair, never the prefix alone text-center, border-none, outline-none, font-mono all red as false positives — the exact failure that scoping the rule to scale-bearing classes exists to prevent
2Resolve classes held in module-level constants and lookup maps, not only literals at className= A className=-only scanner missed 41 classes this way, including all five text-method-* — the primary deletion this WU exists to make. A rule with that blind spot reports the headline change as already done
3Arbitrary […] values must red Trap 3. They emit whether or not a scale is closed, so the rule is the only instrument that can reach them
4Assert no token name collides across two scales sharing a class prefix Trap 2. Invisible to tsc and to 447 passing tests

The reconciliation is what makes the rule's verdict evidence rather than a second opinion: it now agrees with the built stylesheet on all 205 non-arbitrary classes the tree authors

Three ways a closed vocabulary leaks

Each one is a real defect this closure caught, not a hypothetical. "Closed" is a property of each scale, checked per scale — never asserted once.

LeakWhat holds it shutThe defect it caught
An undeclared scale inherits Tailwind's whole ladder Legality is declared-scale membership. The config names every scale the code draws from, at exactly the members it uses 63 open scales — font-bold legal because fontWeight was never declared, while the rulebook said "one weight"
One token name in two scales that share a class prefix — the class then sets both properties at once, and changing one changes the other silently A unit test asserts no duplicate in the generated class list hairline was already a colour token; adding a borderWidth key of the same name made border-hairline emit both properties under one selector, silently re-widthing 22 borders 1px → 1.5px. Found by diffing emitted stylesheets; the build was green and the tests assert on class names
Arbitrary […] values, which emit whether or not a scale is closed — closing the config cannot reach them at all The lint rule reds every one, and the design-side predicate reds every one in a mockup, unless a pragma excuses a template shape carrying no size 10 arbitrary values across the two closed runs, plus text-[11px] in shipped code — a size, chosen past the scale that exists to hold sizes
A fourth hole, and it is the one both checkers are blind to by construction. The lint rule reads class names and the Tier-1 predicates read the design doc, so a value that is never a class is invisible to both. Every off-token magnitude that has actually shipped in a design run shipped through the mockup's own .a- CSS. Four of the twelve predicates therefore read that CSS as a governed surface, and the styling-API escape carries a mechanical colour guard for the same reason.
Structural classes are out of scope by nature, and the discriminator is mechanical. A class is structural iff Tailwind registers it whole — a static utility like flex, absolute, truncate, text-center — rather than generating it from a theme key. It carries no value a scale could govern, so closing a scale can never reach it and the rule has nothing to judge. No allowlist is needed and none exists, which is what keeps the scope from being re-litigated or quietly widened.

Measured over the 208 distinct classes the tree authored on 2026-08-10: 161 scale-bearing / 47 structural. This figure is an output of the rule reconciled against the built CSS, not an input to it — two earlier estimates (103/77, then 144/56) were both wrong, the second by a scanner that read className= literals only. The durable part is the discriminator; the counts are true of that day's tree and of no other.

The two sanctioned escapes

A closed vocabulary needs a way out, or the way out becomes "stop running the check". There are exactly two, both narrow, and neither can excuse the thing the vocabulary exists to govern.

① the design-allow pragma — a template shape

Rule of the escapeWhy
Form is // design-allow: <class> — <reason>, applying to the next line only, written inside the className expressionSame granularity as eslint-disable-next-line. JSX has no comment position inside an opening tag, so the expression container is the one place that works everywhere and keeps the pragma beside the class it excuses
The named class must appear on the line belowAn edited line stops matching and reds again — a stale pragma cannot go on protecting code it no longer describes
The reason must be non-emptyMirrors the merge gate's waived: rule — a suppression with no argument is not a decision
A pragma over a size value is rejected, never honouredIt exists for template shapes — grid-cols-[auto_1fr], a two-column layout with no size in it. The moment it could excuse text-[11px], the vocabulary is advisory
The live count is printed on every runSuppressions are visible debt, not a silent hole. A number that goes up is a conversation; a number nobody prints is a slope

Six sites use it today: five grid-cols-[…] templates and one top-[calc(100%+theme(spacing.chrome-y))] offset — and in the two that do carry a magnitude, the magnitude is theme(spacing.…), a token read out of the config rather than a number. The same five rules govern the pragma on both surfaces; the design-side predicates did not invent a second dialect.

② raw CSS configuring a third-party styling API

An editor's theme object or an injected stylesheet has no className to give it. Such a block is accepted, not excused, on three conditions — it covers the styling API and never a plain element; every colour in it is still a palette value, asserted mechanically over all of ui/src/; and sizes inside it are the author's to justify and are not mechanically checked, which is stated rather than implied. A literal that is a token renders the vocabulary; a literal that is not is a second copy of it. The colour guard is what makes this escape safe rather than a hole; full conditions in the rulebook.

The one thing a mockup must declare: data-wire

Three hard rules — mono-for-wire-data, wrap-not-truncate, wire-order-preserved — turn on which elements render a verbatim payload. That is a fact about content, and no static reader can recover it from markup: a wire value and a label look identical. So the mockup says so: data-wire="<what it is>" on every payload element, data-wire="collection" on a catalog row rendering a captured collection, and data-wire="none" once when the screen renders no payload at all.

The n/a path is an answer; leaving the question unanswered is not one. An unmarked mockup reds — following the house precedent (capabilities·answered, elements·map, frame·example) rather than inventing a third answer called silence, because silence reads as correctly typed when in fact nobody looked. Open for reversal to a silent n/a; it is a two-line change and the ruling is recorded rather than buried.

Options rejected

OptionWhy not
Keep theme.extend and lint the differenceThe lint rule would need its own list of what is legal — a transcription of the config, which is the drift being removed. Worse, an undeclared scale is invisible to it: there is nothing to diff against
Declare the 63 open scales explicitly, one entry each63 entries maintained by hand, and scale number 64 arrives open. The rule change makes the other 54 need no entry at all — anything drawn from them reds on sight
Enumerate the token members in the rulebook so a reader needs one docThe copy drifts, and it drifts silently — the config keeps emitting and the rulebook keeps reading true. The section points at the config and states what the config cannot: what each chromatic token means
One surface only — govern designs, let code follow142 violations across 58 classes are what "code follows" produced over three WUs. A rule that binds a component must be checked on every component change, not only when someone designs a screen
A precedence rule for a class two rules both own (text-pink-500 answers to colour-tokens-only and type-tokens-only at once)It silently exempts whichever rule loses. Double-reporting is noise; a silent exemption is a hole. Measured rather than argued: all six colour-tokens-only reds in the regression are sizes, not colours — 12% of 49, revisited at W9 if it costs a reader something

Consequences

  • DEC-15's Tier-1 tier is complete, one WU early. That record left twelve predicates to W7; the gap line now reads hard rules: 13/13 machine-checked (design). The ordering was a dependency, not a queue — Tier-1 reads the config, so the closed vocabulary is its input, and building the predicates against an open config would have pinned the wrong legality test. W7 keeps Tier-2 self-reflex, Tier-3 adversarial review and the flow e2e.
  • 13/13 is a test, not a sentence in a doc. every_hard_rule_in_the_live_rulebook_carries_a_predicate derives both sides from the rulebook on disk and fails on a hard rule with no check, an orphan predicate, or a hard list that is not thirteen. Retagging a rule re-opens the question automatically.
  • Where the config and the rulebook disagree, the config wins — and where the rulebook and the checkers disagree, the checkers win. ui/tailwind.config.js is the vocabulary; xtask/src/doc.rs is what a design must satisfy; ui/eslint-rules/vocabulary.js is what built code must satisfy; scripts/design-vocabulary.mjs is the bridge, and it derives.
  • Adding a token is a config edit under review — which is the only way a new one can arrive. A design that needs a value the config lacks proposes it (reuse-or-propose), the receipt records the proposal, and confirmation lands both the config entry and the rulebook's meaning for it.
  • A generated artifact that cannot be regenerated stops being generated and starts being a copy. Closing the config broke two files still destructuring the emptied theme.extend — every design doc's CSS variables went dead and the specimen bundle could not be rebuilt, so the render check stayed green against a stale bundle rendering the pre-closure palette. Anything reading the config must be re-run, not assumed.
  • Seven of the thirteen predicates have never red on a real artifact. Clean on both closed runs for stated reasons, but a predicate's only real failing test is an artifact that fails it — the same bet DEC-15 records losing eleven times. W9's fourth design run is where a live screen tests whether they over-fit.
