DEC-57 — a device that cannot paste is handed a code, not a string

Setting up a phone means typing a host, a port and a certificate URL from one screen into another. The clipboard does not cross that gap. Rendering those values as a scannable code is the remedy — and it is a new dependency and a new surface, so it is a decision rather than a widget.

Why this record exists

DEC-55 gave the five off-machine platforms something to point at. What it could not give them is a way to get it there: the screen renders the host, the port and the certificate URL as copyable text, and a phone cannot paste from this machine's clipboard. Three values, typed by hand, on a keyboard the user is holding in the other hand — and one of them is a URL with a port in it, where a single wrong character produces a failure that looks exactly like an untrusted certificate.

Every proxy tool in this space answers this with a scannable code, and that is the shape the PO review asked for. It is not a styling choice: it adds a rendering dependency the app does not have, and it puts a new kind of element on the one screen the epic rebuilt for legibility.

Decision. Where a value must cross to a device this machine cannot reach, the screen may render it as a scannable code beside the value — never instead of it. The code is an additional route for the same fact, so a reader who prefers to type still can, and a reader whose camera fails is never stuck.

The rules a build owes

#RuleWhy
1The code never replaces the value. The typed route stays, in the sentence that names the field it goes ina code is unreadable to a human, so a screen that shows only the code has made a fact uncheckable — and this screen's whole argument is that its facts are checkable
2A code is rendered only for a value that must cross to another device, and only where reach is armedbefore arming there is no address, and on this machine there is nothing to cross. A code for a value the reader can copy is decoration
3It is generated locally, from a dependency vendored like every other — never fetched from a code-rendering servicethe certificate URL names this machine's address on the user's own network. Handing it to a third party to draw is an exposure the user did not confirm, and it would make an offline app need the internet to finish setup
4It is a registry component with its own contract, per DEC-16it is a new visual primitive, and the one thing the epic's design flow exists to prevent is a new primitive appearing inside one screen's build with no contract anyone else can reuse
5What the code encodes is exactly the value beside it, and nothing morea code that encoded a bundle — proxy plus certificate plus a flag — would be a fourth thing on screen whose contents the reader cannot inspect

What this does not decide

Not decided hereLeft to
Which library renders the codethe build, under rule 3: local, vendored, no network call
Whether the proxy address gets one as well as the certificate URLthe build. The review asked for both; rule 2 permits both, and the reading round that designs it decides whether two codes on one screen is one too many
Whether an Apple-style configuration profile would be better than a codeout of scope and deliberately so: a profile is an OS-specific installer, which is a larger capability than rendering a value the screen already shows
