DEC-16 — a design file is retired in one order: distil the why, verify the contract, then remove

Code-as-truth retires the design file, but not everything in it survives the move. The order is what makes the removal lossless — and it is a gate's job, not an author's memory.

DEC-16 · 2026-07-29 · Trawler · E-DFLOW.W5 · status: active · superseded on the Tier-3 exclusion clause by DEC-29 (2026-09-03)

Context

E-DFLOW.W5 built the T1/T2 collection, so the registry's truth moved from docs/work/components/*.html to the components' TSDoc in ui/src/components/. The epic's code-as-truth model then says the design files are transient and a later WU deletes them. The question that surfaced during review is what a deletion loses, because the answer is not "nothing".

A design file is roughly 600 lines. The TSDoc block it compiles down to is nine. The difference is not padding:

The file holdsSurvives into TSDoc?
The contract — first line, @tier, @anatomy, @use/@avoid, @states, @madeofYes — carried verbatim; that is the compile block's whole purpose
Fork cards — the settled choice, the alternatives rejected, and why each was rejectedNo. CopyButton's D1 records why the confirm is a label-swap and not a chip or a toast; D2b records the adjacency test that licenses the icon form. Code shows the choice, never the road not taken
Frame drivers — the use-case pressure each design consequence answersNo. "the payload is usually not displayed → the label names what you'll get" is the reason the label is non-negotiable; without it the prop looks like a convenience
Anatomy specimens, token maps, live examplesSuperseded — the component itself is the specimen, and the tokens are in ui/tailwind.config.js

The forks and drivers are exactly the part nobody re-reads — which is why the file looks redundant once the code exists. The redundancy is an illusion produced by reading only the part that was copied.

Choice

Retiring a design file is an ordered flow of three steps, and step 3 is gated on step 1.

flowchart LR
  D1["① distil the forks
  → docs/decisions/
  the WHY, which code cannot hold"] --> D2["② verify the TSDoc block
  is complete
  it becomes the only contract"]
  D2 --> D3["③ then remove
  the design file"]
  D1 -.->|"skipped"| X["❌ silent data loss"]
The order is the decision. Any two steps in isolation look reasonable; only the sequence is lossless.
StepWhat it meansWhy it is first / next / last
① distil the forks Every fork card whose reasoning still constrains future work moves to docs/decisions/ — the settled value, the rejected alternatives, and the reason. A fork that was purely local ("which prop name") is a dead end and is recorded as such, not preserved. It is the only step that can lose data, so it goes where it cannot be skipped by running out of time. Decisions are append-only (DEC-5), which is the right home for a why that outlives its file.
② verify the TSDoc block is complete The component's TSDoc carries all six tags and matches the design file's compile block. After removal it is the only contract a reuse decision reads. Removing the file promotes the TSDoc from copy to original. A missing @avoid line is survivable while two copies exist and unrecoverable after one is deleted.
③ then remove git rm the design file. The doc/v1 note records action: archived with distilled_to naming where ① landed. Last, because it is the irreversible one — and the gate already refuses an archived entry with no distillation lineage.

Enforcement — two predicates, landed in E-DFLOW.W7

The same reasoning as DEC-15: a convention an agent must remember is a convention an agent forgets. The order is machine-checkable, so it is a check rather than a paragraph. Both halves now exist:

CheckRefusesWhere
6·retirement-order Step ③ before step ①: a docs/work/components/ file absent at the tip whose doc/v1 distilled_to does not name a docs/decisions/ record that really exists there. The general lineage rule accepts a dead-end reason — the right latitude for a scratch plan, and the wrong one for a file whose fork cards are the whole reason a removal loses something. xtask/src/gate.rs
components·unretired Step ③ never happening: a design file whose component has a roster entry is red until it is retired. The registry and the design files are disjoint sets, and this is what keeps them so — two contracts for one component, with nothing comparing them, is the drift this record exists to prevent. xtask/src/doc.rs

W5 removed nothing — it built the code and left every design file in place. W7 removed sixteen, distilling their forks to DEC-18 · DEC-19 · DEC-20 · DEC-21 · DEC-22 · DEC-23 first. Four files remained: BodyViewer, BodyRenderer, HeaderTable and CopyAllHeadersButton, none with a roster entry. W8 removed all four as drops, each with its reason in the epic's note — docs/work/components/ is now empty, and the unbuilt case named below is closed by DEC-25.

Options rejected

OptionWhy not
Delete the design files in W5, alongside the buildThe build WU has the code fresh and the forks cold — precisely the wrong moment. Nothing forces the distillation, and the file that looks most redundant is the one whose forks were most contested.
Keep the design files forever as the fork archiveTwo homes for one contract, which is the drift this epic exists to kill: the file's compile block and the component's TSDoc would diverge with nothing checking them. The forks need a permanent home; the contract already has one.
Copy the fork cards into the component's TSDocTSDoc is what a builder reads at the call site — it answers "may I use this here". A rejected-alternatives essay there is noise at the point of use, and the compile block's shape is fixed by the generated index (W2).
Record the order in the flow spec onlyTried, at epic scale, and it is what DEC-15 was written about: the run broke conventions after writing them down. Prose is where a rule goes to be forgotten.

Consequences

  • W7 owns both halves: the predicate that refuses an undistilled removal, and the removal itself. Landed. The order is refused by 6·retirement-order in xtask/src/gate.rs, and W7 removed sixteen files behind it.
  • A dead end named retires the file; a dead end assumed does not. The predicate first demanded a docs/decisions/ record for every removal — and then refused the case this record calls the majority. Measured over W7's own sixteen retirements: two produced no record, correctly. CopyText's two forks are carried verbatim by its @states; KeyValueRow's three are carried by @madeof and superseded by wrap-not-truncate and data-ink-first. So distilled_to may be a reason instead of a path, provided it says what carries the fork:
    distilled_toRetires the file?
    a docs/decisions/ path that exists at the tipyes the original rule, unchanged
    a reason citing a TSDoc tag — @use · @avoid · @states · @madeof · @tieryes the contract carries it, at the point of use
    a reason citing a slug the rulebook declaresyes a rule outranks it. Checked against the rulebook that seam shipped, never the working tree — read the tree and a later slug rename reddens an already-merged retirement, on a branch no one may amend
    "none" · "nothing survives" · "local prop shape"no a dead end assumed — the loss this record exists to prevent
    The check the amendment keeps is the one that matters: every reason must point somewhere a reader can go. What it gives up is the assumption that "somewhere" is always a decision record.
  • Retirement is not a design review. A removed design file is deliberately not a Tier-3 artifact (DEC-24): this predicate owns the removal, and asking a reviewer to judge a contract the diff deletes is asking about the wrong thing. A design file present in a diff is design-bearing; the same file removed is this rule's business. Superseded for unjudged bytes by DEC-29 (E-GATETRUTH.W2): a design removed at bytes its base never held — amended or authored in the WU that retired it — is a Tier-3 artifact of that WU and this rule's business; the exclusion holds for a design removed at the bytes it was judged at.
  • The decisions KB grows from component forks. Some fork cards become DEC records; most are local and die with the file. Judging which is which is distillation work, per file, and the judgment itself is recorded — a dead end named is not the same as a dead end assumed.
  • A design file with no code is not retired, it is unbuilt. This order applies only when the component exists in ui/src/components/. T3/T4 files (ProtocolLine, HeaderTable, BodyViewer) keep their files because the contract still lives there and nowhere else. Superseded on the survival clause by DEC-25 (E-DFLOW.W8). "Lives there and nowhere else" was a grant, and the grant was the defect: it made a design file a permanent second address for a contract, with nothing comparing it to code and nothing ever asking whether the component arrived. An unbuilt design is now a question its epic must answer — components·unbuilt refuses the epic merge until the roster carries the component or the note records the drop and why. Measured on this epic: all three files named here were dropped with reasons, and only one of the four drops was ever truly unbuilt. The retirement order above is untouched — distil, verify, remove, and both its predicates stand exactly as written.
  • Code wins conflicts, but only after ① has run. Code-as-truth is a statement about the contract. The why was never in the code and code-as-truth never claimed it was, so "the code is the truth" is not a licence to delete the reasoning.
