DEC-72 — git runs the tracked hooks, from each checkout

The hooks that run are the ones in the commit being worked on. No installed copy exists that could drift from them.

Decided 2026-11-05 · E-GATEPAR.W1 · active

The decision

core.hooksPath is the relative path .cargo-husky/hooks, set once per clone by cargo xtask hooks install. Git resolves it against each worktree's root, so every worktree runs the hooks its own branch carries. The four gate entrypoints (verify-dod, gate0, lint, preflight) refuse a checkout where git would run anything else. cargo-husky's copy-install is retired.

Why

Observed (main @ 4d1c1942)Effect
cargo-husky copied hooks into .git/hooks on the first build onlylanded hook changes never reached the machine
the installed pre-commit still ran raw fmt + clippyDEC-54's cached cargo xtask lint never took effect
the installed commit-msg predated DEC-10a rule change was silently unenforced

Rules

SituationWhat happens
core.hooksPath unset, absolute, or pointing elsewherethe gate exits 1, runs nothing and prints cargo xtask hooks install
a tracked hook is not executable (git skips it silently)the gate exits 1 with the chmod +x … && git update-index --chmod=+x … line
hooks install while a linked worktree's tracked hook is not executablerefused, with each worktree listed: the value is repo-wide, and writing it would switch off that worktree's gates
a tree with no .cargo-husky/hooks/no refusal: there is nothing to drift from
hooks install, verify-doc, mrnot guarded: they are the fix, or they gate nothing

Rejected

AlternativeWhy not
Re-install the copies when they drifta copy can always drift again; the drift check would be one more thing to forget
An absolute core.hooksPathpins every worktree to one checkout's hooks, which is the same drift moved somewhere else
A worktree-scoped value (extensions.worktreeConfig) as the steady stateused only as the W1 bridge in one worktree; it must be set per worktree, so the next new worktree is unguarded

Consequences

  • Editing a tracked hook takes effect on the next git operation in that checkout, with no rebuild.
  • A fresh clone gates nothing until cargo xtask hooks install runs. The gate says so on its first run.
  • Supersedes DEC-54's "installed by cargo-husky at build time" consequence.
  • Held by xtask/src/hooks.rs tests, xtask/tests/hooks_install.rs and the epic e2e xtask/tests/e2e_gate_parity.rs.
