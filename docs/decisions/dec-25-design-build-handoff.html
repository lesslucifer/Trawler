DEC-25 — the design → build handoff is one rule with three halves, and the epic is what binds them

A build that adds a surface names the design it read; every other rendered file it touches says why it needed none; a design nobody built does not leave its epic. Three predicates, two fields, and no judgment of conformance.

DEC-25 · 2026-08-13 · Trawler · E-DFLOW.W8 · status: active

Context

DEC-24 put Tier-3 on the merge that lands a closed design — which is before the design reaches development, and it said nothing about what happens after. Three failures live in that gap, and all three had already happened:

The gapWhat it produced
Nothing connects a build to the design it was handed. A UI Working Unit could add a screen with no design at all, or with a design nobody opened, and every gate stayed green the failure mode M1 named: three design runs, zero lines of product code, and no check anywhere that noticed
Nothing asks a build that changes what already exists. A trigger keyed on added files reaches only surfaces that do not exist yet — and the screens all exist the whole screen tier landed undesigned and stayed reachable: 8 product screens, 0 designs (10 non-test .tsx render outside the collection; the other two are the bootstrap and a pre-registry primitives kit), and every future change to one an edit the gate is blind to. The rule would have guarded only the work nobody was doing
Nothing makes an unbuilt design account for itself. DEC-16 granted the unbuilt case a permanent home — "the contract still lives there and nowhere else" the address problem: that grant makes a design file a second, permanent home for a contract, with nothing comparing it to code and nothing ever forcing the question of whether the component arrived. Four such files sat in the tree for three Working Units

Choice

One rule, three halves, and the unit it binds is the epic. Nothing rendered changes without an answer on the record: which design, or why none.

One function, three callers. Gate::surfaces is the trigger for the gate, the epic walk, and cargo xtask design-scope — the same refusal DEC-24 made for design-scope itself. Its added half and the roster are the same function, doc::surface_at: "is this path a surface at this revision", asked once and answered identically for both, so the two can never drift. Its touched half is ui_surface, which asks only whether a file renders.

The path test comes first, and that is load-bearing twice. It keeps a blob from being fetched for a path that could never need one — the ~12% of an epic gate's wall time an earlier round measured — and it stops a screen's membership from depending on a successful UTF-8 decode. Membership that read the bytes first would let one stray byte in a new screen drop it out of the added set, where a stated reason stands in for the design it owes.

And the roster counts screens. roster_at reads @tier components and non-test .tsx outside the collection, so a screen design resolves where its screen was built. Before that, the downstream half could only ever refuse a screen design — designing a screen cost a drop record while designing nothing cost nothing, and the gate paid you to skip the design. The other roster — the node oracle behind verify-doc's retirement check — still reads the collection alone, so it will not ask a screen design to retire into its screen's TSDoc. Nothing leaks (check 6 forces the file out of the tree at the epic tip regardless), and the asymmetry is stated rather than built around.

A rename of a surface is not a new surface — a rename of anything else is. The added set is the one place rename detection runs, because a renamed component is already built and DEC-16 has already retired the design a citation would name: treating the destination as added would demand an artifact the rules guarantee is gone, and the Working Unit could not merge at all. But git pairs on content similarity and knows nothing about surfaces, so the pairing is evidence, not a verdict — the gate exempts a destination only when the path it renames was itself a surface at the base. Read any other way, a new screen scaffolded from a deleted file it happens to resemble would be classed a rename and answered with a sentence, which is the review's own counter-example: an unrelated 60-line filler recycled as padding pairs at R095. A rename that also rewrites the file drops below the similarity threshold and is an add again — correctly, because that is a new surface wearing an old name.

UI work happens inside a Working Unit. The accounting lives on a cr/v3 note and a standalone commit has none, so a commit that renders something outside a Working Unit is refused at commit level. It is the third door, and it is closed for the same reason the other two are.

Why the coupling unit is the epic

Candidate unitWhy not / why
the commita design and its build are never the same diff — the design is docs-only and the build is code
the Working Unitthe ruled shape is design WU, then build WU. A unit that cannot contain both halves cannot be asked whether they met
the epicchosen the smallest unit that contains both, and the last seam where a design that never became code is still in the tree to be seen. It is also where the design files leave the tree (check 6), so the question has to be answered there or not at all
main, or a periodic sweepan unbuilt design would already be merged and the epic dissolved; there is no one left to ask
The epic half reads the range, not the endpoints — and reads all of it. Check 6 forces every docs/work/ file out of the tree by the epic tip, so a design added and then silently git rm'd nets out of an endpoint diff entirely. added_under walks the range's commits — the check cannot be defeated by the deletion the epic already owes.

Walking the commits is not sufficient on its own, which the review found the hard way. Given a pathspec, git's default history simplification follows only the first parent past a merge whose tree is TREESAME for that path — and a design added and removed inside one Working Unit branch makes its merge exactly that. Without --full-history the add commit is never visited and the epic greens on a design nobody built: the one case this half exists to catch, defeated by the very deletion it was written to see through.

Why the pointer carries a blob

Pointer shapeWhat it cannot say
a pathwhich bytes. A design edited after the citation was written still resolves, so the note attests a reading of a file that no longer exists in that form
path + blobchosen nothing — and it is what makes an amendment countable: an amended design is different bytes, so the stale citation reds and the amendment has to re-enter Tier-3 on the merge that lands it

The comparison is made against the tip, never the working tree — the same rule DEC-24 applies to its rulebook pin, and for the same reason: a later Working Unit editing the design must not retroactively falsify a citation that was true when it was written, on a branch nobody may amend.

design.implements is Option<Vec<Cited>>: absent is a silence, [] is a stated nothing, and the two reds say which happened. That is DEC-15's rule — a silence must never read as a pass — applied to the field rather than to the run.

Nothing judges the build against the design

The pointer is a mechanical check, not a judgment. No sixth finder asks whether the code matches the design it cites; UI merges stay at five finders plus the design dimension DEC-24 already defined. What the rule guarantees is that the design was named and readable, not that it was followed.

What would have to change to revisit it. Every check in this epic was born from a defect a run actually shipped (DEC-15). Conformance has no such measurement yet — no real build has ever consumed a handed-over design, so a conformance finder would be a judgment with no observed defect class to catch, which is precisely the shape DEC-24 rejected for the hard rules. The revisit condition is evidence: a real build that drifts from the design it cited, in a way the pointer did not catch. W9 is the first run that can produce one.

Options rejected

OptionWhy not
A new tracked home for unbuilt contracts (a T2 folder, a tier row, an xtask location) it answers the address problem by formalising the second address. The epic predicate answers it by refusing the situation: a contract with no code is a question, not a location
A design-side declaration or marking for the build to find a design-bearing diff already is the marking — design_artifacts_of detects it and DEC-24's check already demands the receipt. Building a second signal is building a second answer to a question that already has one
A conformance dimension on the code review above — no measured defect class, and the same argument DEC-24 makes for keeping hard rules out of the receipt
A date cutoff or a walk waiver to grandfather the trigger the cr/v2 schema string already discriminates, and it cost zero waivers. A date cannot tell a note written before the field from one written badly after it
Demand a design run of every UI edit — the path trigger as W8's discussion measured it (fires on 10 of 11 landed UI Working Units) a gate that reds almost everything gets waived almost every time. The touched half fires on the same population and demands something else entirely: a sentence, not a run, written by the reviewer rather than granted by the builder. What is refused is the silence
Let the builder declare a file undesigned in its own plan or commit the declaration would then be a permission the work grants itself, which is the shape DEC-15 already rejected for design runs. It lives on the cr/v3 note because that note is written by an independent review and bound to diff_sha256
A second epic-level check counting undesigned files the seams already know; they were only being thrown away. The walk now carries each seam's waivers up, so the epic's own receipt lists what it shipped undesigned — one line of plumbing instead of a predicate
Gate the citation at the epic level too the citation names a docs/work/ design, and check 6 forces those out of the tree by the epic tip — the WU seam is the only place the path can resolve. The epic re-asks at every seam its walk re-verifies, which is the same question in the only place it is answerable
Annotate DEC-16's survival clause instead of superseding it the clause is not imprecise, it is wrong in its grant: "lives there and nowhere else" is what created the address problem. An annotation would leave the grant standing next to the rule that revokes it

Consequences

  • DEC-16's survival clause is superseded, its retirement order untouched. An unbuilt design file no longer holds a contract by right; it holds a question its epic must answer. The three-step order — distil, verify, remove — and both its predicates stand exactly as written.
  • DEC-24's timing dependency is answered on the build side. The Tier-3 verdict still fires at the close and is not moved earlier; what the build inherits is a pointer to the exact bytes that verdict covered.
  • A note may carry a design: section without claiming a review. A build's note carries it for the citation and an epic's for the drop record, so check_design returns as soon as the diff carries no design artifact and verdict became optional. Demanding a PASS over an empty artifact list would have made both notes attest a judgment nobody made — DEC-15's own failure mode, one field down.
  • An epic can still ship UI it never designed — it just cannot do it quietly. The touched half refuses silence, not choice: every declared file surfaces as a WAIVE line at its seam and again in the epic's receipt. Whether the reasons are good is a judgment, and judgment stays with the review; "did this epic design enough" is not a predicate and this record does not pretend it is.
  • Deletion is asymmetric, deliberately. At a WU seam a deleted file owes nothing — no design can be cited for bytes that are gone. In a standalone commit it is refused like any other rendered change, because there the question is not which design but who reviewed this, and removing a screen is as unreviewed as adding one.
  • The truth is the code. xtask/src/gate.rs owns when a design is required and what a citation must satisfy; xtask/src/doc.rs owns what a design must contain and what counts as a surface. Where a doc and the code disagree, the code wins.
  • The handoff has never been driven by anything real. It is enforced by two predicates and exercised by a fake build: a stub component, a one-line screen, and no agent that read the contract it cited. A handoff nobody real has driven reads exactly like one that works — which is the failure this record's own context describes. W9 pays it, by making the first real Tier-3 judgment and the first real build the same run.
