DEC-61 — the dot is a switch, and capture proof expires

The header's dot moves between the list and setup in every state, and it reads the newest captured request, not whether capture was ever proven.

Decision. The dot switches screens in every phase: the list opens setup, and setup or the launch check opens the list. It reads the newest request the proxy captured, http or https: red with none, green for 3 minutes after one, then quiet. Setup reaches the list on its own only on its session's first decrypted https request, and its way back is always shown.

The rules

#RuleWhy
1The dot's click is a switch: the list opens setup (a new session, DEC-60), and setup or the launch check opens the list. A click during the launch check ends the check: the app does not then move the user to setupthe user chose the list, and an empty list offers the way in (rule 5)
2The dot reads the newest captured request: checking until the core answers, red with none, green for 3 minutes after one, quiet after that. Imported and sent rows count for nothinga capture proves the proxy worked then. Nothing pushes when a setting changes outside Trawler, so recency is the only honest reading
3Plain http turns the dot green. It never settles the certificate task, and never ends setuphttp proves the proxy is in the path, and nothing about the certificate
4The newest capture is read from every listing and from the core's own newest captured row, so neither a filter nor a clear lowers itthe dot answers for the proxy, not for the list's query
5An empty list nothing has reached offers "set up capture". The way back from setup is shown on every setup screenthe list is a screen to switch to, not a reward for finishing
6Only a decrypted https request that started in this session moves setup to the list on its own, and only before capture was first proven. A row from before the session moves no onethe list is a click away, and an older row is another session's evidence (DEC-60)

Rule 2 replaces DEC-60 rule 5, "once capture has been proven, the dot reads connected in setup too". Setting up a second device still does not turn the dot red: it reads the traffic, which the first device keeps sending.

AlternativeWhy not
Keep the dot green forever once provenit says Trawler is capturing when nothing is

A separate button for the list, beside the dottwo controls for one switch, and the dot was already the only control on screen in every phase
Block the list too while the core is silentthe rows already on screen are still true and still worth reading. Setup blocks because its tasks cannot work without the core
