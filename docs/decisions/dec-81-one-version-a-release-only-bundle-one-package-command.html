DEC-81 — one version, a release-only bundle, one package command

What every Trawler installer is built from: one committed version, a front-end bundle that can never be the e2e one, and one command that builds and checks the host's installers.

v2 · 2026-11-06 · Trawler · T2 decision · minted by E-PKG.W1 from the owner's rulings Q2, Q3, Q8, Q15 and Q18 on the E-PKG plan · UC-INSTALL (the artifact; the release itself is E-PKG2's) · active · numbered DEC-81 because DEC-77 to DEC-80 are held by epics still open

Why this record exists

BeforeWhat went wrong
0.1.0 typed in five filesa release's tag could be checked against none of them, because no one of them was the version
the shell's build script judged ui/dist stale by age alonea cargo run after cargo xtask ui e2e embedded the e2e bundle, WebDriver plugin included (E-ONEAPP.W1's finding)
the app ran only from a clonenothing built, signed or checked an installer

Decision. The version is [workspace.package] version and nothing else. A bundle says which flavour it is, and the app embeds only the flavour its build wants. cargo xtask package is the one way an installer is built, and on macOS it does not finish until the signature verifies.

The rules

#RuleWhy
1The version lives in [workspace.package] version; every member says version.workspace = true; tauri.conf.json carries none, so Tauri stamps trawler-ui's; ui/package.json equals it. the_tree_carries_one_version reads the members through cargo metadata and is red when any member or ui/package.json differs from what trawler-ui shipsa release checks its tag against this one value and never rewrites it (Q8, Q18). Reading cargo metadata, not the manifests' text, leaves membership to Cargo (W1's review, round 3)
2Vite writes ui/dist/bundle-flavour: e2e when VITE_E2E is set, release otherwise. The shell's build script wants e2e only under the e2e feature. A bundle of the other flavour, or one that records none, is stale however new, and is rebuilt in the wanted flavourthe WebDriver plugin can reach a build only through the feature that asks for it
3cargo xtask package [--universal] [--profile <name>] installs the UI's packages from the lockfile unchanged (--frozen-lockfile) and runs tauri build with the host's bundles: app,dmg · msi,nsis · deb,rpm,appimage. VITE_E2E is removed from its environment. A request it cannot meet is refused before any build: --universal off macOS, or without both Mac targets (the refusal names the rustup target add line)the release workflow and the packaging e2e build what a person builds (Q15); a release never rewrites its own lockfile
4No paid certificate (Q3). macOS signs ad-hoc (signingIdentity: "-", Tauri's default hardened-runtime flag kept), and package refuses unless the .app passes codesign --verify --deep --strict. Windows ships unsignedan unsigned arm64 binary is killed at launch; a check inside the command means no caller can skip it
5[profile.package-test] is release without LTO, for the tests that package; --universal builds universal-apple-darwin, one .dmg for both architectures (Q2)a packaging test pays for bundling, not for link-time optimisation

Rejected

AlternativeWhy not
rewrite the version from the tag, as Strata doesthe released binary would be built from a tree no gate proved (Q18)
keep judging the bundle by age, and rebuild it before each releaseleaves cargo run embedding the e2e bundle, which is where the finding came from
read the members' versions from the manifests' textit took two review rounds to stop hiding a member, and it duplicated cargo metadata
