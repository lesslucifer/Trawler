DEC-14 — the design rulebook lives in a fourth T2 KB, docs/design-rules/

Where the design rulebook lives and how it grows with the codebase — a new indexed knowledge base, not a T1 doc, not a decision record, not a use-case.

DEC-14 · 2026-07-25 · Trawler · E-DFLOW.W3 · status: active

Context

E-DFLOW.W3 seeds the design rulebook: enumerable slug-id'd rules (hard/soft) plus fixed vocabularies, the coverage list the design harness (W7) checks receipts against. The epic plan originally slated it as a T1 doc. But the rulebook must grow with the codebase — every UI-touching task can lock a convention, add a vocabulary member, or contradict a rule — and T1 is deliberately hard to grow (permanent, shape-level). It fits no existing T2 KB either:

OptionWhy not
T1 flat doc (the epic plan's original slot)T1 changes only when the shape changes; rules change per-task. A frozen rulebook rots into fiction
decisions/ topic fileappend-only by charter; rules are sharpened in place (W6 literally does that). Exactly the DEC-5 precedent — a living tracker is not an append-only decision
use-cases/ topic fileright mutation model (current truth, updated in place) but wrong contract subject: UC-* binds app runtime behavior; rules bind design artifacts. One KB restating another's charter blurs both
backlog/forward-looking roadmap KB; rules are present-tense truth

Choice

A fourth T2 KB, docs/design-rules/ ("what must every design satisfy") — a single file: design-rules-index.html is both index and rulebook (it splits into topic files only if it ever outgrows one comfortable read). Living like backlog/: entries mutate in place. Two invariants make living rules safe to cite:

  • Slug immutability — a rule slug cited by a design receipt is never renamed, only deprecated with a pointer; growth only widens coverage, old receipts stay valid.
  • Vocabulary-not-vigilance — cross-screen consistency (colours, keys, words, tokens) is fixed vocabularies in the rulebook plus rules forcing designs to pick from them, under the registry's reuse-or-propose contract.

Growth is wired, not promised: the distillation checklist carries a design-convention row (same-session write-back like every T2), doc/v1 notes attest each rulebook edit mechanically at the gate, and the W7 design receipt pins the rulebook blob hash it ran against.
