DEC-20 — business logic lives where its inputs live, and a T1 states what it cannot enforce

StatusPill takes a raw status and resolves it. StatusLine refuses the raw inputs and takes a resolved verdict. A reviewer reads those two as a contradiction — they are one rule, and this record is here so nobody "fixes" the asymmetry.

DEC-20 · 2026-08-12 · Trawler · E-DFLOW.W7 · distilled from StatusLine D1 · StatusPill D4 · TonedText D1/D2 · Notice D3 · StepList D1 · Select D4 · Section F2 · status: active

Context

Two T2 components sit beside each other in the collection and answer the same API question in opposite directions. The design file that settled the second one named the problem itself: "a reviewer will read D1 against StatusPill's D4 and see a contradiction". Code cannot hold that sentence — both components just look like normal components — so the only place it survives is here.

Both put the logic where the inputs live. Only the inputs differ.
CaseWhere the logic goesTest
StatusPill — status in, full display out Inside the component. It owns the mapping, the formatting ("…" for null) and the alt text; call sites shrink to one prop and a wrong tone/value pairing is unrepresentable Status → display is a pure total function of one number. Nothing to import, nothing to observe
StatusLine — one resolved verdict in Outside the component. The domain's resolvers are pure and unit-tested and read probes plus observations. StatusLine owns the shape and the promise of the order; the domain owns which verdict is true Probe + observations + running + error → verdict is a function of app state. Absorbing it would import domain state and duplicate three tested resolvers, letting two copies drift on the one rule that must not

A T1 states the obligation it cannot enforce

The same boundary, one tier down. A primitive can only enforce a rule about its children by inspecting them — and a component that inspects its children is not a primitive.

ObligationWho states itWho discharges it
colour-plus-text — colour never carries meaning alone TonedText, as an @avoid line Its tenants: StatusPill's text is the code, StatusLine's is a glyph plus words
Which actions a failure offers (close · retry · both) Notice, as action?: ReactNode — a slot, not named handlers The panel, which knows why the fetch failed — knowledge the primitive must not have
What a step contains (prose · command · a path · a caveat) StepList, as ReactNode[] — it renders children in order and inspects nothing The screen. Owning "commands get a CopyText" is business logic, which would make it a T2
What an option row draws Select, as an optional element — with label still required, because the trigger renders one line and the filter matches characters The caller. The component renders the slot and asserts nothing about it
Whether the last Section's hairline shows Section — every one carries border-b The scroll container, which clips it. A component that detects its last sibling knows about its siblings' rendering, which is coupling that belongs outside

Options rejected

OptionWhy not
Symmetry — give StatusLine the raw inputs too, since StatusPill takes raw status The real argument for it, and the reason this record exists. Rejected: it imports domain state into a component and duplicates three tested resolvers. Symmetry of signature at the cost of splitting the one rule that must not drift
Tone in, children out for StatusPill (what shipped first) A generic toned mono span with no business logic is a T1 primitive, not this component. It survives — as TonedText, the primitive StatusPill is made of
Named onRetry/onClose props on Notice Guarantees consistent order and wording, which is real. But it hard-codes the two actions today's tenants need; the third either adds a prop or renders its own row
A structured step — {text, command?} — so StepList renders the CopyText and no caller can forget it Tempting for exactly that reason. Rejected: the first step that is neither (a settings path, a caveat) needs a third field or an escape hatch, and the screen still needs the free case
{id, element} — element instead of label The trigger would have nothing to render but a duplicated element and the filter no text to match, so the component needs searchText anyway — which is label with a worse name. It also silently breaks the accessible name
A glyph prop on TonedText beside children Both T2 tenants pair a glyph with words, so it looks natural. Rejected: it makes the primitive responsible for the gap between them, and invites a default glyph per tone — the mapping that was just removed

Consequences

  • The asymmetry is load-bearing. A code review that files "StatusLine should take raw inputs like StatusPill does" is refuted by this record, which is the case DEC-5's index note describes: the oddity is the decision.
  • A design run proposing a T1 that inspects its children is proposing a T2. The tier follows the inputs, not the size of the component.
  • A rule a primitive can only state — not enforce — belongs in its @avoid, and the design run's reuse trace is where a tenant shows it discharged it.
