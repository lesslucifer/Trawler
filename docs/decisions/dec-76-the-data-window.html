DEC-76 — the data window

A data window is a front-end tool that is handed a piece of data by value and helps the user work with it. It knows nothing of flows or the core, keeps the data it was given as the original, and works on a scratch copy that never flows back.

v4 · 2026-11-05 (rule 1: the opener's heading — E-INSPWIN.W11) · Trawler · T2 decision · minted by E-INSPWIN.W1 from the owner's rulings on the epic plan's Q1–Q12 · UC-9, UC-5 · active · numbered DEC-71, then DEC-75, on its epic branch; DEC-76 as landed (E-INSPWIN.W9 and W11: E-QUERY landed DEC-71 and E-GATEPAR2 DEC-75 first)

Why this record exists

TodayThe limit
BodyViewer is a glance: text and JSON cut at 128 KiB, hex at 4 KiB, a 520 px pane, pretty/raw, copy and saveno way past a cut, no search, filter, reformat, decode or edit
UC-5's evidence rule: the pane shows what was captured, never a client-side rewriteany tool that edits must live somewhere that rule does not bind, and say where the line is

Decision. Any component holding data may open a data window with {key, title, bytes, typeHint?, heading?}. The window works only with that payload: it keeps the bytes as the original, lets the user change a working copy freely, and marks find matches over it. Nothing it does reaches the opener, the capture or the core.

The model

flowchart LR
  OP["opener — owns where the data came from, writes the title"] -- "payload, by value" --> SH["shell: create or focus data-<hex(key)>"]
  SH -- "claimed once" --> O["original (immutable, the evidence)"]
  O --> W["working copy (scratch, undoable)"]
  W --> V["find marks (highlights, never a change)"]
  W -. "never" .-> OP
The core is absent by design: the opener already holds the bytes.

The rules

#RuleWhy
1The payload is all the window receives. key is opaque and only focuses an open window; title is the opener's caption; typeHint is a media type, optional; heading, optional, is {what, method, host, path, query} for the header to draw. The window parses neither title nor heading: no heading, the title is shown whole. The shell relays the heading unread. No flow id, leg or source kinda generic tool; every opener is one call; a header drawn from parts the opener names cannot drift from a caption format
2By value, as a snapshot: the shell parks the bytes for the new window, which claims them oncethe window never fetches, so it never talks to the core (DEC-12) and never goes stale mid-edit
3One window per key. Opening a key whose window is open focuses it and leaves its working copy intactreopening is a return, not a reset
4The original never changes; restore original returns its exact bytes. copy and save deliver what is on screen, the working copy; copy original and save original deliver the handed-in bytesthe evidence stays one menu row away
5UC-5's evidence rule binds the pane, not the window. In the window the original is the evidence the pane handed over; everything else is scratch and is marked as suchwhere the line sits between the pane's read-only surfaces and an editable one
6No write-back. Edits live as long as their window; closing one asks nothing; data windows close with the main windowscratch by definition; sending a changed request stays the composer's (UC-8)
7No render caps in the window; a body is at most the core's 10 MiB body capthe window is the way past the pane's cuts
8The bytes cross the IPC as raw bodies both ways, never JSON arrays or base6410 MiB as a JSON number array is tens of MiB of text on each side
9A data-* window holds its own capability: the core default, the save dialog and file write, nothing elsea window that edits scratch needs no more reach than saving what it names
10Every data window shares one geometry record, data-* in DEC-67's windows.json: whichever data window moved or resized last writes it, and a new data window opens there (re-ruled 2026-11-04, E-INSPWIN.W3)a record per key would grow the file by one entry per payload ever opened, and a key is never opened twice in the same place on purpose
11Decode reads a value one way: the peek names the decoder that read it, or says why none did. Replacing with the decoded form is one working-copy step; opening it hands the decoded bytes to a new data window keyed by their content (E-INSPWIN.W6, W8)no value reads two ways under base64, URL, JWT and time, so a switch among them could never show; it returns with a decoder that overlaps one
