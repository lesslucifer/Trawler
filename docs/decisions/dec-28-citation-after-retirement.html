DEC-28 — a design citation resolves at the WU tip, or at the design's last state reachable from it

A build cites the bytes it read. Once the design file has been retired inside the same Working Unit, those bytes are no longer at the tip but they are still in the tip's history — and the gate reads them there, pinned to the last state the file had before it went.

Choice

A citation resolves at the WU tip. When the tip does not ship the path, it resolves at the path's last state reachable from the tip — the blob the path held immediately before the commit that removed it — and the pin must match that state. The note shape is unchanged: path, blob, built. Everything checked over the resolved bytes — that they decode, name a design artifact, and if a run, an archived one — is checked exactly as before, over the bytes history returns.

Why the last state, not any state

DEC-25's blob pin exists to make an amendment countable: different bytes red the stale citation and force the build to re-read. Matching any historical blob would let a build cite a superseded revision of a design amended and retired in the same WU. Matching the last state keeps the rule whole: the build must have read the design as it was when it left the tree. For a design retired unchanged — the ordinary case — the last state is the only state, and the two readings coincide.

Why reachable from the tip

git log <tip> -- <path> is the reach: history the tip stands on, nothing else. A commit not reachable from the tip is not this WU's history and cannot have been what the build read. --full-history is required, for the reason DEC-25 learned on added_under: default history simplification skips a path added and removed inside one branch — the very shape this record legalises. The reach is not narrowed to the WU's own range (base..tip): a later WU that builds a second surface from a design an earlier WU retired cites the same bytes by the same rule, and nothing about the citation's meaning depends on who deleted the file.

Consequences

  • DEC-25's tip-resolution clause is superseded — "the path must resolve at the tip" and "the comparison is made against the tip". Its three halves, the blob pin, the no-conformance rule and the epic as coupling unit all stand. Its rejected option "gate the citation at the epic level too" keeps its conclusion (the WU seam is where the citation is judged) and loses its premise (that the path resolves there): it is the seam's history that answers.
  • DEC-16 is untouched — the order, both predicates, and the authoring-time timing of components·unretired. A build WU still retires the design it built from, in the same WU, distil first.
  • E-GATETRUTH.W2 owes: the right-hand branch of the predicate in check_citation; refusals naming the failed half; the check_handoff fix hint, which today reads blob: <git rev-parse <tip>:<the design>> and must also say where to read the blob for a retired path; the hand-over e2e gaining a leg that retires the design inside the build WU; the negative fixtures for the path half and the blob half.
  • A citation's meaning is unchanged: the design bytes the build read, judged by Tier-3 at the merge that landed them. Only where the gate looks for them widened, from the tip to the tip's history.
  • The truth is the code. xtask/src/gate.rs owns the predicate once W2 lands it; this record owns why. Where they disagree, the code wins.
