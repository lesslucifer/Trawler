DEC-68 — the app supervises its core

Trawler is one program to its user: the app starts the capture core as a child process of its own binary, and the repo is one Cargo workspace whose bare cargo run opens that app. The API boundary does not move.

v1 · 2026-11-03 · Trawler · T2 decision · minted by E-ONEAPP.W1 from the owner's rulings on Q1–Q14 (2026-11-03) · supersedes DEC-12's topology and GUI-free-root-build clauses only · UC-4 · active

Why this record exists

Before (DEC-12)What went wrongRuling
the core (cargo run) and the window (cargo xtask ui dev) launched separately the window could not start, stop or find the core it depends onQ1: a sidecar the app manages
ui/src-tauri excluded from the workspace, so the root build stayed GUI-freecargo run could not open the app, and the app could not be packaged as a wholeQ2, Q3: one workspace; the root build compiles the GUI

Decision. The app process runs the window and supervises a core it spawns as <its own binary> --core. The core reports its bound addresses on one stdout line, logs on stderr, and exits when its stdin closes. The webview stays an HTTP/SSE client of the core. curl reaches the same API. The repo is one workspace, and the trawler package stays GUI-free.

The rules

#RuleWhy
1One core entry, trawler::cli::main, serves both trawler (headless) and trawler-ui --coreQ11: one binary to build, bundle and sign. A separate core binary is missing after a plain cargo run, and an externalBin must be staged before its build
2The first stdout line is {"proxy":"<addr>","api":"<addr>"}, written after both servers bind. Logs go to stderrfixed ports (production) and port 0 (e2e) take one path; the supervisor never parses a log line
3--lifeline: stdin EOF stops the core. It is opt-inif the app dies by any route, SIGKILL included, the pipe closes and no orphan holds the ports. A headless core launched with stdin at /dev/null must keep running
4The workspace's default-members are the core and the app. The app's default-run makes a bare cargo run the app. cargo run -p trawler is the headless coreQ2: the core stays the root package, so src/ and tests/ do not move
5The trawler package never depends on a GUI crate; a test reads its cargo treeQ3 lets the root build compile the GUI. Servers and CI still need a core without it
6The app embeds ui/dist by default (custom-protocol). Its build script rebuilds the bundle when an input is newer and fails naming pnpm install without Node/pnpm. cargo xtask ui dev drops the feature to keep HMRQ13: no separate pnpm step before cargo run. The root cargo test now needs Node + pnpm; cargo test -p trawler does not
7One [workspace.lints] covers core, xtask and appthe app's code meets the core's bar. Two lints are allowed crate-wide in the app because a Tauri command takes its arguments by value
8TRAWLER_API attaches the app to an existing core and spawns none, in every build. Fixed ports 7420/7421, a native dialog on conflict, no automatic restartQ4, Q5, Q9, Q12. Realized by E-ONEAPP.W2
