DEC-2 DoD evidence is four per-tip git notes, judged by a recomputing gate

Statusaccepted · 2026-07-05
OriginEpic E1 (workflow standard) — manager decisions D1–D13 in the archived brainstorm (docs/.archive/2026-07-05-workflow-brainstorm.html, untracked; content in git history before E2)
Wherextask/src/gate.rs · .cargo-husky/hooks/pre-merge-commit · workflow.html

Context

Every line is AI-written and merges are unattended; agents cannot be trusted to remember ritual steps or honestly self-report completion. Evidence must be mechanical, queryable after branches are deleted, and tamper-evident against amend/rebase.

Choices (each looks "fixable" — it isn't)

ChoiceWhy — do not "simplify" it away
Four notes (test/cr/doc/dod), not one blobEach has one writer and one lifecycle: manifests and doc notes are authored during work, the review note by a review run, the receipt only by the gate on green. Merging them would let one writer forge another's evidence.
The dod/v1 receipt exists although it is recomputableManager decision (brainstorm Q4): a queryable index of completed work. It is safe because it is never blind-trusted — any tip can be re-verified offline; a hand-minted receipt fails recomputation.
merge.ff = false everywhereThe epic walk recovers WU tips as merge^2; a fast-forward erases the seam and hides evidence. The post-checkout hook re-heals the config.
The walk skips the epic tip when it is a non-merge commitOne commit cannot carry both an epic-level and a commit-level test note (one note body per ref per commit). The tip's own diff is covered by the epic gate itself.
Diff hashing uses git diff --no-color --no-ext-diffThe review-time hash and the gate-time recomputation must be byte-identical across user configs; bare git diff respects local color/ext-diff settings.
waived (judgment, with reason) vs exempt (rule: docs/infra-only)Waivers stay visible and reviewable — an unjustified one is a review finding; exemptions are mechanical and carry no note at all. Collapsing the two would either bury judgments or demand ceremony for prose fixes.
Code paths are src/, xtask/, tests/The gate itself is code; scoping "code" to src/ alone would have exempted the tool that enforces the rules.
Hook mode resolves the merged tip from GIT_REFLOG_ACTION, with the MERGE_HEAD file as the first choiceDiscovered live on E1's first gated merge, which failed open: pre-merge-commit fires before git materializes MERGE_HEAD for automatic (ort) merges — the merged revs exist only in the reflog action then. MERGE_HEAD is on disk only for conflicted/--no-commit merges, whose completion pre-commit gates through the same path.
Every spawned git scrubs inherited GIT_* env (xtask/src/git.rs · cmd; local copies in the hook-test helpers)Discovered live when the pre-push suite trashed the enclosing repository: git exports GIT_DIR to hook processes, and inherited it overrides -C/current_dir, silently redirecting every "hermetic" temp-repo call to the real repo. Regression tests in dod_gate and dod_hooks run the helpers with a poisoned GIT_DIR.

Consequences

Hooks can be bypassed (--no-verify, ff-merge) but not the epic walk — smuggled content turns the next gate red. Deferred: verify-dod --remote (assert origin has the notes refs) once a second machine or CI consumes them.

DEC-3 Archived docs leave git; the epic gate enforces the tracked-doc layout absolutely

Statusaccepted · 2026-07-05
OriginEpic E2 (doc-archive) — user direction: archives must not be tracked
Wherextask/src/gate.rs · check_tracked_docs · xtask/src/notes.rs · is_expected_tracked_doc · documentation-system.html

Context

Archived T3 docs were tracked under docs/work/archive/. Sessions must never read archives, yet tracked files invite reads, bloat the tree, and make "what docs exist" ambiguous. Archiving already requires distillation, so the tracked copy carries no information the tiers and git history don't.

Choices

ChoiceWhy — do not "simplify" it away
Archiving = git rm + move to gitignored docs/.archive/The archive stays greppable locally for forensics, but git carries only living docs; the pre-archive content remains addressable in history via the commits that added it.
The epic gate checks the whole docs/ tree at the tip (flat T1 files, use-cases/, decisions/), not just paths added since baseA base-relative check fails open: junk landed through an ungated path (or grandfathered before the rule) never turns any gate red. The absolute check makes every epic re-assert repo-wide doc hygiene; main was migrated clean in E2 so any hit is real.
archived doc-note entries keep requiring distilled_to, judged wherever the deletion appears in a gated diffA work doc created and archived inside one epic nets out of the epic diff — its lineage evidence lives at the WU seam that deleted it, so the requirement cannot be re-hung on the epic note.

Consequences

Archives don't replicate through clones — a fresh clone starts with an empty docs/.archive/, which is by design: nothing citable may live there. Any doc path outside the tier layout (a stray docs/<dir>/) now blocks the next epic merge until it is moved into a tier folder or archived. The layout check runs before the docs-only exemption, so even an exempt (docs-only) epic merge re-asserts hygiene — a stray doc cannot ride an ungated merge into main.

DEC-6 main is merge-only — the pre-commit hook refuses direct commits with branch guidance

Statusaccepted · 2026-07-06
OriginEpic E-MAINLOCK — user direction after auditing the direct-to-main path used by the port-change commit
Where.cargo-husky/hooks/pre-commit · tests/dod_hooks.rs · workflow.html

Context

The original workflow allowed standalone commits directly on main: docs/infra-only ungated, code commits with a test/v2 · level: commit note checked by the pre-push range walk. Audit showed that path never requires a code review (check_review is skipped at commit level) and is never revisited — epic gates walk only their own branch range, so main-side history stays behind every future merge-base. Unreviewed code could land on main permanently, gated only by fmt/clippy/tests and a self-attested note.

Choices

ChoiceWhy — do not "simplify" it away
Remove the path (refuse the commit) instead of patching it (requiring cr/v2 at commit level)One uniform rule for an AI committer beats a second evidence contract: any work ⇒ branch ⇒ gated merge. The refusal message teaches the correct move at the exact moment of the mistake.
The guard sits first in pre-commit, before fmt/clippyThe refusal must be instant and unambiguous — not buried after a minutes-long clippy run, and never masked by an earlier failure.
Docs-only commits are refused tooUser decision: "any works". Carve-outs re-open judgment calls the rule exists to remove; the merge gate already exempts docs/infra-only diffs, so the added ceremony is one branch and one --no-ff merge.
Merge completions (MERGE_HEAD on disk) pass the guardConflicted merges into main complete through pre-commit — they are the gated path, not a bypass; the existing MERGE_HEAD block in the same hook runs the epic gate on them.
No pre-push backstop against --no-verify commits on main--no-verify defeats pre-push equally, so a backstop there adds no real enforcement (DEC-2 already accepts hooks-can-be-bypassed); the workflow forbids bypassing gates outright.
epic/* branches keep allowing standalone commitsPlan docs, epic-level notes and small fixes legitimately land there, and the epic walk gates every one of them at merge time — the hole existed only where no later walk ever looks.

Consequences

Every change, including T0/CLAUDE.md edits and doc snapshot bookkeeping, now needs a branch and a --no-ff merge. Post-epic cleanup that used to land directly on main (e.g. archiving a distilled doc) must happen on the epic branch before its merge — which the tracked-doc layout check (DEC-3) already forces. The commit-level rows of the DoD table now apply only to standalone commits on epic/* branches.

DEC-7 Manual review is a fifth note, required by path + level, with identity-only auth deferring the cryptographic form to E-MRSIG

Statusaccepted · 2026-07-06
OriginEpic E-NMWF (manual review) — user direction; plan archived at docs/.archive/2026-07-06-manual-review-plan.html (untracked)
Wherextask/src/mr.rs · xtask/src/gate.rs · check_manual_review/check_commit_trailer · xtask/src/notes.rs · is_doc/is_ui · .cargo-husky/hooks/commit-msg · .mr-allowed · workflow.html · roadmap (E-MRSIG)

Context

Human-facing surfaces must not land silently, yet every line is AI-written and merges are unattended. A sign-off gate has to be as mechanical and un-agent-trustable as the rest of the DoD: whether review is required cannot be an agent's judgment, and the record of who signed must be verifiable. The strong version — a signature no agent can produce — needs its own design and is deliberately split out; this epic builds the whole surrounding gate and leaves one swappable seam for it.

Choices (each looks "fixable" — it isn't)

ChoiceWhy — do not "simplify" it away
Requirement is derived from diff paths + level, never a flag — docs⇒commit, UI⇒WU, epic⇒alwaysAnything an agent asserts about necessity is forgeable; a path predicate (is_doc/is_ui) is not. Same principle as the docs/infra exemption and the code-path definition (DEC-2).
Docs are gated at commit time via a Reviewed-By message trailer, not a noteReviewing after the commit exists is too late — the point is to prevent the commit — and a git note cannot hang on a commit that does not exist yet. The trailer rides in the message; the commit-msg hook enforces it against the staged diff. The change hash needed for the future signature exists pre-commit as git diff --cached and recomputes as parent..commit, so the carrier is already the right shape for E-MRSIG.
Not waivableA waivable human-sign-off is not a sign-off. Unlike a test layer (DEC-2's waived), "required" means a listed authoriser is recorded — nothing to skip.
The check runs before the docs/infra exemptionAn always-required epic (or a docs-only one) must still carry its note even when exempt from test/cr/doc — exactly like the epic tracked-doc check (DEC-3). Path lists use --no-renames so a rename out of docs/ or ui/ can't mask the requirement.
Identity-only auth this epic; the crypto signature is E-MRSIGAn identity in .mr-allowed is agent-forgeable, so today's guarantee is a forced stop + an audit trail of who signed, not proof. This is stated wherever the mechanism is documented, never blurred. E-MRSIG swaps only the auth predicate (identity-match → signature-verify); the rules, carriers, hook, gate check and walk all stay. The seam is a single function — mr::message_authorised / tip_authorised.
The UI path set is provisional (ui/) until E-UIFOUND fixes itThe UI-WU rule needs a predicate now to be built and tested; the real asset paths are unknown until the UI stack is chosen. E-UIFOUND owns the final is_ui (recorded in the roadmap).

Consequences

The gate now honestly enforces a human pause and records an accountable signer; it does not yet prove the agent could not have signed — that is E-MRSIG's job and is called out at every doc touch point. Until E-UIFOUND lands, the UI-WU rule matches only ui/ paths, so no current WU triggers it; epics and doc commits are live immediately. Adding a person to .mr-allowed is itself a tracked, reviewable diff.

DEC-8 The epic walk skips history already on the gate target; a per-seam walk waiver on the cr/v2 note is the only recorded override

Statusaccepted · 2026-07-07
OriginEpic E-GATEBM — the walk's three-parent arm mis-gated a back-merge of already-gated history, which already forced a blanket --no-verify onto main (E-NMWF landed at 8871d7b with no receipt on the back-merged tip). Plan/discussion archived under docs/.archive/ (untracked)
Wherextask/src/gate.rs · is_landed_history/record_seam/tip_walk_waivers · xtask/src/notes.rs · CrNote.walk_waivers/walk_waiver_for · workflow.html

Context

The epic gate's seam walk (check 7) is the one place that re-inspects every first-parent seam, and it is the unbypassable backstop against a fail-open or bypassed sub-gate — so it cannot be removed. But it answered only one classification question: "is the merged-in parent already reachable from the epic mainline?" That misses the normal shape of a stale epic that back-merges an advanced main — the two lineages have diverged, so neither contains the other, yet the merged-in tip is already on main and was gated by main's own history. The walk mis-read that integration as a net-new, ungated WU seam and turned the epic gate red on a legitimate merge.

Choices (each looks "fixable" — it isn't)

ChoiceWhy — do not "simplify" it away
Discriminator #2: skip a seam when its merged-in parent is an ancestor of the gate target (p2 ⊑ main), kept alongside the existing p2 ⊑ mainline checkContent already on main was gated by main's own history — there is nothing to re-gate. It is R2-safe by construction: a genuine forward WU seam always carries commits absent from main, so it can never be an ancestor of the target and the skip can never swallow it. The regression test freezes that property rather than hoping for it.
Rejected #1 (symmetric ancestry: also skip if mainline ⊑ wu_tip)Verified against the real E-NMWF back-merge: the diverged lineages mean neither tip contains the other, so #1 does not fix the reported case. The intuition "a back-merge means one side contains the other" is false once both sides advance — the normal state of a stale epic.
Rejected: removing the walkIt is the only re-inspection of seams and the only backstop that a fast-forward or --no-verify can't defeat (DEC-2). Removing it trades a false positive for a permanent hole.
Deferred #3′ (gated-lineage: skip if the merged-in tip's own chain is fully receipted)The fully-general answer — it also covers unlanded cross-epic siblings — but it re-derives the gate recursively and is costlier. No unlanded cross-epic integration has ever occurred; the standing rule is to serialize cross-epic dependencies through main (land one, back-merge, build the next), which turns that case into a plain back-merge #2 already handles. Build #3′ only if live integrations ever become frequent enough that per-seam waivers turn noisy.
R5 waiver valve: a walk seam failure is suppressable only by a walk_waivers: [{seam, why}] entry on the epic tip's cr/v2 note, per-seam, mandatory non-empty why#2 fixes the known misfire; the walk is subtle enough that the next one needs a surgical, recorded override — never the blanket --no-verify, which skips every gate and already defeated the gate once. The waiver waives exactly one named seam; every other seam and every non-walk check still runs.
The waiver rides cr/v2 — not test/v2, not dod/v1A walk waiver is a review judgment ("I looked at this seam the walk can't classify and skipping its re-check is acceptable"), not test coverage (test) and not the gate's own green-only output (dod, which can't authorise its own pass — DEC-2). And cr/v2 is diff-bound (base + diff_sha256): if main moves and the epic's effective diff changes, the review — and the waiver riding it — is forced to be re-validated, so a waiver can't silently outlive the diff it was judged against. An unjustified waiver is a review finding, the same trust model as every other waived (DEC-2).
Manual review (check 8) stays outside the waiver pathThe walk_waivers valve suppresses walk-classification failures only; a doc commit's missing Reviewed-By trailer is a correctly-detected manual-review gap, and manual review is not waivable (DEC-7). Routing check 8 through the valve would make a human sign-off skippable — the opposite of its point.
Waivers key on the whole seam sha (prefix-tolerant), not per sub-checkThe agent copies the abbreviated sha the walk prints straight into the waiver; per-check granularity is deferred unless it proves too coarse. One named seam, one waiver.

Consequences

A stale epic can back-merge main (or a landed sibling) and walk clean, so the tooling/binary mismatch that forced the bypass self-resolves once a branch is current. The walk's backstop value is intact — genuine ungated seams still turn it red — but its blast radius is defused: a misfire is now a logged, per-seam door on the cr/v2 note, not a blanket --no-verify wall. The standing workflow rule "cross-epic dependencies serialize through main" is now explicit; unlanded live integration has a recorded escape (the waiver) rather than needing #3′.
