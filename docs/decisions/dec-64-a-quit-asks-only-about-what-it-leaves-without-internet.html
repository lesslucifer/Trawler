DEC-64 — a quit asks only about what it leaves without internet

Every quit Trawler can catch asks first while something still routes through it, and only then. The dialog says what it read, and stops routing only through Trawler.

v1 · 2026-10-26 · Trawler · T2 decision · minted by E-ONBRVP.W11 from the owner's rulings Q1–Q5 · relates to DEC-55 · UC-ONBOARD · active · rule 6 amended by E-ONEAPP.W4 (2026-11-04, DEC-69): quitting stops the capture service the app owns

Decision. A quit asks while this machine routes through Trawler, while its proxy could not be read, or while a device could route here: reach is armed, or a running emulator's proxy points here. Any other quit goes through. ⌘Q is Trawler's own Quit and asks as ✕ does.

The rules

#RuleWhy
1The app menu's Quit, on ⌘Q, asks the window to close, so it runs the window's check. The Dock's Quit and a logout terminate unaskedtao implements no applicationShouldTerminate, so a terminate cannot be held; a revert on terminate was removed by E-UISETUP.W6 for its surprise password prompt
2This machine routes through Trawler when its proxy is Trawler's address, localhost on Trawler's port, or one of this machine's own addresses on Trawler's port — as the capture service reports them, or last reported them once it stops answering. Read at the close, on every service on macOS, WinINET on Windows and GNOME's proxy on Linuxeach of those reaches the same listener
3A proxy that is not Trawler's asks nothing of its owna quit changes nothing for it, and turning it off can take the internet it provides
4A proxy nothing here could read asks, says it could not be read, and offers the steps with no button. It has its own opt-out"no proxy is set" would be a reading nobody took; a desktop whose proxy is never readable would otherwise ask on every quit
5With nothing routing here, the dialog asks about other devices only while reach is armed (DEC-55), or an emulator's own proxy reads Trawler's — asked through adb only while the emulator is the platform chosen; a Wi-Fi-only proxy on an emulator sending over mobile data routes nothing. It keeps its opt-outonly then can a device lose anything when Trawler stops; adb starts a server of its own (E-ONBRVP.W8's Q1)
5aEvery read a close waits on is bounded at 1.5 s — the capture service and the emulator, run together, then this machine's proxy (read off the shell's main thread) and the opt-out. A read that does not answer in time claims nothing: an unanswered proxy reads as unreada close held by a read that never settles is a window that cannot be quit (E-ONBRVP.W11's review, rounds 1 and 2)
6The stake is the capture service, not the window. Quitting stops the service the app owns, so the dialog says quitting stops it; an attached service outlives the quit, so there it says the machine has no internet once it stops. While it does not answer, the machine has no internet nowthe app supervises its core and stops it on every exit (DEC-69); attached, the core is its own process (E-ONEAPP's Q15)
7The act is stop routing through Trawler, offered only where the shell can perform it (macOS, Windows). Its steps are the platform's own to turn it off laterone act, one name, one copy of each reversal
