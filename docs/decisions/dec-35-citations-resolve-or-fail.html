DEC-35 — a docstring citation resolves against the tree, or it fails a test

DEC-16 makes a built component's TSDoc its retired design file. A design record that names deleted code is therefore not an untidy comment — it is the contract lying, and until now nothing could tell.

DEC-35 · 2026-09-06 · Trawler · E-RFINISH.W2 · enforces DEC-30's thesis · status: active

Context

DEC-30 was minted because two registry entries redirected to components that did not exist: “a redirect with no destination is worse than no redirect. It reads as guidance and resolves to hand-roll it.” It fixed those two by building the missing components. It could not fix the class, because nothing read the docstrings.

By the time E-RFINISH opened the collection, seven claims across five of the 28 entries were false — and every one had survived a full design run, a Tier-3 review and a merge gate:

A design record is the one artifact nothing re-reads. Code has tests, screens have a review, the rulebook has predicates. A retired design file has only the next reader — and the next reader is the person the lie is aimed at.

The decision

Every name and path a registry docstring cites must resolve in the tree that ships with it, and the collection's test suite refuses the block that does not. What may resolve is derived from the tree, never transcribed — scripts/design-citations.mjs, a sibling of the registry oracle.
QuestionAnswerWhy that answer
What is a citation? a path (x.tsx, optionally :N) and a two-hump name — [A-Z][a-z0-9]+([A-Z][a-z0-9]+)+ a docstring is prose, so shape is the only separator available. The hump admits HeaderTable and StepStatusView while leaving Inter, Pass, Enter, JSON, WCAG and the shouted STANDING unasked
What may a name resolve to? an identifier exported under ui/src · a module basename there · a binding any file imports · a ui/package.json dependency all four are read off the tree, so adding a component, a type or a dependency widens what a docstring may cite without touching the check
What may a path resolve to? anything git ls-files returns, matched on the full path or the bare basename “the tree it ships with” is exactly what is tracked, and no deny-list of build outputs can drift. Prose names a module the way a reader says it aloud — decode.rs, not src/api/decode.rs

What was rejected, and why

RejectedWhy it loses
An allowlist of names that need not resolve
the obvious first reach when a check false-positives		 This is the failure mode wearing the fix's clothes. The first entry costs nothing and every later one is added by whoever is annoyed by the red — which is exactly the person the check exists to stop. Four sources derived from the tree gave zero false positives across all 28 entries; the two names that looked like exemptions, CodeMirror and ReactNode, are a dependency and an import and resolve on their own.
Require full paths in TSDoc
so a path check needs no basename rule		 It would red JsonRenderer and XmlRenderer for citing decode.rs, which is true — the file is at src/api/decode.rs. Legislating how prose spells a module is a writing rule masquerading as a truth check. The question is whether the repo holds the file.
Verify a :N pin points at the right line Nothing can know what the line should say, and a check that merely counts lines passes a rotted pin while claiming to have read it. The residual is stated, not half-solved — decisions/ already writes “as it stood at <sha>” when it must pin a line, and a TSDoc that needs a line number is usually a TSDoc pointing at the wrong thing.
Add @anatomy to the registry's emitted entry
so the check could read parsed tags		 The emitted shape is consumed by every design run. Widening it to serve a checker changes what an author reads; the oracle reads raw source instead and the roster still emits 28 entries with identical fields.
Wire it into cargo xtask verify-doc Rejected on timing, not on standing: a gate change landing inside an epic the gate is judging is what E-REDESIGN's non-goals forbade. Be precise about what does not stand in its place — no hook, gate or CI runs the ui suite at all. gate0, pre-commit and pre-push are cargo-only; verify-dod reads the test/v2 note rather than re-running anything, so it checks an attestation, not a result. This check's standing is therefore an agent running pnpm test and attesting it — identical to all 768 other ui tests, no weaker, and not a backstop. verify-doc already shells out to node for the vocabulary and registry oracles, so the wiring is small and the gain is real. A later move with a named reason, not a gap nobody noticed.

What this forces

WhoWhat changes
Any WU deleting a component The collection's suite reds until every entry that named it is rewritten. DEC-16's retirement order gains the half it was missing: distil, verify the block, remove — and now, prove the survivors still resolve.
Any WU writing a docstring A component may be named before it exists only if it is being added in the same diff. A forward reference to work not yet done is precisely DEC-30's redirect with no destination.
Whoever hits a false positive The fix is to make the tree reach the name — export it, import it, depend on it — or to stop citing it. Not an allowlist.
What is still only a reader's job Three of the seven repairs named no identifier at all: “four fields”, “copy all headers”, “trawler is capturing”. A prose claim about tenancy is invisible to a token check, and no attempt is made to pretend otherwise — the check narrows the surface, it does not close it.
