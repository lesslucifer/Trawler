DEC-4 Plan/result quality is a checklist verified by the harness at authoring time — never a template, never a git hook

Statusaccepted · 2026-07-05

Context

Plans and result reports had no defined minimum: quality was judged by taste, per-session, and nothing at all was produced after the work. Any check an agent must remember gets forgotten; any check at commit/merge time fires after the work already stands on the low-quality doc.

Choices (each looks "fixable" — it isn't)

ChoiceWhy — do not "simplify" it away
Checklists over templatesManager rejection of fixed templates: form must stay free and task-shaped. A template optimizes for uniformity and rots into cargo-cult sections; the checklist constrains substance only.
Verification = strict exact-tag presence, no content heuristicsManager direction: "a simple section (with tag) verifying". Character floors and placeholder detection produce false positives that teach agents to game the checker; presence + non-empty + structure keeps the contract honest and the substance judgment stays with the reviews. The tag is the contract — content under a wrong tag is red on purpose, and the unknown-tag guard names the likely typo so the fix is obvious.
Harness hooks (PostToolUse + Stop), not git hooksManager rejection of git hooks: "commit/merge time is too late — the work is already done on a low-quality doc". The harness executes the check, not agent memory, and in an AI-first repo every author is a harness session, so authoring-time coverage is total.
The write itself is never blocked; drafts (data-status="draft") are silentA doc is written many times before it lands — blocking or nagging mid-authoring is pure false positive. The flip to ready is the checkpoint; from there every edit re-verifies and the Stop hook refuses to end a turn on a red ready doc.
Ungoverned docs (no data-artifact) are ignoredPre-standard docs are skipped, never retrofitted — the standard governs docs that opt in by declaring themselves, so it can land without rewriting history.
Verdicts are never stored — no note schema, no gate changeThe check is re-runnable on any doc at any time; storing its result would only create a stale copy of what one command recomputes.

Consequences

A red ready doc interrupts its author in the same breath as the write, and a turn cannot end while one exists in the tree — so forgetting is not a failure mode. The escape hatch (flip back to draft) is deliberate and visible: a doc left draft while work proceeds on it is a review finding, not a mechanical one. New harness sessions pick the hooks up from versioned .claude/settings.json; sessions started before the hooks landed don't run them — the Stop backstop begins with the next session.
