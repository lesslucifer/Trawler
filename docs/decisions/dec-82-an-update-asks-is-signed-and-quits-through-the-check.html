DEC-82 — an update asks, is signed, and quits through the check

How an installed Trawler takes a new version: never silently, only when the owner's key signed that exact version, and only through the same quit every other quit goes through.

Only one path changes the installed app, and it passes both the signature and the quit check.

The rules

#RuleWhy
1The channel is github.com/lesslucifer/Trawler/releases/latest/download/latest.json. A launch checks it at most once a day, and only in an app installed from a bundle. Check for Updates… checks it at any time. The time is recorded in the app data dir only when a check completes (newer or up to date), from a launch or the menu; a failed check leaves it as it wasa release is what the owner publishes (Q4, Q5). A binary run from target/ has no bundle to replace. An offline launch must not silence the next day's check (F4)
2An update always asks. The dialog names the running and the offered version, and says that installing quits, clears the captured list and keeps the certificate and settings. A launch check says nothing unless it offers. A check the user asked for always answers: up to date, or why it could not checknever silent, forced or delta (Q6). A launch that fails offline is not news
3An update installs only if it verifies against the public key in tauri.conf.json and its signature names the version the channel announced (requireSignedVersion). The owner generated the key and holds both halves. The private half exists only as repository secrets, and no agent ever sees it (Q7, Q22)a channel that serves an old, genuine archive as a new version cannot downgrade anyone. Tauri CLI 2.12 writes the version into the signature
4Install stages the verified update and makes ⌘Q's quit request (DEC-77), so DEC-64's check runs, a windowless app reopening its window to ask. Only the app's end installs (quit_app or the main window's destruction): the shell stops the core it owns (DEC-69), installs and relaunches with the launch's arguments, so a --background launch comes back windowless. A quit request that cannot open its window drops the update. A quit the user cancels drops the update, and the next check offers it again (Q21). An install that fails (a read-only app folder, a declined password prompt) is told in a native dialog, and the app holds its exit until that dialog closes. The next check offers the update againan update is a quit, and leaving the machine routed through a stopped proxy is what DEC-64 prevents. An update must never install on some later, unrelated quit, and a failure must not look like a crash
5Every bundle type updates in place: the macOS .app, NSIS, MSI, AppImage, and .deb/.rpm through pkexec's password prompt (Q20)one flow, one signature check and one relaunch on every platform
6Updater artifacts are built only where TAURI_SIGNING_PRIVATE_KEY is set, which is the release workflow. cargo xtask package without it builds the installers and says the updater artifacts were skippedthe key never leaves the owner's hands, so a local package cannot sign an update
7Every updater request is https: the manifest, the download and each redirect hop. The updater is built through update::https_only (reqwest https_only, carried to the download by the plugin's client hook), so no config flag loosens itthe plugin refuses an http endpoint only in release builds and only warns for an http download URL or redirect (F7); the signature alone would still guard the bytes, but nothing about the channel should travel in clear

Known limits

LimitWhy accepted
On Linux deb/rpm, tauri-plugin-updater 2.14.1 (updater.rs 1346–1400) writes the verified bytes to $TMP/tauri_deb_updateXXXX/package.deb (a user-owned 0700 dir), then runs pkexec dpkg -i / rpm -U as root on that path. The signature covered only the in-memory bytes, so a same-user process can swap the file between write and read and turn the password prompt into root code execution. If pkexec fails, the fallback pipes the password to sudo -S, so Trawler briefly holds it. No command injection: fixed file names, Command::argupstream code, not Trawler's; a same-user attacker already owns the user's session. Recorded as an upstream limit, worth reporting upstream (F3, E-PKG2's close review)
