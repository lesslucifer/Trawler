DEC-74 — the merge into main proves the tree it creates

A merge into main is refused unless Gate 0 passes on the merged working tree, in the checkout making the merge.

Decided 2026-11-05 · E-GATEPAR2.W1 · active · widens DEC-2's GIT_* scrub

The decision

Notes first, then the tree. When HEAD is main, pre-merge-commit (and the conflicted-merge completion in pre-commit) runs cargo xtask verify-dod hook epic and, only if it is green, cargo xtask gate0 merge: fmt, clippy and the suite on the merged working tree, read from the checkout's own tree-keyed marker (DEC-54). A red Gate 0 refuses the merge commit and prints git merge --abort and the back-merge. Every check Gate 0 and lint spawn runs with no inherited GIT_*.

flowchart LR
  M["merge into main"] --> V{"verify-dod hook epic"}
  V -->|red| R1["refused"]
  V -->|green| G{"gate0 merge"}
  G -->|"marker = tree key"| C["merge commit"]
  G -->|"green · marker written"| C
  G -->|red| R2["refused · main unchanged"]
A merge into epic/* stops after verify-dod hook wu.

Why

FactConsequence
verify-dod hook checks notes, hashes and signatures, never the suite (C1)a merge went green on a tree nothing had tested
Gate 0 proves the epic tip; the merged tree is the tip plus everything that landed on main since its fork (C2)two epics, each green alone, could combine into a red main, found only at the push, after the merge commit was on a merge-only branch
Git exports GIT_INDEX_FILE, GIT_REFLOG_ACTION=merge <branch>, GIT_EDITOR, GIT_PREFIX, GIT_EXEC_PATH to the hook (probed 2026-11-05) (C10)a suite run from the hook would read the hook's merge as its own: tests that drive verify-dod hook resolve their tips from the reflog action

Rejected

AlternativeWhy not
Gate 0 at every WU seam into epic/*the epic branch is not shared; combinations meet at main, and the WU already runs Gate 0 in its preflight
Trust the epic tip's Gate 0 greenit proves a different tree whenever main moved after the last back-merge, which is exactly the red case
Share proofs between checkoutsa marker vouches for a build in its own target/ (DEC-73); the main checkout pays one suite run per merge
Strip GIT_* in the hook scriptsit would cover two hooks; Gate 0 is also run by the preflight and by shells started from a hook
Skip Gate 0 for a docs/infra-only mergethe proof is about the tree, and the suite reads docs (link integrity, the verify-doc corpus)

Consequences

  • A red combination is repaired on the epic, after git merge --abort and a back-merge of main; main never holds it.
  • The merge into main pays fmt, clippy and the suite once in the main checkout, unless that checkout already proved this exact tree.
  • The marker the merge writes is the proof E-GATEPAR2.W2's push reads, in the same checkout.
  • Held by tests/dod_hooks.rs (the hook order, refusals and the WU seam), xtask/tests/lint_spawn.rs (the spawned environment, the refusal text, the marker) and the unit tests in xtask/src/gate0.rs.
