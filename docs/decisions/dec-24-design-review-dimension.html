DEC-24 — the design review is a dimension of the code review, not a skill of its own

Where Tier-3 lives, why its verdict is cr/v3, and why a design-bearing diff is never docs-only-exempt.

DEC-24 · 2026-08-12 · Trawler · E-DFLOW.W7 · status: active

Context

DEC-15 named three tiers and built one. Tier-1 is mechanical and complete (13/13 predicates, W6). Tier-2 is the run's own receipt — a self-claim, which is exactly the thing the dev workflow has never accepted from code: never judge your own diff. Tier-3 is the missing reviewer, and the only open question was where to put it.

Choice

Tier-3 is a dimension of the existing code review, not a separate skill. A closed design goes through the same door code goes through.

How
What activates it cargo xtask design-scope <base> <head> — a closed run (data-status="archived") or a component design file present in the diff
What it judges soft rules, the new-component warrant, and the reuse warrant, on the artifact. Rubric: .claude/skills/code-review/design-rubric.md
What it excludes the thirteen hard rules (predicates own them; a second opinion is noise) · a per-rule verdict table (that is Tier-2's receipt, and re-emitting it doubles the artifact and buries the findings) · slugless taste · rulebook edits
Where the verdict lives the tip's cr/v3 note, in a design: section
What refuses it 9·design at the merge · 9·design-schema for a pre-v3 note

One function, two callers. design-scope is not a convenience — it is the refusal to let the reviewer and the gate each decide what counts as design-bearing. Two answers is how a gate and its subject drift.

The design: section — what each field refuses

The schema string is the grandfather rule

A note declaring cr/v2 says, in its own bytes, that it was written before the design dimension existed — so the epic walk drops 9·design-schema at seams, exactly as it already drops manual review there. What it does not drop is a cr/v3 note missing or short-changing its design section: that note's own schema says the dimension was available.

No date cutoff, no remembered list, no waiver. A date cannot tell a note written before the rule from one written badly after it; the artifact can. Measured: adding the rule cost zero walk waivers, against three for the rule one step earlier.

The review closing item is not this verdict: one is provenance (a human overrode the design, and here is the contract it hit), the other a judgment. Merging them loses the provenance half.

A design-bearing diff is never docs-only-exempt

The gate exempts a diff that touches no code — the rule that lets an incidental doc edit through without notes. A design is a docs-only deliverable: the most common design Working Unit writes a run, or a set of component design files, and no code at all. So the exemption was handing this check precisely the diffs it was built to judge.

The evidence, not the argument. 8173f47 — the E-DFLOW.W2 merge — landed component-design-base.html and 14 component design files, the entire registry three later design runs are judged against, with no cr note on its tip at all. Not a stale review; no review. Its test/v2 note gives the reason in its own words — "design/docs-only WU" — which is exactly the claim this rule refuses. Nothing noticed for five Working Units.

It sits beside 6·run-closed, which was already answerable at the merge for the identical reason: the Working Unit that carried the design is ending.

Options rejected

OptionWhy not
A separate design-review skill with its own note four properties rebuilt, each a chance to rebuild it slightly differently — the table above
Keep the verdict inline in the run doc DEC-16 retires the run. A judgment that dies with its subject cannot be re-read at the seam, which is the only place a merge can enforce it
Judge draft runs too Tier-3 judges a finished design. The merge that finishes a draft touches the file again, and that review judges it — so the close and the review are one motion
Judge a removed design file that is retirement, and 6·retirement-order owns it (DEC-16). Asking a reviewer to judge a contract the diff deletes is asking about the wrong thing
A date cutoff for grandfathering it cannot distinguish a note written before the rule from one written badly after it — the schema string can
A per-rule verdict table from the reviewer that is Tier-2's receipt. Re-emitting it doubles the artifact and buries the findings, which are the only thing the reviewer adds

Consequences

  • The three tiers are complete. Tier-1 mechanical (W6, 13/13) · Tier-2 the run's own receipt (shipped at W4 — the default DEC-15 held rather than answered) · Tier-3 this record. A flow e2e drives all three.
  • The finder is unproven, and W9 is its acceptance test. The planned calibration against the three archived runs was waived — they are closed under older contracts — and the replacement argument (that W7's own diff would exercise the tier) turned out to rest on a stale branch ref: W7 carries no design artifact. So everything around the judgment is tested — that it ran, over everything, against the right rulebook, and that its absence is loud — and the judgment itself has never run. W9's fresh-screen run is where it first does, and the defect class it is the sole owner of is the one run #3 shipped: whether a cited @avoid is faithfully paraphrased, which W7 ② measured as mechanically undecidable.
  • Pass the base explicitly. Both design-scope and verify-dod measure from a branch ref, and a local ref behind its remote silently measures the wrong diff — that is how the false reading above happened. Filed as a tooling follow-up; until it lands, the rule is a human one.
  • W8 inherits a timing dependency. Tier-3 fires on the merge that lands a closed design, which is before the design reaches development. Where the design gate sits relative to a UI-touching Working Unit, and what evidence it hands the build, is W8's question — and its answer cannot move the verdict earlier than the close.
  • A rule that cannot be judged as written is a finding, never a same-run loosening. The rubric forbids rulebook edits, which is DEC-15's own failure mode applied one tier up: a gate that bends converts an open defect into a green receipt.
