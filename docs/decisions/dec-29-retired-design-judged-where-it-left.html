DEC-29 — a component design the WU retired at bytes its base never held is a design artifact of that WU

Tier-3 judges every design a seam carries. Once DEC-28 lets a build cite a design the tip no longer ships, the seam that amended — or authored — that design and then retired it is the only seam that can judge those bytes, and its gate asks it to, reading them at the design's last state. The same seam owes DEC-16's retirement order for it.

Context

Found by the W2 code review, round 1. DEC-28 made History B legal — a build WU that retires the design it built from, because components·unretired forces the retirement before the tip. The moment the citation resolved through history, a second check stopped seeing the file:

Same amendment, opposite verdicts, decided by whether the WU also deleted the file. Before DEC-28 the citation refused both tips, so the asymmetry had no consequence.

A second shape has the same hole and is DEC-25 D1c's own case: a design authored, built and retired between one base and one tip. It nets out of the endpoint diff entirely — neither the artifact set nor 6·doc-note ever hears of it, and an honest archived entry for it is refused as a phantom.

Choice

At a Working Unit seam, a component design the range removed whose last state the base never held is a design artifact of that seam. The gate reads it at the last commit reachable from the tip that shipped it (the same place DEC-28 resolves a citation), demands the cr/v3 design section name and judge it, and demands the doc/v1 note record its retirement in DEC-16 order (action: archived, distilled_to). design-scope lists it beside the artifacts the tip ships and says where to read it. A design retired at exactly the bytes the base held is not an artifact here: it was judged where it landed.

Options rejected

OptionWhy not
Keep DEC-24's reading — a removed design is retirement, not a review subject true for a design retired at judged bytes, and that case stays out. For amended or authored bytes it leaves the one seam that could judge them asking nobody, while the citation half of the same check resolves to those very bytes — one check reading one file two ways
Match any historical blob for the artifact set too — every state the range held a design amended twice would be judged at a superseded revision; the last state is what the build read and what the pin must match (DEC-28 §last state)
Apply it at the epic gate as well every design an epic authored and retired would owe the epic note a second judgment. The seams already judged them, and the walk re-asks each seam at its own tip
Leave the one-WU retirement order unenforced, as a follow-up the gate would recognise the design for Tier-3 and stay blind to it for DEC-16 — and refuse the honest archived entry as a phantom. Recognising a file in one check and denying it in the next is the misdirection this epic exists to remove

Consequences

  • DEC-24 is superseded on two clauses: "a component design file present in the diff" now reads the range's last state for a design the WU retired at bytes the base never held; the rejected option "judge a removed design file" holds only for a design removed at the bytes it was judged at. Everything else in DEC-24 stands.
  • DEC-16 reaches the one-WU design: the archived entry with its distilled_to is owed for a design the endpoint diff never shows, and 6·retirement-order reads it as for any other. Its consequence "a removed design file is not a Tier-3 artifact" is superseded for unjudged bytes — such a file is both checks' business; the order and both predicates stand.
  • DEC-25 D1a and D1c hold as written — this record is how they hold once DEC-16 forces the retirement into the build WU.
  • The truth is the code. xtask/src/gate.rs owns the artifact set (retired_designs, joined into design_artifacts for design-scope and the gate alike); this record owns why.
