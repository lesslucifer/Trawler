DEC-92 — the site is a build of the tree and the latest release

The project site is a hand-written frame whose every repeated fact is filled at build time, published by Actions, and it makes no request outside its own origin.

The rules

#RuleWhy
1Address https://lesslucifer.github.io/Trawler/, one constant site::BASE_URL (canonical, OG image, the installers' homepage via DEC-87 rule 4); no custom domain, no CNAME, no sitemap or robotsowner ruling Q1; crawlers read robots only at the host root
2A hand-written frame in site/, every repeated fact filled at build: README pitch (h3), sub line, features heading and shot alts; PRIVACY.md's lead; links.rs guide and source URLs. The markdown renderer is a subset that refuses anything else. GUIDE, full PRIVACY, CHANGELOG, CONTRIBUTING are links to blob/main, never copiedQ2 (option C), Q6: one fact per tier, a drift is a red build, not a stale page
3Downloads are read at build time from releases/latest, never by the visitor's browser; links are versioned (releases/download/v‹x›/‹file›); the build refuses a draft, a pre-release, a missing Os::bundles kind or a version above the workspace's; a releases/latest link and SHA256SUMS are always shownQ3: a client-side API call tells GitHub who reads the page; a latest/download/‹name› link breaks on the next version
4No request outside the origin: the exact CSP meta site::CSP on every page; no absolute src/srcset, CSS url() or @import; no iframe, form, inline script or style, on…=; no analytics, cookies or storageQ4; the product's local-only promise (DEC-91 rule 7) holds on its own site
5One script, same-origin site.js (≤ 4,096 B, site::SCRIPT_BUDGET): OS detection only; no network, storage or code-from-string API; the page is complete without it (no script or an unknown system = the full file list, open)W1 pick D2; a scan refuses the APIs that could leak
6Assets only from site::ASSETS: the DEC-89 generated favicon, dark wordmark and social card, and README screenshots, every PNG re-encoded to the same pixels; system font stacks, no font bytesQ9; nothing is redrawn, nothing is fetched
7Site text is public text: DEC-91 rules 1–2 (one voice, deny-list over every built text file); English only, lang="en"; <title> and description = the README pitchQ5, Q7, W1 pick VOICE
8Look: themes by prefers-color-scheme only (no toggle); every text/background token pair ≥ 4.5:1 per theme and token scope; motion only under prefers-reduced-motion: no-preference, never infinite, settled within 5 s; amber only as glow decoration (DEC-89 rule 6)W1 picks LOOK, HERO, ACCENT; a toggle needs script and storage
9.github/workflows/pages.yml deploys: on push to main, release: published (a pre-release skips both jobs) and dispatch; it reads releases/latest, never the event payload; uploads target/site only; contents: read at the top, pages + id-token write on the deploy job only, environment github-pages; concurrency pages, never cancelled; actions pinned by SHAQ11; a branch or folder source would publish docs/ or the whole repo; it publishes, it gates nothing (DEC-83)
10Nothing else redeploys it: a release on a tag whose commit lacks pages.yml, a pre-release edited into the final (an edit is not published) and an older-line patch each leave the site as it was until gh workflow run pages.yml or the next push to maina release event runs the workflow file at its tag; the steps live in release-process
11site/ is a code path (notes::is_code): the code review covers itQ13: the site carries a script
