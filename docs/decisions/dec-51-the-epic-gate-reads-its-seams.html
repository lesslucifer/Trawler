DEC-51 — the epic's own review is load-bearing

E-SIMPWF.W9 set out to stop the epic gate re-reviewing code its seams had already cleared. Four rounds of its own review found four ways code reaches main that the seams do not cover. The cut is withdrawn; this record is the enumeration it cost, so the next attempt starts from a reading rather than a premise.

Withdrawn 2026-09-16 · E-SIMPWF.W9 · never shipped — the gate behaves as it did before

Status

Withdrawn before landing. No rule changed. The epic gate still runs 3·review, 3·review-nits, 4·review-base and 5·diff-binding over its own base..tip diff, exactly as before. Nothing in workflow.html, DEC-2 or the gate's check list was left changed by the attempt.

What did land from the same Working Unit is DEC-50 — the dimension cut and relevance-batched verifiers — which is independent of this and produced no holes.

The premise, and why it was wrong

The proposal rested on one sentence: an epic's diff is the union of seams every Working Unit review already cleared, so the union adds no subject. The corpus supported the value claim — 29 epic rounds returned 1.79 verified findings each against the WU level's 3.37, with 41% returning nothing. It said nothing about the role claim, and the role claim is the one that mattered.

A round that returns little is not the same as a check that guards nothing. The epic's review was a backstop: its binding is the plain two-dot base..tip code hash, which covers every byte reachable from the tip however it arrived. The seams' bindings are parent-to-parent diffs, and their union is strictly smaller.

The four holes, in the order the rounds found them

Each was reproduced against a real binary, and each is a case where code reached main with no review anywhere in its history. Rounds 2 and 3 were fixed and the fixes kept finding more; round 4 ended it.

#How code arrivesWhy the seams miss it
1A standalone commit inside the epic's range The walk checks it at Level::Commit, which has never demanded a review. CLAUDE.md and the gate have always permitted such commits with only a test/v2
2A standalone commit that is the epic tip DEC-2 has the walk skip the tip — one commit cannot carry both an epic-level and a commit-level test note — and justified the skip by saying the tip's diff is covered by the epic gate itself. That justification was this review
3Bytes a merge commit carries of its own, present in neither parent — a hand-resolved conflict, or any edit between git merge --no-commit and the commit The walk verifies wu_tip against mainline. Bytes that exist only in the merge commit's tree are in neither endpoint, so no seam diff can contain them. This is the case no per-commit check can reach, and it is why the endpoint diff is irreplaceable
4A rendered UI file in a standalone commit at the epic tip check_ui_outside_a_wu runs only at Level::Commit and the walk skips the tip, so 9·design never asks. Pre-existing, not opened by the attempt — recorded here because the same enumeration surfaced it

Hole 3 is the one that decides the question. Holes 1, 2 and 4 are positions, and a position can be patched — each has a commit you could hang a review on. Hole 3 has no such commit: the bytes belong to a merge, and a merge's content is exactly what parent-to-parent diffing cannot see. Any replacement for the epic's endpoint review must cover it, which means a binding over the endpoint diff — which is the thing being removed.

This is also the guarantee DEC-2 states in as many words: "smuggled content turns the next gate red." The attempt gave that up without noticing.
