DEC-86 — a tag ships every platform, as a draft the owner publishes

How a pushed v* tag becomes installers and an update channel, and what can stop it.

The flow

flowchart LR
  T(["tag v‹version›"]) --> V{"= workspace version?"}
  V -- no --> X["red · nothing built"]
  V -- yes --> K{"signing key set?"}
  K -- no --> X
  K -- yes --> B["× 5: rustc host check → package --build-only → package --bundle-only (key) → smoke → upload"]
  B --> R["release-manifest → draft release"]
  R --> P(["owner publishes"])
One red target means no draft: the release job needs all five builds.

The rules

#RuleWhy
1release.yml runs on a v* tag push and nothing else. Its first job fails unless the tag is v plus [workspace.package] version; it rewrites nothing (Q18)the released binary is built from exactly the tagged, gate-proven tree. A dispatch has no tag to check
2Five targets build with cargo xtask package: macOS universal, Windows x64 and arm64, Linux x64 and arm64 (Q16). Not tauri-actionDEC-81 rule 3: the one command that builds an installer also verifies it. A second build path would skip that
3Each build runs cargo xtask smoke before its upload: the package's own installer is installed in a temp dir, its core runs headless, a request through the proxy is captured, the CA is served, and quitting frees both ports. The macOS packaging test runs the same commanda red smoke uploads nothing. One code path runs in the gate and in the release
4The signing key and its password reach only the --bundle-only step, by secret name (DEC-82 rule 6); pnpm install, vite and every build.rs run before it in --build-only, keyless. The first build step fails when the key secret is empty. The job token is read-only except in the release job, and no checkout keeps it in gitleast privilege: third-party build code never sees the key; no agent ever holds the key
5cargo xtask release-manifest writes latest.json with an entry per target and install kind (deb and rpm included, Q20), signatures and tag-scoped URLs, plus notes headed by each OS's first-open steps (.github/release-notes.md). It refuses a missing .sig or targeta partial release never reaches a draft, and an update never meets a platform with no entry
6The release is created with --draft, never --prerelease; publishing the draft is the release (Q5)releases/latest/download skips prereleases, so a prerelease would not reach installed apps. The owner may tick it by hand on a draft nobody should update to
7A version is ≤255.≤255.≤65535 with at most a numeric pre-release ≤65535: rcs are 0.1.0-1, 0.1.0-2, never 0.1.0-rc.1. cargo xtask package's version check calls anything else driftWiX (tauri-bundler convert_version) maps the pre-release into the MSI's fourth field and refuses a non-numeric one; NSIS only warns. No wix.version override to keep in sync
8Every action is pinned to a commit SHA (version in the trailing comment); no cache is restored; each runner's rustc -vV host must be its row's (Windows arm64 really builds arm64); one release per ref runs at a time, never cancelleda moved tag or a poisoned cache cannot reach a signed release; an emulated x64 toolchain cannot ship as arm64
9The release job downloads each artifact into its own folder and flattens with mv -n; a leftover folder (two artifacts sharing a name) is red. A re-run deletes a pre-existing draft of its tag before creating; a published release makes the create failno silent overwrite; a re-run never needs hand cleanup and never touches a published release

Known limits

LimitWhy accepted
The version job proves tag = workspace version, not that the tagged commit is on main or green in CIonly the owner tags; the merge gate already proves every main tree
The smoke passes the NSIS /D= destination through Rust's argument quoting, and the silent installer has no own timeoutthe runner temp path has no spaces, so no quote is added; a hung installer is ended by the job's 90-minute timeout. Windows-only, cannot be proven off a Windows runner

Held by

xtask/tests/suite/release_workflow.rs pins rules 1 to 4, 6, 8 and 9; package's unit tests pin rule 7 and the keyless build split (and the toolchain of DEC-85, which now also covers release.yml's jobs: a bump changes rust-toolchain.toml and every toolchain: line in ci.yml and release.yml). The release_manifest and smoke unit tests pin rules 3 and 5. The run itself needs GitHub, the secrets and a public repository, and is proven by the first rc tag (E-PKG2.W6).
