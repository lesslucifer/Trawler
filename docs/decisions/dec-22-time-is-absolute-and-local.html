DEC-22 — every time Trawler shows is absolute, local, 24 h, seconds-precision

One driver decides all four: a debugging proxy is read side by side with server logs, a terminal and a system clock. Every rejected alternative makes the user do arithmetic before they can correlate.

DEC-22 · 2026-08-12 · Trawler · E-DFLOW.W7 · distilled from TimestampText F1–F4 · status: active

Context

Four independent forks on one component — absolute vs relative, ms vs seconds, local vs UTC, 24 h vs 12 h — settled the same way for the same reason. Read separately they look like four formatting preferences; read together they are one product claim about what the app is for, and it binds every future surface that shows a time.

Choice

ForkSettledThe correlation cost of the alternative
absolute vs relative Absolute HH:MM:SS; relative is opt-in per call site (format="relative") "2 m ago" must be subtracted from now before it matches a log line, re-renders on a timer for every visible row, and goes ambiguous after a few hours. Opt-in confines the 10 s re-render tick to surfaces that asked for it
milliseconds Seconds by default, truncated not rounded; ms via the custom format 12 chars exceeds the list column at the current font size, pushing the host and path columns or triggering truncation. Sub-second ordering within a burst is already carried by list insertion order, so ms in the default adds width with no gain
timezone Always local — every mode, no UTC prop and none planned UTC forces the user to add their own offset before matching a local log line. Useful only if target servers always log UTC and users never use local tooling
12 h vs 24 h 24 h, pinned by the format string over any locale default An AM/PM suffix adds 3 chars, breaking the 8-char stability contract and the column. The shipped toLocaleTimeString() call takes no options, so a US-English locale produces "2:07:52 PM" — 11 chars with variable leading-zero behaviour
Truncate, never round. Rounding to the nearest second can display a time one second ahead of the event, which is the one error a log-correlation tool must not make.

Options rejected

OptionWhy not
Relative as the list default Rejected as a default, kept as a mode. Recency matters on some surfaces; log correlation matters on the list
A hybrid default — relative for recent, absolute after a threshold A branch point with no gain for a debugging tool: it makes the same column mean two things depending on age
A UTC mode or preference Rejected outright, not deferred. A preference implies both readings are useful; only one is, for this product
Locale-default time Unstable width and an unfamiliar format for log correlation. The pinned format string overrides it deliberately

Consequences

  • A new surface showing a time inherits all four defaults. Wanting something else means wanting the custom format prop (format="HH:mm:ss.SSS", format="hh:mm:ss A") — no new fork, and no new component.
  • The 8-char output width is a contract, not an observation: the list column is sized to it, so anything that widens the default reopens the column.
  • The date library that renders all of it, and its exit path, is DEC-23.
