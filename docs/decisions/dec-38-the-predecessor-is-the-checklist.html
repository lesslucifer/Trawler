DEC-38 — a re-run's close walks the run it supersedes, because a dropped answer is not reviewable from the near side

Every review a design run gets asks whether the run's own statements are true. That question cannot reach an answer the run stopped making — there is no statement to test. So a re-run closes by walking its predecessor and classifying every answer in it, and the design flow makes that step ①.

DEC-38 · 2026-09-07 · Trawler · E-EXPORT.W9 round 11 · status: active

Context

A re-run inherits a predecessor's answers and is trusted to say which ones moved. Two failure shapes follow, and only one of them is reviewable:

What the re-run didWhat it leaves behindCan a reader of the new run find it?
Changed an answer and said soa delta notenothing to find — it is disclosed
Changed an answer silentlya false statement, or two statements that disagreeyes — read the document and test it
Dropped an answernothingno — every statement present is true, and the absent one has no location to be wrong at
The third row is the whole record. Reviewing the new run is a search over statements; a dropped answer contributes none, so the search space does not contain it.

E-EXPORT.W9 ran the experiment without meaning to. It re-ran a superseded design over sixteen review rounds, and the rounds divide exactly on which document they read:

RoundsWhat they readInherited answers found moved in silence
1 – 7, 9, 11 – 14the new run only, asking whether its statements were true0 — and every statement they tested was true. They found other defects, in quantity; none was an inherited answer
8one inherited answer, checked against the predecessor1 — the predecessor had the focus answer right and the re-run had flipped it
9bthe same, one answer further1
10the predecessor end to end, every answer classified4, each of which had survived every earlier round
Six in total, and every one of them from one of the three rounds that opened the predecessor. The thirteen rounds that did not were not careless; they were asking a question that cannot return these six.

Choice

When a design run supersedes another, closing it begins with a walk of the predecessor: stage by stage, over the old run, classify every answer in it as held, changed, or dropped. The predecessor's answers are the checklist, and an unclassified one is the defect. A held answer is cited rather than left to be inferred. This is close step ① in design-flow, and it is first because the later steps all read the new run.

Nothing machine-checks it. Tier-3 is the only reader that can, and it must be handed the predecessor's path — a reviewer given only the new run is structurally in the position of the thirteen rounds that found none of the six.

Options rejected

OptionWhy not
Leave it to the review — reviewers should walk the predecessor they will, once told which document that is and that the walk is owed. Absent both, the review reads what it was given; W9's thirteen new-run-only rounds are the demonstration. The obligation has to sit where the predecessor's identity is known, which is the run's own close
Make it a receipt item — a table of the predecessor's answers with a verdict each the receipt is the run's claim about itself against the rulebook, and its coverage is checked against the rulebook on disk. A predecessor is not a rulebook and has no fixed row set, so the check would be the walk, unverifiable, wearing a checked item's badge
File it as a vocabulary Proposal — how W9 first recorded the lesson Proposals is for entries the design needed and the vocabulary lacked. A process step is not vocabulary, and filing it there leaves the flow unchanged while looking as though something landed
Put the numbered step last, after the run is otherwise green the walk is what tells the later steps what to fix. Run it last and its findings arrive after verify-doc and the archive flag, i.e. as a reopen

Consequences

  • design-flow §7 owns the step: ① walks the predecessor, and the four steps that were ①–④ are now ②–⑤. The step exists only when there is a predecessor.
  • Tier-3 is told the predecessor's path. That is the only reader that can refuse an unclassified answer, and it cannot do so from the new run alone.
  • A held answer is cited, not silent. Silence is indistinguishable from a drop, so the walk's output is text in the run, not a private pass.
  • The incident stays here. The flow doc states the mechanism; the six reversals, the round-by-round split and the design they were about are E-EXPORT.W9's own record — this record is where that history is kept.
