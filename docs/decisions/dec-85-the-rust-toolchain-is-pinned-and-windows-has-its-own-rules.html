One compiler everywhere, and the rules the first green three-OS run taught.

The pin

#RuleWhy
1rust-toolchain.toml pins an exact version (1.99.0, with clippy and rustfmt), and every ci.yml job installs the same versionCI floated to the newest stable while the Mac ran 1.97, so clippy lints differed between the two and a tree green locally went red on CI
2A bump is one commit that changes rust-toolchain.toml and every toolchain: line in ci.yml together, with the tree clean under the new clippythe ci_workflow suite fails when the file and any job disagree, or when the version is not exact

Windows rules

RuleHolds because
tauri-plugin-wdio-webdriver stays locked at 1.5.1, and Cargo.lock holds one webview2-com and one windowstwo versions made the plugin's COM types incompatible with webview2-com's; ci_workflow checks the lock
The app build script launches pnpm.cmd on Windowsa bare pnpm is a shell shim Command cannot spawn
The build script embeds the Common Controls v6 manifest into test executables on MSVCtauri-build passes the manifest link argument to binaries only; an integration test without it dies at start with 0xc0000139
Test helpers and imports used only by Unix tests are cfg(unix)Windows clippy runs -D warnings, so dead code and unused imports are errors there. Tests that need sh, hooks or /tmp are Unix-only
Mock-runtime invoke tests send the platform's local app origin: tauri://localhost, and http://tauri.localhost on Windowstauri treats any other origin as remote and refuses the app commands
.gitattributes holds * text=auto eol=lffixtures and snapshots are LF bytes; a CRLF checkout fails them. ci_workflow checks the line

Held by

xtask/tests/suite/ci_workflow.rs pins the toolchain agreement, the lock and the attributes line. The rest is held by the Windows job of ci.yml (DEC-83): a signal, not a gate.
