DEC-15 — a design run is a governed artifact; hard rules are predicates, not claims

How a design run is enforced: what the machine checks, what stays human, and why the receipt covers only the rules a machine cannot judge.

DEC-15 · 2026-07-26 · Trawler · E-DFLOW.W4 · status: active

Context

The design flow's conventions were written down and then broken by the agent that wrote them — three times inside one Working Unit: the interactive element map was lost, component CSS was re-typed instead of composed, and a hand-written satisfied was recorded against a rule the same mockup was breaking. Each failure happened after the rule existed in the flow spec. A convention an agent must remember is a convention an agent forgets.

Choice

A design run is a fifth governed artifact (data-artifact="design-run"), checked by cargo xtask verify-doc on every write and at every turn end through the existing doc hooks. Three parts, each load-bearing:

RuleWhy
The receipt covers soft rules only; a hard slug in a receipt is reda rule with a Tier-1 predicate is judged by the predicate. The receipt exists for what a machine cannot judge — a hand verdict on a machine-checkable rule is the one row that can be wrong for free, and was: the run wrote satisfied against spacing-scale while its mockup re-typed three components' padding on-scale. Every hard verdict is instead a predicate, a finding with an owner, or a proposal
Coverage is read from the rulebook on disk, never from a copyadding, killing or retagging a rule re-opens every receipt automatically. Every slug exists in exactly one place — the count is deliberately not stated here, because the rulebook is living and a number in an append-only record rots — and a receipt that cannot be checked (unreadable rulebook) is red, never silently green
The unimplemented gap is printed, not filed — hard rules: n/m machine-checked on every green run, both numbers computeda follow-up row rots; a computed line cannot. The denominator moves when the rulebook grows and the numerator moves as predicates land, so the worklist maintains itself

The receipt is YAML parsed by serde_yaml — the same #[derive(Deserialize)] path every gate note already uses — with a fixed seven-verdict enum: satisfied · inherited · satisfied-via-proposal · blocked · n/a · violated · violated-inherited. The last exists because a screen that composes a violating component must not read as the violator: without it, re-authoring a component's CSS turns a red row green, hiding a substrate bug and forking the component in one stroke.

A doc that cannot render is not a governed doc (E-DFLOW.W10). Every governed doc carries the two things the htmldoc skill owns — a minted data-htmldoc-id on <html> and the htmldoc.js bootstrap that injects doc.css — and htmldoc·id / htmldoc·bootstrap refuse a doc without them. They run before the exempt gate, because a draft and an archived run both still have to render, and this is the one property no later predicate can see: a layerless doc has every structure the others read, and every var(--…) it writes resolves to nothing. Both are checked where the runtime reads them — the id on the root element (document.documentElement), the bootstrap at its canonical origin — because a check that accepts the id anywhere, or any file of that name, passes the doc whose comment and diff layers are dead. Scope is the governed set: an ungoverned page stays silent, which is the doc hooks' standing promise.

Composition is checked too, because reuse that is only asserted is not reuse: the Elements catalog must be a keyed data-map, the mockup must carry a state toggle, both shared specimens must actually be loaded (the attribute, not a prose mention), and the run doc's own CSS must hold no colour literal — which is colour-tokens-only's own Tier-1 predicate, implemented.

What the gate does not prove

The harness proves a receipt is complete and well-formed — never that it is true. Whether a verdict is honest, whether a fit judgment holds against a component's @use/@avoid, whether a violation was recorded or quietly fixed, whether a Frame driver is case-specific or a restated rule: none of it is mechanical. It is Tier-3's, and Tier-3 is the design dimension of the code review, recorded in the tip's cr/v3 note (DEC-24, W7). A green design run is not a good design.

What makes a false row expensive to write is composition — a mockup built from the design files' own specimen CSS renders what the registry actually agreed to, so a contradiction shows up as pixels instead of prose. The checker only makes an absent row impossible.

Consequences

  • W6 settles four hard rules before they can have honest predicates: the spacing floor, DEC-11's syntax tokens, a hover-wash token name, and overflow-declared's granularity.
  • W7 implements the remaining twelve predicates and must not rebuild what landed here — soft coverage, the enum, colour-tokens-only, the composition checks. Superseded: W6 built all twelve. Tier-1 reads the config, so DEC-17's closed vocabulary is its input — building the predicates first would have pinned legality to the open config they were meant to catch. The ordering was a dependency, not a queue. The gap line now prints hard rules: 13/13 machine-checked (design), and colour-tokens-only widened from grepping literals to reading the config. W7 keeps Tier-2 self-reflex, Tier-3 adversarial review and the flow e2e — W7 closed all three, and nothing rebuilt what landed here.

Neither judges the build against the design — that would be a hand verdict on an unmeasured property, which is the row this record refuses in its own receipt.
  • The flow is covered end to end. xtask/tests/e2e_design_flow.rs drives a fake human and a fake designing agent through all three tiers over a real git tree — the epic test level W1 through W6 each waived in identical words. Writing it found two live holes in this model's own enforcement, which is the same lesson as everything else in this record: a check that has never been executed against an artifact built to break it is a claim.
  • The completed tier is one surface, not two. 13/13 is machine-checked (design) — the label is printed, because the same rules bind built components too and that surface is the design/vocabulary ESLint rule, not this gate. Which surface owns a rule is the rulebook's binds axis (DEC-17).
  • Truth lives in xtask/src/doc.rs. The flow spec describes the checks for a reader; where the two disagree, the code wins, and a run doc's tally line is generated so it cannot drift.
  • A finished run is archived, not retrofitted. Every predicate reads the live rule set, so tightening a stage's form re-opens runs that closed before the rule existed — a later run's form checks red the runs before it — measured rather than assumed. Reopened today, run #2 reds on 30 checks and run #3's form checks are three of them; run #1 reds on 12, of which 10 are missing items because it predates the item-tagging convention entirely, and the other two are a missing specimen and an undeclared payload. Both are records of what the flow was rather than work anyone will redo, and the numbers move every time a predicate is added — which is the point, not a defect. data-status="archived" exempts a run for the opposite reason to draft: finished under an older contract, not unfinished. A run still open is never archived — that hides exactly the reds the flow exists to surface. Nor is the newest one, which the checks are calibrated against: its tests pin that the predicates hold on a real artifact, and archiving returns Draft before any check runs, so the pins would pass vacuously. Amended in W6: that rule was the wrong instrument for a real hazard. Leaving the newest run live is what left run #3 red in the tree for two Working Units — closing a run was nobody's step, so it never happened. A finished run is archived when it finishes, and the vacuum is closed where it actually occurs: a pin that reads a real artifact lifts the flag itself and asserts the lift changed something, so the day a run stops being archived the pin fails instead of going quiet. Mutation-proved in both directions. The hazard was never archiving — it was a pin that cannot tell an exempt doc from a clean one.
  • A predicate's vocabulary is closed; the artifact is the suspect. Because every check is born from a run that broke it, the tempting fix when it reds is to widen the check — and run #3 did exactly that, adding a fourth capability state so its own "dropped, then recovered" row would pass, in the same commit that introduced the rule. The code then contradicted this record and the flow spec, and the gate certified the defect it was built to catch. cr/v2 caught it; the author did not. An outcome that does not fit a predicate's vocabulary is the run reporting something under-designed, so loosening one is a rulebook change needing its own reasoning — never a same-commit accommodation of the artifact that tripped it. A gate that bends is worse than no gate: it converts an open defect into a green receipt.
  • A run's own failures are the check inventory. Every predicate added after the first round exists because a run shipped the defect it catches — the inert element map, a reuse that cited @use and violated two @avoids, a Tune stage of prose, a received capability designed away. This is the model working as intended rather than a sign it was under-specified: a convention only earns a predicate once it has been broken, and the break is what tells you what to measure.
