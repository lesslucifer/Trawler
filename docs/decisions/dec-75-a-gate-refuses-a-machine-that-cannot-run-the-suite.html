DEC-75 — a gate refuses a machine that cannot run the suite

Before Gate 0 runs its checks it proves the machine: cargo-nextest present, and a freshly linked binary first-launching within 2 s. A failure names the machine's fix, never the tree's.

Decided 2026-11-05 · E-GATEPAR2.W3 · active · complements DEC-74 · evidence: push timing report

The decision

Machine first, then the tree. On a marker miss, Gate 0 (gate0, gate0 merge, gate0 push, the preflight) checks cargo nextest --version, then links a nonce-bearing tiny program with $RUSTC and waits at most 2 s for its first launch. Either failure exits 2 with its fix line and runs no check. The suite runs only through cargo nextest run --all. TRAWLER_ACCEPT_SLOW_LAUNCH=1 skips the probe.

A marker hit runs neither check. The override goes straight from nextest to the checks.
RuleWhy
Exit 2, not 1, and gate0 merge/push do not append their tree refusala red tree tells the agent to abort and back-merge; a slow machine is fixed in System Settings, and the merge is retried as it stands
A fast verdict is cached per boot at $XDG_CACHE_HOME or ~/.cache /trawler/launch-fast (the boot key, not a bare verdict)a fast machine pays one link; the assessment backlog is machine state, so a reboot measures again
A slow verdict is never cachedenabling Developer Tools takes effect on the next run, with no cache to clear
The probe never waits past 2 s; the launch is timed on another threadthe assessment can block inside the spawn; the refusal costs the link plus 2 s, not the 21 s median wait
Threshold 2 sslow machine: 4.8 s minimum first launch · fast machine: 0.01–0.06 s

Why

FactConsequence
Each freshly linked binary's first launch waited a median 21 s on a Gatekeeper scan (C6, F1)a 15-minute suite; launches past a 10 s test deadline were false reds (F3)
Without nextest Gate 0 fell back to serial cargo test --all (C7, F5)no overlap of launch waits, and one red binary hid every later one

Rejected

AlternativeWhy not
Keep the cargo test fallbackit is the slow path the report measured, and two runners make two suites
Probe on every runa fast machine would pay a link per miss for an answer that does not change within a boot
Cache per checkout under target/the wait is the machine's, not the build's; seven worktrees would each pay it
Change macOS security settings from codeout of scope (epic non-goal); the gate only names the setting

Consequences

  • Every contributor machine needs cargo install cargo-nextest --locked before its first suite-running gate.
  • nextest runs no doc-tests: Gate 0 runs none on any machine (it ran none already where nextest was installed). E-GATEPAR2.W4's guard fails a crate that gains a runnable example.
  • Held by xtask/tests/suite/lint_spawn.rs (the real xtask gate0 against cargo and rustc shims) and the unit tests in xtask/src/launch.rs and xtask/src/gate0.rs.
