DEC-73 — each worktree builds into its own target; only third-party artifacts are shared

Worktrees no longer share one target/. Third-party build artifacts are still shared, as APFS copy-on-write blocks.

Decided 2026-11-05 · E-GATEPAR.W2 · active · reverses the ~> target symlink in .gitworktreecopy

The decision

Every checkout's target/ is a directory of its own. A new worktree's target/ is seeded: an APFS clone (cp -c, mtimes kept) of the main checkout's third-party artifacts, without any workspace-crate artifact, incremental/, uplifted binary or gate marker. Off macOS it starts empty. A gate in a checkout whose target is a symlink is refused.

flowchart LR
  A["worktree A"] --> TA["A's target/
own crates + incremental"]
  B["worktree B"] --> TB["B's target/
own crates + incremental"]
  TA -. "APFS clone: third-party blocks shared" .- TB
Only what is identical across checkouts is shared, and it is shared as blocks, not as a path.

Why — sharing was unsound, not only slow

FactConsequence
A workspace crate's artifact hash is the same in every checkout, and freshness is judged by mtimeworktree B's build can accept A's artifact as fresh and link A's code
Uplifted binaries (target/debug/xtask) carry no hashwhoever built last owns the binary every worktree's gates run
Met live in E-GATEPAR.W1clippy linted another worktree's xtask lib; 4 false test reds ran another worktree's binary
Shared tree measured 2026-11-05: 72 GB — 727 workspace-crate hashes, ~828k leftover .rcgu.o, ~17 GB third-party, 12–20 GB incremental/the sharing saved little that a clone of the third-party part does not

Commands

CommandDoesWhen
cargo xtask target seedthird-party-only clone into an absent target/post-checkout, via the source checkout's built xtask
cargo xtask target isolate [<checkout>]replaces a symlinked target with a seeded one; leaves a directory aloneonce per pre-E-GATEPAR worktree
cargo xtask target prunedrops workspace-crate artifacts and incremental/, keeps third-party, prints bytes and volume free space before/after; folds a legacy target/.gate-tally into the common-dir tallyany time the tree grows; once after the sync

Rejected

AlternativeWhy not
Keep the shared target/unsound (above)
Symlink only the third-party partscargo keeps both kinds in the same deps/, build/, .fingerprint/, distinguished only by hash, so no directory symlink can separate them
sccachea service to run and debug for a saving the clone already gives
Change the dev profile's debug infonot needed yet: if the leftover objects grow back, prune is the fix

Consequences

  • Gate markers (.gate0-green, .lint-green, DEC-54) are per worktree, so one worktree's green no longer overwrites another's (cause C5).
  • The gate tally (DEC-42) moves to <git-common-dir>/trawler-gate-tally, so a machine still keeps one tally.
  • A seeded worktree's first build compiles only the workspace crates. Measured: 13.6 s for 3 crates; prune freed 65.5 GiB on the main checkout.
  • Held by xtask/src/target.rs tests, xtask/tests/suite/target_isolation.rs, tests/worktree_setup_hook.rs and the epic e2e xtask/tests/suite/e2e_gate_parity.rs.
