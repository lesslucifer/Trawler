DEC-80 — the HTML preview holds no reach

The data window may draw captured HTML, but in a frame that runs no script, loads nothing, goes nowhere and holds none of the app's powers.

Why this record exists

TodayThe risk
The app runs with no content security policy (tauri.conf.json security.csp: null), and a data window holds core:default, the save dialog and file write (DEC-76 rule 9) captured HTML is untrusted: rendered into the window's own document, its scripts would reach the app's IPC
DEC-76: the data window makes no requestan image, stylesheet, font or prefetch in the page would make one, and tell its server the page was opened

Decision. The html kind's preview renders the working copy through srcdoc in <iframe sandbox="">, with a CSP <meta> placed before any author content and meta refresh and <base> removed. It is read-only and follows the working copy. Source ⇄ preview is a toggle inside the html kind (Q10).

The guards

#ThreatGuard
1Script reaching Tauri IPC, the parent window or storagean empty sandbox: no allow-scripts, no allow-same-origin — the frame is an opaque origin that runs nothing
2A request leaving the machine: tracking pixel, CSS url(), font, prefetch, mediaCSP default-src 'none'; style-src 'unsafe-inline'; img-src data:, first in the document; DEC-76's "no request" stays true
3Navigation, form posts, popupsthe empty sandbox withholds allow-forms, allow-popups, allow-top-navigation
4A meta refresh, or a <base> re-pointing relative linksremoved before render, under any case and attribute order
5A write-back through the previewread-only; edits happen in the source view, the preview re-renders from the working copy
