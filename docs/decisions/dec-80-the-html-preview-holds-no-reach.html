DEC-80 — the HTML preview holds no reach

The data window may draw captured HTML, but in a frame that runs no script, loads nothing, goes nowhere and holds none of the app's powers.

v2 (the guards as built: form-action, links, MathML, nested content, a fixed-point clean; E-INSPWIN2.W9) · v1 · 2026-11-05 · Trawler · T2 decision · minted by E-INSPWIN2.W1 from the owner's rulings on the epic plan's Q9–Q10 · UC-9 · extends DEC-76 · active · planned as DEC-79 (DEC-next-c); DEC-80 because E-BGSVC.W1 minted DEC-77 first · built by E-INSPWIN2.W7 and W9, proven end to end by W9's J4

Why this record exists

TodayThe risk
The app runs with no content security policy (tauri.conf.json security.csp: null), and a data window holds core:default, the save dialog and file write (DEC-76 rule 9) captured HTML is untrusted: rendered into the window's own document, its scripts would reach the app's IPC
DEC-76: the data window makes no requestan image, stylesheet, font or prefetch in the page would make one, and tell its server the page was opened

Decision. The html kind's preview renders the working copy through srcdoc in <iframe sandbox="">, with a CSP <meta> placed before any author content, and every address that could take the frame anywhere neutralised before render. It is read-only and follows the working copy. Source ⇄ preview is a toggle inside the html kind (Q10).

The guards

#ThreatGuard
1Script reaching Tauri IPC, the parent window or storagean empty sandbox: no allow-scripts, no allow-same-origin — the frame is an opaque origin that runs nothing
2A request leaving the machine: tracking pixel, CSS url(), font, prefetch, mediaCSP default-src 'none'; style-src 'unsafe-inline'; img-src data:; form-action 'none', first in the document; DEC-76's "no request" stays true
3Navigation, form posts, popupsthe empty sandbox withholds allow-forms, allow-popups, allow-top-navigation, but not a frame navigating itself, so every link is aimed away: a and area (HTML and SVG) get target="_blank" and lose ping and download, a <base target="_blank"> of the preview's own is the only base, and every MathML href is removed, since WebKit treats a MathML element with href as a link (it matches :any-link) that no target retargets
4A meta refresh, or a <base> re-pointing relative linksevery meta[http-equiv] and every base removed before render, under any case and attribute order; so are template, link, nested frames and plugins, whose content the walk cannot reach
4aA serialise-and-reparse that turns cleaned text into live markupthe cleaned markup is cleaned again until a reparse changes nothing; a page that never settles is shown as inert text, not markup
5A write-back through the previewread-only; edits happen in the source view, the preview re-renders from the working copy

How it is held

LevelWhat
unithtmlPreview.test.ts: policy first, refresh and base under every spelling, links and MathML, nested content, the fixed point
e2eJ4 in inspect-window-v2.spec.ts: a page that reaches out by script, image, stylesheet and refresh reaches a local beacon unguarded and never in the preview; the real engine's :any-link over the preview's markup finds only retargeted anchors. The embedded WebDriver cannot click or run script inside an opaque frame, so the frame is measured from outside

Accepted cost

Once focus is inside the frame, ⌘F, ⇧⌘V and Esc do not reach the window (guard 1: the frame can pass no key out); the status-bar switch and ⋯ stay reachable.
